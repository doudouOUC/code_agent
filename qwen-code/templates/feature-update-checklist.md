# Feature 文档增量更新检查清单

Feature 文档是跨 PR 的长期技术方案，不应在每次日更时整篇套模板重写。Agent 应保留现有架构和叙事，只更新受当前 PR 证据影响的最小范围。

## 更新前

- [ ] 确认 PR 确实属于该 Feature，而不是只共享关键词。
- [ ] 阅读 Feature 当前结构、已有 PR 状态和代码锚点。
- [ ] 检查当前 PR 是 merged、open 还是 closed 未合入。
- [ ] 对照最新 `main`，确认历史描述是否已经被后续实现取代。

## 内容要求

- [ ] 更新背景、架构、流程或边界中真正发生变化的部分。
- [ ] merged PR 使用最终实现措辞；open PR 标明“当前 open diff”；closed 未合入 PR 标明历史观察。
- [ ] 代码锚点使用 `file:symbol` 或稳定路径，避免依赖易漂移行号。
- [ ] 写清设计决策、兼容边界、失败路径和已知限制。
- [ ] 新增 PR 引用时同步更新 Feature 总览、子文档和周报覆盖表。
- [ ] 不把 PR body、计划文档或未合入测试当作运行时事实。

## 更新后

- [ ] 搜索并清理同一 PR 的旧状态措辞。
- [ ] 检查 Feature README 与子文档的 PR 列表一致。
- [ ] 检查新增 Markdown 相对链接均可解析。
- [ ] 检查没有空章节、重复段落或遗留模板占位符。
- [ ] 检查没有纳入目标作者之外的 PR。
- [ ] 查看 whitespace diff 和最终统计，确认没有无关改动。
