## 解决了什么问题

该 PR 与 #12445 处理同一问题：内存 Tool Execution ledger 无法跨 Java 重启或多 Broker 进程保留幂等身份、取消意图、dispatch fencing、`UNKNOWN` 和最终结果。它作为平行分支继续补充 opaque JSON、数字往返、哈希碰撞和并发 fencing 证据，但在另一实现合入后不再具备独立交付必要性。

## 关闭前方案

关闭前 diff 同样新增 `JdbcToolExecutionRepository` 与 `qwen_tool_execution`，复用 DataSource、行锁、数据库时钟和 owner/generation/version fence。评审迭代修复了正指数 `BigDecimal`、fastjson2 对 `$ref`/`@type` 的解释、Float/Double 往返比较，并增加十组 dispatch/renew/cancel/UNKNOWN 并发见证和 fail-closed 哈希校验。

该分支最终由作者明确关闭，因为 #12445 已以 `d2e4cc74d5` 合入相同持久化范围，并包含经过评审的大小写敏感 execution lookup、opaque payload 与 H2/MySQL 验证。这里仍有价值的额外测试只能作为后续 focused PR 的线索，不能从关闭分支推导 `main` 行为。
