# PR #12552 最终实现：attestation 后采用本地 Runtime 进程

> PR: [feat(sdk-java): Adopt a Managed Runtime only after attestation](https://github.com/QwenLM/qwen-code/pull/12552)
> 状态：merged；最终 head `d1689c168b17`，合入提交 `3c6b614b29d6`。
> 规模：+1220 / -6，11 个文件

## 解决了什么问题

Java attestation client 已合入，但 Broker 仍缺少启动 worker、核验 ready 身份并在再次使用时确认进程存活的实际采用路径；仅把 lease 写成 READY 会错误复用失效端点。

## 最终实现方案

最终合入 diff 的 `LocalProcessRuntimeProvisioner` 生成实例/lease/seed/token，向子进程 stdin 写 boot JSON，等待读取 ready 记录，再用 Java client attestation；只有核验成功才返回 lease 供 Broker 置为 READY。Broker 对本 JVM 已有 live binding 调用 `confirm`；本地 provisioner 检查进程仍存活并重新 attestation。合入版还补了启动/超时/取消竞争测试与 Java CI 配置。该 PR 合入时 worker 只暴露 attest，Java `execute` HTTP POST 会得到不可重试 404；后续主干才挂载 v2 工具路由。PR 测试使用 Node fake worker 与 accepting transport，并非真实 TypeScript worker 的完整 Tool Runtime 链路。

## 关键代码路径

- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/LocalProcessRuntimeProvisioner.java`：启动、ready 验证、attestation 和 owned process 生命周期。
- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/RuntimeBrokerService.java`：已有 live lease 的 confirm gate。
- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/HttpRuntimeTransport.java`：新增 execute HTTP 客户端路径。
- `packages/sdk-java/runtime-broker/src/test/java/com/alibaba/qwen/code/runtimebroker/LocalProcessRuntimeProvisionerTest.java`：fake worker、404 与进程失活回归。

## 验证方式

本次核对最终合入 diff、测试与最新主干 worker 能力；本文未本地重跑 Maven。可在 `packages/sdk-java/runtime-broker` 执行 `mvn test`、`mvn checkstyle:check`；真实 worker 的 boot/attest 端到端及 Tool Runtime 执行仍需单独验证，不能从 fake worker 测试推断已交付。

## feature 文档处理

已更新 [[qwen-code/feature/managed-agents/README|Managed Agents]]、[[qwen-code/feature/managed-agents/managed-runtime-attestation.zh-CN|Runtime 身份核验]]、[[qwen-code/feature/sdk|SDK]] 与 [[qwen-code/feature/README|feature索引]]，将本地进程采用标为已合入，但不扩大为生产 Tool Runtime。

## 边界与风险

- #12552 自身没有 Tool handler、Spring/Flyway 部署装配或跨进程持久 READY reconcile/CAS 证明；后续主干已加入 worker 工具路由，并将本地 provisioner 的 kind 改为 `local-process`，但其 observe 仍不能接管非本进程持有的资源。
- 本 PR 的 Java `execute` 方法并不单独证明完整工具执行链路。
