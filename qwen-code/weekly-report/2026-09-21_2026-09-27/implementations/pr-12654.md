## 解决了什么问题

Java 产品控制面缺少 Hosted Harness 专用 client，无法以进程 generation、capability digest 和原 prompt 身份安全地创建/加载会话、提交 turn、续 heartbeat、追 SSE 与处理恢复。

## 最终实现方案

最终合入 diff 在 `qwencode` SDK 加入 `HostedHarnessClient`：构造时读取 `/capabilities`，验证 REST/private-v1、协议版本、digest 并固定 boot ID；后续 Session HTTP 与 SSE 带 protocol/boot/client headers，generation 漂移失败关闭。按调用者提供的 session/prompt 身份做创建、提交、状态/转录分页、SSE、cancel/detach/close/title 和 managed Runtime recovery；单 Session 只允许一个活跃 prompt，未知受理重试须复用相同身份、内容和 deadline。客户端 `close()` 只释放本地 HTTP/心跳/stream 资源，不隐式销毁远端 Session。Java product 的公共 Session/Event 持久投影和授权不由本 PR 实现。

## 关键代码路径

- `packages/sdk-java/qwencode/src/main/java/com/alibaba/qwen/code/daemon/HostedHarnessClient.java`：协商、代际 fence、会话操作、SSE 与 heartbeat。
- `packages/sdk-java/qwencode/src/main/java/com/alibaba/qwen/code/daemon/HarnessEventStream.java`：事件流生命周期。
- `packages/sdk-java/qwencode/src/main/java/com/alibaba/qwen/code/daemon/HarnessRuntimeRecovery.java`：恢复响应投影与未知结果边界。
- `packages/sdk-java/qwencode/src/test/java/com/alibaba/qwen/code/daemon/HostedHarnessClientTest.java`：mock HTTP 交互与失败路径。
- `packages/sdk-java/qwencode/src/test/java/com/alibaba/qwen/code/daemon/ManagedHostedRuntimeE2ETest.java`：需外部环境变量启用的集成场景。

## 验证方式

本次独立核对最终合入 diff、最新主干代码、客户端和测试条件，未本地重跑 Maven。可在 `packages/sdk-java/qwencode` 执行 `mvn test`；`ManagedHostedRuntimeE2ETest` 只有提供 `QWEN_MANAGED_HOSTED_E2E_BASE_URL` 等环境才运行，不能把测试源码当作实际 E2E 通过证据。生产接线前仍应以真实 Hosted profile 验证冷启动、取消、隔离和重连。
