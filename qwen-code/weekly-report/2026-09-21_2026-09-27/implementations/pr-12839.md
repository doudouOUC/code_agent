## 解决了什么问题

Runtime 丢失后原执行终态和 holder 清理可能被 READY/新代际校验阻断，或被证据不足的清理释放。

## 最终实现方案

终态 execution 可按原引用重放而不重新执行；LOST 清理要求 stopped-writer/loss 证据、无活跃 execution 和 live operation claim，同事务核对 binding/session/holder 后释放。

## 关键代码路径

- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/RuntimeBrokerService.java`：终态重放与 LOST 清理。
- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/JdbcRuntimeBindingRepository.java`：原代际事务恢复。
