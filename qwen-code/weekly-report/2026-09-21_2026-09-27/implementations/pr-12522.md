## 解决了什么问题

Java Broker 尚不能按已合入的 v2 契约向 worker 发起真实身份核验。单靠共享 fixture consumer 无法阻止错误 endpoint、宽松响应或身份不匹配被当成可用 Runtime。

## 最终实现方案

`HttpRuntimeTransport.attest` 对 v2 路由发送 bearer、`Cache-Control: no-store` 和 lease 头，编码 provision seed 与 workspace scope；响应受 16 KiB 上限约束。解析器只接受封闭成功对象，严格比较 lease、seed、scope 和 request identity；401/403、400/413、409、404/405 等契约失败不可重试，连接故障和 5xx 可重试。该 PR 尚未将核验接入 Broker 的 READY/reconcile 流程。

## 关键代码路径

- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/HttpRuntimeTransport.java`：HTTP 请求、bounded response 与错误分类。
- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/RuntimeAttestation.java`：成功响应身份模型。
- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/RuntimeProvisionSeed.java`：provision 时约定的身份种子。
- `packages/sdk-java/runtime-broker/src/test/java/com/alibaba/qwen/code/runtimebroker/HttpRuntimeTransportTest.java`：HTTP 与失败路径验证。
