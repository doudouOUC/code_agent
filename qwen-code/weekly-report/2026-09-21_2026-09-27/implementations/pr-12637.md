## 解决了什么问题

Java `HttpRuntimeTransport` 目前只具备 attestation；没有按稳定原调用引用发起 execute、查询 status 和 cancel 的严格客户端，Broker 无法据此完成工具结果恢复。

## 最终实现方案

最终合入 diff 在 #12630 契约基础上为 HTTP adapter 增加 v2 execute/status/cancel：请求只编码引用身份、工具名/输入或查询游标，限制 256 KiB 请求与 1 MiB 响应；响应严格校验 state、settled result、executionStatus 和序号。`execute` 要求返回 settled，`status` 的 `unknown` 保持未知而非重派。最终 7 个文件只包含 Java transport/测试及中英设计更新，不再重复提交共享 schema/fixtures；worker handler 由后续主干接线，这些 HTTP 方法不等于完整 `RuntimeTransport` 的 acquire/prepare/release 已接线。
