## 解决了什么问题

#12391 的内存 Tool Execution Repository 能约束幂等、dispatch owner、取消和 `UNKNOWN`，但 Java 重启会丢失 execution identity、取消意图和已结算结果，多 Broker 进程也没有共享账本来阻止重复副作用。普通字符串索引在 MySQL 大小写不敏感 collation 下还会合并本应不同的 execution/idempotency 标识，直接序列化任意 Tool JSON 则可能解释 `$ref`/`@type` 或损失数字语义。

## 最终实现方案

最终实现新增第四张私有表 `qwen_tool_execution` 和 DataSource-only `JdbcToolExecutionRepository`。每次 mutation 在事务中 `SELECT ... FOR UPDATE`，使用数据库时钟判断 dispatch lease，并同时校验 immutable identity、record version、owner 与 dispatch generation。过期 `PREPARED/DISPATCHING` 可提升 generation 接管；过期 `EXECUTING/CANCEL_REQUESTED` 只转为不可重放的 `UNKNOWN`；取消与权威 unknown resolution 延续内存契约。

execution call、idempotency key 和 Runtime Session 使用 SHA-256 辅助索引以适配列长与 collation，但每次读取都会复核完整明文和哈希，碰撞时失败关闭。JSON 载荷通过 fastjson2 持久化，保留显式 null、把 `$ref`/`@type` 当作不透明数据、拒绝 NaN/Infinity，并以实际持久词法比较数字；正指数 `BigDecimal` 使用普通十进制写出，避免读取时收窄或溢出。H2 与可选真实 MySQL profile 共用同一 Repository 合约。
