## 当前实现方案

当前 diff 增加私有 CSI Session/tool turn 和 native activation proof；CSI file backend 核验挂载 receipt，冻结原调用批次与文件历史，按原 journal/checkpoint 组织对话和恢复。

最新 head 已从只准备调用批次扩展到真实 Read/Write/Edit 执行：先持久提交每项 `tool.intent` 和 `await_runtime` 批次，再经原 Broker 执行；worker 核验原 activation、context、参数摘要及 Write/Edit 的 prepared history，拒绝缺失或不匹配的证据。结果发布为完整 outcome，写入 `tool.receipt` 和消息后才 resolve/consume 原等待状态，并提交结果后的文件历史快照。

冷恢复按原 writer generation 重开 journal，核对原 prompt 和已提交 receipt；只从已结算结果继续，不重新执行原工具。结果超过持久 Session 限额、历史未闭合或原证据不足时保持恢复阻塞。

本次 head 刷新主要对齐最新主干：无工具 Parts 保全已由 #13750 独立合入，不再计作本 PR 新实现；CSI request pin、first activation pin 和 native execution authorization 的迁移现为 V56/V57/V58。私有 CSI 执行及恢复范围不因 rebase 扩展。
