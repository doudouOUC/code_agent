## 当前实现方案

当前 diff 增加私有 CSI Session/tool turn 和 native activation proof；CSI file backend 核验挂载 receipt，冻结原调用批次与文件历史，按原 journal/checkpoint 组织对话和恢复。

最新 head 已从只准备调用批次扩展到真实 Read/Write/Edit 执行：先持久提交每项 `tool.intent` 和 `await_runtime` 批次，再经原 Broker 执行；worker 核验原 activation、context、参数摘要及 Write/Edit 的 prepared history，拒绝缺失或不匹配的证据。结果发布为完整 outcome，写入 `tool.receipt` 和消息后才 resolve/consume 原等待状态，并提交结果后的文件历史快照。

冷恢复按原 writer generation 重开 journal，核对原 prompt 和已提交 receipt；只从已结算结果继续，不重新执行原工具。结果超过持久 Session 限额、历史未闭合或原证据不足时保持恢复阻塞。

最新 head 进一步按完整原批次核对 Broker `executions:read-batch`：数量/顺序、执行 ID、binding/generation、input/definition bytes 摘要、原 tool.intent/checkpoint、prepared history 和原始模型调用都必须一致；只消费已结算 inline result，不重新执行文件副作用。`acceptedCsiToolInput` 将原模型参数规范为受限相对路径与字段集合，并由 `publishHostedCsiReceipt` 持久发布原 execution 的完整 outcome。

本次 diff 还包含 generic publication/retention 的原 Session guard、锁后 scope/inventory 复核和 PUT attempt 完成对账：UNKNOWN 不按成功 RETURNED 清理，read lease 关闭在事务回滚后恢复可用状态。这些仍属该大分支当前观察。#13750 Parts、#13894 普通/K1 锁序和 #13899 worker/local-process 边界均已合入，不重复计作该 open 分支新交付。

当前 head 新增 boot6/finalization handle v4 与 `qwen-csi-file-finalize/1`，不自动升级旧 boot4/5。observe 固定原 retirement/prepared commit，封 executor 准入并 join 原操作，导出 QUIESCENT execution、preparations 与文件 inventory 为 FROZEN_CANDIDATE。finalize 读取已保存 CUT，核验原 frozen/prepared/cut digest，重新对账 inventory 后关闭 executor/composition/backend/mount；descriptor 全闭合且无 pending/blocked/closeFailed 才返回 DRAINED。应用清理回执不证明 Pod/disk 已删除。

`JdbcCsiApplicationProgress`/`JdbcCsiApplicationRetirement` 同连接锁原 reservation/seal/retirement，阶段限定 SETTLING/FROZEN/CUT/DRAINED；数据库时间限制原五分钟 settlement 窗口，continuation lease 不超原 deadline。Kubernetes source gate 仅对原 UID/resourceVersion/spec 条件移除，原 Pod DELETE 接受不证明已停止。离线 inventory/file-checkpoint 只读导出，不启动或释放 worker。
