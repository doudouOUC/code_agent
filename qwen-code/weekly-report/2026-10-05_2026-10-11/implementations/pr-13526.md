## 当前实现方案

当前 diff 增加私有 CSI Session/tool turn 和 native activation proof；CSI file backend 核验挂载 receipt，冻结原调用批次与文件历史，按原 journal/checkpoint 组织对话和恢复。

最新 head 已从只准备调用批次扩展到真实 Read/Write/Edit 执行：先持久提交每项 `tool.intent` 和 `await_runtime` 批次，再经原 Broker 执行；worker 核验原 activation、context、参数摘要及 Write/Edit 的 prepared history，拒绝缺失或不匹配的证据。结果发布为完整 outcome，写入 `tool.receipt` 和消息后才 resolve/consume 原等待状态，并提交结果后的文件历史快照。

冷恢复按原 writer generation 重开 journal，核对原 prompt 和已提交 receipt；只从已结算结果继续，不重新执行原工具。结果超过持久 Session 限额、历史未闭合或原证据不足时保持恢复阻塞。

最新 head 进一步按完整原批次核对 Broker `executions:read-batch`：数量/顺序、执行 ID、binding/generation、input/definition bytes 摘要、原 tool.intent/checkpoint、prepared history 和原始模型调用都必须一致；只消费已结算 inline result，不重新执行文件副作用。`acceptedCsiToolInput` 将原模型参数规范为受限相对路径与字段集合，并由 `publishHostedCsiReceipt` 持久发布原 execution 的完整 outcome。

本次 diff 还包含 generic publication/retention 的原 Session guard、锁后 scope/inventory 复核和 PUT attempt 完成对账：UNKNOWN 不按成功 RETURNED 清理，read lease 关闭在事务回滚后恢复可用状态。这些仍属该大分支当前观察。无工具 Parts 已由 #13750 合入，不重复计作新能力；#13894 单独拆出普通/K1 锁序，#13899 单独拆出 worker/local-process 边界，均尚未合入。
