# PR #13763 最终实现：sdk-java PR 的可信验证工具链

> 规模：+971 / -17，8 个文件

## 解决了什么问题

通用 verify 容器缺少 Java/Maven，sdk-java 变更可能只获得 TypeScript 验证，或因 sibling 依赖未安装而失败。若不区分工具链、依赖准备与测试结果，就会将未覆盖的 Java 误报为已验证。

## 最终实现方案

工作流按完整 PR diff 是否触及 `packages/sdk-java/` 决定 Java 准备。在 checkout 不可信 PR 前，由 root 安装固定、校验 checksum 的 Temurin 21/Maven 3.9.11 到 `/opt/verify-java`，写 root-owned ready marker；总 verify 超时从 190 增至 210 分钟。准备失败走 best-effort 的 Not covered，不伪造 Java 覆盖。

Maven cache 在 PR 执行前只 restore，不保存 PR 产生的缓存。TS build 后，以移除 GitHub token 的 node 用户安装 qwencode/runtime-broker siblings，各有 300 秒预算并记录独立状态；失败必须写入未覆盖原因。仅可信 ready marker 存在时暴露 JAVA_HOME、MAVEN_ARGS 和 QWEN_VERIFY_JAVA。

另设 main push/manual 的可信 cache producer，使用同容器、路径和 key 填充 Maven 依赖。保存前删除 qwencode-sdk、runtime-broker、managed-agent-server 和 acp-sdk 的项目固定版本 JAR，防止旧 main JAR 掩盖 PR sibling 安装失败。verify skill 同步覆盖/未覆盖报告要求。

## 关键代码路径

- `.github/workflows/qwen-triage.yml`：diff 门禁、可信工具链、restore-only 缓存和 sibling 准备。
- `.github/workflows/verify-maven-repo.yml`：可信 cache producer 与旧项目 JAR 清理。
- `.qwen/skills/verify-pr/SKILL.md`：Java 覆盖、Not covered 与失败分类口径。

## 验证方式

本次独立阅读完整工作流 diff 与主干，未运行 CI 或源码测试。工作流回归入口为 `node --test scripts/tests/qwen-triage-workflow.test.js .github/scripts/qwen-triage-workflow.test.mjs`。检查 Java-only/mixed/non-Java diff、工具链及 sibling 失败、PR cache 不保存、不可信用户无 token、可信 producer 清除旧项目 JAR。真实 CI 还须核对 Java 测试报告和明确的 Not covered 原因，不能仅看通用 verify 绿色。

## 边界与风险

- 工具链可用不证明 Java/MySQL/OSS/物理故障门禁已执行。checksum、网络或依赖准备失败仍可能导致 Java 未覆盖。
