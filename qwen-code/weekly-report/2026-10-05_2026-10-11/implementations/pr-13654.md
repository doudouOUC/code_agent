## 解决了什么问题

大 publication 的 seal/terminal 验证占据 HTTP 请求和线程，固定请求预算可能让完整输出无法及时结算。

## 当前实现方案

当前 diff 先持久提交 PENDING verification operation，再由有界 verifier executor claim/验证；Runtime 轮询原 operation status，claim epoch/deadline fence 防止旧验证者提交。

默认 async-verification-enabled=false；需先部署 V56 并升级全部 server，开启 journal-head-authorization 后才能启用异步准入。最新 head 把 FAILED operation 也视为终态，避免失败的 prefix 验证永久阻塞 collector；所有 object 仍必须 VERIFIED，其它引用/退休保护也仍生效。CANDIDATE/QUARANTINED 对象不能据 operation FAILED 释放 bytes 或 quota。

## 关键代码路径

- `packages/sdk-java/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/store/ToolPublicationDataStore.java`：异步 submission 与 operation 状态。
- `packages/sdk-java/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/store/ToolPublicationVerifier.java`：有界后台验证。
- `packages/sdk-java/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/store/ToolPublicationRetentionStore.java`：FAILED operation 的终态资格和 object_verified 清理屏障。
