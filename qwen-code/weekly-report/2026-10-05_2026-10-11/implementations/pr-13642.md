# PR #13642 当前实现观察：JDBC Runtime 历史有界保留方案

> 规模：+3072 / -26，31 个文件

## 解决了什么问题

终态 binding/session/execution 历史无上限增长，直接删除会破坏 Workspace、publication 和子运行引用。

## 当前实现方案

当前 diff 的 JdbcRuntimeRetention 以数据库时间、游标和有界 batch 分阶段扫描终态记录，在 slot/行锁内核对年龄、状态和 claim；Managed reference guard 排除仍被 holder/publication/未结算 lineage 引用的记录。

最新 head 的 retention index 已顺延为 V69，无单位 maxAge 按天解释、scanDelay 按毫秒解释，maxAge 不小于 1ms；新增 `managed_workspace_execution_lease(binding_id, runtime_generation)` 索引，Flyway 与幂等 JDBC schema 都补齐。writer 锁协议与独立 Hosted cleanup 释放证明均验证前 cleanup 保持关闭。关闭开关不恢复已删历史，receipt/幂等保留因此有期限。

`backgroundRunUnsettled` 保护同原 tenant/Workspace/Session/binding/generation 下未结算的 background_shell `:process` execution，二进制身份比较避免 collation 混淆 owner；不能删除进程行后让 Session-open 误认 Shell 从未启动。

最终复核 head 先按原始 Session 值和二进制身份共同 DISTINCT 去重，再查 child_run，避免每个 process 重复扫描同 Session；大小写折叠的数据库也不能合并原 owner。这是保守 Session 级保护，不是每个 Shell 与 execution 一对一匹配。

## 边界与风险

- 仍 open、默认部署开关受控；引用判断和并发删除需真实 MySQL 验证，不能作为 main 已清理承诺。
- retention V69 是当前分支版本；#13654 的 V68 async migration 已在主干 `18f80f56666a`，原同号冲突已通过顺延解决。仍须部署前核对最新迁移顺序及全部 writer 锁协议。
- 部署须继续保持 retention 关闭，直到原身份 Hosted cleanup 释放证明另行交付并验证。当前未实现这份契约：owed descriptor 可比 RELEASED binding 保留更久，binding 被收集后原 releaseOriginal 会因身份无法证明而冲突并阻塞 Session。仅升级 writer 锁协议不足以允许生产开启。
