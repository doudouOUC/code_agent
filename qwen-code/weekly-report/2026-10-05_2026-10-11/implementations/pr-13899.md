## 解决了什么问题

已有 CSI worker 身份证明没有独立的真实文件执行和 retained history owner。沿用通用 pathname IO 或本机 provisioner，会混淆原挂载、备份和 Session 身份；仅在 HTTP body 带工具参数也无法证明该调用来自已授权的原批次。

## 最终实现方案

独立 `csi-files-retirement/1` profile 只允许 Read/Write/Edit，并将 history 与结果保留作为 manifest 组成部分。container boot v4/v5 与 Pod/namespace、context、storage/disk、Session/capability 严格匹配；v4 不开放 history/execute，v5 才开放这些入口。通用 boot、旧 CSI boot 和 `LocalProcessRuntimeProvisioner` 拒绝私有 digest，不能降级到本机执行。

v5 先核对 Broker native readback，再以原 Session UUID 绑定空 history 目录。prepare 按持久 intentRef 串行执行，核对控制面的原观察并保留准备后的备份 pin。execute 不接受 body 自带的任意工具输入，而是从原 execution 的有界 readback 读取 input/definition/grant，验证 args digest、原 prompt/batch/ordinal/call ID、context 以及 prepared history；write/edit 必须有相符的准备证据，read 可使用无 prepare 的授权。

`ManagedCsiFileBackend` 借用经过 mount/disk/dev/inode 核验的原 root descriptor，逐级 no-follow 打开工作路径。工作文件与 retained 目录/备份不得别名；备份固定 dev/inode/长度/内容摘要/mode，观察验证完整目录 inventory。Read 共用 descriptor；Write/Edit 接入可选的 scoped text mutation writer，验证原文件后原句柄写入、truncate、sync 并复核身份，新文件使用 exclusive/no-follow 创建。普通 filesystem service 保留原路径。

挂载、工作目录或备份身份冲突，以及 EIO/ENOSPC/EDQUOT/ENODEV/ESTALE/EBADF 等存储故障永久 fence。普通读/路径打开的 ENOENT、目录/非目录/symlink/权限拒绝不单独证实挂载失效；Read 的 EISDIR/ENOTDIR/ELOOP/EACCES 包装为 FileReadOpenError，ENOENT 沿原错误传播。Write/Edit 在修改前保存原 bytes，部分写入或取消后复核原 inode/mode/alias，再恢复原句柄内容或删除刚创建的文件；回滚失败聚合原错误并 fence，不能据此宣称整个调用或目录 metadata 原子回滚。

history prepare 前投影 retained inventory 的最坏 wire 大小，限制 100 个 snapshot 和 64 KiB history envelope，容量不足在分配新 preimage 前拒绝。准备失败后再次观察，与准备前严格相等才移除失败准备并允许原引用重试；效果变化或无法证明时置 historyFailed，关闭 executor，拒绝后续 prepare/execute 和已排队 snapshot，要求退休。bind 在尚未构造 composition、原准入仍有效时才清除失败缓存重试；已构造 history 不换 owner 重建。execute settled result 使用 executor result-body 预算加 16 KiB envelope，而非套用 64 KiB history 限额。

drain seal 固定 retirement ID 并封 executor 新准入，等待已跟踪操作，但始终返回 `DRAINING/BLOCKED` 和 `file-admission-unavailable`，保留已绑定 history；失败 history 还登记 `history-prepare-failed`。seal 后只允许仍可证明的 snapshot 观察，不因无 pending invocation 就宣称可删除。close join 操作、executor、history/backend/mount，聚合清理错误，不删除 retained backups。

最终版本以 preparingHistory/activeExecutions 排斥 prepare 与 executor invocation：新请求、先开始 native readback 的请求均在 prepare 期间拒绝，已有执行时准备在 readback/preimage 前拒绝。此类时序拒绝不退役 Session，原请求可在互斥操作结束后重试。scoped 新文件/目录请求 0600/0700，已有文件保留 mode；仅成功回滚且错误是原 signal 取消 reason 才恢复可用，ENOSPC 等存储故障即使恢复 bytes 也 fence。普通 Write 无 textFileIo 时直接委托旧路径，保留取消与未取消的 pre-write 抛错行为。

## 边界与风险

- 最新主干已包含该私有 worker/profile，但不包含 #13526 的完整 Java native readback/Hosted 准入、boot6 admission/finalize 资格及物理释放闭合。依赖方仍须按实际合并顺序接线。
- retained backups 不自动删除，drain 不返回 READY；公共选择、Shell、Hooks/MCP、后台工具和跨 owner 冷恢复不由此开放。
- 写入现有 inode 不是 rename 原子替换或不可变快照；执行器内部配置不替代控制面原批次的授权/审批证明。
