## 解决了什么问题

Hook 的原 Runtime Session 在冷恢复/退休时缺 live handle，直接 release 会遗留 holder 或误删不确定资源。

## 最终实现方案

最终合入代码根据原 binding/session 观察并使用已持久 drain receipt；在无活跃 execution、stop 证据和精确 holder 匹配下，同事务结算 stopped Session release。无法确认的原资源继续阻塞。

## 关键代码路径

- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/RuntimeBrokerService.java`：原 Session 观察与 drain/release。
- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/JdbcRuntimeBindingRepository.java`：stopped release 和 holder 核对。
