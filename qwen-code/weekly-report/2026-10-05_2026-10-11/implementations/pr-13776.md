# PR #13776 当前实现观察：完整文件读取复用一次打开的源

> PR: [feat(core): Keep complete file reads on one opened source](https://github.com/QwenLM/qwen-code/pull/13776)
> 状态：open；仅记录 head `39a05a857d42` 的当前 diff，不能作为 `main` 已落地能力。
> 规模：+1518 / -139，18 个文件

## 解决了什么问题

读取前 stat/sniff、正文、图片和 PDF 子进程多次按 pathname 打开文件；路径在中途被替换时，大小/类型校验与最终模型内容可能来自不同文件。已有大文本 borrowed-handle reader 尚未覆盖整个 read_file 媒体与缓存流程。

## 当前实现方案

FileSystemService 增加可选 `withReadFile(request, callback)`。标准 Linux/macOS inline 读取以 O_RDONLY/O_NONBLOCK 打开一次并 fstat，向 callback 交付 descriptor 与准入 metadata，finally 关闭。read_file 将内容处理、缓存与媒体流程包在此作用域内，使用准入 stats，失败时使 descriptor/path 缓存失效；只有 FileReadOpenError 映射为原读取错误，取消继续传播。

`FileReadSource` 将 descriptor 与兼容 pathname 源显式区分。sniff、编码、小文本、范围、图片、音视频、Notebook 和 native PDF 共用源；descriptor bytes 用 64 KiB 有界块及 explicit-position reads，检查 AbortSignal。图片 overview 与 Notebook 格式化改为接受已读取 bytes，避免内部重开路径。

PDF 的 pdfinfo/pdftotext/pdftoppm 子进程继承 FD 3，读取 Linux `/proc/self/fd/3` 或 macOS `/dev/fd/3`，保留输出/时间预算及 TERM 到 KILL 的退出清理。渲染输出目录固定 descriptor 并检查 dev/inode，拒绝非预期条目和 symlink/non-regular 输出，清理前再验证目录身份。

Windows、其它平台或 Omni pathname delivery 保留 path 源；不实现 callback 的自定义 filesystem service 走原兼容路径。该 PR 不将其它入口自动升级成整个系统的单 descriptor 保证。

## 边界与风险

- 固定 inode 能防路径替换，不冻结同一 inode 的并发写入；不是不可变文件快照或新增授权/sandbox 保证。
- path 兼容分支不具备 descriptor 源保证；完整媒体读取仍受原大小与输出预算限制。
