> 规模：+1414 / -112，8 个文件

## 解决了什么问题

挂载身份验证后再按 pathname 解析 cwd，会留下 root 替换、子目录 symlink/device 切换和关闭竞态。一次成功 observe 不能证明后续目录解析仍来自同一 CSI 挂载，未 join 的借用还可能在 descriptor 关闭后继续运行。

## 当前实现方案

`ManagedCsiRootDirectory` 以 O_DIRECTORY/O_NOFOLLOW 固定根 descriptor，在借用前后核验命名 root 的 realpath/lstat 与 fstat dev/inode；任一身份或清理异常永久 fence，close 等待全部借用结束并保留清理错误。

`ManagedCsiMount.withVerifiedRoot` 在回调前后检查内核 mount identity 与 disk serial。相对目录沿 `/proc/self/fd/<parent>/<child>` 逐级打开 O_NOFOLLOW directory handle，比较 lstat/fstat 与根 device，返回前复核已借子目录，最后逆序关闭。关闭等待观察任务，但 fence 路径不 self-await。

Worker 启动的 route 注册、listen 和失败退出也接入 mount close；正常关闭在 executor 和 server 清理后释放根 descriptor，避免启动失败或执行器关闭异常泄漏挂载句柄。

## 关键代码路径

- `packages/cli/src/serve/managed-csi-root-directory.ts`：根 descriptor、借用生命周期及永久 fence。
- `packages/cli/src/serve/managed-csi-mount.ts`：mount/disk 核验和 descriptor-relative cwd 遍历。
- `packages/cli/src/serve/managed-runtime-attestation-worker.ts`：启动失败和正常退出的清理接线。
