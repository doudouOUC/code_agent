## 解决了什么问题

公共 Workspace 创建仍使用 files profile，开放 Shell 若没有部署门禁与 asking mode 会绕过用户确认。

## 最终实现方案

最终合入代码通过默认关闭的 Shell 部署开关选定 shell/1，并持久 default/auto-edit 审批模式；Shell 拒绝空/未知/yolo 配置。关闭 Shell 开关拒绝新 Shell 回合，但保留原 key 重放和已准入取消/结算；这不绕过 Workspace files 的总准入开关，后者关闭时连带输入的创建重放也拒绝。`workspaceTurns` 只说明 Workspace 授权，Shell 客户端还须核对 `foregroundShell=true`。Connector 在创建、装载、取消恢复、message stop 和 lifecycle attachment 中再次核验持久审批模式，不因已有 attachment 绕过校验。

Java create/load 都向 Hosted 传递 public Shell 的 `suppressChildAgents`，原始私有 Shell lane 不受该标志默认影响。Hosted 只有实际挂载 child orchestrator 才挂接其 Session message funnel；公共 Shell 不因前台命令入口隐式得到 child agent。公共 Shell 的 close/archive/unarchive/delete 在 capability 和后端 admission 都保持关闭，包括 protocol-0 路径。发送仍受最新主干 OPERATOR 与原创建 actor execution facts 约束。
