## 解决了什么问题

公共 Workspace 创建仍使用 files profile，开放 Shell 若没有部署门禁与 asking mode 会绕过用户确认。

## 当前实现方案

当前 diff 通过默认关闭的 Shell 部署开关选定 shell/1，并持久 default/auto-edit 审批模式；Shell 拒绝空/未知/yolo 配置。关闭 Shell 开关拒绝新 Shell 回合，但保留原 key 重放和已准入取消/结算；这不绕过 Workspace files 的总准入开关，后者关闭时连带输入的创建重放也拒绝。`workspaceTurns` 只说明 Workspace 授权，Shell 客户端还须核对 `foregroundShell=true`。Connector 在创建、装载和取消恢复时再次核验持久审批模式，不因已有 attachment 绕过校验。
