# PR #9763 最终实现：恢复后 `ask_user_question` 合法性加固

> PR: [fix(daemon): keep restored ask_user_question valid after load](https://github.com/QwenLM/qwen-code/pull/9763)
> 状态：merged，2026-08-23 合入 `main`。
> 规模：+884 / -78，16 个文件

## 解决了什么问题

#9665 让 daemon 可按 opt-in flag 在 load/resume 后重新挂起尾部 `ask_user_question`，但合入后复核发现恢复链仍有多处竞态。普通用户文本可能直接接在悬空 function call 后，形成 Anthropic-compatible provider 拒绝的 `model[functionCall] -> user[text]`；restore turn 会插入幽灵 file-history snapshot，造成后续 rewind 下标错位；worktree/background-agent notice 可能过早清空或丢失；同一 restored batch 中一个问题 timeout/session close/abort 后，已排队 sibling 结果可能被持久化，使 transcript 再也无法识别为可恢复尾部。cold bulk replay 和只读 `qwen/session/loadUpdates` 也可能在“跳过 finalize”与“实际不会 re-hang”之间失配，留下无人处理的 pending card。

## 最终实现方案

普通用户发送不再继承 restore preserve 例外：send 前的 orphan repair 会为悬空 AUQ 补 synthetic functionResponse，再把用户文本放进同一合法 user turn；真正的 restore answer 自带 matching functionResponse，因此不会被重复修复。daemon 若确定不会 re-hang（无 attached client、fork 等），通过 private suppress meta 同时关闭 Core preservation 和 replay skip，使 Gemini history 与 UI replay 一起 finalize；只读 `loadUpdates` 也不传 skip set。

cold bulk replay 在 chat 尚未初始化时从 transcript records 的最后 history content 计算 `skipFinalizeCallIds`，避免先 finalize、再在 load 阶段重复提示恢复。restore turn 不消费 file-history snapshot、system reminder 或一次性 notice；worktree 和 recovered-agent notice 被插入 answer 后的下一条 model request，并只在该 message 成功落地后清空，send/compression 失败则保留到下一次真实 prompt。

Session 对 restored call batch 维护 unattended 状态。timeout、`session_closed` 或等待中的 abort 会让整批 call 的 durable tool-result write 都跳过，包括此前已排队的 answered sibling；内存仍生成 functionResponse 以维持当前进程协议合法，磁盘尾部则继续保持 dangling，供后续 attended load 再次 re-hang。用户主动 cancel 仍按既有语义持久化。

## 边界与风险

- 恢复仍由默认关闭的 `--restore-ask-user-question` 控制，未新增 public capability；客户端不能只靠 `/capabilities` 推断 operator 是否开启。
- unattended path 故意让磁盘 transcript 保持 dangling；当前进程的 in-memory history 与 durable history 会暂时不同。
- persisted `parentSessionId` 一律拒绝、重复 raw call id 的更广匹配、daemon cancel provenance、late attach/coalescing 和 mixed text+functionCall compression 仍不在本 PR 范围。
- PR 只声明 macOS 与包级测试；没有完整 daemon restart、Windows 或 Linux E2E。
