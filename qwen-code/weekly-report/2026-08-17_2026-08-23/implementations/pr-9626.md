# PR #9626 当前实现观察：persisted session maintenance

> PR: [fix(serve): Repair persisted session lifecycle](https://github.com/QwenLM/qwen-code/pull/9626)
> 状态：open，未合入 `main`。
> 规模：+2931 / -318，29 个文件

## 解决了什么问题

空文件、损坏或 torn JSONL、以及 legacy orphan transcript 可能属于当前 workspace，却不满足普通 readable/provenance 分类，导致 delete/archive/unarchive 无法安全维护。active/archive 两侧同时存在时，默认 conflict 也缺少显式、可审计的保留一侧修复方式。

此前 draft 曾覆盖 transcript/export/organization/sidecar 等广域 logical/storage identity 统一；当前 diff 已明显收窄，只处理 persisted maintenance，不能继续按旧 77 文件方案描述。

## 当前实现方案

Core 增加 physical maintenance classifier，把文件是否由当前 runtime 拥有、是否可维护与 transcript 是否可正常 replay 分离。目标必须是 exact owned regular file；foreign workspace、symlink、directory、FIFO、大小写歧义或身份无法证明时 fail closed。delete/archive/unarchive 在 writer lease 与 runtime generation 下捕获物理候选和 identity snapshot，并在 unlink/rename 前复核，避免检查后替换竞态。

archive/unarchive 默认仍不修改冲突文件，批量 lifecycle response 通过 HTTP 200 的 per-session `errors` 返回 conflict；workspace-qualified route 不再使用单独 HTTP 409 envelope。只有客户端先 gate `session_storage_conflict_repair` 并显式发送 `resolveConflicts:true`，才执行 keep-destination repair：archive 保留 archived、unarchive 保留 active，并在响应中追加 `resolvedConflicts`；不合并 transcript。delete 保留 delete-both 语义。

workspace-qualified route 固定使用已选可信 runtime；普通 workspace-less route 保持 primary。只有 internal Conversations 且 owner 唯一明确时可路由到非 primary；owner ambiguous/unavailable 时拒绝，不做 primary fallback。
