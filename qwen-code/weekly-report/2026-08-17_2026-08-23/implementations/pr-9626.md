# PR #9626 当前实现观察：persisted session storage lifecycle boundary

> PR: [fix(serve): unify persisted session storage lifecycle](https://github.com/QwenLM/qwen-code/pull/9626)
> 状态：open draft，未合入 `main`。
> 规模：+13788 / -1900，77 个文件

## 解决了什么问题

#9513 只恢复同拼写 active+archived 双副本的 load/resume 等五项回归，并没有统一整个生命周期的 logical id 与持久化文件名。删除、重命名、归档、恢复归档、transcript 分页、导出、organization、scheduled task 和 sidecar 等相邻操作仍可能重新用 logical id 拼路径；空文件、损坏文件和 orphan transcript 也因为不满足严格的 readable/provenance 分类而占用存储却无法安全维护。

active 与 archived 同时存在时，既有 delete-both 行为缺少统一 storage identity fencing；archive/unarchive 默认 conflict 也没有显式、可审计的保留一侧修复方式。多工作区下若 workspace-less mutation、runtime generation、Live task 或 writer lease 使用的身份层次不一致，还可能操作错误 runtime 或在文件替换竞态中提交陈旧判断。

## 当前实现方案

当前 draft 把 caller-visible logical id 与 filesystem-only `storageSessionId` 分离。`SessionService.resolvePersistedSessionStorage()` 枚举 active/archive 中匹配 logical id 的精确物理拼写，并把同状态 case twins、非 regular entry 与 foreign-project transcript 作为显式 fail-closed 错误。读取、列表、游标、导出和组织投影对外继续返回 logical id；只有 transcript、worktree sidecar、prompt ledger、attachment 和 organization alias 等存储操作携带物理拼写。

维护路径不再依赖 transcript 必须可加载。删除、归档和恢复归档会先捕获 regular-file identity，再在 writer lease、runtime generation、Live activity 和 maintenance guard 下复核 dev/inode/ctime/size 与候选集合，防止检查后文件被替换。空、损坏或 orphan regular transcript 可被当前 runtime 维护；foreign workspace、symlink、directory、真实 case twins 与无法证明 identity 的候选继续拒绝。

archive/unarchive 默认仍在 active/archive 双副本时返回 conflict。只有客户端先 gate `session_storage_conflict_repair` capability 并显式发送 `resolveConflicts:true`，才执行 deterministic keep-destination repair：archive 保留 archived 历史并删除 active，unarchive 保留 active 历史并删除 archived；不合并 transcript，并在响应中追加 `resolvedConflicts`。delete 保留既有 delete-both 语义。

路由层继续保持普通 workspace-less lifecycle mutation 只作用于 primary；可信 secondary 走 workspace-qualified route，internal Conversations 维持 owner routing。ACP、REST、Live、scheduled task、organization、prompt ledger、worktree sidecar、attachments、transcript paging/export 和 TS SDK 都沿用同一 logical/storage identity contract。

- `packages/core/src/services/sessionService.ts`：`PersistedSessionStorage`、`storageSessionId`、maintainable ownership/identity snapshot、删除/归档/恢复归档与 sidecar reconciliation。
- `packages/cli/src/serve/server/session-archive.ts`：maintenance guard、writer lease、runtime generation/Live activity fencing，以及 `resolveConflicts` 事务语义。
- `packages/cli/src/serve/routes/session.ts`：logical id 与 storage id 的 transcript/read/export/lifecycle 路由映射、primary/workspace-qualified ownership 和稳定错误响应。
- `packages/cli/src/serve/live/live-session-coordinator.ts` / `live-task-service.ts`：Live coordinator 的 provisional activity、maintenance exclusion 与 persisted spelling 传递。
- `packages/cli/src/serve/acp-http/dispatch.ts` / `packages/acp-bridge/src/bridge.ts`：ACP restore、prompt ledger、attachment 与 lifecycle operation 的 logical/storage identity 分层。
- `packages/cli/src/serve/capabilities.ts` / `packages/sdk-typescript/src/daemon/DaemonClient.ts` / `types.ts`：additive `session_storage_conflict_repair`、`resolveConflicts` 和 `resolvedConflicts` surface。
- `docs/design/2026-08-20-session-storage-boundary-lifecycle-repair.md`：storage boundary、故障矩阵和兼容约束。

## 边界与风险

- 当前是 open draft，77 个文件横跨 Core、daemon、ACP 与 SDK；不能作为已发布协议或运行时承诺。
- `resolveConflicts` 只保留目标状态一侧，不合并历史；调用方必须 capability gate 并明确接受被丢弃副本。
- Windows/Linux 未本地验证；文件 identity、rename 和大小写语义仍依赖 CI 与跨平台复核。
- 父会话到 child transcript 的级联删除、全局 file-history backup 清理与 transcript merge 不在本 PR 范围内。
