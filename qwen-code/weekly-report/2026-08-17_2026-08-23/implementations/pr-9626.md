## 解决了什么问题

空文件、损坏或 torn JSONL、以及 legacy orphan transcript 可能属于当前 workspace，却不满足普通 readable/provenance 分类，导致 delete/archive/unarchive 无法安全维护。active/archive 两侧同时存在时，默认 conflict 也缺少显式、可审计的保留一侧修复方式。

此前 draft 曾覆盖 transcript/export/organization/sidecar 等广域 logical/storage identity 统一；最终实现已明显收窄，只处理 persisted maintenance，不能继续按旧 77 文件方案描述。

## 最终实现方案

Core 增加 physical maintenance classifier，把文件是否由当前 runtime 拥有、是否可维护与 transcript 是否可正常 replay 分离。目标必须是 exact owned regular file；能解析的首条物理记录必须同时包含 string `sessionId` 和 `cwd`，active/archive 一侧 local、一侧 foreign 时按 ambiguous ownership 拒绝。foreign workspace、symlink、directory、FIFO、大小写歧义或身份无法证明时均 fail closed。delete/archive/unarchive 在 writer lease 与 runtime generation 下捕获物理候选和 identity snapshot，并在 unlink/rename 前复核，避免检查后替换竞态。

archive/unarchive 默认仍不修改冲突文件，批量 lifecycle response 通过 HTTP 200 的 per-session `errors` 返回 conflict；workspace-qualified route 不再使用单独 HTTP 409 envelope。只有客户端先 gate `session_storage_conflict_repair` 并显式发送 `resolveConflicts:true`，才执行 keep-destination repair：archive 保留 archived、unarchive 保留 active，并在响应中追加 `resolvedConflicts`；transcript 不合并，但两侧 PR binding 合并到保留侧，败方 worktree/prompt sidecar 清理。usage salvage 只在 transcript 成功删除后提交，并在写入前再次去重。delete 保留 delete-both 语义。

transcript 提交后的 worktree/PR/prompt sidecar、file history、scheduled task、organization store 和 attachment cleanup 都传递 runtime generation commit fence；attachment directory 先 rename 为唯一 tombstone 再递归删除，避免清理旧目录时误删同名 successor。

workspace-qualified route 固定使用已选可信 runtime；普通 workspace-less route 保持 primary。只有 internal Conversations 且 owner 唯一明确时可路由到非 primary；owner ambiguous/unavailable 时拒绝，不做 primary fallback。

## 边界与风险

- `resolveConflicts` 丢弃非目标状态副本而不合并历史；调用方必须 capability gate 并明确接受该语义。
- session list、transcript/export、organization 语义扩展、Live/task identity、general mixed-case、parent-child cascade 与 transcript merge 不在当前范围；PR sidecar merge 只是 conflict repair 的跟随行为。
- PR 只声明 macOS 本地验证；Windows/Linux 的 file identity、rename 与大小写行为仍待复核。
