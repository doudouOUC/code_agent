# PR #9687 最终实现：daemon per-session model restore

> PR: [feat(cli): restore each daemon session onto its last selected model](https://github.com/QwenLM/qwen-code/pull/9687)
> 状态：merged，于 2026-08-22 合入 `main`。
> 规模：+2423 / -17，21 个文件

## 解决了什么问题

daemon session 内切换模型后，选择只保存在当前 ACP Session 内存。detach、idle reap 或 daemon restart 触发 cold load/resume 时，新 Session 会重新使用进程级 `settings.model.name`，导致不同 session 的 provider/model 选择漂移；默认模型本应只决定新建 session，而不应覆盖已有 session 的最后选择。

## 最终实现

成功 model switch 后，ACP Session 通过 `ChatRecordingService` best-effort 追加 last-wins `system/session_model` JSONL 记录。payload 保存 canonical model id、auth type、可选 registry `baseUrl` 和 runtime-snapshot marker；不保存 credentials，相同 binding 不重复写。空的新 daemon session 不为默认值单独创建 transcript。

cold ACP load/resume 从 transcript projection 恢复 binding，并在认证前执行 `restoreSessionModelThenAuthenticate()`。新记录优先于历史最后一个 assistant `model`；旧 transcript 没有两者时才回退 settings default。registry route 必须命中当前配置 allowlist，未知 host 被丢弃；runtime snapshot 只有当前仍存在时才恢复。switch 失败非致命，认证失败可回滚 settings model/route 后重试；same-id runtime snapshot 与 implicit registry binding 不被误判成 no-op。

普通 history replay 忽略 `system/session_model`。rewind 后重新追加内存中的当前 binding，使 active branch 的 last-wins projection 与 Config 一致。load/resume 保持 read-only，不把恢复结果再写一遍；TUI/CLI `--resume` 有意维持原行为。

## 边界与风险

- 只恢复 daemon ACP cold load/resume；新 session 和普通 TUI/CLI resume 的模型选择语义不变。
- JSONL 不存 credential；registry route 必须由当前配置重新认可，runtime snapshot 必须仍存在。
- best-effort 持久化失败不会阻止 switch，因此极端 I/O 失败后下一次恢复可能回退旧 binding/default。
