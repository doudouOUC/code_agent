# PR #9563 最终实现：WebShell session title catalog refresh guard

> PR: [fix(web-shell): Stop repeated session title catalog refreshes](https://github.com/QwenLM/qwen-code/pull/9563)
> 状态：merged，2026-08-20 合入 `main`。
> 规模：+20 / -2，2 个文件

## 解决了什么问题

Web Shell 在连接元数据没有 display name 时，会通过 persisted catalog 解析首轮 prompt 派生的 fallback title，并且 header 已经显示该标题。但旧的 turn-completion guard 只看连接侧 title，不看已解析的有效 fallback title；因此后续每个 turn 仍会继续触发两次 `sessions?size=200` fresh catalog 请求，造成重复磁盘/session catalog 扫描。

## 最终实现方案

`App.tsx` 在决定是否启动 session-title catalog recovery 时改为检查 effective display title：只要 header 已经从连接 metadata 或 persisted catalog fallback 得到可显示标题，就不再为后续 turn 安排新的 immediate/trailing catalog refresh。标题仍不可用时，保留原有首次 immediate lookup 和 2 秒 trailing recovery lookup。

该改动不触碰 daemon protocol、catalog API、live-state route 或 title precedence。turn completion 后的 live session activity reconciliation 仍照常运行；后续如果 live metadata title 到达，仍可覆盖 catalog fallback。

## 关键代码路径

- `packages/web-shell/client/App.tsx`：把 title recovery gate 从 connection-only display name 改为 effective title 判断，避免 fallback title 已显示后重复刷新 catalog。
- `packages/web-shell/client/App.test.tsx`：覆盖 missing connection title 的 `0 -> 2 -> 2` 请求计数、connection-provided title 的零请求 control，以及 turn activity 和 live metadata title 覆盖行为。

## 验证方式

PR 声明在 macOS、Node.js 24.12.0 下用 jsdom Vitest 和连接 mocked daemon routes 的 Chromium 本地验证：连接 title 缺失时第一次 unresolved turn 仍发出 immediate + trailing 两次请求，catalog fallback title 显示后第二个 turn 不再新增 `sessions?size=200` 请求；connection-provided title control 保持零请求。Windows/Linux 浏览器未本地验证。本次文档更新未重复运行 WebShell 测试。

## 边界与风险

- 有效 fallback title 出现后，后续带外生成标题的恢复依赖现有 live metadata event 或 reconnect，而不是每个 turn 重复 catalog polling。
- 未验证真实 daemon 磁盘扫描延迟和 Windows/Linux 浏览器行为。
