# PR #9341 最终实现：standalone conversation isolation primitives

> PR: [feat(cli): Add standalone conversation isolation primitives](https://github.com/QwenLM/qwen-code/pull/9341)
> 状态：merged，2026-08-20 合入 `main`。
> 规模：+4973 / -391，33 个文件

## 解决了什么问题

standalone session 后续要在唯一 Conversations runtime 中拥有自己的 persisted source 与 private directory，但在 lifecycle service 落地前，系统必须先能可信地区分 explicit standalone、兼容 legacy projectless 与 Live transcript。旧路径如果把空 metadata result 当作 legacy standalone 证据，或在大小写不敏感文件系统上用非权威 session id lookup，就可能把损坏 Live/child transcript 提升为 standalone，或者把请求绑定到错误的 persisted identity。

## 最终实现方案

#9341 最终合入 PR2A primitives，不新增 `/standalone/*` 路由、public capability、SDK API 或 WebUI 行为。`session-source.ts` 新增 `STANDALONE_SESSION_SOURCE_TYPE`、reserved standalone source 判断和 `readLoadableConversationSession()` 分类器：top-level explicit standalone、top-level legacy projectless、Live source 与 child transcript 必须满足 active/archive location 稳定、parent lineage 有效、source/sourceId 不冲突。explicit standalone child 可通过 persisted parent ID 保留 standalone；legacy child 必须能解析 surviving top-level parent，避免把 damaged Live child 提升为 standalone。

`SessionService` 新增 `readCreationMetadataIfReadable(sessionId, state)`，只读取指定 active/archive location，且要求扫描到的 JSONL 头部完整可读。底层 `jsonl-utils.ts` 新增 `readLinesWithIntegrity()`，保留普通 tolerant reader 对完整 `}{` glued records 的恢复能力，但会把 truncated、garbage、scalar/array 或无法完整恢复的行标记为 incomplete；source classification 看到 incomplete 时 fail closed，普通 transcript recovery 不变。

持久化 ID 解析从 exact path fallback 提升为 archive-aware、大小写不敏感的权威查找。`SessionService.findSessionIdIgnoringCase()` 同时扫描 active 与 archived storage；若出现 case-only duplicate、active+archived 双位置或 location conflict，抛 `SessionIdCaseConflictError`。REST/ACP load/resume 在读取 metadata 前先使用 persisted spelling；internal Conversations runtime 上的 generic restore 对 explicit standalone 或混合大小写 standalone transcript 返回 not found/conflict，而不是以普通 workspace session 方式加载。

目录侧新增 deterministic identity helpers。`conversation-directory-identity.ts` 对 Conversations root 和 `conversation-${sha256(storageSessionId)}` child 做 lstat/realpath/lstat 三段校验，要求非 symlink directory、owner-only mode、同 device/inode、direct child、expected identity match，并区分 `not_empty`、`not_direct_child`、`identity_changed` 等原因。`ConversationWorkspace` 暴露 `prepareStandaloneDirectory()`、`inspectStandaloneDirectory()` 和 `ensureStandaloneDirectory()`，用于后续 PR2B 在绑定 private child 前确认目录身份与空目录条件。

REST 和 ACP creation 路径同步拒绝保留 source。普通 `/session` 与 ACP `session/new` 如果收到 `sourceType:"standalone"`，返回 `reserved_session_source`；Live reserved source 仍只允许 daemon-owned Live path。Live task/service、ACP Agent 和 workspace routes 改为通过 `readLoadableLiveConversationMetadata()` 精确过滤 explicit standalone，防止 standalone transcript 从 Live compatibility path 泄漏。

最终 diff 还补了 dispatch-error、session-archive、config 和 transport 相关回归：把 standalone/private runtime 的 canonical lock、session source 与 typed error 映射固定到 route/transport 边界，避免后续 PR2B 将 directory identity 或 reserved source 失败误呈现为普通 not-found；config/transport/session service 用例继续覆盖 reserved source、case conflict 和 metadata integrity 的入口边界。后续 review round 又收紧 persisted spelling guard、restore shared guard、case resolver 的 inode/I/O 分类、canonical private directory key 与 caller-supplied session-id admission，让 PR2A primitives 在 macOS/Linux CI 行为上保持一致。

- `packages/cli/src/serve/conversations/session-source.ts`：standalone/Live source 分类、parent lineage、active/archive location 稳定性。

- `packages/core/src/utils/jsonl-utils.ts`：`readLinesWithIntegrity()` 和 tolerant parse 的完整性标记。
- `packages/cli/src/utils/conversation-directory-identity.ts`：Conversations root/private child identity、mode/owner/symlink/direct-child checks。
- `packages/cli/src/serve/conversations/conversation-workspace.ts`：standalone private directory prepare/inspect/ensure facade。
- `packages/cli/src/serve/routes/session.ts` / `packages/cli/src/serve/acp-http/dispatch.ts` / `packages/cli/src/config/config.ts`：reserved standalone source 拒绝、load/resume persisted spelling、internal runtime filtering 与配置入口保护。

- `docs/design/standalone-daemon-sessions.md` / `docs/plans/2026-08-14-standalone-pr2-core.md`：PR2A/PR2B split、containment boundaries 和后续 service 计划。
