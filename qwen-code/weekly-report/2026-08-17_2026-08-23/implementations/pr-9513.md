> 规模：+784 / -410，22 个文件

## 解决了什么问题

#9341 收紧 persisted session provenance 与 identity 后，暴露出 active/archive 双副本和移动竞态的兼容问题：请求 spelling 与存储 spelling 完全相同时，CLI resume 能读 active copy，但 REST、daemon ACP 和 embedded ACP load/resume 会拒绝；creation metadata 读取期间发生 archive move 会误报 not found；旧版 nil、UUIDv7 或 agent-suffixed parent id 被过严形状 gate 拒绝；conversation directory 在 probe 间被并发删除会误报 identity changed；restore 还会重复扫描 catalog。

最终 diff 还补齐了相同 identity 在 transcript/export/delete 上的行为，避免 load 可恢复但只读或删除仍选错物理副本。

## 最终实现

REST、daemon ACP 与 embedded ACP 的 load/resume 都以生命周期锁内的 persisted resolution 为权威。请求 spelling 与 active/archive 文件 spelling 完全一致且两侧都可读时，恢复和 writer activation 选择 active copy；大小写不同、存在多个 case candidate 或 archive/unarchive mutation 时继续 fail closed。

同一 active-first 规则扩展到 persisted transcript 和 export。显式 delete 在 writer lease 下删除 active/archive 两侧，保留 delete-both 契约；archive/unarchive 仍不把冲突静默修复。creation metadata 按 active 后 archived 做 integrity-aware 读取以容忍中途移动，并先做 single-segment/path-safe 校验；legacy parent 不再要求特定 UUID 形状，而是交给 storage resolution。directory probe 间的 `ENOENT` 按 already gone 处理，restore 去掉锁前重复扫描并使用异步 case-insensitive lookup。

## 边界与风险

- active-first 只适用于 exact spelling；异拼写 case twin、歧义 candidate 与跨 workspace ownership 继续拒绝。
- archive/unarchive 不自动 repair active/archive 冲突；显式 delete 才保持 delete-both。
- 更广的 session list、organization、scheduled-task 与 Live/task identity 统一不在此 PR 范围。
- 本次整理未独立复跑 macOS 测试，Windows/Linux 文件系统大小写语义也未本地验证。
