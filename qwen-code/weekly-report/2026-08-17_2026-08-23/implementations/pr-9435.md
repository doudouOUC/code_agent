# PR #9435 最终实现：visible daemon stop for duplicate provider tool-call breaker

> PR: [fix(cli): surface the daemon duplicate tool-call breaker as a visible loop-detected stop](https://github.com/QwenLM/qwen-code/pull/9435)
> 状态：merged，2026-08-19 合入 `main`。
> 规模：+238 / -26，3 个文件

## 解决了什么问题

既有重复 provider tool-call id 的 circuit breaker 已在多数入口变成 loop-detected stop，但 ACP daemon session 仍保留一条 bespoke internal flag：重复 duplicate response 被丢弃后，前台 prompt 可能只是静默停止，用户看不到标准 `loop_detected` turn error，也无法从 telemetry/error payload 判断是 `global_tool_call_duplicate`。

## 最终实现方案

#9435 删除 `RunToolResult.repeatedDuplicateProviderToolCall` 分支，把 ACP Session 的重复 provider id breaker 接回既有 `loopDetected` 管道。`Session.runToolCalls()` 命中 repeated duplicate provider id 时设置 `loopDetected:true`，让共享 `toolLoopState` 记录 `LoopType.GLOBAL_TOOL_CALL_DUPLICATE`；前台 prompt 因此走统一 loop stop 逻辑，发布 visible `loop_detected` turn error，并把“模型超过工具调用安全限制”的上下文说明保留到未发送 history。

cron/background notification turn 继续保持 daemon 已有 loop stop 语义：不向前台用户伪造交互错误，只完成当前 end-turn 并保留上下文。测试同时确认 repeated invalid tool parameters 等其它 loop guard 不受影响。

## 关键代码路径

- `packages/cli/src/acp-integration/session/Session.ts`：移除 bespoke repeated-duplicate flag，统一通过 `loopDetected` 和 `toolLoopState` 终止 ACP turn。
- `packages/cli/src/acp-integration/session/Session.test.ts`：覆盖前台 ACP prompt 可见 `loop_detected` error、history context preservation 和 cron/background parity。
- `docs/design/2026-08-19-duplicate-provider-toolcall-id-guard.md`：记录 duplicate provider id guard 的 visible daemon stop 与后续 args-aware replay 设计。

## 验证方式

PR 声明已通过 `cd packages/cli && npx vitest run src/acp-integration/session/Session.test.ts`，并在真实 daemon + mock provider 场景确认重复 provider id 会显示 loop-detected stop、不再发送空 follow-up。macOS 本地通过，Windows/Linux 由 CI 覆盖。

## feature 文档处理

已在 [tool-call-id-integrity.md](../../../feature/tool-call-id-integrity.md) 登记为 duplicate provider id breaker 的 daemon 可见终止化 follow-up。该 PR 只改变重复 id breaker 的终态呈现，不改变 tool-call id normalization、OpenAI payload cleanup 或 dangling replay 修复。

## 边界与风险

- 该修复只覆盖 repeated duplicate provider id breaker；不同参数的 raw id 复用仍由 #9436 处理。
- 前台 visible stop 依赖既有 loop-detected UI/telemetry 管道，不能替代 provider 侧 id 唯一性约束。
