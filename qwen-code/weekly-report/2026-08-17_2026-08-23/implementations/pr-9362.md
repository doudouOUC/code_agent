# PR #9362 当前实现观察：runtime record I/O retryability

> PR: [fix(cli): Keep transient runtime record I/O retryable](https://github.com/QwenLM/qwen-code/pull/9362)
> 状态：open，未合入 `main`。
> 规模：+148 / -7，3 个文件

## 解决了什么问题

#9181 引入的 Conversations runtime owner record 与 Live discovery record 读取路径把所有 open/read 失败都视为持久化状态损坏。一次瞬时 `EMFILE`、`EIO` 或资源压力导致的 read failure 会锁存为 `conversation_runtime_ownership_compromised`，之后即使记录有效也无法 reclaim，需要重启 daemon 才恢复。

## 当前实现方案

#9362 当前 open diff 保留 fail-closed integrity 语义，但把 transient I/O failure 从 invalid persisted state 中拆出来。`conversation-runtime-ownership.ts` 的 `readOwnerRecord()` 在 `open()` 失败时只把 `ELOOP` 包装成 `UnsafeOwnershipStateError`，继续视为 terminal compromise；其它 open error 原样抛出。成功打开后先完成 stat/identity/permission/single-link 校验，再单独执行 `handle.readFile('utf8')`，read I/O 错误同样原样抛出；只有 JSON parse、record shape、identity、permission 或 unsafe file 问题仍进入 unsafe terminal state。

`live/discovery.ts` 对 Live discovery record 采用相同分类：`ELOOP`、malformed JSON 与 unsafe file 继续映射为 `LiveDiscoveryStateError`，但非 `ELOOP` 的 open/readFile I/O 错误不再被吞成 state corruption。上层 ownership acquisition 因此把这些错误报告为 retryable `conversation_runtime_unavailable`，下一次 acquisition 可以在故障消失后重新 reclaim dead owner 或 stale discovery record。

测试使用 hoisted `node:fs/promises.open` mock 精确注入一次性故障。对 ownership record 与 Live discovery record 分别覆盖 open 阶段 `EMFILE`、readFile 阶段 `EIO`：第一次 acquire 预期 reject 为 `conversation_runtime_unavailable` 且 `retryable:true`，第二次 acquire 在故障清除后成功 reclaim。`ELOOP` open 仍预期 `conversation_runtime_ownership_compromised` 且 `retryable:false`。

## 关键代码路径

- `packages/cli/src/serve/conversations/conversation-runtime-ownership.ts`：owner record open/readFile 错误分类，`ELOOP` terminal、其它 I/O retryable。
- `packages/cli/src/serve/live/discovery.ts`：Live discovery record 读取错误分类同步调整。
- `packages/cli/src/serve/conversations/conversation-runtime-ownership.test.ts`：ownership/Live discovery transient open/read failures 与 terminal `ELOOP` 回归覆盖。

## 边界与风险

- 当前未合入，不能作为 `main` 行为承诺。
- 错误分类不能过宽；`ELOOP`、lock compromise、permission/identity change、malformed JSON、invalid shape 与 provisional ownership failure 仍必须保持 terminal。
- 本 PR 不改变 owner/discovery record 格式、ownership ordering、routes 或 public API。
