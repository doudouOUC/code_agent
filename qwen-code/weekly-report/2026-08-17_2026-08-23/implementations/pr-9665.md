## 解决了什么问题

`ask_user_question` 的待回答状态与 permission `requestId` 只存在于 ACP/daemon 内存。daemon 重启后，load/resume 会把 transcript 尾部未完成提问当作 orphan tool call 补成失败结果；旧 request id 已失效，客户端无法继续投票，模型也收不到真实答案。

通用 `continueLastTurn` 会合成 error response，并可能重复 user echo、system reminder、hook 或 worktree notice，因此不能等价恢复原提问回合。

## 最终实现

新增默认关闭的 `qwen serve --restore-ask-user-question`，仅作用于 ACP load/resume。Core scanner 只接受 transcript 尾部全部为结构合法 AUQ calls 的纯 batch；混合 dangling tools、非法参数或非尾部问题继续走既有 orphan repair。符合条件时 replay 跳过对应 orphan finalize，并通过内部 restore hint 进入 bridge；外部 meta 不能伪造该 hint。

bridge 统一通过 tracked prompt helper 重新挂起提问，并用 `pendingPromptCount + goalTurnActive`、无 attached client、非 fork 等条件避免与现有工作重叠；sync throw 也被收敛为受控失败。Session 重新执行原 AUQ calls，生成新 request id，复用既有 permission vote。daemon-known decline 带 suppress metadata，使 replay skip 与 re-hang 对齐。

恢复空 prompt 不写 user message，也不重复 echo/hook/reminder；有 active todo 时不消耗 reminder，worktree notice 延迟到答案后的模型请求。timeout 不伪造 decline，而是保留 dangling transcript 供后续 load/resume；`continueLastTurn` 会先 decline 可恢复问题。cold lookup 规范化 session id，paged replay 和 compression side query 也避开尾部 dangling AUQ 的误处理。

## 边界与风险

- 只恢复尾部纯 `ask_user_question` batch，不恢复 exec/edit/其它 permission，也不做 boot-time scan。
- 不持久化旧 request id 或 permission audit；每次 re-hang 都生成新 request id。
- 未提供 settings key 或 capability tag，client 需要带外确认 operator 是否启用 flag。
- 未在本次整理中独立复跑 restart E2E 或 Windows/Linux 验证。
