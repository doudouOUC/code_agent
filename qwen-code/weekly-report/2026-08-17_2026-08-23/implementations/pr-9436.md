# PR #9436 最终实现：argument-aware duplicate provider tool-call replay detection

> PR: [fix(core): treat duplicate provider tool-call ids as replays only when arguments match](https://github.com/QwenLM/qwen-code/pull/9436)
> 状态：merged，2026-08-19 合入 `main`。
> 规模：+1231 / -147，21 个文件

## 解决了什么问题

#5107 的 duplicate provider id guard 用 provider raw id 判断“是否 replay”。这能阻止旧 id 重复执行副作用，但对 Kimi 等 provider 的另一类行为过于激进：同一个 raw id 在后续 turn 被复用，但工具名或参数已经不同。旧逻辑会把这种真实新调用误判为 replay，发 synthetic duplicate response 并吞掉执行，表现为用户命令没有真正运行。

## 最终实现方案

#9436 将 replay 判定收紧为“provider id 相同且 canonical tool name + arguments fingerprint 相同”。新 leaf 模块 `packages/core/src/utils/tool-call-repeat-key.ts` 提供稳定 repeat key，复用 loop guard 的 canonical name 与 JSON-compatible 参数排序逻辑，避免从 `loopDetectionService` 反向引入 import cycle。

`toolCallIdUtils` 现在维护 handled provider id 到 fingerprint 的映射。incoming call 若 id 与 fingerprint 都匹配已处理记录，仍被视为 replay：先合成 duplicate tool response，重复出现时触发 #9435 可见 breaker。若 id 相同但 fingerprint 不同，则保留 #5107 的 suffixed local id 路径，把它当 fresh call 执行并写入 history；原始 fingerprint 不被后续 collision 覆盖，后续 replay 原调用仍能被识别。

这一判定贯穿 core turn/scheduler、TUI stream、non-interactive CLI、Agent headless/core runtime、ACP Session 和 GeminiChat history-derived fingerprint map。synthetic duplicate message 也补充提示：若模型确实想发起新调用，需要使用新的 tool-call id 或显式不同参数。

## 关键代码路径

- `packages/core/src/utils/tool-call-repeat-key.ts`：稳定 canonical tool name + arguments repeat key。
- `packages/core/src/core/toolCallIdUtils.ts`：provider id + fingerprint replay predicate、duplicate response breaker 和 suffixed local id 保留逻辑。
- `packages/core/src/core/geminiChat.ts` / `turn.ts` / `coreToolScheduler.ts`：history fingerprint map、turn 入口和 scheduler guard。
- `packages/cli/src/ui/hooks/useGeminiStream.ts` / `packages/cli/src/nonInteractiveCli.ts` / `packages/cli/src/acp-integration/session/Session.ts`：TUI、headless CLI 与 ACP daemon 入口共用 args-aware replay 判定。
- `packages/core/src/agents/runtime/agent-core.ts`：Agent runtime 的 duplicate provider id guard。

## 验证方式

PR 声明覆盖 core `turn`、`toolCallIdUtils`、`geminiChat`、`loopDetectionService`、`agent-headless`、`agent-core`，以及 CLI `nonInteractiveCli`、`useGeminiStream`、ACP Session targeted suites；另用 bundled CLI + mock provider 验证同 raw id 不同参数会执行、同 raw id 同参数仍合成 duplicate response 并触发 breaker。

## feature 文档处理

已在 [tool-call-id-integrity.md](../../../feature/tool-call-id-integrity.md) 登记为 #5107 duplicate id guard 的语义修正：replay 从“id 相同”升级为“id 与参数指纹相同”。该 PR 不改变 OpenAI payload cleanup 的目标，也不迁移已损坏历史。

## 边界与风险

- 同一 turn 内同 id 且同参数仍只执行一次；这是安全边界，不尝试猜测 provider 的真实意图。
- 对旧历史的 fingerprint map 只能从已配对 assistant call / tool result 推导；无法还原缺失或损坏记录的参数语义。
- `arguments` fingerprint 依赖 JSON-compatible canonicalization；非 JSON 结构不会被当成 provider 合法 tool-call 参数处理。
