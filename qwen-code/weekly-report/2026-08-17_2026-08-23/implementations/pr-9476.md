# PR #9476 最终实现：WebShell consumes live-state session activity timestamps

> PR: [feat(web-shell): Consume live-state session activity timestamps](https://github.com/QwenLM/qwen-code/pull/9476)
> 状态：merged，2026-08-19 合入 `main`。
> 规模：+785 / -27，10 个文件

## 解决了什么问题

#9396 让 `workspace_session_live_state` 返回 optional `updatedAt` activity watermark，但 WebShell 仍必须安全消费它。turn 完成后如果直接信任任意 in-flight live-state response，可能用旧响应清掉刚完成的 pending activity；如果把未知、archived 或 filter 外 row 插入当前 catalog page，又会破坏 session list 的 ownership/filter 语义。缺少 consumer 后，WebShell 仍需要在 turn completion 后限频 full catalog reload 来更新 recency。

## 最终实现方案

#9476 在 WebShell session catalog controller 中为 turn completion 记录 per-session sequence。live-state poll 启动时 snapshot 当前 pending completions，只有请求开始时间晚于 completion 的 response 才能 settle 对应 sequence；请求飞行期间又发生更新时，旧 response 不会清掉新 pending。

`SessionCatalogStore.applyLiveState()` 在合并 volatile state 时吸收合法 `updatedAt`：只更新当前已加载、cursor-less、active、非 archived、无 source/group 过滤页面中的已知 row；timestamp 必须有效且严格更新，unknown session、archived row、cursor page、group/source filter page 和缺失 watermark 都不会插入或重排。可吸收的 watermark 会按 server comparator 重新排序：organized view 保留 pinned block 优先，再按 activity time 和 stable id tie-break。

如果 live-state 缺少 watermark、服务端仍是旧形状、row 不在当前可重排页面，或者 live-state 请求失败，completion pending 会继续走既有 10 秒 coalesced full catalog refresh fallback。初始化 `live A -> catalog/groups -> live B` handshake、create/archive/delete/rename local invalidation 与 legacy daemon fallback 保持不变。

## 关键代码路径

- `packages/web-shell/client/session-catalog/workspace-session-live-state.ts`：completion snapshot、post-completion response settle、fallback reconcile 和 wake loop。
- `packages/web-shell/client/session-catalog/session-catalog-store.ts`：live watermark absorption、page ownership checks、activity re-sort 和 pending completion sequence。
- `packages/web-shell/client/session-catalog/session-catalog-hooks.ts`：turn completion routing by live-state ownership。
- `packages/web-shell/client/components/ChatPane.tsx` / `App.tsx`：prompt completion 通知 session catalog controller。
- `packages/web-shell/client/session-catalog/*.test.tsx?`：live watermark reorder、stale response、fallback、failure recovery 与 hook routing 回归。

## 验证方式

PR 声明已通过 `cd packages/web-shell && npx vitest run client/session-catalog client/components/ChatPane.test.tsx client/App.test.tsx`；真实 daemon E2E 确认 turn 完成后目标 session 在下一次 live-state poll 内移动到顶部，且没有额外 full `/sessions` 请求。

## feature 文档处理

已在 daemon WebUI/transport、session lifecycle 和 daemon 总览中登记为 #9396 activity watermark 的 merged WebShell consumer。文档强调 `updatedAt` 缺失时仍必须保留 full catalog fallback，且 live-state 只能更新当前页面已有 row。

## 边界与风险

- `updatedAt` 是 daemon-observed live activity watermark，不是 transcript 持久化确认；UI 仍需支持后续 persisted catalog 结果与其合并。
- cursor page、archived/group/source-filtered page 不做 live reorder，避免局部页面被 volatile 活动破坏过滤语义。
- 老 daemon 或未命中 row 的 completion 仍会触发限频 full catalog refresh。
