# PR #9380 最终实现：ACP child peak old-generation heap measurement

> PR: [feat(serve): measure ACP child peak old-generation heap](https://github.com/QwenLM/qwen-code/pull/9380)
> 状态：merged，2026-08-19 合入 `main`。
> 规模：+1518 / -3，11 个文件

## 解决了什么问题

#8508 已在 daemon status 中建模 per-child heap partition，但只知道 child 数量是否超出 modeled pool，不能判断真实 workload 是否能在较低 old-generation ceiling 下存活。RSS 覆盖 Buffer、external allocation 与 young generation，`heapUsed` 也混入 young generation；它们都不能回答 V8 old-generation limit 约束的对象到底达到过什么高水位。若仅靠 refusal count 打开 enforcement，健康 daemon 可能被误推入 OOM 循环。

## 最终实现方案

#9380 最终实现把测量放进 daemon-spawned ACP child 自身，而不是 daemon sampler。`ChildHeapProbe` 在带 daemon marker 的 ACP child 中安装 GC observer 和 unref interval，按既有 child resource poll 每 5 秒读取 lifetime accumulator；交互式 CLI、IDE companion、direct embed bridge 和 standalone ACP 不安装 probe。

探针统计整个 old generation，而不是只看 `old_space`。它把 V8 heap space 分类为 old-generation committed bytes，记录 `peakOldGenerationBytes`、major GC 后仍存活的 `peakLiveSetBytes`、`peakTotalHeapBytes`、`majorGcCount`、`majorGcMs`，以及无法分类的 `unclassifiedSpaceNames`。如果后者非空，其它 byte figures 可能是低估，daemon status 必须把这个信号原样暴露。

`packages/acp-bridge/src/bridge.ts` 校验 child resource report，丢弃非法 heap report，并限制未归类 space 名称长度/数量。`daemon-status.ts` 将多个 child 的 heap peaks 作为 per-child ceiling 语义处理：RSS 仍求和，但 heap peak 取独立最大值，`reported` 表示有测量贡献的 child 数。没有样本时返回 `runtime.memory.children.heap: null`，避免把未观测误写成零需求。

所有改动均为 observe-only：不改变 ACP child spawn argv，不拒绝 spawn，不新增 enforcement，`limits.memory.enforced` 仍保持 `false`。

## 关键代码路径

- `packages/cli/src/acp-integration/child-heap-probe.ts`：V8 heap space 分类、major GC observer、lifetime high-water accumulator。
- `packages/cli/src/acp-integration/acpAgent.ts`：只在 daemon-owned ACP child 安装 probe，并接入 resource poll report。
- `packages/acp-bridge/src/bridge.ts` / `bridgeTypes.ts`：child resource report schema、heap block validation 与 bridge-side projection。
- `packages/cli/src/serve/daemon-status.ts`：多 child heap peak aggregation、`heap:null` 未采样语义。
- `packages/sdk-typescript/src/daemon/types.ts`：daemon status child heap optional 类型。
- `docs/design/2026-08-18-acp-child-peak-old-generation-measurement.md` / `docs/developers/qwen-serve-protocol.md`：测量动机、状态字段和非 enforcement 边界。

## 验证方式

PR 声明已通过 `npm run build && npm run bundle`，并在真实 daemon Node 24.12.0 下确认未采样时 `heap:null`、采样后 peak 单调、child argv 不变、两 workspace 场景 RSS 求和而 heap peak 取最大。单元覆盖包括 `child-heap-probe.test.ts` 11 条、`daemon-status.test.ts` 54 条、ACP bridge/spawn/child-heap-policy 771 条、SDK public surface 15 条；V8 space classifier 额外在 Node 22.19.0、22.22.3、24.12.0 上检查。

## feature 文档处理

已在 resource budgeting、capabilities/protocol、SDK 和 daemon 总览登记为 observe-only merged status 字段。不能写成 enforcement、spawn refusal、child argv 变化或完整 process-tree memory measurement；channel worker 与 MCP descendant heap 仍不在范围内。

## 边界与风险

- `peakLiveSetBytes` 是上界，不是 exact live set；GC observer 异步到达，误差方向偏大。
- 未归类 heap space 一旦非空，其它 byte figures 可能低估，调用方不能忽略。
- 这不是 workspace/session cap，也不是 #8093 ResourceBudget production wiring。
