# PR #9512 最终实现：standalone conversation primitives hardening

> PR: [fix(serve): Harden standalone conversation primitives](https://github.com/QwenLM/qwen-code/pull/9512)
> 状态：merged，2026-08-20 合入 `main`。
> 规模：+156 / -34，7 个文件

## 解决了什么问题

#9341 合入的 PR2A primitives 在 review 中留下三类边界：standalone directory 在 ensure race 中被并发创建时可能未经完整 identity inspection 就被采纳；integrity-aware JSONL head reader 的预算以 recover record 数理解会让固定前缀检查不稳定；`ConversationDirectoryIdentityError` 的 `cause` 手动挂载会暴露 enumerable `cause: undefined`，不符合普通 Error 行为。

这些问题暂时没有扩大公开 API，但 PR2B 会直接依赖 directory ensure 与 JSONL classification contract，因此需要先把内部 primitive 的状态语义和读取预算收紧。

## 最终实现方案

`ConversationWorkspace.ensureStandaloneDirectory()` 的 race path 改成二次 inspection：第一次检查缺失后，如果 materialize 前已有并发创建者赢得目录创建，代码不再直接返回可用，而是用相同 inspection 重新验证目录 owner、mode、realpath、direct-child 与 identity verdict；首次创建返回新增的 `created` 状态，只有捕获过 identity 后目录消失再重建才返回 `recreated`。

`readLinesWithIntegrity()` 改为按物理非空行计量 integrity budget。即使某一行含 glued records 并恢复出多条 record，fail-closed verdict 仍覆盖固定的前 N 个非空行；普通 head reader 继续保留 record-budget contract，malformed/scalar/blank 不消耗预算，glued records 也不会让返回结果超过请求数。

`ConversationDirectoryIdentityError` 改用 ES2022 native `ErrorOptions` 传递 cause。没有 cause 时实例不再有自有 `cause` key；有 cause 时仍可读取，但不会出现在 `Object.keys()` 或 `JSON.stringify()`，避免错误对象序列化面漂移。

## 边界与风险

- `created` 是 ensure result union 的新增成员，但当前 primitive 仍无生产消费者；PR2B 接入时需要处理该状态。
- integrity-aware reader 可因一条 glued line 返回超过行预算数的 records；唯一生产消费者按扫描窗口解释，plain reader 仍保持明确 record cap。
- #9490 item 1/2 仍未在本 PR 内解决，预计继续随 PR2B trusted write seam 与 persisted spelling lock identity 收敛。
