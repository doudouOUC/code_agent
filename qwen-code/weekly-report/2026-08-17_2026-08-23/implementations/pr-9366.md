> 规模：+2220 / -117，10 个文件

## 解决了什么问题

WebShell sidebar 之前把完整 `/sessions` catalog 当作两秒一次的 live status poll。该路径会扫描 persisted session、organization/group、worktree sidecar 并合并 bridge live state；多处 sidebar/overview/dialog 消费者并发时容易重复发起昂贵 catalog 请求。#9261 已提供轻量 live-state protocol 后，WebShell 需要改成只在 catalog version 变化时刷新完整 catalog，并保证 full catalog 与 groups 不会从未 fencing 的刷新结果发布。

## 最终实现方案

#9366 最终实现让 WebShell 在 daemon 广告 `workspace_session_live_state` 时使用 live-state coordinator。`WebShellSidebar.tsx` 会按 capability 将 workspace 分为支持 live-state 的 absolute cwd 集合与 legacy fallback 集合；旧 daemon 或不支持 capability 的 workspace 保留原有 catalog polling。

新增 `useWorkspaceSessionLiveState()` 与 `workspace-session-live-state.ts`。首次加载或 source 变化时，客户端执行 `live A -> full catalog -> session groups -> live B`；只有 A/B 的 `generation+revision` 相等，且 catalog/group 请求在 A 之后启动并成功，才提交同一 bundle。稳态每 2 秒只 poll live-state 来更新 `clientCount`、active prompt 与 wait flags；live-state 失败退避 30 秒，catalog reconcile 有 10 秒冷却，显式刷新或 local invalidation 会立即唤醒。

`SessionCatalogStore` 增加 live-state ownership 和 staging 语义：`registerWorkspaceLiveStateUser()` 记录哪些 workspace 由 live-state 消费者接管；`stageWorkspaceRefresh()` / `commitWorkspaceRefresh()` 把 full catalog 与 group catalogs 暂存到同一版本栅栏下；刷新请求带 `interactive` / `invalidated` provenance，避免 legacy non-staged request 满足 staged waiter，旧响应或反复拒绝的 commit 不会覆盖当前 page 或形成 hot loop。live-state 中缺失的 row 只清理已知 catalog row 的 volatile 字段，不删除 persisted row。

E2E mock daemon 增加 live-state route，Playwright 用例固定 request pattern：首次加载有 live-state A/B 与一次 full catalog，稳定状态只 poll live-state；source change 或 mutation 后才触发一次版本 fencing 的 full refresh。Vitest 覆盖 store concurrency、fallback、group catalog equality、subscription 变化与 stale publication guard。

## 边界与风险

- live-state coordinator 接管 catalog scheduling 后，错误 ownership handoff 可能抑制必要 refresh 或发布 stale page；本 PR 通过 staged bundle、version equality 和 focused race tests 覆盖。
- first live-state request 失败时会先做一次 unfenced catalog fallback，再用 backoff 重试 live-state。
- 该 PR 不实现 server-side `updatedAt` activity watermark；该服务端字段已由 #9396 合入，WebShell 消费端由 #9476 合入。
