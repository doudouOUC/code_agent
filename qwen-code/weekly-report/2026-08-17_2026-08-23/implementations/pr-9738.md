> PR: [feat(serve): add --open-with-auth](https://github.com/QwenLM/qwen-code/pull/9738)

> 规模：+1216 / -23，19 个文件

## 解决了什么问题

loopback Web Shell 若未配置 bearer，daemon 的非 strict 路由仍可被其他本机进程调用；每次手工生成并传递 token 又增加一次性本地交互的启动成本。直接把 bare `qwen serve --open` 改成自动鉴权会破坏既有 token-less curl/SDK、embedded caller 与 Chrome extension 兼容，因此需要一个明确 opt-in 的完整启动模式。

## 当前实现方案

当前 diff 新增独立、默认关闭的 `--open-with-auth`，该 flag 本身包含 browser open intent，不要求再写 `--open`，冗余 `--open` 或 `--no-open` 也不会关闭认证模式。yargs 和 fast-path 两条 CLI startup path 都在 listener 创建前调用 `applyOpenWithAuth()`：非 loopback、`--no-web` 或缺失 Web Shell assets 直接 boot-loud 失败；通过后复用显式 `--token` 或 `QWEN_SERVER_TOKEN`，两者都没有可用非空值时才生成 32 个随机字节并编码为 base64url。

`resolveServeToken()` 集中既有的 option-over-environment、先选择再 trim 规则；显式空 option 仍会 shadow environment，因而在新模式下触发生成。选中的 token 进入原有 `runQwenServe()` bearer middleware、WebSocket、strict mutation、worker handoff 与 redaction 链，不新增认证协议或 credential store。`RunHandle.resolvedToken` 继续作为 browser handoff 的唯一权威值。

browser eligible 时，CLI 在 runtime ready 后把 token 放入既有 `#token=` fragment 并启动 Web Shell；Web Shell 已有逻辑会把 token 写进当前 tab 的 `sessionStorage`、清理 fragment，并为 fetch/SSE 附加 `Authorization: Bearer`。browser ineligible 时新模式仍启动 daemon，但打印带 fragment 的手动 URL。bare `--open`、direct embedded caller、Chrome extension、未传新 flag 的 invocation 与 Local Control 独立 pairing token 保持原行为。

## 关键代码路径

- `packages/cli/src/serve/open-with-auth.ts`：pre-listen loopback/Web Shell/assets 校验、token 复用或 256-bit 生成，以及非 secret 提示。
- `packages/cli/src/serve/serve-token.ts`：统一 option-over-environment 和 trim 规则。
- `packages/cli/src/commands/serve.ts`：yargs flag、完整启动路径接线，以及 eligible/manual browser handoff。
- `packages/cli/src/serve/fast-path.ts`：fast parser 与同一 helper 接线，保持两条 startup path 行为一致。
- `packages/cli/src/serve/run-qwen-serve.ts`：消费统一 resolved token，并通过 `RunHandle.resolvedToken` 交给 browser flow。
- `docs/design/2026-08-22-serve-open-with-auth.md` / `docs/plans/2026-08-22-serve-open-with-auth.md`：最终 opt-in 契约、兼容边界与实现分解。

## 边界与风险

- 当前 open；flag 名、pre-listen 校验、headless fallback 与 token 选择仍可能在合入前变化。
- opted-in daemon 的本地客户端若没有 bearer 会收到 401；多客户端和可重开场景应显式配置稳定的 `QWEN_SERVER_TOKEN`。
- token 会出现在 browser launch process command 或 headless 手动 URL 中；该模式只面向可信单用户 loopback 主机。
- 不提供持久 token store、跨 tab 分享、cookie、client identity、独立 revoke、SDK/extension credential discovery 或 non-loopback 自动凭据。
