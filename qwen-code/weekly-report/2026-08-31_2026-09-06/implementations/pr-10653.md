## 解决了什么问题

#10634 已让管理员通过 schemaVersion 2 instance 和自有 Dialect V1 使用 configurable Mem0 runtime，但 `@qwen-code/external-context-mem0` 仍标记为 private。管理员缺少受支持的 scoped npm 安装、固定版本升级和 release provenance 路径；若独立手工维护版本，又会让 package、Extension manifest 与 Qwen Code release 漂移。

## 当前实现方案

当前 diff 移除 package 的 `private` 标记并补 repository metadata，让 package version 与 `qwen-extension.json` manifest version 都由现有 `scripts/version.js` 随 Qwen Code release 一次更新，release commit 同时 stage integration package 与 manifest。`@qwen-code/external-context-mem0` 还加入 `PUBLISHED_PACKAGES`，因此 partial publish 后的 release retry 会先检查精确版本，不能覆盖已发布版本。

release workflow 在其它 npm 包之前增加 provenance publish，但由 `NPM_EXTERNAL_CONTEXT_MEM0_TRUSTED_PUBLISHING_ENABLED == 'true'` 显式门控。原因是 npm trusted publisher 只能在首次 package 存在后配置；maintainer 必须先完成一次 bootstrap publish、绑定 `release.yml`/`production-release`，再启用 repository variable。dry-run 保持可验证，实际版本已存在时安全跳过。

package 内容边界不变：dry-run tarball 只允许 README、bundle、package metadata、Extension manifest 和两个 canonical schema。安装不会创建 instance/dialect、credential 或普通 Qwen setting，也不加入 provider preset、Core wiring、write 或 Auto Recall。

## 关键代码路径

- `integrations/external-context-mem0/package.json` / `qwen-extension.json`：公开 scoped package metadata 与同版本 manifest。
- `scripts/version.js`：在统一 release versioning 中更新并格式化 Extension manifest。
- `scripts/get-release-version.js`：把 Mem0 package 纳入已发布版本/回滚 guard。
- `.github/workflows/release.yml`：bootstrap variable gate、版本存在检查、dist-tag 与 provenance publish。
- `integrations/external-context-mem0/src/manifest.test.ts` 与 `scripts/tests/`：package 内容、版本写回、workflow 顺序和 trusted publishing contract。
