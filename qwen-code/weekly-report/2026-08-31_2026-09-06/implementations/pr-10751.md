## 解决了什么问题

WebShell 的 turn rail 只能从当前已经加载的 transcript blocks 推导。长会话受初始页、block retention 和 byte budget 限制，早期 turn 不在浏览器状态里时既不可见，也无法用现有顺序 transcript API 直接定位。若仅用页内 ordinal 或未冻结的 record cursor 跳转，后续 append、compaction 或归档变化还会让同一次导航看到不一致的数据。

## 最终实现方案

最终 Phase 1 在既有 active-chain transcript index 上生成稀疏 turn index，只纳入普通 user prompt、realtime 和 scheduled/cron turn，排除 notification、goal runtime、mid-turn 和 live-only shell 记录。持久 user record UUID 作为稳定 `turnId`；ordinal 只描述当前 snapshot 内的位置。label 与 assistant preview 均有界，生成 attachment token、thought、tool call/argument/result 和原始 payload 不进入公开 detail。

首次 turn-index 请求签发 HMAC snapshot，绑定 workspace、session、transcript file identity/size、active leaf 与时间。owner-resolved 和 workspace-qualified route 都返回同一契约；后续 index 分页与 transcript 锚定读取必须携带匹配 snapshot。transcript route 增加 inclusive `atRecordId`，返回 additive `targetRecordId` 和 `hasOlder`；`cursor` 与 anchor 互斥，`start` 也必须绑定 snapshot。daemon 只有在 turn-index 与 anchor operations 同时可用时才广告 `session_turn_navigation`，ACP vendor method 与 TypeScript SDK 再做 capability gate 和有界响应校验。

## 关键代码路径

- `packages/core/src/services/session-transcript-reader.ts`：从 active-chain index 构建稀疏 turn metadata，裁剪公开 label/detail 并按 record anchor 读取 transcript。
- `packages/cli/src/serve/routes/session.ts`：owner-resolved 与 workspace-qualified turn-index route、snapshot 校验和 transcript anchor 参数约束。
- `packages/cli/src/serve/capabilities.ts`：只在完整操作集安装时广告 `session_turn_navigation`。
- `packages/acp-bridge/src/bridge.ts`：把 turn-index 与 anchor transcript 暴露为 daemon vendor method。
- `packages/sdk-typescript/src/daemon/DaemonSessionClient.ts`：capability-gated turn index、snapshot 分页和锚定 transcript API。
