## 解决了什么问题

#10198/#10420 建立了 owner-scoped 命名任务和输出归因，但只要 selected 任务 busy，owner 就不能创建或切换到另一个 task；取消也只能指向 selected task。权限命令在并发任务下还需要区分 bare 快捷操作与显式 request ID，避免误处理 inactive task 的请求。

## 最终实现

`NamedSessionManager` 在 owner lock 下增加 exact `lookup()` 和 `resumeReserved()`。入站 turn 在异步 media preparation 前保留 exact session，完成准备后不改 selected task 就可恢复保留目标并发送。create/use/fallback 不再被 selected/destination busy 全局阻塞，但 close busy task 仍拒绝，防止正在运行的 session 失去 catalog owner。

`/session cancel [name]` 可以针对 selected 或 exact owned open task，只在目标存在 active prompt 时复用已有 cancellation。bare approve/deny 仅搜索 selected session 的 pending permission；用户提供 exact request ID 时才可路由到 owned inactive task。`multiSession:false` 的旧路径保持不变。

## 关键代码路径

- `packages/channels/base/src/named-session-manager.ts`：exact lookup、owner reservation 和并发恢复。
- `packages/channels/base/src/ChannelBase.ts`：turn admission、named cancel 和 permission request 路由。
- `packages/channels/base/src/named-session-manager.test.ts` / `ChannelBase.test.ts`：并发 task、cancel、permission 与 disabled-mode 回归。
