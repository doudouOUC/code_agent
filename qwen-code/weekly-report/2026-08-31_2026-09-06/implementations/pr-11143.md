## 解决了什么问题

#10751 已交付 daemon/SDK turn index与 anchored transcript协议，但 WebShell的 live transcript仍只能从尾部顺序加载。客户端缺少权威 page边界、可重建 gap、session-wide turn metadata和持久 prompt/record identity，因此无法在固定内存预算内随机打开长会话中段。

## 关闭前方案

该单提交方案沿 #11020原始设计保留 flat `DaemonTranscriptStore`作为唯一 render source，并在 `DaemonSessionProvider`旁增加三组协作状态。`transcriptPageLedger`记录 replay、prepend和 anchored fetch各自对应的 block range以及显式 gaps，使 trim/rewind后仍保留可重新抓取的 locator；`turnIndexStore`独立加载 newest/older metadata pages，按 prompt terminal做 append-only refresh或保守 reset，并用不会缩减通告总数的 LRU限制内存；message adapter则把 `sourceRecordIds`与 `promptId`投影到 rendered message，供 exact定位和去重。

会话 actions增加 `openTranscriptAtTurn`、older continuation和 newer continuation。锚定页先隔离 materialize、按 record ID再按 prompt ID去重，再依据 snapshot ordinal原子 splice进 flat store；continuation严格区分 `{beforeRecordId,snapshot}`与单独 signed cursor。daemon整页拒绝、客户端窗口拒绝、终态容量溢出、snapshot失效和 anchor缺失被映射为不同失败原因，供后续 rail选择重试或降级。

该实现与 #11053属于同一 flat-store ledger路线，但文件切片和 review阶段不同；最终两者均关闭未合入。`main`采用 #11054的 separate-store Phase 2A，不把随机历史页拼入 connected live transcript。

## 关键代码路径

- `packages/web-shell/client/daemon/session/transcriptPageLedger.ts`：flat render store上的page边界、gap、trim与锚定 placement。
- `packages/web-shell/client/daemon/session/turnIndexStore.ts`：snapshot-aware metadata分页、tail refresh、provisional与有界cache。
- `packages/web-shell/client/daemon/session/DaemonSessionProvider.tsx`：capability gate、index生命周期、锚定读取和atomic admission。
- `packages/web-shell/client/adapters/transcriptToMessages.ts`：持久 record/prompt identity投影。
- `packages/web-shell/client/daemon/session/actions.ts`：锚定打开及双向 continuation入口。
