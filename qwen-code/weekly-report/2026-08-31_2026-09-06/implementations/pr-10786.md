# PR #10786 关闭方案观察：standalone task 的 workspace 导航

> PR: [fix(web-shell): Preserve workspace navigation in standalone tasks](https://github.com/QwenLM/qwen-code/pull/10786)
> 状态：closed 未合入；以下仅记录关闭前 head `f98f7edae3` 的历史方案，不能视为 `main` 已落地能力。
> 规模：+1,247 / -103，17 个文件

## 解决了什么问题

standalone chat 接入后，全局 New task 曾隐式偏向无 workspace，进入 standalone context 后又同时隐藏 workspace 导航、Plugins 和 Scheduled Tasks。用户因此难以明确选择下一任务的 scope，也可能在错误 workspace 上创建或管理 scheduled task。

## 关闭前方案

关闭前 diff 把全局 New task 拆成 workspace 与显式 No workspace 选择，并为默认 trusted workspace 建立单独的 scope 决策。前端 gate 不再只依赖单一 `workspaceFeaturesActive`，而是拆分 project navigation、workspace management 和 workspace-only capabilities，使 standalone task 内仍能导航回 workspace，同时让真正依赖 workspace runtime 的页面继续 fail closed。

scheduled task 路径还准备传递 exact workspace cwd，并按 owner workspace 调用 daemon，避免从 standalone context 猜 primary workspace。该分支最终关闭且未合入；复核最新 `main` 时，只能确认较窄的 workspace-first New task 和 composer 中显式的 projectless standalone 选择，不能把关闭分支中的 Plugins、Scheduled Tasks 或 owner-routing 扩展写成现状。

## 关键代码路径

- `packages/web-shell/client/components/sidebar/WebShellSidebar.tsx` / `WorkspaceSelector.tsx`：全局 New task 的 workspace/No workspace scope 选择与导航入口。
- `packages/web-shell/client/App.tsx`：区分 standalone、project navigation、workspace management 和 workspace-only feature gates。
- `packages/web-shell/client/components/dialogs/ScheduledTasksDialog.tsx`：关闭前按 exact workspace owner 路由 scheduled task 的方案。
