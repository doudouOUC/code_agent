## 解决了什么问题

daemon 发生 JSON-RPC 内部错误时，HTTP envelope 常为顶层 `error: "Internal error"` 并将稳定原因放在 `data`、`data.details` 或 `data.message`。TypeScript SDK 原来只用顶层 error 生成 exception，导致诸求调用方不能看到可诊断细节。

## 最终实现

`DaemonClient` 的共享 HTTP error formatter 在 status >= 500、顶层 error 精确为 generic `Internal error` 且 code 为数字时，按非空 `data` 字符串、`data.details`、`data.message` 的顺序解包稳定详情。其它形状保留原行为：具体顶层错误不被覆盖，4xx、非数字 code、非 JSON 和原始 status/body 不被新规则重写。该 formatter 是 SDK-wide HTTP 边界，所以所有符合形状的 daemon JSON-RPC 5xx 都受益，不只是 model route。

## 关键代码路径

- `packages/sdk-typescript/src/daemon/DaemonClient.ts`：HTTP error body 解析、generic 5xx 限定和 detail 选择。
- `packages/sdk-typescript/test/unit/DaemonClient.test.ts`：5xx/detail 形状和兼容 fallback 测试。
