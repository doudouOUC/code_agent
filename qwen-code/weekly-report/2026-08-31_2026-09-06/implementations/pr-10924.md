# PR #10924 当前实现观察：Conversations mandatory session writer fences

> PR: [feat(serve): Fence Conversations writers with mandatory session leases](https://github.com/QwenLM/qwen-code/pull/10924)
> 状态：open；以下描述 2026-09-04 复核到 head `67f23fe4f6` 的当前 diff，不能视为 `main` 已落地能力。
> 规模：+1,084 / -19，25 个文件

## 解决了什么问题

#10828 已合入的 relaxed ownership 设计准备让多个同机 daemon 同时挂载共享 Conversations root，但当前 runtime 仍依赖进程全局 owner。后续移除该 gate 之前，必须先证明 standalone、Live、scheduled-task controller/run 等每个 Conversations writer 都会获取同一 per-session lease；否则一个未启用实验开关或 marker 未真正传入 child 的 writer 会绕过围栏。现有本地 stale reclaim 在 Linux 上也缺少 PID namespace 身份，batch lifecycle 会把 writer conflict 压成通用失败，daemon-local directory pin 还可能在 session generation 结束后误判合法重建目录。

## 当前实现方案

当前 open diff 先落地纯增量 fence，不移除外层 global owner。daemon 的共享 child overrides 显式删除 `QWEN_CODE_PRIVATE_CONVERSATIONS_RUNTIME`，只给 `live-conversation` runtime 的 ACP child 注入精确值 `1`。CLI 在第一次 `await` 和环境文件加载前捕获并删除 marker，只有 ACP mode 且 private parent capability 存在时才接受；accepted provenance 冻结到进程生命周期，使 writer lease 不再依赖 `experimental.sessionWriterLease`，并把 managed child 的 reclaim policy 设为 `local`。workspace/user `.env` 和后续 settings reload 不能重新引入 marker。

`createSpawnChannelFactory()` 用包内 `WeakSet` 标记真正会把 overrides 合并进 child env 的 factory；bridge 只在 frozen overrides 含精确 marker 且 factory 带 forwarding proof 时产生 immutable `mandatoryLeaseAttested`。`ConversationRuntimeManager` 在采用已有 runtime 或发布新 candidate 前强制验证该证明：新 candidate 拒绝并 dispose，已有 runtime 终态 quarantine，之后持续返回不可重试的 `conversation_root_compromised`。review 发现 fast path 通过 core barrel 导入 marker 会拉入重量模块；最新 head 将常量移到 `./conversationsRuntimeMarker` leaf export，使 serve pre-listen bundle gate 恢复通过。

core writer record schema v2 可选记录 Linux PID namespace inode。`local` reclaim 只有 hostname 相同，Linux 上 boot ID 与 PID namespace 也都存在且匹配，并且 PID 已死亡或 start identity 证明复用时才把 active record 判 stale；旧记录缺身份、foreign/live/stalled/不确定状态继续 fenced。standalone parent lifecycle/maintenance acquisition 也改用同一 `local` 策略，batch archive/delete 在对应 item 保留 `SessionWriterError.errorKind`。

working-directory pin 只在匹配的 resident bridge event epoch 存在时有效；terminal close、idle reap、session missing 或 epoch 替换后丢弃本地 pin 并重新检查目录，active generation 内 replacement 仍 fail closed。marked Conversations session 在 scheduler 启动前安装 durable-fire predicate，unbound task 必须等待 daemon keepalive 通过既有 task-file transaction 提交 controller binding 才能执行。

## 边界与风险

- PR 仍为 open；mandatory marker/attestation、identity-qualified reclaim、batch writer error 与 generation-scoped pin 都不能视为 `main` 已有能力。
- 外层 process-global Conversations owner 仍存在，本 PR 不允许多个新 daemon 并发挂载；legacy owner migration、global gate removal、deletion-journal bootstrap、Live publisher admission/pending-intent 线性化与 WebShell inline degradation 由后续 PR 交付。
- Linux 旧 schema record 缺 PID namespace 时有意 fail closed，只能走文档化人工清理；这避免在共享文件系统或容器身份不确定时误回收 live writer。
- unbound-task predicate 只消除 controller binding 竞争造成的提前执行，不改变 prompt dispatch 后、fired-state 持久化前既有 at-least-once 窗口。
