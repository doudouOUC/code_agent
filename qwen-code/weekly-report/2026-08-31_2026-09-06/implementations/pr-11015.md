## 解决了什么问题

#10643 已让 named Channel task 使用 daemon 证明的独立 worktree，但 Part 4A 有意拒绝对选中 worktree task 执行 `/clear`、`/new` 或 `/reset`。用户无法保留同一 checkout、branch 和 task 名来重开 conversation。合入后的 Part 4A 还留下 post-spawn cleanup、stale SDK claim、marker 写失败与缺名参数等边界缺陷。

## 当前实现方案

当前 open diff 已实现 `session_worktree_reset_v1` 和 `POST /session/:id/worktree-reset`。route 在 canonical worktree-keyed ownership lock 下验证旧 session、sidecar、marker 与 cwd，安装 `worktree_reset_active` admission barrier并等待 active/deferred prompt quiescence；随后在 registered root 创建 replacement、relocate 到同一 worktree，写带 `supersedes`/`supersededBy` 的双向 sidecar，翻转前再次验证 quiet state，最后以 marker owner/file identity compare-and-swap提交。提交后返回 `persisted-v1` 证明并 sever superseded session；不删除用户已有 checkout、branch、文件或旧 transcript。

崩溃恢复由 marker 决定权威方：pre-commit shape只回滚本请求创建的 replacement sidecar/record并重试 transfer；marker已指向 replacement时幂等恢复，busy replacement返回 typed active failure而不做破坏性写。restore新增 superseded redirect、missing-marker与 interrupted transfer分类。Channel manager在 owner lock 下替换 registry session ID，保留创建时间并更新选择/更新时间；失败后清理 stale live ID，收到 superseded signal时自愈到 replacement，并只对 interrupted窗口做一次自动重试。replacement attach同步恢复 channel-loop MCP注册。

同一 diff还修复 Part 4A 四个残余缺陷：post-spawn generation失败时移除 session从未进入的无主 checkout；SDK在 resume无 worktree object时清除 stale durable claim，但对未证明/路径不符继续 fail closed；exclusive marker写失败只在路径仍是本次 inode时清理，成功后的 close失败不误删完整 marker；任何 leading-flag缺少 task name都返回 usage。
