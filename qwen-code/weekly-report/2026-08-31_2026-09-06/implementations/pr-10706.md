# PR #10706 最终实现：延后 standalone provisional reasoning 选项

## 解决了什么问题

daemon-owned standalone create/load/resume 会先返回 provisional ACP session，再由 managed activation 初始化认证、workspace 和 content generator。若此时已选择支持 reasoning 的模型，config option builder 会直接读取尚不存在的 generation config 中的 `thinkingMandatory`，触发 TypeError 并让 exact standalone 请求返回 HTTP 500。

## 最终实现方案

`getConfigOptions()` 继续先构造不依赖 LLM initialization 的 mode/model 选项，然后用 optional `getContentGeneratorConfig?.()` 读取 generation config。provisional 阶段缺失时立即返回 mode/model，不刷新 auth、不激活 provisional workspace，也不安装 filesystem state。该分支只延后 `reasoning_effort`，不伪造默认值。

managed activation 建立 live generation config 后，既有 `qwen/session/context` refresh 再经过完整路径生成 reasoning options。mandatory-thinking model 继续过滤 `none`，因此修复没有放宽模型约束，也没有改变非 standalone 已认证 session 的 option path 或 wire shape。

## 关键代码路径

- `packages/cli/src/acp-integration/acpAgent.ts:getConfigOptions`：generation config 缺失时返回安全的 mode/model provisional 选项。
- `packages/cli/src/acp-integration/acpAgent.test.ts`：覆盖 standalone new/load/resume 的无副作用 provisional response，以及 activation 后 mandatory reasoning 恢复。

- provisional response 有意暂缺 `reasoning_effort`；consumer 需接受 activation 后的 session-context refresh 才获得完整选项。
- 修复不改变认证顺序、daemon lifecycle、WebShell UI、自动重试或非 standalone session 行为。
