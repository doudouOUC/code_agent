## 解决了什么问题

WebShell的 live transcript仍是单个 prepend/append store。它无法记录哪些 blocks属于一次权威 page、哪些范围已被淘汰，也没有 durable record/prompt identity供 session-wide rail使用。即使 daemon已支持 turn index和 anchored read，客户端仍不能在固定预算内安全纳入中段历史页。

## 关闭前方案

关闭前方案沿 #11020原始方案保留 flat SDK store为唯一 render source，并在 provider旁记录 replay、prepend与 anchored fetch对应的 page ledger。retention trim/rewind按实际保留 blocks裁剪 pages，gap集合显式表示未加载范围；prepend替换 head gap，双向 eviction按方向重建 gap而不声称未证明的 page连续性。

message adapter从已有 `sourceBlockIds`后处理派生有序去重的 `sourceRecordIds`与 `promptId`，不污染明确要求剥离 block identity的 raw projection。独立 turn-index store按 server `start`和各页自己的 snapshot缓存 metadata，支持 newest seed、older paging、append-only tail refresh、rewind/divergence reset、page/byte LRU和 `transcript_too_large` fallback；provisional只按 exact prompt/record匹配。

`openTurnAt(turnId)`使用 entry所属 snapshot发起 `atRecordId`读取，隔离 materialize并在 anchored路径关闭 prepend-only echo dedup，再按 snapshot ordinal计算 flat-store splice位置。ledger据 `hasOlder`和 frozen-tail事实建立双向 gaps，支持 cursor、anchor和 newer-neighbor backfill resolver；单页/当前占用/绝对预算失败分别返回 `page_too_large`、`window_full`、`window_impossible`。最终 review head又补 owner/stale-request fencing、只在顺序可证明时 placement、repair checkpoint合并、tail fill逐页纳入、window reset检测和 index page LRU修正；visible rail仍未消费这些 headless API。

## 关键代码路径

- `packages/web-shell/client/daemon/session/transcriptPageLedger.ts`：flat store page边界、gap、placement、trim与 resolver。
- `packages/web-shell/client/daemon/session/turnIndexStore.ts`：snapshot-aware index pages、refresh/reconcile、provisional与 memory bounds。
- `packages/web-shell/client/daemon/session/DaemonSessionProvider.tsx`：capability gate、seed/refresh/retry、anchored materialization和 atomic admission。
- `packages/web-shell/client/adapters/transcriptToMessages.ts` / `messageTypes.ts`：持久 record/prompt identity投影。
