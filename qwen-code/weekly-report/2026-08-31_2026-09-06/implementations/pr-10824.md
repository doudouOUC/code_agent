# PR #10824 最终实现：重复 New task 后重载 standalone 模型

> 规模：+31 / -1，2 个文件

## 解决了什么问题

#10719 让零 session 的 standalone 页面读取模型选项，但 reload effect 主要受 session context 变化驱动。第一次清理 task 时 context 会变化，第二次在同一个 deferred standalone context 中再点 New task，context key 不变，effect 不会重跑，清空后的 model picker 因而无法恢复。

## 最终实现方案

最终实现复用既有 `restoreSessionNonce` 作为显式 reload trigger。清理当前 provider state 前先记录它是否属于 standalone；清理完成后，仅对 standalone 递增 nonce，使 deferred connection effect 重新读取 `GET /standalone/session-options` 并恢复 provider/model controls。该 trigger 不创建 standalone session，也不改变 workspace 和 Live context 的 clear 行为。

回归测试在同一 deferred standalone draft 上连续清理两次：options fetch 计数从初次 1 次增至第二次后的 3 次，每次 picker 都恢复，同时确认未发送 standalone create。这样覆盖的是重复清理状态转换，不靠修改 context identity 触发偶然重跑。

## 关键代码路径

- `packages/web-shell/client/daemon/session/actions.ts`：清理前捕获 standalone context，并在清理后递增 restore nonce 触发 options reload。
- `packages/web-shell/client/daemon/session/DaemonSessionProvider.test.tsx`：覆盖同一 deferred standalone draft 连续两次 New task/clear 的 fetch 与不创建 session 约束。
