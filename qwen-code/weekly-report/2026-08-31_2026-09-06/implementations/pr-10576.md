## 解决了什么问题

systemd 和 launchd 启动的 daemon 不会自动读取交互 shell profile。因此管理员可能用绝对路径成功启动 `qwen`，但新 session 中的 Shell 找不到 `gh`、`git`、`npm`、`node` 等必要工具。通过每条命令临时注入 PATH 不仅不稳定，也会让 daemon/ACP child 的实际环境难以审计。

## 最终实现

本 PR 仅修改部署文档。systemd unit 和 launchd plist 都应设置明确、受信、绝对目录组成的 PATH，同时覆盖 `qwen` 解释器和用户期望的工具。token 继续独立保管：systemd 使用 `EnvironmentFile`，launchd 使用受保护 plist，不与 PATH 配置混合。reload/restart 后必须从新建 daemon session 执行 bare `command -v gh` 等验证，不依赖登录 shell 或单次 inline PATH workaround。

PR 声明已在 macOS launchd 下重载 service，验证 daemon health 与新 session bare `gh` 解析，并通过 Prettier、diff check 和 plist lint。Linux systemd 部分仅做配置复核，未由当时的真机证据独立验证。本次按 merged diff 和最新 `main` 文档核对，不涉及代码测试。

已在 [[qwen-code/feature/daemon-serve-mode/README|daemon 总览]] 登记 managed service 不读 shell profile 和显式 PATH 验收口径。

## 边界与风险

- 本 PR 不修改 Shell Guard、Git guard 或 daemon 运行时代码。
- PATH 应只放管理员信任的绝对目录，不应加入可被非信任用户写入的路径。
