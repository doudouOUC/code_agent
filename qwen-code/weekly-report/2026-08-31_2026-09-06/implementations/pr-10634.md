# PR #10634 最终实现：管理员所有的 Mem0 dialect

> 规模：+582 / -502，16 个文件

## 解决了什么问题

#10149 已合入 configurable Mem0 extension skeleton，但 `builtInPresets` 故意为空，因此不能连接真实 provider。直接在 Qwen Code 中增加 provider-specific preset 会把协议演进、凭据结构和运维责任固化到产品代码；开放任意模板/JSONPath 又会破坏 closed dialect 安全边界。

## 最终实现方案

instance config 升级为 schemaVersion 2，用绝对 `dialectPath` 指向管理员所有的 Dialect V1 文件，并删除 built-in preset registry。instance 和 dialect 独立做 64 KiB 有界读取、JSON/schema 校验与固定脱敏 error category。loader 先校验绝对路径、endpoint/static path、closed dialect 语义和 scope，之后才读 `credentialEnv` 指定的环境变量。

Dialect V1 仍只允许枚举 GET/POST、固定鉴权/字段位置和静态结果路径，不允许任意 header/template/JSONPath/code、env expansion、redirect、retry、probe、cache 或 write。旧 schemaVersion 1 preset config 明确 fail closed，需迁移到 v2 dialect 文件，避免默认选择不同 provider 语义。

## 关键代码路径

- `integrations/external-context-mem0/src/config.ts`：V2 instance/dialect 有界加载、严格校验、credential 读取顺序和脱敏错误。
- `integrations/external-context-mem0/schemas/`：instance/dialect JSON schemas 和迁移样例。
- `integrations/external-context-mem0/src/request-engine.ts`：继续消费 closed dialect，不扩大 transport 语法。
- `integrations/external-context-mem0/src/main.test.ts`、`schemas.test.ts` 与 `request-engine.test.ts`：路径、schema、redaction、credential 顺序和端到端 loopback。

## feature 文档处理

## 边界与风险

- dialect 文件可配置协议投影，不提供任意网络编程能力或 provider 管理面。
- v1→v2 是显式迁移；旧 config 不会被猜测转换。
- credential 仍存在运行环境中，最小权限、provider ACL 和审计由外部系统保证。
