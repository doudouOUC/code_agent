# PR #11120 最终实现：失败 session reclaim probe 的退避与诊断

> 状态：merged（2026-09-06）；最终 head `e544384c5f7e`。
> 规模：+923 / -5，5 个文件

## 解决了什么问题

cron、goal、monitor notification或 history mutation中的 session可能无法把工作表达为 negotiated active-work hold，daemon因而把它列为 idle auto-close候选。child又会等待自己未计数的 turn settle，导致 conditional close probe耗完整 drain budget并失败。该 probe此前每次 snapshot都立即重试、日志把跨 JSON-RPC传来的 plain object打印成 `[object Object]`，无 completion promise的 settle loop还会按 `setImmediate`高速空转。

## 最终实现方案

最终在每个 bridge session entry记录 consecutive unanswered probe count和 next retry timestamp。第一次失败后的单次恢复重试仍立即发生；第二次起按60秒、120秒等指数退避，最高1小时。backoff放在 candidate判定处，因此被抑制的 probe不再产生日志或关闭 admission窗口。child回答 closed/held、snapshot重新报告 hold，或 snapshot已不再包含该 session时都会清零失败序列；`child_dropped`因而可以立即做 exact reconciliation，而不会被旧 backoff挡住。

是否需要 round trip由共享 predicate统一决定：未协商 active-work或已被 lifecycle判定 condemned的 channel直接本地收敛，不进入 probe退避，否则 retained ghost entry会反过来阻塞 condemned channel排空。已经 dying但未满足本地授权的 channel仍保持原 retain语义。

失败日志复用 bridge已有 `extractErrorMessage()`，保留 Error和 JSON-RPC plain object中的 code/message/detail，而不是字符串化成 `[object Object]`。`Session.waitForActiveTurnsToSettle()`有 completion promises时先 `allSettled`再让出一次 macrotask；goal/history等无 promise形态改为10ms timer poll，避免在 drain budget内烧满CPU。

## 边界与风险

- backoff和polling已进入 `main`，但没有让 cron/goal/monitor/history mutation进入可协商 hold taxonomy；误判 idle的根因另行跟踪。
- 退避中的 session仍留在内存且不会被该自动回收路径关闭；用户显式 close/kill和 child后续有效回答不受 backoff阻挡。
