## 解决了什么问题

Phase 3全局 rail需要独立于当前 loaded messages的 session-wide metadata、任意 turn定位、历史 page边界和 exact live reconciliation。若把随机历史页直接塞入 connected transcript store，会影响现有 streaming、permission、Todo、prompt settlement、repair和 loaded-only rail语义。

## 最终实现方案

最终 Phase 2A选择双 store边界：现有 `DaemonTranscriptStore`继续只拥有 connected live window；新的 `HistoricalTranscriptPageTable`保存 immutable、证明连续的历史 pages/ranges及双向 boundary。随机 anchor结果保持独立 range，只有 continuation或 exact overlap才能证明邻接；record-ID dedup、whole-page LRU与 page/byte budget都在 table内完成，不 reset或拼接 live store。

`DaemonTurnNavigationStore`按各 index page自己的 snapshot缓存 turn metadata，支持 aligned ordinal load、append-compatible head refresh和 divergence epoch reset。它维护 exact `turnId -> {live|historical block}` locator、bounded provisional prompts和已移除 prompt集合，只按 promptId或 source record identity reconcile。`locateOrdinal()`在 entry所属 snapshot下拉 anchored transcript，`loadOlder/loadNewer`沿 frozen boundaries扩展 range；mode在 `legacy/loading/ready/degraded`间切换，capability缺失、index too large和initial error保留旧 loaded-only行为。

Provider为 active `DaemonSessionClient`配置唯一 external store，观察 live blocks/terminal events，向 actions注入 prompt admitted/removed callback，并通过 context/hooks暴露 headless snapshot与命令。最终 review修复让 queued prompt保留 exact `promptId`，使 admission、live block与 index可跨到达顺序对账；历史尾页淘汰后保存 snapshot-bound gap recipe，恢复时从原 anchor向后有界遍历到保留记录，只纳入最近缺页。单页超限不可重试，selection pin导致的 window-full可在移动选择后重试。现有 sequential prepend migration留给 Phase 2B，visible rail/selection留给 Phase 3。
