## 解决了什么问题

Agent SDK 会把 provider HTTP 错误包成 JSON-RPC error，真正可操作的消息常在 `error.data.error.message`。bridge 原来只识别 `data`、`data.details` 和 `data.message`，因而 terminal `turn_error.data.message` 只剩通用 `Internal error`，WebUI、live-state、transcript 与 SDK 都无法告诉用户真正失败原因。

## 最终实现

`extractJsonRpcErrorDetail()` 保留原有优先级：先看非空 `data` 字符串，再看 `data.details` 和 `data.message`，最后解包 nested `data.error`，它可以是字符串或含非空 `message` 的对象。这个共享提取结果进入已有 prompt terminal 错误链，所以 refresh/live-state/transcript 与 TS SDK 无需另外解析。wire event schema、`errorKind`、retry 和 provider 调用次数不变。

## 关键代码路径

- `packages/acp-bridge/src/bridge.ts`：JSON-RPC error detail 优先级和 prompt terminal 消息生成。
- `packages/acp-bridge/src/bridge.test.ts`：nested error 形状、优先级和 fallback 回归。
- `integration-tests/cli/qwen-serve-streaming.test.ts` 与 `integration-tests/fake-openai-server.ts`：真 daemon/ACP child 通过 fake OpenAI provider 的 terminal event 链路。

## 边界与风险

- 只从已知 JSON-RPC error 形状提取有界消息，不改变 provider 重试或错误分类。
- 具体 `data`/`details`/`message` 仍优先于 nested `data.error`，避免改变已有 consumer 的选择结果。
