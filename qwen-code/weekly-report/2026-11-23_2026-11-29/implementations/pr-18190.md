# PR #18190 最终实现：身份连接保留可索引的列侧类型

> PR: [fix(managed-agent): keep identity joins on full index keys](https://github.com/QwenLM/qwen-code/pull/18190)
> 状态：merged；已合入 main，merge `f2c689c812b5`，最终 head `55565be1c7b4`；对照 main `be11490df47e`。
> 规模：+342 / -71，15 个文件

## 解决了什么问题

资源、artifact、取消证据和恢复候选查询对索引列做类型转换，可能把精确身份连接变成大量扫描或回调往返。

## 最终实现方案

将 ma_session_record.record_resource_id 对齐为 VARCHAR256、ma_artifact.result_id 为 VARCHAR128，文本对文本直接连接，覆盖 journal、诊断、资源回收及 artifact 读取。取消证据把 operation 二进制 probe 转为 UTF8文本而保 ma_turn 原列；Broker recovery 则反向把 binding probe 转二进制，保 operation target 索引列裸露。

retention guard 增加普通 domain/record_id 等式帮助命中唯一键，仍保精确二进制残余校验；删一个需要元数据回调的 JdbcTemplate 重载。新 MySQL 测试读取实际捕获 SQL 的 JSON EXPLAIN 与 used_key_parts，并用规模化干扰行约束查询；不是本次测得的性能提升。当前 V1 仍48表，开发目录重建而非提供升级链。
