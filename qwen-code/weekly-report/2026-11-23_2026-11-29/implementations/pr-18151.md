## 解决了什么问题

首个 Phase4 仅覆盖少数可恢复等待；直接放开图片、wake、子 Session、Hooks/MCP 或 command-step，会出现能停靠却无法冷恢复的形状。

## 最终实现方案

6文件交付是双语设计、父设计更新及实施前测试，不含产品运行时代码。设计要求“冷恢复覆盖先于或同步于停靠覆盖”，先共享 Session-shape 资格并记录拒绝原因，再拆 S1 图片、S7 command-step、S2 background+Action、S4 wake、S3 child、S5 Hooks、S6 MCP 和需另行设计的 Shell-before-dispatch。

background/wake 新证书形状拟用 grant bit 协商；wake 拟复用 due-time scan，不新增 ma_turn，不能将拟议字段当成当前 DDL。测试定义核 text+image 冷恢复历史、decision delivery 的 passive load、wake plain load，以及 writer acquisition 清证书后不留 scan-pending。模型/执行采用替身，设计中的真实进程/MySQL 与负载占比仍待执行。

最新 main 已有后续 #18157 的资格/拒绝计数、#18173 的 metrics 暴露和 #18172 的崩溃 aftermath 修正；#18164/#18166/#18170 仍开放。设计正文引用“implemented”仅能作线索，不能覆盖这些状态。MCP owner 的回收豁免还见 #18186 已合入的文档修正，运行时保护仍待实施。
