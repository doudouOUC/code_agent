## 解决了什么问题

后台工作尚在运行时，原 Action park 资格一概拒绝；直接清证书唤醒又会失去原审批的恢复身份。

## 最终实现方案

沿既有 actionParking 配置协商 backgroundActionParking grant，Harness 仅在具备该能力和后台持有证据时将 backgroundHeld 与 parkedTurn 一起 seal。保留原 prompt、approval revision 与到期身份，不增加新配置或业务表。

与早期设计不同，staged wake 不再清除停靠证书：stageBatch 在同一事务把 wake_retry_at 和 wake_seal_parked_until 提前到 NOW，并解除 SQL Action Turn 停靠；seal 若已见 staged wake 同样缩短 until。这样能唤醒原等待又保留证书。该 PR 尚不允许 pending wake 自己持有 Action park，后续18194才实现。

最新main的18290仅拆分职责；原PR的生产路径以其当时diff为准，以下锚点按当前模块归属更新。

- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/JdbcRuntimeStageStore.java`：在stage事务中提前wake期限并解除SQL Turn停靠。
