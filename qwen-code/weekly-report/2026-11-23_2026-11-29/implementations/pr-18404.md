## 解决了什么问题

Session已持久封存却仍占原Harness placement，健康池不能及时交接；只因成员失联就抢占又会破坏写者隔离。

## 最终实现方案

Store仅在wake dispatch启用时随grant协商suspensionPlacementRelease。Harness停续租后依次quiesce placement、释放activation、按原wake stamp封存，再用固定operationId/commit proof释放ownership；seal成功后释放失败可独立重试，不重新seal。SEALED释放仍校验writer身份、token hash、generation、wake seal revision和已提交前缀。

池refresh增加最多32条离任回收：缺失成员或已协商且所有incarnation均不可达才可进入候选，未知健康成员仍排除；还需SQL证明SEALED/READY、租约到期、activation released且revision一致，随后经原takeover再次校验。没有健康接班成员则不回收。后续18443补RELEASED接管时截断旧lease，非以网络不可达替代存储证据。

## 关键代码路径

- `packages/cli/src/serve/hosted-harness-session/session-suspension.ts`：停续租后的quiesce、固定seal与独立重试ownership release。
- `packages/core/src/managed-runtime/http-managed-session-store.ts`：解析placement释放grant并允许已seal后的原证明释放重试。
- `packages/managed-agent-server/adapters/src/main/java/com/alibaba/qwen/code/managedagent/harness/HarnessPoolConnector.java`：健康接班成员选择与最多32条离任placement回收。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/JdbcHarnessPlacementStore.java`：按SEALED/READY、DB lease到期和原revision证明扫描候选。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/JournalWriterLifecycle.java`：SEALED释放仍核writer身份/token和wake seal/commit proof。
