# PR #18431 最终实现：跨控制面提交的 SSE 水位唤醒

> PR: [feat(managed-agent): Wake event streams for other instances' commits](https://github.com/QwenLM/qwen-code/pull/18431)
> 状态：merged；已合入 main，merge `0a1a87831f22`，最终 head `98dc5b28bf49`；对照 main `95502a5c27b9`。
> 规模：+621 / -8，14 个文件

## 解决了什么问题

本机event hub只接本机commit，其他副本提交后本机SSE要等原长轮询周期，用户会延迟看到事件。

## 最终实现方案

EventTailPoller固定延迟200ms，仅取本机有订阅的tenant/session，按500键一批查询ma_event_stream的SESSION公共流last_sequence；无订阅不查，退订删本地水位。发现首次/增长水位通知hub，而非通过通知携事件正文。

hub使用每订阅noticesSeen及signalAll记住等待外到达的通知；返回overflowed使流从SQL按原cursor回读，本机已有更高事件则忽略通知。轮询异常捕获后保后续tick，流仍有原轮询兜底。不新增消息总线/业务表或承诺200ms端到端SLA，大量订阅会分批执行。

## 关键代码路径

- `packages/managed-agent-server/control-plane/src/main/java/com/alibaba/qwen/code/managedagent/session/EventTailPoller.java`：200ms固定延迟轮询本机订阅水位，失败保留后续tick。
- `packages/managed-agent-server/control-plane/src/main/java/com/alibaba/qwen/code/managedagent/session/SessionEventHub.java`：noticesSeen保留等待外通知，唤醒后要求SQL回读。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/AgentEventJournal.java`：500个tenant/session键分批读取公共SESSION流last_sequence。
