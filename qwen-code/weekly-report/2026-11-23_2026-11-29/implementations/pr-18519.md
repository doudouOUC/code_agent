## 解决了什么问题

只有Store接收路由还不能送事件；Harness需从已提交journal按原cursor发送，并在停靠seal/release之间安全结束发送。

## 最终实现方案

advertise event-ingest/1；fresh prompt显式携eventDelivery={mode:ingest,turnId}且有stores才启动。返回原202 admission后从lastEventId起读committed journal，250ms tick、单flight、每批64条，用events路由同eventEnvelope和已stream delta去重规则；空批按服务端renewAfter heartbeat，尚未收到receipt时默认20秒。

transport/5xx/contention可后续重试，cursor mismatch按服务端cursor重建delta集合，not_ready最多等60秒；其他失败记录日志并停。停靠先pause等inflight、flush，再seal、尝试parked尾标记，最后才release placement；park是一次有界生命周期尝试，失败/缺尾后结束推送，不保证标记送达，后续依赖原lease恢复。Core仅准许尚未release/stop的干净sealed writer发送parked。

只交付第二片条件推送器及测试。最新main中Java/SDK还没有生产eventDelivery选择和dispatch_owner转交，设计的event-ingest.enabled也未接线；正常dispatcher仍用stream。不可把capability广告或单元测试当作已启用功能、Java实例死亡无中断或完整pull scheduling。
