## 解决了什么问题

原shape一概拒Hooks/MCP；只去掉判断会重放Hook、重发现出不同MCP目录，或让bare load写tool_result破坏原continuation。

## 最终实现方案

共享owner门只接受durable MCP或config-scoped extensions-components owner，Hooks必须同owner或可重取配置owner；activation owner拒绝。native plan为每call保存有序PreToolUse/PermissionRequest resultDigest，缺结果/recovery_blocked拒绝，Hooks memory batch/command-step混用仍受限。恢复先逐一核原digest，只读回ask/allow、不重跑已完成Hook；启动Hook也不重触发，历史仍是已接受prompt。

MCP要求parkable原连接（settled runs、enabled配置/connection generation与Broker能力）。保存MANAGED_MCP_TOOL/mcp-invoke身份，恢复重推导输入除grant外必须deep-equal，执行前续grant；目录工具声明原核对仍保留。takeover/resident/wake共用shape，bare load不回答已保存批次；普通冷load不因此获得执行权。18234的回收guard保等待期间目录。无新开关：沿既有默认关闭actionParking及MCP parking能力。

最新main的18290仅拆分职责；原PR的生产路径以其当时diff为准，以下锚点按当前模块归属更新。
