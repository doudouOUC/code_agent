## 解决了什么问题

持久输入只有附件时，原 prompt-text truthy 判断把合法空文本误当丢失，阻止停靠或恢复；原始附件本来可从 managed-input 读回。

## 最终实现方案

最终 diff 已合入 main。hostedOriginalPromptText 先保有文本行为；无文本时通过 readHostedInput 读取原附件，有附件返回空串，真正缺失才 undefined。停靠、resident approval、takeover 的 model/approval/memory/skill 路径统一按 === undefined 判断。拒绝原因从 prompt_text_missing 改 original_prompt_missing，不放松其他 Session-shape 或证书门。

测试覆盖纯图片 park 与故障接管、空 prompt 及恢复历史中的原图片；不引入新的图片下载/任意路径能力，也不宣称真实 provider 请求已独立验证。最新 main 已采用附件存在与 undefined 区分，其他资格不因纯图片豁免。
