## 解决了什么问题

Broker 回调线程的 context ClassLoader 可能看不到宿主 provider JAR，导致已安装后端被误报未安装；只改成 system loader 又会漏掉自定义应用加载器。

## 最终实现方案

RuntimeProviderRegistry.discover 先取定义该类的 application loader；context 为空或相同则只查一次。两者不同时依次 ServiceLoader.load，并按实际 factory Class 去重，保留 child context 中扩展 provider。真正不同类声明同 kind 仍由原 duplicate-kind guard 拒绝；创建后端仍执行 validate、kind 对齐与不匹配时 close。

测试辅助加载器改为隔离所选 provider 的可见性，覆盖不可见 context、自定义 defining loader、维护入口和 SSH wiring；它们不是本次已运行的部署证据。
