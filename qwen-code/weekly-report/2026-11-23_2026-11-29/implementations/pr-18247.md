## 解决了什么问题

现有Java扩展客户端没有完整公开Session/Turn/Action查询写入和SSE接入，调用者需重复签名、错误处理与游标控制。

## 当前实现方案

当前 open diff，不能作为 main 能力承诺。新增ManagedAgentClient，提供agent定义、Workspace/Session生命周期、输入/取消、Turn/Item/Event/Action、recovery/resources/catalog/MCP管理等显式方法，扩展发布客户端复用ManagedHttpTransport。当前候选已将公开请求/响应换为命名builder与DTO：ManagedCreateSessionRequest、ManagedAgentDefinitionRequest、Session/Turn/Action/Operation/Recovery/Resources、分页与MCP目录等；开放schema/配置JSON仍按契约保Map，不是把服务端所有动态字段封死，也不是跨语言客户端。

共享transport以qwen-broker-auth-v1/HMAC-SHA256覆盖method/raw path/query/tenant/actor/time/body digest/idempotency key；拒重定向，调用者持有写幂等键，30秒请求与8MiB JSON界限，网络未知结果不自动重试mutation。SSE用Last-Event-ID与单调ID，保无序号resync控制事件，不自动重连/分页；调用者从Items快照回补再重开，close丢弃buffer。复用Daemon异常并扩展message/code，不代表SDK已发行。

新增ManagedPage<T>/专用Item与Event页暴露next_cursor/水位，不自动遍历。SSE Event给text/reasoning delta、Turn终态和resync命名payload，其他事件仍JsonPayload；类型化不取消原单调ID和回补责任。
