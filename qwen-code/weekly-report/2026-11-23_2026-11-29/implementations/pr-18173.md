## 解决了什么问题

suspensionStats 和逐等待拒绝原因只留在路由实现内部，运维入口无法读取，不能据此观察停靠覆盖的实际分布。

## 最终实现方案

HostedHarnessInstance 增可选 suspension 回调，session routes 将真实 suspensionStats 接入；内部 GET /internal/hosted-harness/v1/metrics 在原 instance/process 指标旁增加 suspension。沿用 hostedHarnessContractMiddleware 与 Cache-Control:no-store，不新增公开业务 API，也不改变准入或挂起默认开关。

兼容未提供回调的实例，不输出 suspension 字段；测试核有/无回调以及 parkRefusals。计数是进程内生命周期统计，不是跨实例持久聚合，更不能据此宣称冷开延迟、内存收益或负载比例已测。

## 关键代码路径

- `packages/cli/src/serve/hosted-harness-instance.ts`：内部 metrics 路由和可选统计回调。
- `packages/cli/src/serve/hosted-harness-session.ts`：把真实挂起统计回调传给实例 metrics。
