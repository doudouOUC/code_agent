## 解决了什么问题

crash aftermath 消耗 wake 输入但留下 await_action checkpoint，后续 continuation Turn 无法启动，可能持续卡在旧审批等待。

## 最终实现方案

最终 diff 在 aftermath 中始终读取 Harness authorization，不再只在 Broker 配置存在时读；非持久 blocked/未读到 checkpoint 的 verdict 抛错，保留 block 和原输入，不能先消费。原 Runtime stop/release 证据分支仍在。

runnable、相同 turn 且 phase=await_action 时，只把仍 requested 的原 requestId Action 结束为 cancelled，再调用 resolveDurableWait 推进 checkpoint，之后继续原崩溃结算。已终态 Action 不改写。它是 fallback 取消结算，不是继续原审批或新增停靠覆盖；#18170 的恢复等待候选仍开放。
