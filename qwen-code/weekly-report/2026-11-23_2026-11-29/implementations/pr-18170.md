## 解决了什么问题

wake Turn 已尝试且在 await_action 崩溃时，原 pump 不恢复可重建的审批等待；新增恢复臂还必须保留取消/失败不确认 child result 消费的原门禁。

## 当前实现方案

当前 open diff，不能作为 main 能力承诺。createMonitorWakeRunTurn 在既有 prior-attempt 分支先询问 resumeInterrupted；只对 monitor、automation、loop、child notification 的 runnable 同 turn await_action、native 非 command-step continuation 和合格 shape/原文本返回原 executeHostedTurn。channel、pr_event、session-message 仍走自己的结算。

读计划或取消状态失败返回 busy 留待重读；源已取消则预 abort 恢复，不发新输入、不重跑整个原 wake。只 completed 映为 settled，cancelled/error 为 settled_incomplete，不能确认 child 消费。最新 main 的 #18172 仅修 aftermath 的取消/推进，尚无本候选 resumeInterrupted 接线；因此“不会卡死”不等于“保留原审批等待”，更不是 wake-owned parking 已实现。
