# PR #18506 最终实现：replay floor 待办索引与水位等值查询

> PR: [perf(managed-agent): Avoid replay floor full-table scans](https://github.com/QwenLM/qwen-code/pull/18506)
> 状态：merged；已合入 main，merge `43dc92488255`，最终 head `84486ed02f28`；对照 main `95502a5c27b9`。
> 规模：+13 / -5，5 个文件

## 解决了什么问题

covered_sequence与replay_floor_sequence逐行比较不能直接利用待办索引；大量tenant/session row-constructor IN也可能退化全表扫描。

## 最终实现方案

V1为ma_event_stream新增generated is_replay_floor_pending=(covered_sequence > replay_floor_sequence)及stream_kind/stream_id/flag/gmt_modified复合索引；候选查询改为flag=TRUE，原未完成Turn排除、排序/限制等条件保留。projection与boolean列清单同步，49表数量不变，仍原地V1重建而非升级链。

批读订阅水位仍500键一批、tenant/session精确成对；仅把row-constructor IN展开成OR等值组。目标是给优化器可用索引条件，不更改cursor推进或租户归属；PR没有新增测试，本次未执行EXPLAIN、MySQL或负载测量，不能宣称已量化加速。

- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/AgentEventJournal.java`：500组tenant/session键的OR等值水位读取。
