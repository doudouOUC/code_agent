## 解决了什么问题

daemon/ACP cold-start 优化已经有 initialize/profile 类指标，但“用户发出第一条 prompt 后多久看到模型内容”缺少可复现、可审计的度量。仅看 process startup 或 session readiness 不能解释 provider lazy construction、SSE readiness、prompt admission、模型首包、首段 answer text 与最终 terminal 的分布，也无法让 #7767 这类 preload 改动用 paired experiment 证明收益。

## 最终实现方案

新增 gated first-output benchmark harness，目标是 measurement-only，不改变生产协议或 `ttft_ms` 语义。benchmark 以 fresh process spawn 到 first model-derived output 为主线，记录 process-to-session-ready、prompt-to-provider-request-arrival、prompt-to-first-model-output、prompt-to-first-answer-text、provider-ready-to-first-output、prompt-to-terminal 等阶段。

实验模式分两类：单 bundle cold/warm baseline 用来观察同一构建的冷/暖差异；双 bundle paired comparison 支持 AB/BA ordering，隔离进程、workspace、home、Qwen home、端口与 compile cache，避免上一轮样本污染下一轮。事件关联不依赖单一日志字符串，而是锁定 accepted top-level prompt id，并从 session event、fake provider request 与模型输出中建立同一 prompt 的时间线。

事件过滤也被显式定义：message、thought、initial tool-call 可以成为 first model-derived output；replay/status/usage/role-only/user echo/compression diagnostics/tool updates 不计入首输出。artifact 使用 versioned JSON 与 Markdown 双格式，保留每个 sample、failure code、relative timestamp、request count、cleanup evidence、percentile summary、seeded paired median bootstrap CI、order sensitivity 与 provider preload gate。

fake OpenAI server 增加 benchmark 专用行为：在 benchmark streaming response 后确定性关闭连接，防止 HTTP keep-alive 连接池让下一轮样本复用上一轮 provider 连接，从而污染 first-output latency。
