## 解决了什么问题

#7761 的 first-output benchmark 已能衡量 daemon session ready、provider request arrival、first model output、first answer text 与 terminal，但 immediate prompt 场景还缺少 prompt acceptance 与 user echo 两个关键阶段。没有这些指标时，很难判断首轮延迟来自 daemon queue wait、HTTP 202/SSE echo、还是 provider dispatch。

## 当前实现方案

当前 diff 将 benchmark artifact schema 升到 v2，并新增 immediate prompt dispatch metrics：`promptAcceptedAt`、`userEchoAt`、`daemonPromptQueueWaitMs`、`promptToAcceptanceMs`、`acceptanceToProviderRequestArrivalMs`、`promptToUserEchoMs`、`userEchoToProviderRequestArrivalMs`。这些指标与已有 provider/first-output/terminal 时间并存，不改变原 benchmark 的 opt-in 性质。

`FirstOutputTracker` 只按 accepted top-level prompt id 关联 relayed `user_message_chunk`，并会缓存 acceptance 之前到达的 echo；transcript replay 不算 user echo，user echo 也不会被误归为模型输出。由于 provider request 可能先于客户端收到 HTTP 202 或 SSE echo，`acceptanceToProviderRequestArrivalMs` 与 `userEchoToProviderRequestArrivalMs` 允许 signed negative delta；其它负时长仍被视为 invalid sample。

daemon status snapshot 在 isolated turn 后读取，只有 pending counter 恰好推进一次且 `lastMs` 为有限非负值时，才接受 queue-wait 指标，避免把其它 prompt 的队列状态混入样本。
