## 解决了什么问题

session writer lease 需要在 append 前证明 transcript 没被其它 writer 改写。旧完整性检查把 `birthtime`、`ctime`、`mtime` 也作为强信号，容易在 virtiofs、容器共享目录或文件系统 timestamp drift 下误报 `session_transcript_changed`。但完全忽略变更也不行，因为 symlink swap、inode 变化、长度变化、owner 丢失和 tail mismatch 都可能代表真实双写或篡改风险。

## 当前实现方案

当前 diff 将 transcript timestamps 降级为 advisory signal。强完整性仍覆盖 file existence、expected length、device/inode/file identity、regular-file type、mode、owner/group、link count 和 tail validity；这些检查失败仍 fail-closed。

writer 获取已有 transcript 时会建立一次 streaming SHA-256 baseline，读取使用 1 MiB buffer，避免把大 transcript 一次放进内存。普通 append 成功后，candidate digest 通过新增内容增量推进，并继续做常量级 metadata/ownership 检查。若只发现 timestamp drift，则进入 full-content reconciliation：在 handle/path pre-check、post-check 和 exact-owner 校验之间重新扫描整文件，对比 digest 与 expected state。

reconciliation 最多重试 3 次；如果 timestamp 在扫描期间继续变化或文件状态不稳定，返回 `session_writer_unavailable`，不抢写、不继续 append。替换成 symlink/非 regular file 仍保持 integrity failure：已有 baseline 时是 `session_transcript_changed`，没有 baseline 时是 `session_writer_unavailable`。

shutdown 路径也配合调整。pending lease activation 前可以启动 exact-record release，长 baseline read 在每个 chunk 之间检查 release 状态，使 managed shutdown 不会被长 snapshot 无界阻塞。
