## 解决了什么问题

PR #7586 的 Direct External Context 只提供 retrieval-only MCP tool，需要模型主动调用 `context_search({query})`。这种模式对“每次用户提交都基于原始文本检索一次私有上下文”的需求不够确定：模型可能不调用、可能基于扩展后的 prompt 检索，也可能把 `@file` 展开内容、reminder 或系统上下文误送给外部 provider。

## 最终实现方案

最终实现新增 Auto Recall profile，并明确与原 MCP profile 互斥。它由管理员安装为 `UserPromptSubmit` command hook，不注册 MCP tool，也不提供 remember/write/delete 管理面。v2 config 增加 `autoRecall.repositoryRoot` 和 `autoRecall.timeoutMs`；v1 MCP `context_search` 配置继续保留，避免旧 profile 被自动解释成 hook profile。

hook 入口只处理 `hook_event_name === 'UserPromptSubmit'` 且 payload 含非空 `submitted_prompt` 的请求；缺失、空值、非法 JSON、旧版只含 `prompt` 的 payload 都返回 `{}`，并且在这些 fail-open no-op 路径上不加载配置、credential、proxy 或 provider。运行时会对真实 `cwd` 和配置的 `repositoryRoot` 做 realpath containment 校验，拒绝 filesystem root 和纯字符串前缀伪装。

查询内容来自 `submitted_prompt`，不是 model-bound `prompt`。sanitizer 会归一 whitespace、过滤常见 accidental secrets、拒绝 code-fence-only 输入、限制 512 Unicode code points，并限制 sanitizer 输入大小以避免正则/回溯拖住 hook。provider 调用最多一次，无 retry/cache，默认 1500ms timeout，允许配置 1..5000ms。

召回结果以 `untrusted_external_context` JSON envelope 写入 `UserPromptSubmit.hookSpecificOutput.additionalContext`，追加到用户层上下文，不提升为 system instruction。输出最多 5 条，每条 content 1000 code points，整体序列化 4000 JS code units，并把尖括号编码为 Unicode escape，降低被当作标签/指令边界的风险。

## 关键代码路径

- `integrations/external-context/src/auto-recall.ts`: hook payload 解析、submitted_prompt 提取、root guard、sanitizer、provider 调用与 additionalContext 渲染。
- `integrations/external-context/src/config.ts`: v1/v2 配置解析、autoRecall timeout/root 校验、MCP 与 hook profile 互斥。
- `integrations/external-context/src/main.ts`: command hook entry 与 MCP entry 的分流。
- `integrations/external-context/src/proxy.ts` / `mcp.ts`: 复用 provider/http/proxy 基础设施，但 hook profile 不注册 tool。
- `integration-tests/interactive/external-context-auto-recall.test.ts`: TUI E2E 验证 `@file` expansion 不送 provider，模型上下文同时看到文件内容与召回上下文。
