## 解决了什么问题

daemon status 已经能每 5 秒采样自身 RSS/heap 和 primary ACP child RSS，但没有 cgroup、host、heap、configured budget 或 effective budget 这些 denominator。运维只能看到绝对字节数，无法判断 daemon 离内存耗尽还有多近，也无法把后续 resource budget/admission 工作建立在统一容量基线上。

## 当前实现方案

当前 open diff 在 daemon boot 时解析 memory budget figures，并通过 status、wire protocol、SDK types 和 docs 报告。configured budget 与 effective budget 分离：configured 代表用户/默认配置；effective 会被 cgroup 或 host memory cap 截断。derived budget 如果低于 documented minimum，状态报告 `insufficientMemory`，而不是向上 clamp 后假装可用。

该 PR 不改变 ACP child spawn argv，不实施 admission/enforcement，也不改变现有 route 行为。wire 上明确 `enforced:false`，并把 derived quantities 放进 `modeled` object；per-child shares 只标成 advisory。这样 status 先给出可信 denominator 和风险信号，后续 PR 再基于同一模型接入具体 budget enforcement。
