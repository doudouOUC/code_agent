## 解决了什么问题

独立发布的 `@qwen-code/mobile-mcp` 包仍声明 Node.js 18 兼容，但仓库 `.nvmrc`、实际发布流程和验证环境已经按 Node.js 22 运行，继续保留 Node.js 18 声明会形成未验证的兼容承诺。同时旧版 `@modelcontextprotocol/sdk` 1.26.0 会把 `@hono/node-server` 限在受 GHSA-frvp-7c67-39w9 影响的 1.x 依赖路径上；仅升级 SDK 也不足以阻止既有 consumer lockfile 继续保留 Hono 1.x。

PR #8206 只处理 direct external-context integration 的依赖收敛，未迁移 mobile MCP。PR #8311 是独立的 mobile-mcp runtime/dependency 迁移记录。

## 当前实现方案

当前 open diff 将 `@qwen-code/mobile-mcp` 的运行时基线提升到 Node.js 22，并把 `@modelcontextprotocol/sdk` 升级到 1.30.0。package 同时直接依赖 `@hono/node-server` `^2.0.12`，把它作为 resolution floor：既保证不会回落到 1.x advisory path，又允许后续 Hono 2.x patch 被 lockfile 接收。

根 `package-lock.json` 和 `packages/mobile-mcp/package-lock.json` 被重新生成，移除了 mobile-mcp 下嵌套的 MCP SDK 1.26.0 / Hono 1.x dependency tree。mobile-mcp 的 README、CHANGELOG 和 vendored patch 清单同步记录 Node.js 22 breaking change、MCP SDK/Hono 依赖边界和发布侧注意事项。

TypeScript 层面，工作区布局可能让 MCP SDK 与 mobile-mcp 解析到不同的受支持 Zod 副本，导致 schema 类型不兼容。当前 diff 在 `packages/mobile-mcp/src/server.ts` 增加 type-only `sdkInputSchema()` 边界，把本地 Zod shape 作为 SDK 接受的 schema shape 传入；该函数不改变 runtime schema，也不改 validation 行为。两个 `inputSchema` 注册点都经过该边界：通用 `tool()` helper 和直接注册的 screenshot tool。

## 关键代码路径

- `packages/mobile-mcp/package.json`: engine 提升到 `>=22.0.0`，依赖升级为 MCP SDK 1.30.0，并加入 `@hono/node-server` `^2.0.12`。
- `package-lock.json`、`packages/mobile-mcp/package-lock.json`: 移除旧 SDK/Hono 1.x 解析树，同步 standalone package 解析结果。
- `packages/mobile-mcp/src/server.ts`: 新增 `sdkInputSchema()` type-only bridge，并覆盖所有 `inputSchema` 注册点。
- `docs/design/mobile-mcp-node22-baseline.md`: 记录 Node.js 22 baseline、Hono 2 resolution floor、split-Zod workspace boundary、验证和 rollback 条件。
- `packages/mobile-mcp/.vendored-patches.md`: 把 Node runtime / MCP SDK / Hono / Zod bridge 纳入本 fork 相对 upstream 的本地 patch 清单。
- `packages/mobile-mcp/README.md`、`packages/mobile-mcp/CHANGELOG.md`: 面向消费者记录 Node.js 22 要求和未发布的 breaking/security 变更。

## 风险与边界

- 这是 open PR 当前 diff，不是已合入 `main` 的能力。
- Node.js 18/20 consumer 需要在下一次 mobile-mcp 发布前升级到 Node.js 22 或更高版本。
- `@hono/node-server` 是 resolution floor，不是当前源码直接 import 的运行时代码；未来依赖清理不能把它误删，否则旧 lockfile 可能重新保留 Hono 1.x。
- `sdkInputSchema()` 是工作区 split-Zod 的类型兼容边界；发布用 standalone lockfile 是单 Zod 布局。后续仍需要把 monorepo 依赖图收敛到单一 Zod 副本，或给 mobile-mcp 建立持续 CI。
- 设备相关 Playwright 覆盖、ADB/mobilecli/真机环境、Windows/Linux 本地验证，以及 mobilewright 独立依赖树里的无关 advisory 都不在该 PR 范围内。
