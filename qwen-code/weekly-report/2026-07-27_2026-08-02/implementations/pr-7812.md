## 解决了什么问题

single-writer session persistence 要求同一 transcript 只有一个 live owner。daemon-managed ACP child 在 shutdown、replacement 或 crash-adjacent teardown 时，如果没有释放 exact-owned writer locks，新 daemon 可能遇到 stale owner。managed daemon replacement 常跨 hostname 或容器边界，不能安全地通过 hostname、age、container-visible PID 推断旧 owner 已死；盲目抢锁会产生 split-brain 双写，不抢锁又会让会话卡在 writer conflict。

## 当前实现方案

当前 diff 为 daemon-managed ACP children 建立 cooperative shutdown。第一次 shutdown signal 到来后，session admission 和 turn admission 同步关闭，已接受的 transcript work 被允许 drain；只有 exact-owned writer locks 会在 writer phase 中原子 retire。SessionEnd hooks 与 resource cleanup 不再抢在 writer phase 之前执行，而是在 writer phase settle 后继续，减少 close/append/lease release 的交叉窗口。

daemon scope 增加 ACP child process registry，覆盖 primary、secondary 和 dynamic runtimes。shutdown timeline 先对所有 tracked ACP children 发送 SIGTERM，5 秒后对仍未退出的 raw process 发送 SIGKILL，并要求 10 秒内完成 reap；非零退出、signal 退出或未 reap 都被视为 unclean。partial channel construction、spawnChannel teardown 与 overlapping live-channel teardown 会 join 同一个 terminal outcome，避免一边还在建 channel 另一边释放资源。

writer lock acquisition 的策略也按 managed/standalone 区分：managed acquisition 不再基于 hostname、age 或 container-visible PID 回收 existing owner；standalone ACP 保留 local stale-owner recovery，因为它仍可在本地进程边界内证明 owner 可回收。
