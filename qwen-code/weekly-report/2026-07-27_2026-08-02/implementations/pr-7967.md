## 解决了什么问题

#7947 为 Serve 大文本有界读取引入了 caller-owned file descriptor 路径，但 Core 的文本范围读取仍把 path-read、handle-read、强制 streaming 与扫描上限揉在同一个 helper 里。这样的接口既容易让借来的 fd 被误关闭，也会让后续 byte-cursor paging 继续复制一套“从同一 descriptor 读窗口”的逻辑。

## 最终实现方案

最终实现是在 #7947 与 #8002 合入后折叠成窄范围 follow-up。它保留 `readTextRangeFromHandle()` 作为 caller-owned descriptor 读取入口，并通过 `packages/core/src/utils/fileUtils.ts` 清理仍可能在 handle 场景误走 path 的分支，使 handle request 继续由外层已打开的 fd 和 stat-size bound 约束。

测试侧补了三类边界：`workspace-file-read.test.ts` 固定 Serve route 对非有限 limit/Infinity 的参数处理；`fileSystemService.test.ts` 固定 Core handle request 调用 `readTextRangeFromHandle()` 的入参；`fileUtils.ts` 的改动删除了不再可达的 legacy path/handle 混合逻辑。它不再承担 #7947 的 bounded large text read 或 #8002 的 cursor paging 主体，只记录 descriptor-threading 的后续收敛。

## 关键代码路径

- `packages/core/src/utils/fileUtils.ts`: 清理 handle/path 混合遗留分支。
- `packages/core/src/services/fileSystemService.test.ts`: 固定 handle request 调用 `readTextRangeFromHandle()` 的参数。
- `packages/cli/src/serve/routes/workspace-file-read.test.ts`: 固定非有限 limit、Infinity 与 route 层参数边界。
