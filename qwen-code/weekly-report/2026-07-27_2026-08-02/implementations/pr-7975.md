## 解决了什么问题

daemon 的 session archive/delete/unarchive、scheduled rollback、keepalive late-spawn cleanup 与 ACP orphan cleanup 都属于“维护任务”，但它们同样可能修改 transcript 或 session metadata。multi-workspace runtime 落地后，如果维护任务仍复用进程级 `Storage`/`SessionService` 或不拿 writer lease，就可能在错误 runtime root 下写入，或在 shutdown/replacement 时与 live session writer 交叉。

## 最终实现方案

最终实现让每个 workspace runtime 在创建时 pin 住自己的 absolute session runtime root，并把该 root 传给 managed ACP child。维护路径进入 `runWithWorkspaceRuntimeStorage()` 或 `createWorkspaceRuntimeSessionService()` 后，才创建 runtime-local `Storage`/`SessionService`，避免跨 runtime 复用默认存储。

所有会写 transcript/session state 的 daemon 维护操作都会先获取 daemon writer lease，包括 archive、unarchive、delete、disconnect rollback、scheduled task rollback、late-spawn cleanup 和 ACP orphan cleanup。维护 lease 使用 `processKind: 'daemon'`，不走 hostname/PID/age reclaim；batch 维护会保留前面已完成 session 的结果，后续某个 session 发生 writer conflict 时不回滚整批。

shutdown 路径同步收紧：daemon 先 seal maintenance admission，等待已准入的维护 lease settle，再把 REST/ACP 层错误稳定映射为 `daemon_draining`。它不会等待共享 transcript export 这类非 writer teardown，managed child termination 也会尽早启动，避免 close 被无关导出阻塞。
