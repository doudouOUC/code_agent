## 解决了什么问题

`UserPromptSubmit` hook 过去只能拿到最终送入模型的 `prompt`。这个字段已经混入 reminder、file/resource expansion、slash command、extension、vision 或其它系统追加内容，安全审计、日志和外部 hook 无法判断用户实际提交了什么。直接替换 `prompt` 又会破坏既有 hook 与模型上下文，因此需要新增一个可选 provenance 字段。

## 最终实现方案

hook payload 新增 `submitted_prompt`，保持 `prompt`、timing、blocking、hook order 与 additionalContext chaining 不变。TUI 只在 fresh `UserQuery` 上提供该字段，并在文件/resource/slash/extension/vision expansion 之前捕获 trimmed text projection；large paste 不展开原文，而是使用 compact placeholder projection。

恢复与延迟执行使用 sidecar 传递 provenance。deferred turns 和 exact in-memory restorations 可以保留原始提交文本；edited restorations、ambiguous batches、same-turn steering、recursive continuations、retries、machine traffic、unsupported producers、`--prompt-interactive` startup、Vim NORMAL direct submissions、image-only 等无法证明“这就是用户原始提交”的路径直接省略字段，避免伪造确定性。

取消恢复路径也被同步修正：exact cancellation restoration 仍归属于 main turn，同时允许并发 `/btw` side question 运行；coupled history guard 只在最新 persisted user entry 仍属于被取消 main turn 时移除，避免误删 side question 或后续输入。

文档面把 `submitted_prompt` 定义为 optional additive field，要求 hook consumer forward-compatible 解码。对于 strict-schema consumer，迁移建议是忽略未知字段或升级 schema；函数 hook 仍是 same-process trusted boundary，不把该字段直接等同外部安全边界。
