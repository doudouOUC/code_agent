## 解决了什么问题

阿里云 ARMS Session Analysis 需要 span 级 `gen_ai.user.id` 才能按 end user 聚合 GenAI 会话。qwen-code 既有 telemetry 能记录 session、provider、operation、usage 和工具调用，但没有一个 operator-supplied pseudonymous user id；如果由客户端自动推断真实账号或写入 Resource/log/metric，又会引入隐私和多用户 daemon 误归因风险。

## 最终实现方案

最终实现新增 `telemetry.userId` setting 和 `QWEN_TELEMETRY_USER_ID` 环境变量。环境变量 trim 后优先；若 env 为空字符串，则回退 settings；settings 中非 string 值直接配置失败，避免导出 `null`、对象或其它非预期类型。`Config.getTelemetryUserId()` 对 telemetry 层提供统一读取入口。

span 写入发生在 interaction span 创建时。`gen_ai.user.id` 会随 interaction context 传播到 LLM、Tool、Agent spans，包括 tool-result continuation 与 linked-root background agents；这样 ARMS 可以在 Session/User view 中按同一 pseudonymous id 聚合完整调用链。实现不写 Resource 属性、LogRecord、Metric、Baggage，也不双写 `enduser.id` 或 `user.id`，避免把用户维度变成进程级资源维度或跨进程传播字段。

该配置只适合一进程一用户的部署。共享 multi-user daemon/channel 如果用进程级 env 或 settings 写入，会把不同用户混成一个 id；这种部署需要上层按会话或请求提供更细粒度身份后再扩展协议。

## 关键代码路径

- `packages/core/src/config/config.ts`: `telemetry.userId` 解析、env precedence 与 `getTelemetryUserId()`。
- `packages/core/src/telemetry/config.ts`: telemetry config surface。
- `packages/core/src/telemetry/session-tracing.ts`: interaction span 创建时写 `gen_ai.user.id` 并传播到子 span。
- `packages/core/src/core/coreToolScheduler.ts`: tool/result continuation span 继承用户 id。
- `packages/cli/src/acp-integration/session/Session.ts`: ACP session telemetry propagation 覆盖。
- `docs/developers/development/telemetry.md` 与 `docs/users/configuration/settings.md`: operator 配置文档。
