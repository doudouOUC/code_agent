## 解决了什么问题

#7812 能在 managed daemon shutdown 时尽力释放 exact-owned writer lock，但 daemon replacement 场景仍缺一个可验证的交接协议。新 daemon 不能凭 PID/hostname/age 抢 active lock，否则共享目录或容器边界下可能双写；但如果旧 daemon 已经完整 flush，继续把 session 卡在 writer conflict 也会影响恢复体验。

## 最终实现方案

最终实现把 session writer lock schema 升到 v2，并引入 sealed handoff state。active record 仍表示当前 writer；sealed record 表示旧 managed writer 已在 durable drain 后完成交接准备，并携带 runtime-relative transcript proof：路径、存在性、byte length、SHA-256 digest、sealed timestamp 与旧 owner diagnostics。

handoff 使用固定 `<lock>.claim` 文件保护 active→sealed 和 sealed→active 两段转换，避免多个 replacement 同时写 primary lock。managed shutdown 在 admission close 与 durable drain 之后调用 `closeSessionWriter({ handoff: true })`；`ChatRecordingService` 只有 flush 成功才 seal，flush 失败会继续保留所有权，不制造不可信 proof。

trusted managed replacement 设置 `takeoverPolicy: 'certified'` 后只接受 sealed state。它先打开 expected transcript 并计算 digest，再获取 fixed claim，随后重新验证 sealed primary、descriptor/path/metadata、length 与 digest，最后安装新的 active candidate；未知 successor、proof mismatch、symlink、truncate、残留 claim、未 sealed active lock 或竞争失败都 fail closed。
