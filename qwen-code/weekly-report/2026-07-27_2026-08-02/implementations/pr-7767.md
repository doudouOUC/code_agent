## 解决了什么问题

#7761 的 first-output benchmark 把 ACP 首输出拆成多个阶段后，暴露出 lazy Provider 构造仍可能落在用户第一条 prompt 的关键路径上。之前的优化已经压缩 initialize/session create 的静态闭包，但如果 provider 在 prompt 到来时才 import/construct，用户仍要等待这段初始化成本。

## 当前实现方案

当前 diff 在 ACP `session/new` response 成功写回 child transport 之后，调度一个 best-effort provider preparation。这个调度发生在 session 已经对 host 可见之后，不延长 session creation response；同时第一条真实 prompt 会复用同一个 in-flight 或 completed preparation promise。若 preload 与立即 prompt 竞争，只构造一次 Provider，不产生两套 generator。

非 lazy content generator 没有 preload work，直接 no-op。background preparation failure 会被捕获，避免 unhandled rejection，但 rejected promise 仍被 memoized，让第一次真实 model operation 看到同一个初始化失败，而不是悄悄重试并隐藏 preload 失败。

无用 preload 的生命周期被收紧：Qwen OAuth hot model switch 改变 generator config、ACP worktree relocation 改变 cwd 时，尚未用于请求的 preload 会被 invalidated；已经被真实请求使用的 generator 不会被替换，避免 mid-request 状态漂移。scheduled callback 不持有 stale wrapper，而是在执行时重新寻找 live session/current generator。

## 关键代码路径

- `packages/cli/src/acp-integration/acpAgent.ts`: `session/new` 写回后的 provider preparation 调度与 first prompt 复用。
- `packages/core/src/core/contentGenerator.ts`: lazy generator preparation/reuse surface。
- `packages/core/src/config/config.ts`: config/model/cwd 改变时的未使用 preload invalidation。
- `packages/cli/src/acp-integration/acpAgent.test.ts`: session create 后 preload、immediate prompt race、failure memoization、relocation/model switch 边界。
- `packages/core/src/core/contentGenerator.test.ts` 与 `packages/core/src/config/config.test.ts`: generator preparation 与 invalidation 单测。

## 验证方式

当前 PR 使用 fake provider 100ms dwell 作为受控场景，展示 process-to-first-model-output P50 paired median 改善 49.38ms，immediate prompt 非劣，RSS gate 正常。该结论依赖 #7761 的 benchmark 数据门控；PR 尚未合入，后续仍需以最终 diff 与 CI 为准。
