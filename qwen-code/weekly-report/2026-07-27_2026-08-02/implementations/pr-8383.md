## 解决了什么问题

Serve workspace `readText` 的 `meta.lineEnding` 与 `encoding`、`bom`、`sizeBytes` 一样应描述整个文件。但当前实现会对即将返回的 slice 检测 line ending，并且 byte truncation 分支还会对截断后的 slice 重新检测。

CRLF 文件按 cursor 分页时，第一页如果只返回一行，该 slice 的 `\n` 已作为行终止符被消费，返回 content 只以 `\r` 结尾；对这个 slice 调 `detectLineEnding()` 会得到 `lf`。第二页可能再报告 `crlf`，导致同一文件的不同页给出矛盾 metadata。信任第一页 metadata 的客户端保存时可能把 CRLF 内容静默改写成 LF。

## 当前实现方案

当前 open diff 在 `readTextSnapshotFromResolvedFile()` 中改为对完整 `decoded.content` 只检测一次 line ending，并把结果写入 `meta.lineEnding`。后续 line/limit slice 和 `maxOutputBytes` byte truncation 都不再重新检测 line ending，因此分页中的每一页都报告同一文件级值。

测试新增 CRLF cursor 分页回归：写入 `aa\r\nbb\r\ncc\r\n`，用 `limit: 1` 读取第一页，再沿 `nextCursor` 读取第二页；两页 content 分别是 `aa\r` 和 `bb\r`，但 `meta.lineEnding` 都必须是 `crlf`。PR body 记录该测试在还原一行实现后会在 main 上失败，报 `expected 'lf' to be 'crlf'`。

## 关键代码路径

- `packages/cli/src/serve/fs/workspace-file-system.ts`: `lineEnding` 从 `detectLineEnding(content)` 改为 `detectLineEnding(decoded.content)`，并删除 byte truncation 分支中的重新检测。
- `packages/cli/src/serve/fs/workspace-file-system.test.ts`: 新增 CRLF file cursor paging metadata 一致性测试。

## 验证方式

PR 记录的验证命令是 `cd packages/cli && npx vitest run src/serve/fs/workspace-file-system.test.ts`，在 Linux + Node.js v22.22.1 下运行 touched suite 共 119 个测试。新增测试通过还原实现验证过会在 main 上失败。

## 风险与边界

- 这是 open PR 当前 diff，不是已合入 `main` 的能力。
- 行为变化是 `lineEnding` 从“返回 slice 的特征”回到“文件级 metadata”；这与字段位置和其它 metadata 语义一致，但依赖 slice 语义的非预期调用方会看到变化。
- 该 PR 不改变 returned content、cursor encoding、snapshot/hash、encoding/BOM、sizeBytes、line/limit、maxOutputBytes 或 truncation 语义。
- 本地只记录 Linux 验证；macOS/Windows 依赖 CI 或后续验证。
