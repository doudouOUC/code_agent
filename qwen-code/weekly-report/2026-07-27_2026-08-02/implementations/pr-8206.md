## 解决了什么问题

external-context integration 的生产 audit 命中 MCP SDK、Hono server、body parser 和 URI parser dependency path 的安全 advisories。需要修复 direct external-context MCP profile 的依赖风险，同时避免把这个 PR 扩大成 mobile MCP package 的 runtime 迁移。mobile-mcp 的 Node.js 22 / Hono 2 迁移另由 #8311 处理。

## 最终实现方案

最终实现将 `@qwen-code/external-context` 的 direct MCP integration 升级到 MCP SDK 1.30.0，并只对 MCP SDK 1.30+ consumer 选择 patched Hono 2 dependency line。`package-lock.json` 同步刷新 request/body/URI parsing 相关传递依赖，`packages/vscode-ide-companion/NOTICES.txt` 重新生成许可证 notice。

override 是 scoped 的：#8206 只收敛 direct external-context dependency path，不把 mobile MCP package 强行迁移到新的 runtime baseline。这样 direct external-context 的 advisory path 收敛，同时把 mobile-mcp 的 breaking runtime/dependency 决策留给 #8311 单独记录。

## 关键代码路径

- `integrations/external-context/package.json`: external-context direct MCP SDK 版本升级。
- `package.json`: scoped dependency override，把 Hono 2 选择限制在 MCP SDK 1.30+ consumer。
- `package-lock.json`: 传递依赖刷新，收敛 request/body/URI parser 路径。
- `packages/vscode-ide-companion/NOTICES.txt`: 依赖刷新后的 notice 重新生成。

PR 声明的验证重点是 package resolution，而不是业务逻辑：检查 external-context direct integration 解析到 MCP SDK 1.30.0 与 patched Hono 2 line，同时确认该 PR 没有把 mobile-mcp 的 runtime/dependency 迁移混入 #8206。合入前已通过的验证以 PR 记录为准；后续依赖再刷新时仍需复查 workspace tests 和 license notice。
