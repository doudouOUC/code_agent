## 解决了什么问题

daemon 已有 workspace/session 数量类 guard，但缺少 process-wide bytes、bulk queue、spawn/process lane 和 completion reserve 的统一资源保护。多 workspace 场景下，一个 workspace 可以通过大批量任务、process output buffering、replay/export/fanout 等路径消耗进程内存或排队槽位，影响其它 workspace 的 prompt completion、错误响应和 shutdown cleanup。

## 当前实现方案

当前 draft diff 只新增 resource budgeting foundation，不接生产路由、不广告 capability，也不改变现有 daemon 行为。新增 `ResourceBudget` 是同步、进程级、可组合的 admission primitive：一次请求可以同时预留多个 category，检查 parent cap、normal admission cap、category cap 与 emergency pool 后再原子提交。失败返回结构化 `resource_admission_exhausted`，成功返回 lease。

lease 支持 split、grow、shrink、transfer owner 和 idempotent release。normal work 默认受 `normalAdmissionBytes` 限制，completion priority 可使用 completion reserve；emergency category 单独保留低于 3 MiB 的响应池，不能和业务 category 混合预留，避免业务工作吃掉最后的错误响应容量。snapshot 暴露 used/high-water/category caps，便于后续 status route 或 health surface 接入。

调度侧新增 fair bulk/spawn/process scheduler。每条 lane 有 global active/wait limit、workspace active/wait limit、30s wait timeout、abort handling、seal admission 和 nested-operation 拒绝。drain 按 workspace round-robin 轮转，避免一个 workspace 的长队列独占 global active slots。`runBufferedProcessOperation()` 在进入 process lane 前先预留最大 buffered bytes，并在成功、失败、abort、timeout 任意完成路径释放 lease。
