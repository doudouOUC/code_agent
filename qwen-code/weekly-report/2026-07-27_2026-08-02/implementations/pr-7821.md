## 解决了什么问题

Todo Stop Guard 会在自然 stop 且可信 top-level Todo 仍未完成时自动续跑。旧实现能覆盖基本续跑，但 continuation 的 ordering 与 ownership 还不够原子：用户输入、model selection、compression/provider submission、Stop hooks、workspace relocation、session disposal 或 overlapping prompt 都可能穿插进同一条 work chain，导致 Guard prompt 被错误保留、成功工具响应丢失、旧 prompt 修改新 owner，或外部 Stop hook 被误吞。

## 当前实现方案

当前 diff 将 continuation 排序改为 owner-scoped claim/release state machine。可信 bridge invocation prompt id 作为 owner key；Guard preparation 在 queued input/model selection 之后、compression/provider submission 之前 claim 自己的排序位置，确保 continuation 与真实用户 prompt 在同一队列里有确定先后。claim/release 协议同步迁移到 daemon bridge、channel bridge 与 desktop shared agent consumer，旧 bridge client 不满足新协议时 fail closed。

失败恢复改为保留已 drain 用户内容与已经成功返回的 function responses，只移除 synthetic Guard prompt。若 continuation supersedes inspected response，会重跑 Stop hooks，避免基于旧 response 的 hook 结果继续支配新 response；非阻断 allow 后重置 consecutive block accounting，claim 失败时仍允许独立外部 Stop hooks 按普通路径执行。

session lifecycle 也同步加固：work-chain agent 与 monitor lineage 被追踪，workspace relocation 通过 close gate 串行化，session disposal 或较旧 overlapping prompt 不能再修改较新的 owner。cron queue cap 被修正为只精确限制 unrelated cron work，不通过驱逐 related result 来解决 related overflow；related overflow 另由 #7805 继续跟进。
