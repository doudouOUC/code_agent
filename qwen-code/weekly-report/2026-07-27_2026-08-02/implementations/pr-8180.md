## 解决了什么问题

#8176 统一了 tool-call terminal status，但 terminal status 仍只能描述“整个 tool call 最终怎么结束”。它无法区分 validation failure、permission deny、PreToolUse blocking、host invocation guard 等未进入 `invocation.execute()` 的 synthetic failure，和真正调用工具实现后发生的 failure/cancel。观测侧只看到失败率，无法判断 executable boundary 是否健康，也无法把“工具没开始”与“工具执行失败”分开治理。

## 最终实现方案

最终实现是在 terminal status 旁边新增 execution-specific outcome。Core scheduler 与 ACP tool call 共用状态契约：validation、permission deny、PreToolUse blocking、host invocation guard、duplicate call 等 pre-execution 响应标记为 execution not started；一旦真正进入 `invocation.execute()`，执行结果会被冻结为 succeeded、failed 或 cancelled，并贯穿 hooks、result persistence、recording、image bridging 与 batch post-processing。

telemetry normalization 在 terminal normalization 基础上增加 call id、execution status、取消/错误分类和 execution child span。metrics 新增低基数 execution-outcome counter，执行 child spans 只为 attempted executions 创建，避免把未进入工具实现的拦截路径伪装成 execution latency。user-facing TUI、JSON protocol 与既有 terminal status 字段保持兼容，新增字段用于观测和后续告警，不改变工具执行行为。

## 关键代码路径

- `packages/core/src/core/coreToolScheduler.ts`: Core tool 调度中记录 pre-execution、execution-started、execution-finished 三类边界。
- `packages/core/src/core/turn.ts` 与 hooks 相关路径: execution outcome 穿过 hook blocking、result persistence、recording 与 batch finalization。
- `packages/core/src/telemetry/session-tracing.ts`: attempted executions 创建 execution child span；未开始路径只落 terminal/tool-call event。
- `packages/core/src/telemetry/log-to-span-processor.ts`: tool-call log 到 span 的 execution outcome 映射。
- `packages/core/src/telemetry/loggers.ts`、`metrics.ts`、`types.ts`: 记录 execution status、错误分类与低基数 counter。
- `packages/acp-bridge/src/Session.ts`、`SubAgentTracker.ts`: ACP / subagent tool-call event 带 execution outcome 口径。
- `packages/core/src/tools/mcp-tool.ts`: MCP tool invocation 与 synthetic failure 的 execution boundary。
- `docs/design/tool-execution-status.md`: terminal status 与 execution outcome 的职责拆分。

## 验证方式

PR 声明覆盖 core scheduler、ACP session/subagent tracker、MCP tool、non-interactive、UI hook、telemetry logger/metrics/span tests。测试重点包括：permission/validation/hook blocking 不标记 attempted execution、真正进入 `invocation.execute()` 后结果冻结、cancel/error 分类稳定、execution child span 只包裹实际执行、terminal status 与 execution status 兼容、recording 和 JSON/TUI 输出不回归。
