## 解决了什么问题

Direct External Context Auto Recall Hook 是一次性 Node 子进程，但 provider timeout 只 abort 请求，不会销毁 `EnvHttpProxyAgent` 持有的 CONNECT socket。结果是 Hook 可能已经向 stdout 输出 `{}`，但进程仍被黑洞代理连接留住，超过 Qwen 外层 8000ms command-Hook timeout。

同一块文档还存在入口契约漂移：shared config loader 接受 v1/v2，但 MCP entrypoint 实际只接受 v1，Auto Recall Hook 只接受 v2；v2 顶层 `timeoutMs` 也没有 auto recall runtime consumer，Hook 请求 timeout 只由 `autoRecall.timeoutMs` 控制。

## 最终实现方案

最终实现让每次 Auto Recall Hook 安装并持有自己的 environment-aware proxy dispatcher。`runAutoRecall()` 在通过 event/config/cwd/query 校验后调用 `installEnvironmentProxy()`，随后构造 provider、发起最多一次 search、渲染 additional context；无论 search 成功、返回空结果、provider failure 还是 render failure，都会在 `finally` 中 `await dispatcher.destroy()`。

早期 no-op 路径不会创建 dispatcher：malformed event、unsupported event、缺失/空 `submitted_prompt`、v1 config、repository root mismatch、cwd 越界和 code-fence-only query 都在 proxy 安装前返回 `{}`。长驻 MCP 进程不改生命周期，仍安装一个全局 dispatcher 并在整个 process lifetime 内持有，避免把一次性 Hook cleanup 扩散到 on-demand MCP request。

`installEnvironmentProxy()` 从 `void` 改为返回 `EnvHttpProxyAgent`，调用方可显式销毁；proxy 单测同步断言返回值与 `setGlobalDispatcher()` 的对象一致。文档同步修正：MCP entrypoint 只接受 v1，Hook 只接受 v2；v2 顶层 `timeoutMs` 只为兼容旧 v2 config file 保留，当前没有 runtime consumer。

## 关键代码路径

- `integrations/external-context/src/auto-recall.ts`: Hook-owned dispatcher 的 install / `finally destroy()` 生命周期边界。
- `integrations/external-context/src/proxy.ts`: `installEnvironmentProxy()` 返回 `EnvHttpProxyAgent`，供一次性 Hook 显式释放。
- `integrations/external-context/src/auto-recall.test.ts`: mock dispatcher cleanup、早期 no-op 不安装 proxy、真实子进程黑洞 CONNECT proxy 回归。
- `integrations/external-context/src/proxy.test.ts`: dispatcher 返回值与 global dispatcher wiring 覆盖。
- `integrations/external-context/src/config.ts`: v2 top-level `timeoutMs` 注释修正。
- `docs/design/direct-external-context-auto-recall.md`、`integrations/external-context/README.md`: Auto Recall / MCP v1/v2 entrypoint、timeout ownership 与 proxy lifecycle 文档修正。

## 验证方式

PR 记录的验证包括 external-context workspace 97 个测试、external-context build/typecheck/lint，以及仓库级 build/typecheck/lint。新增黑洞 CONNECT proxy 回归要求只观察到一次 `CONNECT context.invalid:443`，child stdout 为 `{}`、stderr 为空，并在 8000ms guard 前以 exit code 0、无 signal 自然退出。作者还用 Node.js 22.22.3 对构建产物做了两次独立黑洞代理验证，确认修复后约 1.45 秒退出。

## 审计备注

该 PR 是 lifecycle fix，不改变 provider、request protocol、query sanitizer、result rendering、Hook schema 或 MCP surface。文档应避免把它写成新的 retrieval capability；它只保证 Auto Recall Hook 的一次性代理资源在检索尝试后被释放，并修正 v1/v2 entrypoint 与 timeout 说明。
