## 解决了什么问题

session writer lease 只有在所有并发 transcript writer 都参与同一 lease protocol 时才安全。若默认开启，混合版本、混合配置或未重启的 ACP/daemon 可能出现一部分 writer 走 lease、一部分仍直接写 JSONL 的局面；这种 rollout 比单纯关闭 lease 更危险，因为会让操作者误以为已有单写保护。

## 最终实现方案

最终实现新增 restart-required 的 `experimental.sessionWriterLease` setting，默认 `false`。只有该设置明确为 boolean `true`，且会话运行在 ACP/daemon 路径时，session writer lease 才会启用；interactive 与 headless session 保持 legacy recorder，不因为用户局部 settings reload 自动切换。

ACP agent 在 bootstrap config 阶段 snapshot 一次 effective gate，并在该 ACP 进程服务的所有 session 中复用。这样同一个 ACP child 不会因为 per-session settings reload 而混用 lease writer 与 legacy writer。需要开启 lease 的部署必须先 drain 旧 writer、统一配置、重启 ACP/daemon，再让新进程用同一 gate 接管。

配置、schema 与文档同步更新：用户 settings 文档说明该字段是 experimental 且 restart required；CLI settings schema、VS Code companion schema、settings UI schema 与 config tests 都覆盖该字段。非 boolean settings value 被拒绝，不会被宽松 coercion 误开。
