## 解决了什么问题

#10751 已提供全局 turn index/anchored transcript protocol，#11054 已把历史 pages 与 live transcript 拆到独立 store，但 WebShell 仍只渲染 connected live window。用户无法用普通滚动连续阅读被淘汰历史，也无法从一个 bounded 全量 rail 跳到远端 turn；旧 snapshot toolbar 与宽文本列表还会割裂既有聊天阅读方式。

## 最终实现方案

新增 `TranscriptViewport` 与 `useTranscriptViewport`，把 page table 中选定 range 转成只读消息窗口；历史窗口关闭 approval、branch/retry、streaming 等 live mutation surface。滚动接近上下边界时按 range edge加载 older/newer page，加载前记录第一条可见 source/tool row 和像素 offset，page 合并或相反边淘汰后反复校正，从而保持阅读位置。返回 latest 时释放 viewport pin并切回持续接收更新的 live store。

`GlobalTurnNavigation` 用 64px rail 呈现固定高度的 compact ticks，在 5,000 turn 等长会话中只渲染有界 mark；hover/focus展示 index 中已有 prompt/preview而不触发 transcript请求，click/Enter再通过 locator按需加载目标 range。Home/End/方向键支持键盘定位，窄视口和 split pane 保留 compact/hidden策略。

数据层扩展 page table/range adjacency、viewport pin 与 live boundary capture。顺序 `loadMoreTranscript` 的已加载窗口仍可向上滚动；只有 snapshot/index能力完整时启用全局历史 viewport，cursor-only或旧 daemon继续原行为。session切换、reconnect、rewind、branch和迟到 selection均由 revision/owner/intent token阻止 stale result替换当前视图。

## 边界与风险

- 历史窗口是有界冻结视图，不接收 live mutation；实时输出继续进入 live store，需返回 latest查看。
- 窄视口、split pane、cursor-only和能力不足 daemon不启用全局 rail；origin family共享 cache预算时可能保留重复范围。
- reconnect during browsing、owner failover、真实 rewind/branch等生命周期组合虽有 fixture覆盖，但本次未独立做真实 daemon端到端复核。
