# PR #11308 当前实现观察：Channel worktree route 的 managed cold restore

> PR: [fix(channels): restore worktree-task routes through the managed load path](https://github.com/QwenLM/qwen-code/pull/11308)
> 状态：open；以下描述 2026-09-08 复核到 head `9f1acd07939c` 的当前 diff，不能视为 `main` 已落地能力。
> 规模：+404 / -4，4 个文件

## 解决了什么问题

#10643 的worktree named task会把route cwd持久化为worktree路径。Channel worker冷启动时，`restoreSessions()`原本对所有route调用generic `loadSession(sessionId, cwd)`；daemon只能用注册workspace root解析owner，因此worktree cwd得到 `workspace_mismatch`，route被丢弃。下一条消息可由named-session manager懒自愈，但eager route table和主动投递语义已丢失。

## 当前实现方案

当前open diff为managed worktree route额外持久化 `isolation:'worktree'` 与 `workspaceCwd`。`NamedSessionManager`在create/select与懒恢复成功后把task isolation、workspace root和attested worktree cwd一并传给router；共享task及无新metadata的旧route保持原格式和行为。

eager cold restore发现完整metadata后不走generic load，而调用既有 `loadManagedSession`：请求cwd使用workspace root，成功后再校验daemon list snapshot中的 `persisted-v1` attestation、worktree绝对路径和预期cwd。若session已被reset取代，managed load跟随 `worktree_session_superseded`重定向replacement并重写route ID。lazy `restoreRoutes()`也再水合相同metadata，route heal/remove/dispose全程同步清理或迁移metadata。

## 关键代码路径

- `packages/channels/base/src/SessionRouter.ts`：persisted route schema、managed metadata map、eager managed restore、superseded heal与持久化。
- `packages/channels/base/src/named-session-manager.ts`：选中/创建/懒恢复task时传递 isolation与workspace root。
- `packages/channels/base/src/SessionRouter.test.ts`：managed cold restore、replacement redirect、attestation failure和旧route兼容。
- `packages/channels/base/src/named-session-manager.test.ts`：route metadata登记与lazy rehydration。

## 边界与风险

- 旧build写出的route没有metadata，首次cold start仍按旧路径丢弃一次，再由lazy消息自愈。
- 新route被旧build读取时额外字段被忽略，退化为旧恢复行为而非格式错误。
- 当前PR只恢复route，不修复worktree delete泄漏；后者由#11309当前方案承接。
