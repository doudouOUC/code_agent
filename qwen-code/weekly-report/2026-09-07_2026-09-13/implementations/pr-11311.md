## 解决了什么问题

configurable Mem0 package在#11246后已有只读MCP与独立Auto Recall，但可信daemon workspace仍不能显式保存共享事实。写入是外部非幂等副作用，若沿用搜索的retry或把timeout视为失败可能重复记忆；同时generic MCP permission在content为空、raw args序列化文本与title相同的情况下会隐藏完整待写参数，用户无法审查正文。

## 最终实现方案

最终实现新增独立writer bundle、严格schemaVersion 4 instance与closed WriteDialect V1。管理员固定endpoint、credential、scope、repository root和create response mapping；writer MCP只暴露 `context_remember({content})`。每次获准调用校验最多4000 Unicode code points的非空正文，原样构造一条user message，固定 `infer:false`，只发送一次POST且拒绝redirect，不做pre-search、dedupe、cache、poll或自动retry。

response解析明确区分 `stored`（得到record ID）、`accepted`（provider确认接收operation ID）、`failed`（提交前输入/配置失败）和 `unknown`（HTTP/timeout/断线/shape不确定，可能已写入）。后两类以不同提示约束后续动作，尤其unknown不能自动重试；MCP tool annotations标记非只读、非幂等，复用Core已有unsafe replay guard和daemon permission，没有新增daemon route。

WebShell adapter对没有专用text/diff preview的permission读取 `rawInput/input/args`，将完整JSON pretty-print并转义控制字符，标记 `contentIsInput`；ToolApproval即使正文等于title也显示该参数块。审批仍服从现有policy，YOLO或批准型Hook的既有行为不变。

## 边界与风险

- provider可能在response timeout或transport断开前已提交，因此unknown不代表rollback，必须人工核对后再决定是否重试。
- 当前真实Holo预检返回403，真实service的 `infer:false`、existing record保留和跨session召回闭环未验证。
- 固定scope/cwd是本地routing约束，不是tenant授权边界；自动写入、删除、CLI/TUI onboarding与跨workspace迁移不在范围内。
