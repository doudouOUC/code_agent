## 解决了什么问题

#11398合入的浏览器通知只显示通用完成/失败状态，点击后仅聚焦原窗口。多个任务并行时用户无法从通知辨认具体会话，也不能从设置页、分屏或另一会话直接回到产生通知的目标。

## 当前实现方案

当前open diff让通知携带会话标题、本轮提问与回复。标题使用`QwenCode · <session title>`，无标题时回退本轮问题首行；提问和回复先去除常见Markdown结构、折叠空白，再分别限制为80和120个Unicode code point，标题限制60。失败通知不展示部分回复或错误详情，内容缺失时省略对应行；同时通过`Notification.icon`提供随包128×128图标。

`DaemonSessionProvider`在terminal事件完成transcript projection后，按`promptId`从顶层user/assistant block提取当前turn内容；admission label与pending event文本提供prompt fallback。binding同时捕获workspace、standalone或Live session context。点击通知后，provider向所属实例的私有`EventTarget`派发`qwen:open-session`，`App`校验session/context和locked workspace，退出设置/分屏并走既有session加载路径；目标已经是健康current session时只收起面板，不重复load或中断当前turn。

`WebShellWithProviders`新增可选`browserNotifications`配置，允许宿主设定默认开关、应用名和图标；默认仍关闭。内置standalone入口传入`defaultEnabled:true`，只影响没有保存偏好的站点，用户保存的开关优先，且仍不会自动请求浏览器权限。这些变化目前都只存在于open diff。

最新review修正把“没有保存偏好”与“storage不可读”分开：只有明确读到`null`才应用内置默认值，storage异常时保持关闭但仍允许本次显式选择。文本清理不再把TypeScript泛型、比较运算符或代码围栏中的HTML当标签删除；点击健康current session时还会显式清理受控split状态并恢复chat底部跟随。

## 关键代码路径

- `packages/web-shell/client/daemon/session/turn-notification-context.ts`：按promptId提取turn内容、保留admission fallback并捕获session target。
- `packages/web-shell/client/daemon/session/DaemonSessionProvider.tsx`：在transcript投影后组装通知内容。
- `packages/web-shell/client/browser-turn-notifications.tsx`：文本摘要、品牌、图标、默认偏好和点击事件派发。
- `packages/web-shell/client/App.tsx`：验证通知目标并复用既有session导航，避免健康current session重载。
- `packages/web-shell/client/index.tsx`与`main.tsx`：宿主配置surface和内置standalone默认接线。

## 边界与风险

- 通知会把标题、提问和回复摘要暴露给系统通知中心或锁屏，是否预览由操作系统策略决定。
- 原页面及目标chat仍须运行/挂载；closed-page push、Service Worker、Channel和未挂载会话不在范围。
- 内置standalone默认值、嵌入式配置surface与点击导航尚未进入`main`，不能作为当前产品承诺。
