# PR #11309 当前实现观察：删除 daemon session 时回收自有 worktree

> PR: [feat(cli): reap owned worktrees when daemon sessions are deleted](https://github.com/QwenLM/qwen-code/pull/11309)
> 状态：open；以下描述 2026-09-08 复核到 head `5c9593c5e5e` 的当前 diff，不能视为 `main` 已落地能力。
> 规模：+1,055 / -48，6 个文件

## 解决了什么问题

#10643创建的named worktree在daemon session删除时只移除transcript record和sidecar，checkout、`.qwen-session` marker、git worktree registration与branch都保留。stale worktree sweep按设计不碰named worktree，因此每次删除都会永久累积资源；同时清理是破坏性动作，不能仅凭路径或过期记录推断owner。

## 当前实现方案

当前open diff把worktree删除拆成delete前分类和delete后执行。delete前先严格读取active/archived sidecar；只有存在 `workspaceCwd`且不是已superseded predecessor才构造plan。随后按canonical worktree路径获取共享ownership lock，重新验证sidecar未变、marker精确指向session、realpath位于workspace/repo允许的 `.qwen/worktrees` root下，并扫描其它sidecar排除共享checkout；reset产生且精确指向当前replacement的tombstone predecessor不计共享。

在锁内完成session record/sidecar删除后，只有结果确认为removed且上述ownership仍有效才执行cleanup。`git status --porcelain`包含tracked/untracked工作，除daemon marker外任意改动都保留checkout；clean checkout通过 `GitWorktreeService.removeUserWorktree(..., {deleteBranch:true})`移除registration/path，branch只做非force删除，含未合并提交时保留并记名。任何读取、containment、marker、sharing或执行歧义都fail closed为保留并写明原因，不阻止session记录本身删除。

## 关键代码路径

- `packages/cli/src/serve/server/worktree-orphan-cleanup.ts`：preclassification、ownership验证、dirty检查、保守执行与具名日志。
- `packages/cli/src/serve/server/worktree-ownership-op.ts`：按worktree路径共享的ownership operation lock。
- `packages/cli/src/serve/server/session-archive.ts`：在worktree lock→archive coordinator顺序下包围delete/cleanup事务。
- `packages/cli/src/serve/routes/session.ts`：reset与delete共用同一worktree锁，避免ownership转移交错。
- `packages/cli/src/serve/server/session-archive.test.ts`：真实git仓库覆盖分类、保留和执行分支。

## 边界与风险

- bridge idle reaper仍保留可恢复session的完整worktree；不提供历史泄漏worktree的周期扫描。
- 外层已持有archive batch lock的internal-runtime删除跳过worktree cleanup，以避免锁顺序反转；该类runtime按设计不拥有Part 4A worktree。
- 无source metadata的reset replacement可能没有可达transcript record，仍不在删除route覆盖范围。
