# PR #11309 最终实现：删除 daemon session 时回收自有 worktree

> PR: [feat(cli): reap owned worktrees when daemon sessions are deleted](https://github.com/QwenLM/qwen-code/pull/11309)
> 状态：merged；head `f77d94356f04` 已于 2026-09-08 合入 `main`，以下按最终 diff 与最新 `main` 复核。
> 规模：+1,547 / -49，7 个文件

## 解决了什么问题

#10643创建的named worktree在daemon session删除时只移除transcript record和sidecar，checkout、`.qwen-session` marker、git worktree registration与branch都保留。stale worktree sweep按设计不碰named worktree，因此每次删除都会永久累积资源；同时清理是破坏性动作，不能仅凭路径或过期记录推断owner。

## 最终实现方案

最终实现把worktree删除拆成delete前分类和delete后执行。delete前严格读取active/archived sidecar；只有存在 `workspaceCwd`且不是已superseded predecessor才构造plan。随后按canonical worktree路径获取共享ownership lock，重新验证sidecar全部ownership字段、marker精确指向session、realpath位于允许的 `.qwen/worktrees` root下、slug重新推导的删除目标就是已验证checkout，并扫描其它sidecar排除共享checkout。runtime workspace存在时还要求sidecar workspace精确匹配、original cwd位于workspace/repo根集合。

在锁内完成session record/sidecar删除后，只有结果确认为removed、ownership仍有效且workspace generation仍允许写入才执行cleanup。dirty gate固定启用untracked与ignored枚举并清理继承Git环境，除daemon marker和可再生的 `node_modules/dist/coverage`外，任何tracked、untracked或ignored用户内容都保留checkout。clean checkout通过 `GitWorktreeService.removeUserWorktree(..., {deleteBranch:true})`移除registration/path，branch只做非force删除。

`session_closing`不会被当作真正not-found折叠record，以免child仍以checkout为cwd时误触清理。执行失败后重新观察目录：仍有内容才声明保留，内容已被部分移除则显式报告可能partial delete。superseded predecessor静默跳过，reset后的current replacement可忽略精确tombstone predecessor后正常清理；任何歧义均fail closed且不阻止session记录本身删除。

## 边界与风险

- bridge idle reaper仍保留可恢复session的完整worktree；本PR不扫描历史已泄漏worktree。
- 外层已持有archive batch lock的internal-runtime删除跳过worktree cleanup，以保持worktree→archive锁顺序；该类runtime按设计不拥有Part 4A worktree。
- cleanup尽量fail closed，但底层Git/文件系统删除可能部分完成；最终实现只保证不会在未重新观察时误报checkout完整保留。
