## 解决了什么问题

已发布 configurable Mem0 Extension 只提供模型按需调用的 `context_search`。需要在每个合格用户提交前确定性召回的管理员必须另建集成，同时 endpoint、credential、scope和仓库适用范围不能交给模型或用户 prompt选择。

## 最终实现方案

包内新增独立 `UserPromptSubmit` command-Hook bundle与严格 schemaVersion 3 instance。管理员继续提供绝对 `dialectPath`、credential env和固定 scope，并额外绑定 canonical、非文件系统根的 `repositoryRoot`；运行时 realpath校验当前 cwd必须在该 root内。默认 Extension manifest仍只有 `context_search`，schemaVersion 2 MCP部署不接受 v3配置且无需迁移。

Hook只读取 `submitted_prompt`，先限制 sanitizer输入与最终 query长度，再移除 fenced code、credential原文、常见 secret assignment、Bearer/JWT和长token。它复用现有 closed Dialect V1 request engine，provider timeout/异常/空结果均 fail open为 `{}`，成功时最多五条结果以 structured `untrusted_external_context`进入 user-layer additional context。stdin、config、response和 wall-clock均有界，FIFO/special file配置被拒绝，超时后主动结束输出进程。

## 边界与风险

- 启用后，sanitized user prompt会发送到管理员配置的外部服务；sanitizer是best effort，不是DLP。
- provider结果仍是非可信用户层上下文，且会进入会话历史；不提供生命周期总量治理、ACL或审计。
- 未验证真实 vendor服务、Windows/Linux运行、写操作、redirect/retry或provider-specific preset。
