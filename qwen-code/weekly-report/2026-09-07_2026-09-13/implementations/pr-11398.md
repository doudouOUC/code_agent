## 解决了什么问题

daemon terminal events与侧栏未读标记只能在WebShell页面内表达状态。用户切到其它窗口后，当前/分屏聊天完成或失败没有browser-level提醒；若把该能力做成daemon setting或自动请求Notification权限，又会混淆设备本地偏好与workspace配置，并造成意外授权弹窗。

## 最终实现方案

最终实现在standalone、顶层WebShell的Settings→UI中加入Browser task notifications。偏好默认off，保存于当前browser origin的localStorage并监听storage事件跨tab同步；用户显式开启时才请求Notification权限，撤销权限不会清除偏好。embedded host不自动启用，切换Workspace/User settings scope也不写daemon settings。

`DaemonSessionProvider`在transcript projection之后通过`TurnNotificationContext`提供现有terminal事实，并在same-session recovery期间保留已admit prompt。observer只跟踪当前或split pane中仍挂载的聊天：页面隐藏/失焦时，完成或失败产生不含chat正文、错误详情或workspace path的通用通知；cancelled、initial history、未观察chat和已在前台消费的terminal静默。

同page多个pane先做内存去重；Web Locks与localStorage可用时，再以turn identity的SHA-256 hash建立最多1024条same-origin claim，实现跨tab一次尝试。能力不足时退化为page-local去重与notification tag replacement。点击通知尝试focus并close。共享Switch同时修正Radix `data-[state=checked]`选择器，使轨道与thumb状态可见。

## 边界与风险

- 页面和目标chat必须保持运行/挂载；closed-page push、service worker、未挂载chat、Channel与embedded host不在范围。
- OS策略、browser permission与调度可阻止实际投递；shared claim只证明一次attempt，不证明用户看到通知。
- cross-tab去重依赖Web Locks和可用shared storage，能力不足时可能重复；没有新增daemon route、settings schema或public SDK callback。
