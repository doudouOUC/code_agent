# PR #11397 最终实现：按 Mem0 SDK 放宽 DELETE 响应解释

> PR: [fix(external-context): Align deletion responses with Mem0 SDK](https://github.com/QwenLM/qwen-code/pull/11397)
> 状态：merged（2026-09-09）；以下按最终head `5791f56dd347`及最新`main`记录。
> 规模：+92 / -77，6 个文件

## 解决了什么问题

#11337合入时把英文示例回执当作closed协议常量，只接受 `Memory deleted successfully`或带`!`的message，并约束可选status/event/cascade/error字段。真实Holo返回HTTP 200和 `Memory <id> deleted successfully.`，目标随后确实为404，但client因为message不匹配仍报告`unknown`。

## 最终实现方案

最终实现将DELETE响应处理与Mem0 SDK的HTTP层口径对齐：接受任意`response.ok`状态，继续做1MiB有界、严格UTF-8 JSON解析，但不再解释message/status/event/cascade/error等provider字段。JSON内容可以是object、array、null或任意合法值；成功HTTP状态本身仍不证明删除完成。

只有随后一次exact GET按既有absence contract确认目标不存在，结果才是`deleted`。目标仍存在、final GET不确定、非2xx、transport失败、空body/204、坏JSON或超预算body都返回`unknown`，且DELETE最多一次、不自动retry。删除前的ID、scope、全文、repository binding、审批与deadline语义保持不变。

## 边界与风险

- 最终实现会忽略2xx JSON中的provider-specific error/status字段，删除结论依赖后置exact GET absence。
- 204虽是成功HTTP状态但没有JSON，仍为unknown。
- 不改变非原子GET/DELETE竞态、full-text审批、fixed scope或unknown后的人工核对责任。
