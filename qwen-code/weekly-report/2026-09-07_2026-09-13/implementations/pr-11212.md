## 解决了什么问题

WebShell E2E Smoke 与三条 sibling lane 使用相同表达式路由到 self-hosted ECS pool，却只有它固定 20 分钟。runner争用会让依赖安装和浏览器阶段同时变慢，健康时约 8至10分钟的任务在约2倍劣化时被误杀；若简单全局放宽，又会让 hosted runner 的真实 hang 额外占用资源。

## 最终实现方案

CI workflow 的 `timeout-minutes` 改为按 runner选择表达式：self-hosted route 使用40分钟，显式 hosted或缺失 self-hosted输出的 fallback仍为20分钟。现有 workflow property test读取真实 YAML表达式并在三种 routing输入下求值，因此回退为固定20、降低 self-hosted预算或把 hosted也放宽都会失败。

## 关键代码路径

- `.github/workflows/ci.yml`：为 WebShell E2E Smoke 增加与 sibling lane同形的 runner-aware timeout表达式。
- `scripts/tests/ci-platform-lanes.test.js`：断言 self-hosted 40分钟、hosted及缺失输出 fallback 20分钟。

## feature 文档处理

本 PR 只调整 CI runner预算与回归守卫，不改变用户、daemon或 WebShell运行时能力，因此未更新长期 feature 技术方案。

## 边界与风险

- self-hosted上的真实 hang现在最多占用40分钟；hosted仍保持20分钟。
- 本改动不解决 runner池负载不均、sandbox容器泄漏或全仓 rebuild成本。
