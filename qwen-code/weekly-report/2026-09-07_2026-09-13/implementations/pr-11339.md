## 解决了什么问题

WebShell已有三个workspace session live-state轮询入口，但默认固定2秒，部署方无法按daemon压力调节；interval也没有通过capability在daemon与browser之间协商。直接重建整个polling effect还会在配置变化时丢状态或制造重叠请求。

## 最终实现方案

最终实现新增process-wide环境变量 `QWEN_SESSION_LIVE_STATE_POLL_INTERVAL_MS`：只接受1000到2147483647范围内的十进制整数，缺失或非法值统一回退5000ms。daemon capabilities在支持live-state时附带optional `sessionLiveStatePollIntervalMs`；字段可选以兼容旧daemon，WebShell字段缺失或非法也使用同一5000ms fallback。

`workspace-session-live-state` hook把interval timer effect与active polling state effect拆开：interval变化只更换下一轮调度，不清空现有snapshot，也不与in-flight read重叠。App、SessionOverviewPanel与WebShellSidebar三个入口都消费解析后的统一值。页面重新可见和本地invalidations仍立即刷新，连续错误仍采用30秒backoff；默认轮询只从2秒改为5秒，没有改成SSE或完整catalog轮询。

## 边界与风险

- interval是daemon进程级配置，不支持按workspace覆盖；变更后需重启daemon并刷新browser。
- 轮询请求量仍与可见workspace/tab数量相关，较大interval会延迟观察其它client产生的变化。
- 本PR不增加SSE订阅、batch read或自适应interval；旧daemon只得到browser五秒fallback。
