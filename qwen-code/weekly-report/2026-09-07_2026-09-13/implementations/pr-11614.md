## 解决了什么问题

Linux上的既有sandbox依赖Docker或Podman；容器runtime不可用、daemon不可访问或无root能力时，显式sandbox请求可能无法形成操作系统级文件系统边界。简单把整个工作区设为可写也不够：Git worktree的index、HEAD、objects与reflog位于checkout外部，只授权workspace会让`git add`、commit和stash因只读文件系统失败。

## 最终实现方案

最终把`bwrap`加入显式sandbox backend。启动前执行最小`--ro-bind / / --dev /dev --die-with-parent -- true`探针，确认二进制不仅存在而且当前内核允许真正进入约束；显式请求失败会报错退出，不静默回到unconfined。容器backend仍要求image，`bwrap`与Seatbelt这类in-place backend不再被缺失image错误门控。

`resolveBwrapWritableRoots()`先规范化cwd、系统临时目录、cache、Qwen配置/运行目录、显式include目录及Git元数据。HOME或其祖先一律拒绝；不存在root丢弃，父root已覆盖的子root去重。Git授权通过`gitEnv()`清除ambient repository selector，并要求当前cwd位于真实top-level内；普通仓库只接受真实`.git`目录，linked worktree还必须匹配common-dir登记项和`gitdir`普通文件反向指针，避免工作区内伪造`.git`文件扩大外部写权限。独立Git目录与未登记submodule需显式授权。

最终review follow-up把sandbox控制和可写root来源纳入project-env硬拒绝集合：workspace `.env`或`settings.env`不能设置`QWEN_SANDBOX`、`QWEN_SANDBOX_IMAGE`、`QWEN_SANDBOX_PROXY_COMMAND`、`QWEN_SANDBOX_NET`、`XDG_CACHE_HOME`、`TMPDIR/TMP/TEMP`，防止仓库内容决定host侧backend、执行proxy命令或把HOME敏感目录伪装成cache/temp后获得读写bind。operator继承环境与用户级`.env`仍是可信输入，但在可写Qwen目录之上把该`.env`重新只读bind，防止受限子进程改写host下次会读取的决策；reload冻结project-env拒绝集合，避免会话中途改变边界。

实际hop用宿主根只读bind、`/dev`设备视图和逐root可写bind重新执行CLI。closed网络只增加`--unshare-net`；不启用PID namespace，以免共享Qwen目录中的host PID owner记录在namespace内产生假存活。`/tmp`保持宿主bind以保留display与ssh-agent socket，因此`full`只描述文件系统mount enforcement，不代表host Unix service隔离。子进程保留Node参数和managed Electron模式，但移除显示变量，避免受限浏览器profile把OAuth表现成认证故障。

`qwen sandbox`命令报告backend、enforcement、网络模式、target与可写root；`--verify`检查workspace内写入、root外EROFS、host PID可见性和network namespace，`-- <command>`在同一边界透传stdio与退出码。safe mode的backend选择与真实hop一致，但继续排除settings-derived额外root；include目录会展开`~`，解析到HOME内部的仓库可控额外目录会被拒绝，非法`QWEN_SANDBOX_NET`也直接报错而不是退回open。root解析拒绝被转成可读的非零报告，并关闭`--`后数字参数的自动转换。verify用`mktemp`避免覆盖已有探针文件，固定C locale，并要求网络probe退出成功、stdout确实包含loopback后才判断open/closed，避免缺少命令或stderr文本造成假通过。

## 边界与风险

- `full`只覆盖文件系统mount；open/proxied保留host网络，closed模式仍可访问宿主Unix socket。
- operator启动环境、writable Git hooks/config、共享`/tmp`和Qwen settings仍可能影响后续无约束进程；本PR不构成完整sandbox安全批准。
- Landlock fallback、seccomp、按命令隔离与一次性提权、默认启用、Windows和Seatbelt既有Git/proxy缺口均不在本PR范围；工具级迁移仍仅存在于后续 open PR。
- `qwen sandbox --verify`不验证Git写入或host socket隔离，真实worktree commit仍需单独检查。
