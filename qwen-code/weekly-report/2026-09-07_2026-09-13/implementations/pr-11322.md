# PR #11322 最终实现：卸载 MessageList 时取消定位滚动 timer

> 规模：+93 / -1，2 个文件

## 解决了什么问题

#11208 的消息定位路径在滚动后创建150ms cooldown timer。列表若在timer触发前卸载，回调仍会调用 `scheduleSessionTimelineRangeUpdate()`并继续安排animation frame；测试 teardown移除browser globals后就可能间歇性报 `requestAnimationFrame is not defined`。连续定位还会留下多个待执行timer。

## 最终实现方案

最终实现用 `locateScrollTimer` ref持有唯一定位timer。每次新定位先清除上一timer，再创建新的150ms timer；回调先将ref置空，再沿用既有 `scrollCooldownCount` generation guard释放cooldown并更新timeline。组件unmount cleanup也清除该timer并置空，然后继续原有frame/listener清理。

这没有改变定位语义：`scrollIntoView({block:'center'})`、目标flash高亮和generation-scoped cooldown继续工作；只是让timer生命周期与MessageList实例绑定，并让较新的定位替代旧timer。

## 关键代码路径

- `packages/web-shell/client/components/MessageList.tsx`：`locateScrollTimer` ownership、新定位替换、unmount cleanup与原cooldown callback。
- `packages/web-shell/client/components/MessageList.dom.test.tsx`：149ms后卸载不再请求RAF、重复定位后无pending timer、正常滚动与高亮转移。
