# PR #11727 当前实现观察：让 Shell producer 决定自身输出预算

> PR: [fix(core): let the producer's own budget decide shell output size](https://github.com/QwenLM/qwen-code/pull/11727)
> 状态：open；以下描述2026-09-13复核到head `8ac6e4d60243`的当前diff，不能视为`main`已落地能力。
> 规模：+907 / -31，8 个文件

## 解决了什么问题

Shell结果先按工具声明预算做head-and-tail截断，随后`CoreToolScheduler`又按全局threshold加headroom执行通用单结果持久化。默认配置下通用门槛低于Shell预算，因此落在两者之间的输出会被第二层改成short head，反而丢失Shell刻意保留在尾部的退出码、signal和错误摘要，模型常需重跑命令才能确认终态。

## 当前实现方案

当前open diff在内部`ToolResult`增加`outputBudgetApplied?: boolean`。Shell只有在字符串`llmContent`真正执行过自身预算检查后才设置标记，无论结果是否发生截断；background launch、spawn/setup failure等未走该检查的路径不标记。该字段记录“已做尺寸决策”，与`persistedOutputFiles`记录的“已落盘”保持独立。

scheduler的普通成功和soft-failure路径把标记传给`maybePersistSingleToolResult()`；标记为true时只跳过这一个generic single-result gate。普通错误路径更严格：只有`errorMessage`仍逐字节等于已标记的`llmContent`时才让行，独立构造的spawn错误或追加failure Hook上下文后的字符串仍受通用门槛保护。timeout是独立分支：带标记且工具声明`maxOutputChars`时，detail会按producer字符预算再次检查并保留新生成的artifact；没有标记时继续走generic gate，避免标记成为无上限豁免。

Shell在正文截断前先计算long-run advisory与AI attribution warning的追加字符，将这部分从正文threshold中预留，保证标记描述的是最终拼装字符串已经接受预算决策。attribution warning异常文本另限制为120字符，完整错误仍写debug log。Shell自己的per-tool pass、combined pass、aggregate batch finalizer与send边界no-I/O cap都不变，聚合阶段仍可决定持久化。实现不按tool name猜测、不扫描输出文本，也不改变外部function response schema、Hook/ACP/JSON/telemetry或持久化UI metadata。

## 边界与风险

- 默认门槛与Shell预算之间的输出将完整进入模型，单次请求可能比当前`main`更大，但仍受producer、timeout、combined和batch上界约束。
- 退出码、signal和timeout仍嵌在格式化正文，后续batch reduction仍可能裁掉；结构化状态分离不在本PR范围。
- 本PR不处理其他拥有producer预算的工具，也不新增逐调用size/token telemetry。
