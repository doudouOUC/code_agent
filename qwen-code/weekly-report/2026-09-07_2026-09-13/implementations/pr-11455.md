## 解决了什么问题

普通daemon/ACP提问会运行管理员安装的`UserPromptSubmit` Hook，但原session路径只传model-bound `prompt`，没有#7762已有的optional `submitted_prompt`。configurable Mem0 Auto Recall只以该字段查询，因此即使profile、repository和凭据配置正确，也会返回`{}`、不访问provider且不把记忆加入模型输入。直接把所有fresh ACP文本推断为用户提交又会误覆盖scheduled task、sub-session和Live等机器生成输入，触发不应发生的外部检索。

## 最终实现方案

最终实现改为逐请求显式声明。WebShell在host `prepareSubmit`、slash command改写和附件展开前捕获composer文本，通过`_meta["qwen.submittedPrompt"]`随普通或本地queued submission发送；generic action、手动scheduled run、retry与server-restored queue不制造声明。其它ACP/daemon客户端也只能按合格请求显式opt in，不能由transport全局补齐。

REST与ACP transport只把合格public声明放入bridge request context；channel-worker metadata存在时拒绝建立provenance。bridge删除请求中的public/private键，只把trusted context重新注入私有`qwen.daemon.submittedPrompt`，并排除channel与promoted mid-turn。直接ACP客户端可用public键opt in；trusted parent只接受private键，不能用public键fallback或伪造父级声明。

Session只在既有fresh、非channel turn且声明为非空白字符串时给`UserPromptSubmit` input附加`submitted_prompt`，保留声明中的原始空白。缺失、非法、空白值不会回退到request text或`promptDisplayText`；retry、continue、restored question、runtime goal和tool-result re-entry都不会获得声明。legacy `prompt`、hook顺序、recording和默认extension注册保持不变。

## 关键代码路径

- `packages/web-shell/client/App.tsx`、`components/ChatPane.tsx`与`hooks/useQueuedPrompts.ts`：在用户提交边界捕获原始composer文本并独立保存到本地queue。
- `packages/cli/src/serve/routes/session.ts`与`serve/acp-http/dispatch.ts`：消费public声明、排除channel-worker输入并传入owner bridge context。
- `packages/acp-bridge/src/bridge.ts`与`packages/cli/src/acp-integration/acpAgent.ts`：剥离可伪造metadata，只沿受信任父链转发private声明。
- `packages/cli/src/acp-integration/session/Session.ts`：仅在fresh、非channel、非空白显式声明上发布hook字段，不从其它投影推断。
- `docs/design/daemon-user-prompt-submit-provenance.md`：记录ACP producer所有权、兼容性、隐私和验收范围。

## 边界与风险

- 只有显式启用Auto Recall且producer逐请求声明的ACP/daemon提交会把eligible文本发送到管理员provider；默认extension注册不变。
- 单个v3 profile仍只绑定一个canonical repository root和scope，不提供per-workspace profile routing。
- `submitted_prompt`是caller声明的provenance线索，不是认证或DLP边界；channel human/automation在当前统一marker下都被排除，Windows/Linux、PolarDB和真实模型自主行为未验证。
