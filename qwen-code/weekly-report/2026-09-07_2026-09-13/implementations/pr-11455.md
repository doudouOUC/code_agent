# PR #11455 当前实现观察：ACP Auto Recall 提交文本 provenance

> 规模：+214 / -1，4 个文件

## 解决了什么问题

普通daemon/ACP提问会运行管理员安装的`UserPromptSubmit` Hook，但当前session路径只传model-bound `prompt`，没有#7762已有的optional `submitted_prompt`。configurable Mem0 Auto Recall只以该字段查询，因此即使profile、repository和凭据配置正确，也会返回`{}`、不访问provider且不把记忆加入模型输入。

## 当前实现方案

当前open diff在resource、slash command和model-only扩展前确定submission projection：已有可信`promptDisplayText`时优先使用，包括显式空字符串；否则把ACP request中的text blocks按空格连接。原始空白保持不变，image/audio/resource正文、model-only delegation和扩展后指令不会进入该字段。

只有既有`isFreshUserTurn`判定为true且projection非空白时，`UserPromptSubmit` input才附加`submitted_prompt`；legacy `prompt`、hook执行顺序和失败策略不变。retry省略provenance，空display也不会回退到内部channel指令，tool continuation、restore/runtime goal等既有非fresh路径不因此重复Auto Recall。该字段仍是用户可控文本线索，不是身份或DLP边界。

## 关键代码路径
