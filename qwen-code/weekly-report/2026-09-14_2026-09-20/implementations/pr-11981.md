## 解决了什么问题

#11614 已把 whole-CLI bwrap backend 合入 `main`，但原 PR 的自动化主要是 spawn/argv 单测和手工 Linux 证据。mock 无法证明真实 mount/network namespace、普通 CLI 工具 hop、linked-worktree Git 写入、跨边界 writer lease 或信号清理；缺少 bwrap 的 runner 也可能通过跳过形成假绿。

## 关闭前方案

关闭前 draft 新增显式 `npm run test:integration:sandbox:bwrap` 和独立 Ubuntu 22.04 workflow。job 以只读权限安装 bubblewrap/Git/curl、完成锁文件安装与 integration typecheck，再运行真实 bwrap suite 并上传 JUnit。缺少 Linux/bwrap 或最小 namespace probe 失败时，显式命令退出非零；普通 integration 配置继续排除 Linux-only suite，避免其它平台静默跳过后把覆盖误算为成功。

14 项用例使用构建后的 CLI、可丢弃目录、真实本地 endpoint 和 scripted model response，验证 open/closed 网络、workspace/越界写、linked worktree commit、missing backend、直接/代理 fake-model Shell、writer ownership recovery，以及 SIGINT/SIGTERM 对 payload、descendant 和 proxy 的清理。测试还检查 namespace/runtime identity，并用 negative control 确认移除 confinement 后关键断言确实会失败。该实现未合入；后续工具级 bwrap 验收由 #12064 等分支重新组织，不能把它们的结果回填成该关闭 PR 的通过状态。
