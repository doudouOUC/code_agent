## 解决了什么问题

#12067 已把 structured launch、trusted receipt 和 file worker foundation 合入 `main`，但没有公开设置或工具路由。旧 whole-CLI bwrap 会把模型通信、认证、会话状态和 UI 一起放入边界，而只迁移少量工具又会让未适配的命令、扩展或宿主副作用绕回 host；公开 cutover 需要一份不可被 workspace 放宽的 policy，并在所有未接线入口执行前 fail closed。

## 当前实现方案

当前第三阶段 draft 增加 operator-only `tools.executionSandbox`，要求显式 `filesystem: read-only|workspace-write` 与 `network: open|closed`，backend 为 optional `auto|bwrap`。policy 只从 SystemDefaults、User、System 或可信 programmatic runtime 构造读取，完整对象按优先级替换；Workspace/project env、bare/safe mode、model arguments 和普通 include directories 不能放宽或关闭它。Linux 外、未知字段、损坏的 sandbox policy、backend 探针失败及与 legacy sandbox/network/proxy marker 混用都在执行前拒绝。

公开支持面是 ordinary headless、Ink/OpenTUI，以及 Shell、Read、Write、Edit、Monitor、prompt shell interpolation 与终端 `!` 等已接入 runtime boundary 的入口。footer、system info、status line 和 `qwen sandbox` 展示 requested/effective backend 与文件系统/网络策略。旧 `--sandbox bwrap`、`tools.sandbox:"bwrap"`、`QWEN_SANDBOX=bwrap` 和继承的 `SANDBOX=bwrap` 返回迁移错误；whole-CLI bwrap restart、root/state grant 与 re-entry helper 被删除，Docker/Podman/Seatbelt 保留。

未移植路径在 host side effect 前显式拒绝或禁用：ACP/serve、web terminal、MCP/LSP、extensions/hooks/discovery、自动 worktree/Arena、custom executors、技能 Git/usage 写入、speculative merge、IDE detection、Mermaid/image helper、restore/diff 等。设计明确隐藏模型工具声明并不足以构成安全；每个 direct adapter 也要 guard。后续 review fix 让 bare-mode 读取只在损坏文件实际声明 `executionSandbox` 时因该策略失败，并恢复 operator legacy sandbox 字段以防 workspace 合并清除冲突证据；最新提交又让 settings-cache 的 failure/recovery fixture 直接使用 malformed sandbox policy，与新的 fail-closed 语义对齐。#12269 已合入并成为该 PR 的 `main` 基线，但 exact-head Linux x64/aarch64 enforcement 仍留给后续 acceptance workflow，因此当前不能写成公开工具级 bwrap 已可用。

## 关键代码路径

- `packages/cli/src/config/execution-sandbox-settings.ts`：严格解析 operator policy、scope 选择、旧 selector 迁移与 unsupported surface guard。
- `packages/cli/src/config/execution-sandbox-config.ts`、`packages/core/src/sandbox/runtime-shell-policy.ts`：构造 immutable runtime policy，固定 canonical workspace/installation/state roots 并拒绝 legacy 环境。
- `packages/cli/src/config/config.ts`、`settings.ts`、`settingsSchema.ts`：把 policy 接入 Config、设置来源和 schema，阻止 workspace parent replacement 绕过。
- `packages/cli/src/commands/sandbox.ts`、`scripts/sandbox_command.js`：删除 whole-CLI bwrap hop，让 inspect/verify/command 复用工具执行边界。
- `packages/cli/src/services/prompt-processors/shellProcessor.ts`、`ui/hooks/shellCommandProcessor.ts`：把 prompt interpolation 和两套 TUI 的 `!` 路由到 runtime shell executor。
- `packages/cli/src/serve/fast-path.ts`、`run-qwen-serve.ts`、`acp-integration/acpAgent.ts`：在 listener、ACP child 或 payload 副作用前拒绝当前不支持的 execution sandbox。
- `packages/cli/src/ui/components/Footer.tsx`、`ui/opentui/opentui-footer.tsx`、`ui/systemInfo.ts`：展示 requested/effective backend 与 policy。

## 边界与风险

- 当前 PR 已直接基于包含 #12269 的 `main`，但自身三个提交仍未合入，公开设置、whole-CLI 删除和 fail-closed 扩面都只能作为当前方案观察。
- 新模式刻意缩小功能面；未列举或漏 guard 的 host-effect path 会直接破坏 sandbox 契约，因此完整入口清单和 exact-head Linux negative controls 是合入门槛。
- bwrap 提供 write 与 command-network confinement，不承诺 secret confidentiality、完整 host isolation、Landlock、Windows/macOS backend 或 web/daemon 支持。
