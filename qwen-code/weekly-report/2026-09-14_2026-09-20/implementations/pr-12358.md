## 解决了什么问题

Managed Agent 需要在 workspace Runtime 尚未就绪时持久受理请求并开始模型推理，在真正发生工具调用时再使用隔离 Tool Runtime；同时产品控制面要拥有 tenant/admission/public API/durable state，常驻 Harness 保持模型循环，WebShell 还要与既有 `qwen serve` legacy 会话并存。Java 重启后也不能只信任数据库中的旧 URL：端口、Pod 名称或 IP 可能已被其它物理 Runtime 复用。当前 preview 试图给出一条 Java、Harness、Runtime、浏览器与 durable recovery 的端到端拓扑。

## 当前实现方案

该 draft 汇总 154 个提交形成架构预览：独立 Spring Boot Managed Agent 服务承载 tenant-scoped API、Managed Session store、Hosted Harness connector、内嵌 Runtime Broker、event materialization 与 WebShell adapter；TypeScript `qwen serve --profile hosted-harness` 保留模型执行，并通过 managed runtime provider 把 workspace 工具交给 Tool Runtime。公开 API、Java/MySQL、Harness transcript 与 Broker 复用一个 RFC UUID Session ID，避免多套身份映射。

状态侧包含 Managed Session record/authority/checkpoint/approval restore、Java `AgentStateStore`、有界事件批次、同事务 sequence/terminal commit、提交后本机 SSE、Item/Snapshot 物化和 WebShell snapshot+tail 恢复。Runtime 侧现包含 JDBC binding/session/execution repository 与 Flyway V3、AES-GCM 加密 provision seed、版本化 resource handle、per-binding operation lease，以及 reconcile 后再走私有 `v2/attest` 的 gate；scheduler timeout/unknown 不会被当作 not-found，也不会自动重放结果不明的工具调用。

local-process provisioner 使用确定性 generation directory、PID 与 process-start identity，在同一 placement domain 可由新 JVM 接管原进程；Kubernetes adapter 以确定性 Pod/Secret、UID/resourceVersion、条件删除和 Pod IP observation 表达物理资源，冲突身份 fail closed。Spring 只在 DataSource、JDBC repositories 与 credential key 完整时启用 Broker，缺配置不会退回内存。当前 PR 仍是 broad architecture preview，不是可合入的 review unit；真实 Kubernetes 集群、RBAC/networking/service-account rotation、生产多节点 rollout、MQ/Redis fan-out、完整 preflight 与 Linux/Windows 运行尚未闭合，应从 `main` 拆成独立基础、接线、持久化与 E2E PR 再评审。
