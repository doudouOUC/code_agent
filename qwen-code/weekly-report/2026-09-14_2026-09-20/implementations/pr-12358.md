## 解决了什么问题

Managed Agent 需要在 workspace Runtime 尚未就绪时持久受理请求并开始模型推理，在真正发生工具调用时再使用隔离 Tool Runtime；同时产品控制面要拥有 tenant/admission/public API/durable state，常驻 Harness 保持模型循环，WebShell 还要与既有 `qwen serve` legacy 会话并存。现有分散原型缺少一条可运行的 Java、Harness、Runtime 与浏览器端到端拓扑。

## 当前实现方案

该 draft 汇总 148 个提交形成架构预览：独立 Spring Boot Managed Agent 服务承载 tenant-scoped API、Managed Session store、Hosted Harness connector、内嵌 Runtime Broker、event materialization 与 WebShell adapter；TypeScript `qwen serve --profile hosted-harness` 保留模型执行，并通过 managed runtime provider 把 workspace 工具交给 Tool Runtime。公开 API、Java/MySQL、Harness transcript 与 Broker 复用一个 RFC UUID Session ID，避免多套身份映射。

状态侧包含 Managed Session record/authority/checkpoint/approval restore、Java `AgentStateStore`、有界事件批次、同事务 sequence/terminal commit、提交后本机 SSE、Item/Snapshot 物化和 WebShell snapshot+tail 恢复。Runtime 侧同时包含 Java binding/session/execution repository、local process provisioner、HTTP transport 与 JDBC 预览。WebShell 提供 dual-path Managed 页面，legacy daemon 路径继续可用。

当前 PR 明确是 broad architecture preview，不是可合入的 review unit。精确 head 已包含 Runtime Broker JDBC repository、schema、H2 contract test 与 MySQL integration test，但生产 DataSource/migration 接线、durable reconcile、worker health replacement、多节点调度、Kubernetes、MQ/Redis fan-out、完整 preflight 与 Linux/Windows 运行仍未闭合。应从 `main` 拆成独立基础、接线、持久化与 E2E PR 再评审。

- `packages/sdk-java/managed-agent-server/`：Spring application、public/WebShell controllers、Harness coordinator、Managed store/event/materialization 与 Flyway schema。
