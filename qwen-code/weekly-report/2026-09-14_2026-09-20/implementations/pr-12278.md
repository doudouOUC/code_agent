## 解决了什么问题

工具级 bwrap 依赖 bubblewrap 二进制、user namespace 与 mount 能力；部分 Linux 主机无法满足这些前置条件。直接回退宿主执行会破坏 fail-closed 契约，而把整个 CLI 放回旧沙箱又会重新约束模型传输、认证与会话状态。需要一个只提供文件系统内核约束、并诚实暴露能力缺口的后端。

## 当前实现方案

当前 stacked draft 为 `tools.executionSandbox.backend` 增加 `landlock`。显式 `landlock` 在启动时探测随包静态 helper、Linux x64/arm64 与 Landlock ABI >= 3；`auto` 仍先探测 bwrap，只在 bwrap 不可用且 command network 为 `open` 时选择 Landlock。effective backend 只解析一次，不会把已经尝试的用户 payload 换后端或回放到 host。

Landlock helper 对宿主提供广泛只读访问，给私有 scratch 写权限，并仅在 `workspace-write` 时给 workspace 写权限。因为 Landlock 不提供 PID/network namespace，后端固定报告 `partial`；`network: closed` 在 payload 前拒绝。relay 使用独立 status FD 报告 prepared ABI 与 exec 结果，Core 只在 receipt 完整时标记 confirmed。构建脚本用固定 Zig 产物生成并校验 x64/arm64 helper，专用 workflow 覆盖拒绝、继承、receipt 与 bundle reproducibility。

## 关键代码路径

- `packages/core/src/sandbox/landlock-execution.ts`：helper 解析、ABI/policy probe、Landlock launch 与 open-network 限制。
- `packages/core/src/sandbox/landlock-status.ts`、`landlock-relay.ts`：有界 status wire、prepared/exec evidence 与 confirmed/unconfirmed 判定。
- `packages/core/src/sandbox/execute-sandbox.ts`、`sandbox-execution.ts`：在已解析 backend 上分派 bwrap/Landlock，共用 relay 生命周期且不重放 payload。

## 边界与风险

- Landlock 只提供部分 filesystem enforcement，不隔离 PID/network namespace，也不覆盖全部 metadata、Unix socket 或秘密读取面。
- `auto` 可能从 full bwrap 转为 partial Landlock；要求完整边界的操作者必须显式选择 bwrap，但公开 policy 本身仍依赖未合入的前置 PR。
