# PR #11781 最终实现：提高根构建 Node heap 上限

> PR: [fix(ci): raise the build heap cap from 3072 to 4096 MB](https://github.com/QwenLM/qwen-code/pull/11781)
> 状态：merged；2026-09-13 21:46 UTC合入，以下按head `49a6527372c5`及最新`main`描述最终实现。
> 规模：+1 / -1，1 个文件

## 解决了什么问题

全仓 `tsc --build` 的 Linux 实测 RSS 已约为3.14 GiB，接近根构建脚本的3072 MB Node old-space上限。在runner CPU争用、GC吞吐下降时，同一提交可能在部分build lane以`Ineffective mark-compacts near heap limit`和core dump退出，而在其它lane或重跑时成功；这种结果反映资源余量不足，而不是稳定的编译诊断。

## 最终实现方案

最终只修改根`package.json`的`build`脚本，将`NODE_OPTIONS="--max-old-space-size=3072"`提升为4096。所有调用`npm run build`的CI和本地构建入口共享新上限，但`test`、`test:ci:workspaces`与`test:release:workspaces`继续使用3072，因为该PR没有对应的测试进程OOM证据。

4096是V8 heap ceiling，不是启动时预留；正常构建不会因此固定占用4 GiB。该变更也不处理CLI类型面持续增长的根因，不改变应用运行时或发布产物行为。

## 关键代码路径

- `package.json:scripts.build`：为根构建进程设置4096 MB Node old-space上限。

## 验证方式

PR声明在干净Linux worktree用Node 22执行`npm ci`、`/usr/bin/time -v npm run build`并成功退出，旧main基线最大RSS为3,298,588 KiB；PR自身的Test、Lint & Static、Integration、Desktop Shell、WebShell smoke与Java SDK等构建lane成功。当前PR快照仍有一条自动review workflow失败，因此本文不把全部check概括为全绿。本次独立核对1文件diff、合并状态以及最新`main`中根`build`脚本为4096，未复跑十分钟构建或runner争用场景。

## feature 文档处理

该PR只调整仓库根构建CI的资源上限，不改变可发布产品能力、daemon资源预算或CLI运行时，因此未新增或修改长期feature文档。

## 边界与风险

- 极小内存机器上的构建进程现在可能继续增长并触发swap，而不是在约3 GiB heap处更早失败。
- 测试脚本仍为3072；若后续出现测试进程OOM，需要基于独立测量调整，不能由本PR推导。
- 提高上限缓解当前CI不稳定，但不替代拆分TypeScript project或控制类型图增长。
