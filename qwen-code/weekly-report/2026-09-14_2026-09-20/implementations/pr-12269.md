## 解决了什么问题

#12067 已合入结构化进程启动、可信 bwrap receipt 和受限文件 worker，但尚未把这些底座接到生产工具。若只接 Shell，Write/Edit、Monitor、派生 agent 或其它宿主副作用仍可能绕过；若在运行中临时决定策略，workspace 内容又可能扩大已准入边界。该 PR 需要建立一个由可信宿主一次性注入、运行期不可放宽的内部策略层。

## 当前实现方案

当前 PR 在 `ConfigParameters.shellExecutionSandbox` 上接收可信宿主策略，规范化 workspace、installation、state 与 mask，拒绝和保护目录重叠、工作目录越界、旧 whole-CLI bwrap 环境、非 Linux/探针失败，以及 SDK/ACP、MCP/LSP、extension、worktree executor 等未支持集成。准入后的 policy 冻结；派生 Config 必须保持同一 workspace ceiling。

Shell 和 Monitor 通过共享 runtime shell executor 进入 bwrap；Write/Edit 在读取阶段捕获 file version，发布时由受限 file worker 校验 expected version、目标类型与 namespace receipt，避免 host 侧直接写或陈旧目标替换。受限 registry 只保留已经接线的工具，speculation、外部 agent、自动 worktree、checkpoint 写入及其它 host-effect surface 在设置或执行前拒绝。当前没有公开设置、环境变量或 CLI 开关，用户不能直接启用。

## 关键代码路径

- `packages/core/src/sandbox/runtime-shell-policy.ts`：可信策略准入、canonical path、protected-root/mask 校验与 bwrap capability probe。
- `packages/core/src/sandbox/runtime-shell.ts`、`bwrap-execution.ts`：前后台命令通过共享结构化 launch 和 receipt 路径执行。
- `packages/core/src/sandbox/runtime-file.ts`、`file-worker-client.ts`：捕获 file version，并由 worker 执行受限写入与结果核验。
- `packages/core/src/config/config.ts`：冻结并传播 runtime policy，缩减受限工具 registry，阻断未接线 host effects。
- `packages/core/src/tools/shell.ts`、`monitor.ts`、`write-file.ts`、`edit.ts`：生产工具接入点。
- `scripts/sandbox-runtime/`：跟踪 production-path verifier、构建和 source-manifest 约束。

## 边界与风险

- 当前只有可信 programmatic host 能注入策略；没有公开配置或普通用户启用路径。
- 未支持 surface 采用 fail closed，会在启用内部策略时主动缩小功能面；遗漏的 host-effect 入口仍是主要审计风险。
- 广泛宿主读取、pathname Unix socket、secret confidentiality、Landlock、ACP/serve 与 exact-head Linux acceptance 不在本 PR 交付范围。
