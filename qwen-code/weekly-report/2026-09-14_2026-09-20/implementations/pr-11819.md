# PR #11819 最终实现：补齐 Qwen Triage verify 的 zip 依赖

> 规模：+5 / -1，1 个文件

## 解决了什么问题

Qwen Triage的`verify` job在`node:22-bookworm`容器中运行单测。镜像自带`unzip`但没有`zip`，而`install-script.test.js`在POSIX CI主机缺少任一archive工具时会于collection阶段主动抛错，防止安全用例被静默skip。verify lane此前只安装`util-linux`，于是每轮都可能把这个基础环境缺口报告成与被测PR无关的`consistent-fail`。

## 最终实现方案

最终只在`.github/workflows/qwen-triage.yml`的`Install verify runner tools`步骤中，将apt包列表从`util-linux`扩为`util-linux zip`。注释同时写明依赖关系：基础镜像已有`unzip`，补`zip`后archive suite可正常收集和执行。

主Qwen Code CI的test job原本已经安装zip，因此无需修改；兄弟`tmux-testing` job不运行该archive套件，也不扩大安装范围。变更发生在checkout之前，继续避免PR控制的`.npmrc`影响runner工具安装。

## 关键代码路径

- `.github/workflows/qwen-triage.yml:jobs.verify`：在受信任的verify runner初始化阶段安装`util-linux zip`，再进入checkout和测试。
- `scripts/tests/install-script.test.js`：既有CI-host archive工具守卫是本修复所满足的契约，文件本身未修改。

## 验证方式

PR声明Qwen Triage workflow相关Vitest为181项通过、10项跳过，并用`yaml.safe_load`确认workflow语法；本地未触发真实self-hosted verify run。GitHub快照中主要Qwen Code CI lane成功，另有一条自动review job取消。本次独立核对1文件diff和最新`main`中verify步骤已安装`zip`，未启动`node:22-bookworm`容器或重跑workflow测试。

## 边界与风险

- 真实self-hosted verify lane未在PR作者本地触发；最终运行仍依赖apt源和runner网络。
- 该改动只消除缺少`zip`导致的collection hard-fail，不会掩盖archive测试自身的真实失败。
- `tmux-testing`未安装zip，因为它当前不运行相关套件；若职责变化需同步重新评估。
