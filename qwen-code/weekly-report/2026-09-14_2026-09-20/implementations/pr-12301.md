## 解决了什么问题

Managed Agent 控制面在并发 provision、复用、排空和替换 Tool Runtime 前，需要一个稳定的多租户状态契约。若 binding/session identity、乐观版本和操作租约没有先固定，不同 Java 实例可能重复创建 generation、跨 tenant 复用、让过期 owner 修改状态，或把逻辑 Session 绑定到错误 Runtime。

## 当前实现方案

该 PR 新增独立 Java 21 `runtime-broker` 模块，定义 `RuntimeScope`、完整 `RuntimeProvisionRequest`、物理 `RuntimeBindingRecord`、逻辑 `RuntimeSessionRecord` 与 Repository 接口。Binding 具有单调 generation/version、PROVISIONING/READY/DRAINING/FAILED/RELEASED 状态、operation owner/lease/generation 和 health/activity 字段；终态后才能为同一完整 request 建新 generation。

线程安全内存实现用原子 `findOrCreate`、CAS 和可过期 operation claim 约束写入。Session lookup 必须携带权威 scope，同 scope 冲突、跨 scope replacement、重复生成 binding ID、过期 lease 或 stale version 都拒绝；当前 owner 续租不改变 operation generation。该模块不依赖 Spring、HTTP、CLI 或真实 provisioner，也不提供生产持久化 adapter。

## 关键代码路径

- `packages/sdk-java/runtime-broker/src/main/java/.../RuntimeScope.java`、`RuntimeProvisionRequest.java`：多租户 placement 与完整 provision identity。
- `RuntimeBindingRecord.java`、`RuntimeBindingRepository.java`：物理 generation、状态、版本和 operation lease 契约。
- `RuntimeSessionRecord.java`、`RuntimeSessionRepository.java`：scope-qualified 逻辑 Session 绑定与活跃计数。
- `InMemoryRuntimeBindingRepository.java`、`InMemoryRuntimeSessionRepository.java`：线程安全原子参考实现。
- `InMemoryRepositoryTest.java`：并发创建、generation、CAS、租约接管、tenant/scope 隔离与 Session identity 回归。
- `.github/workflows/sdk-java.yml`、`scripts/tests/sdk-java-workflow.test.js`：仅在 Java 21 matrix 运行新模块，保留现有 SDK Java 11 target。

## 边界与风险

- 当前只有内存 Repository；接口原子性、scope 与 lease fencing 必须由后续 JDBC/生产 adapter 保持。
- 不包含 HTTP、Spring、MySQL、真实 Runtime、Harness、工具执行或 restart recovery。
- 新模块要求 Java 21；现有 Java SDK 的 Java 11 兼容目标未改变。
