## 解决了什么问题

Managed Agent 后续需要恢复模型尝试、审批、工具执行、checkpoint、压缩和生命周期状态；如果 writer、projection 与 Harness 各自先发明记录格式，会形成多个事实源。还需要提前把私有日志 subtype 注册为合法 transcript artifact，避免它们被当成普通对话或触发未知记录导致历史不完整。

## 当前实现方案

该 PR 只交付 v1 wire contract 与验证器：header、event、commit marker 三个 subtype，固定 format/minimum reader、Session key、actor、subject、30 个 domain、event kind、lifecycle/action state、durable ref、transaction range 和 SHA-256 digest。原始 JSON parser 在 `JSON.parse` 前检测重复 key，typed parser 拒绝未知字段、非 JSON 值、控制字符、非法 actor/subject、生命周期跃迁、非连续 transaction、深度/事件/事务字节超限及不兼容版本。

三个 subtype 被加入 transcript 运行时白名单和非对话投影集合，因此可以保留在 transcript 中而不进入普通消息链。Core index 导出 contract，但没有 writer、route、feature flag、Harness、Runtime、迁移或恢复消费者；生产端仍必须自行绑定端到端原始记录 byte cap 并保证解析结果不可变所有权。

## 关键代码路径

- `packages/core/src/managed-runtime/managed-session-records.ts`：v1 types、closed enums、limits、strict parser、actor/state/transaction/digest validation。
- `packages/core/src/managed-runtime/managed-session-records.test.ts`：unknown/malformed/duplicate-key、边界值、actor/transition、transaction 与固定 digest fixture。
- `packages/core/src/utils/transcript-records.ts`、对应测试：登记三种 reserved subtype，并从 ordinary conversation projection 排除。
- `packages/core/src/services/chatRecordingService.ts`：扩展系统记录 subtype 联合类型。
- `packages/core/src/index.ts`：公开导出 contract。

## 边界与风险

- 采用 v1 后不兼容语义必须升版本，不能静默改变 parser 接受范围。
- clone/freeze、端到端原始字节上限、checkpoint/Harness/Runtime 协调和已有 Session 迁移仍未实现。
