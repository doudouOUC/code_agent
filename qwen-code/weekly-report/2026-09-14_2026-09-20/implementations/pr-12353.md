## 解决了什么问题

#11911/#11940/#12008 已把 modeled child count 接入准入与恢复，#12265 也合入固定堆校准证据，但 `observe`/`admit` 仍让 child 使用旧的 host-derived heap 参数。旧 raise-only 逻辑不能应用较小 ceiling，导致 status 中的 fixed partition 与真实 V8 old-space 授权不一致，无法做受控 enforcement 验证。

## 当前实现方案

该 PR 增加显式 `qwen serve --child-heap-mode enforce`。daemon 启动时从同一 memory budget 解析固定 `perChildCeilingMb` 和 `maxConcurrentChildren`；主 workspace、启动次级 workspace 与动态 workspace 共用同一 count admission。每个受管理 ACP child 都通过解析后的私有 env/execArgv 启动：删除继承的 fixed `--max-old-space-size`，拒绝 percentage 参数冲突，保留其它 `NODE_OPTIONS`，再附加唯一的 fixed ceiling 与 `--expose-gc`。

`limits.memory.enforced` 只有在 count admission 和受管理 child heap wiring 都存在、mode 为 `enforce` 时为 true。默认仍是 `observe`；`off`、`observe`、`admit` 保持旧 heap 行为。零可建模 child、未支持的注入 bridge 或参数冲突在 spawn 前失败；workspace 注册仍不等于 child 名额，既有零 Session reclaim 和 loaded runtime stop 语义保持。

## 边界与风险

- ceiling 约束 V8 old space，不约束总 RSS、native allocation、MCP descendant 或宿主整体内存。
- 小 ceiling 会改变 GC/OOM 行为；当前证据不足以确定生产默认值，且没有自动 fallback 或 live resize。
- 默认行为不变；回滚需重启并改回 `admit`，仍保留 count admission。
