## 解决了什么问题

工具级 bwrap 不能继续用 shell 字符串重建 executable/argv/env，也不能把 payload stdout 或初始 PID 当作已成功进入约束的证据。它还需要复用现有 pipe/PTY 生命周期、传递 binary stdin、在不安全的 setup/PTY 失败后禁止重放，并让文件写入在同一 kernel boundary 内完成。

## 当前实现方案

当前第一拆分在 `ShellExecutionService` 增加内部 structured launch：绝对 executable/cwd、字面量 argv、精确且预先 snapshot 的 env、可选 string/Buffer stdin。pipe 在发送 stdin 后关闭，并在 stdio closure 或 child exit 后最多 1 秒 drain 中先到者结算，避免持有继承 pipe 的 grandchild 永久阻塞；PTY 要求显式 TERM/PWD。只有尚未创建进程时才允许 PTY fallback，spawn 后异常会终止已创建进程，不通过 pipe 重放 payload。stdin `EPIPE` 只有在没有任何 exit 信息时才作为 execution error，已有退出状态仍优先。

bwrap adapter 通过独立 relay 启动 namespace，使用 payload 不继承的 status FD 与受保护 0600 control file记录最终 receipt。`confirmed`、`unconfirmed`、`interrupted`、`running` 状态与 payload output 分离；缺失/损坏 receipt 不证明 payload 未运行，也不授权 retry。证据保留按 `payloadExitObserved` 三态决定：明确 pre-exec 失败可清理，post-exec 或未知结果保留；不能从缺失字段反推“未执行”。relay 监视 parent，后台 promotion 保留 scratch/control 至 settlement，结束后清理 owned descendants，并在 scratch root admission 阶段拒绝受保护路径重叠。

binary file worker 使用“最多 16 KiB、换行终止的 JSON header + 精确 binary content length” framing，在 bwrap 内执行现有 atomic write；短包、长包和额外尾部字节均拒绝。客户端传入观察到的 file version，worker 在提交前复核并拒绝 stale、outside/symlink/special-file 目标；host client 同时校验 trusted sandbox status、结构化 worker reply 与独立 diagnostics。bundle/package 增加 relay 与 worker 两份资源，缺失资源在执行前失败。该层不公开设置、不路由现有工具，旧 whole-CLI backend 仍保留。

## 边界与风险

- receipt 只在最终退出确认，不提供 realtime exec-ready；post-exec 或不可判定 crash 可能保留 control/scratch 目录，本层无 GC。
- file version check 不是对所有并发 writer 的原子 CAS，binary input 也在内存中缓冲。
- 不覆盖 runtime policy、tool routing、公开设置、Linux x64、Windows、Landlock 或 Bun standalone。
