## 解决了什么问题

MCP 工具调用本身成功时，其 App UI resource 仍可能因为 MIME/URI 不匹配、空内容、超过 1 MiB、读取超时或 transport 错误而无法显示。既有实现只把原因写入 debug log，并退回普通工具文本；用户会看到成功数据却不知道 iframe 为什么缺失，WebShell 也无法区分普通 compact fallback 与 App 加载失败。

## 当前实现方案

当前 diff 保持工具调用结果、`llmContent` 和成功状态不变，只把可选 App resource 的失败转换为 `McpAppResultDisplay`：`html` 为空，`fallbackText` 先写明 server、resource URI 和失败原因，再拼接原工具文本。WebShell 沿用既有空 HTML fallback 展示文本而不挂载 iframe，因此 TUI/WebShell 都能看到诊断，而模型输入不会新增警告或 App HTML。

资源限制仍是 1 MiB 和最多 10 秒。实现按 UTF-8 字节计算大小并报告实际值与上限；读取 timeout 使用 `min(mcpTimeout, 10000)`，提示中写出生效毫秒数。invalid metadata、空 HTML 和普通读取异常使用实际错误文本。若 caller signal 已 abort，则只保留原工具结果，不制造 App 失败警告，避免把用户取消误报为资源故障。

## 关键代码路径

- `packages/core/src/tools/mcp-tool.ts:loadAppResource`：计算资源 deadline/UTF-8 字节数，将非 caller-cancel 失败转换为带空 HTML 的可见 fallback。
- `packages/core/src/tools/mcp-tool.test.ts`：覆盖 MIME/URI/空内容、1 MiB 边界、text/blob、短/长 timeout、读取失败与 caller cancellation。
- `packages/web-shell/client/components/messages/ToolGroup.test.tsx`：验证 compact 与加载失败 fallback 均显示文本且不创建 iframe。
