## 解决了什么问题

MCP 工具调用本身成功时，其 App UI resource 仍可能因为 MIME/URI 不匹配、空内容、超过 1 MiB、读取超时或 transport 错误而无法显示。既有实现只把原因写入 debug log，并退回普通工具文本；用户会看到成功数据却不知道 iframe 为什么缺失，WebShell 也无法区分普通 compact fallback 与 App 加载失败。

## 最终实现方案

最终实现保持工具调用结果、`llmContent` 和成功状态不变，只把可选 App resource 的失败转换为 `McpAppResultDisplay`：`html` 为空，`fallbackText` 先写明 server、resource URI 和失败原因，再拼接原工具文本。WebShell 沿用既有空 HTML fallback 展示文本而不挂载 iframe，因此 TUI/WebShell 都能看到诊断，而模型输入不会新增警告或 App HTML。

资源限制仍是 1 MiB 和最多 10 秒。实现按 UTF-8 字节计算大小并报告实际值与上限；读取 timeout 使用 `min(mcpTimeout, 10000)`，提示中写出生效毫秒数。最终 review 修正了归因：SDK 自身的 `SdkError(REQUEST_TIMEOUT)` 和 host deadline 才标记生效上限，server 返回的 JSON-RPC `-32001` 保留原错误；URI 缺失也与 MIME 错误分开报告。若 caller signal 已 abort，则只保留原工具结果，不制造 App 失败警告。

- `packages/core/src/tools/mcp-tool.test.ts`：覆盖 MIME/URI/空内容、1 MiB 边界、text/blob、host/SDK/server timeout 归因、读取失败与 caller cancellation。
