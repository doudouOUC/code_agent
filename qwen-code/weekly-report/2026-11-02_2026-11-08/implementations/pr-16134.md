## 解决了什么问题

拆分后通用 Failsafe 声明进入默认 build，会使普通验证激活原本需专用 profile/环境的集成测试。默认门禁和真实 Runtime 资格不能靠选择器漂移混在一起。

## 最终实现方案

verification POM 将共享 Failsafe 版本和 managed.module.root/qwen.cli.entry 系统属性移到 pluginManagement，移除默认 build 的 Failsafe 声明；原 specialist profiles 仍显式声明插件，复用同一配置。没有删除测试、改变各 profile 选择器或 artifact-packaging 执行，也不把专用门禁改成默认通过。

0.26.5 的原 SOURCE_SHA 围栏延续 #16114，工作流同时校验 Javadoc 和 verification 两个补丁摘要，要求干净 tracked checkout，并对两份补丁共同 check 后再共同 apply。summary 分别记录 blob；元测试验证修复后 profiles 段与原输入完全一致、默认 build 无 Failsafe、打包配置不变，任一补丁被改、源不符或 checkout 脏均在应用前拒绝。
