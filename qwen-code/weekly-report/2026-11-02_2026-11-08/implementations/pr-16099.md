# PR #16099 最终实现：修复模块拆分后的 Javadoc 解析

> 状态：merged；最终 head `98e140135439`，merge `95e647754fcb`，对照 main `45cde869985a`。
> 规模：+2 / -1，2 个文件

## 解决了什么问题

模块拆分后，External Runtime 的文档类型引用缺 import，数值规范注释又把小于号当 HTML，Javadoc 构建会失败。跳过 doclint 会隐藏文档错误，而不是修复发行输入。

## 最终实现方案

ExternalRuntimeProvisioner 补 ExternalRuntimeKinds import，让文档类型解析到 contracts 的正确类型；ManagedEventEnvelopes 将数值范围中的小于号转义为 `&lt;`。jsNumberToString 的算法、阈值和跨语言 digest 字节未修改，Runtime 准入和执行也不改变。后续 #16114 将这两个改动以固定补丁带到原 v0.26.5 产品提交；#16134 再加入 profile 修复，两项另行归因。

## 关键代码路径

- `packages/managed-agent-server/runtime-external/src/main/java/com/alibaba/qwen/code/runtimebroker/provisioning/external/ExternalRuntimeProvisioner.java`：补文档类型 import；由后续 #16141 从原 adapters/provisioning 移到此处，历史发行补丁仍用原目录。
- `packages/managed-agent-server/contracts/src/main/java/com/alibaba/qwen/code/managedagent/contracts/event/ManagedEventEnvelopes.java`：仅修复 Javadoc 数值范围转义。

## 验证方式

本次核对两个最终 patch 和 main，没有执行 Maven/Javadoc 或发行。JDK 21、匹配 SDK 和隔离仓库就绪后，在当前 `packages/managed-agent-server` 用 `mvn -pl contracts,runtime-external -am -DskipTests package javadoc:javadoc` 先构建所选 reactor 再检查文档解析；这是编译/文档生成检查，不是完整 verify 或发行验收，不能据此声称 0.26.5 已发布。原发行源的模块选择不能照搬最新 main。
