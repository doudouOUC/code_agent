## 解决了什么问题

审批变更在已存在的 REPEATABLE READ 快照中普通读 approval_revision、rules 或 plan，会基于旧状态错误提交/发事件；仅先查缺失 receipt 还会给不同 Session 引入索引 gap 竞争。

## 最终实现方案

保持 Session/actor/能力和 expectedRevision 围栏，在同事务先尝试插入最终 receipt，唯一键冲突后用当前锁定读验证 replay 语义并返回原结果。新请求以 FOR UPDATE 一次读当前 approval_revision、permission_rules_json、is_plan_enabled，未显式提供的 rules/plan 取此行；UPDATE 带 revision CAS 且受影响行必须为 1，否则 approval_selection_conflict 回滚 receipt/事件。不是插入后提前独立提交；最终 receipt、选择与公共事件仍同事务。
