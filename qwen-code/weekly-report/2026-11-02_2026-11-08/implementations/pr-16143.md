# PR #16143 最终实现：统一共享 MySQL 基线约定

> PR: [refactor(managed-agent): align shared MySQL schema conventions](https://github.com/QwenLM/qwen-code/pull/16143)
> 状态：merged；最终 head `04a5cad11bdf`，merge `b1cd4ac0c615`，对照 main `45cde869985a`。
> 规模：+2472 / -1765，150 个文件

## 解决了什么问题

共享基线的主键、标志字段、索引命名和列约定不统一，规范化若只改 DDL 而漏 SQL、目录校验或 CSI inventory，会导致读错列、拒绝有效库或错误接受不匹配 catalog。表数/schemaVersion 相同不表示新旧 writer 可混用。

## 最终实现方案

仍原地修改唯一 V1，38 业务表增加数据库生成的 id BIGINT UNSIGNED AUTO_INCREMENT 主键，原业务键保 UNIQUE，业务代码仍按原 tenant/scope/identity 查写，不以新 id 代替协议身份。布尔列统一 is_ 前缀和 TINYINT UNSIGNED/0–1 CHECK，整数、摘要及 gmt 时间列按目标约定声明，表/列增加注释、文本表使用 utf8mb4_bin；普通/唯一索引命名归 idx_/uk_。物理 ID 不是 journal sequence 或恢复 locator。

最终实现同时移除数据库外键，保业务唯一性与应用层资源/owner 逻辑，并将“外键必须不存在”纳入 catalog 检查；不能再把数据库 FK 当作原资源引用完整性保证。ManagedSchemaCatalog 校验自增、整数 signedness 和 MySQL/MariaDB 索引前缀；缺失自增或多余 FK 拒绝，不 repair。DDL 前还要求 global/session sql_mode 都含精确 STRICT_TRANS_TABLES 或 STRICT_ALL_TABLES，避免无严格模式时非法值被截断接纳；MariaDB CHECK 开关要求仍保留。Rows/Projection、各 JDBC 查询更新列名，新增 is_paused/is_plan_enabled/is_wake_pending/is_wake_scan_pending 等布尔映射；CSI application inventory 同步逻辑列声明和检查，避免新旧列形状混用。

新增/更新测试覆盖所有表 id 生成、业务重复拒绝、非法 boolean、移除 identity/添加 FK 后拒绝，以及投影/目录/inventory。最终补齐严格 SQL 模式拒绝、数字 boolean 映射和新自增列 fixture 的复制/隔离处理，不能把旧候选的 129 文件规模沿用到最终 150 文件。尚无本次真实 MySQL 运行证据；没有 V2、旧库 ALTER 升级或兼容视图，开发 catalog 仍需重建。此前 #16153 的模型密文列和后续 #16205 的存储计数独立归因，不因仍 38 表就保证旧 writer 兼容。

最新 main 演进：#16288 已替代本 PR 合入时的 GLOBAL+SESSION 要求。内嵌 Druid 每个新 MySQL/MariaDB 物理连接追加 STRICT_TRANS_TABLES，DDL 前只核当前 SESSION；不读取或修改 GLOBAL。外部 DataSource 仍需自行保证所有应用连接严格，其他 V1/38 表、generated id、无 FK 和 catalog 拒绝规则保留。

2026-11-06 最新 main 复核：#16369 在唯一 V1 中将 is_execution_exclusive 改为 is_rewind_pending，并删除 exclusive_member_key；仍 38 表，旧 catalog 不兼容，需重建。

## 边界与风险

- 已合入；物理主键、列名和 FK 约定变化需要全部 writer/工具同步，不只是 DDL 格式调整。
- 唯一 V1/相同表数不是升级或回滚兼容保证；旧 catalog、旧 Java/Broker writer 与新基线不能据此混跑。
