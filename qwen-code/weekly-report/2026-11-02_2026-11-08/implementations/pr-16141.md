# PR #16141 最终实现：按 classpath 选择可选 Runtime 后端模块

> 规模：+3416 / -603，155 个文件

## 解决了什么问题

嵌入普通 control-plane library 时，不应因 server 对所有实现的编译依赖而强制携带每种 Runtime 客户端；classpath 已安装、配置选择、Workspace 注册和实际创建又是不同状态，不能通过自动回退掩盖缺后端。

## 最终实现方案

在六生产模块基础上增加 runtime-http/runtime-host 两个共享模块，以及 local/external/kubernetes/ssh/static 五种 provider 模块，共十三生产模块；verification 仍独立。contracts 放 RuntimeProviderFactory/Dependencies、选择与 SSH/Kubernetes 支持端口；server 通过 ServiceLoader 登记 factory，发现/kinds 不应创建资源，拒绝重复或保留的 kubernetes kind，选中未安装的 provider 明确报错，不回退 local。

server 对五种 provider 使用 runtime/optional 依赖：普通 Maven 消费者需显式加需要的 provider，完整 exec 仍携带它们；这不是构建时删除后端。Registry 先 validate 再 create，返回 kind 不符则关闭并拒绝。Factory 自管具体配置、preflight、原 provisioner/transport 装配与离线维护入口；共享 Dependencies 缺失所需持久端口时 fail closed，不伪造外部存储或 CSI authority。

RuntimeBackendSelection 先看 broker enabled：关闭时不解释未启用配置；ssh-process 必须有 nodes，local-process+nodes 选择 local/SSH 混合，其余 primary 与 nodes 组合拒绝。SSH 注册开关不是是否选 SSH 的依据。server 只为选中 SSH 创建共享连接并由 Spring close；EmbeddedRuntimeBroker 构造失败清理已创建 provider，原正常资源所有权不移交 discovery。维护 factory 契约禁止 acquire/启动 worker，具体离线实现仍核原身份。external-workspace 仍是前置存储准入，不能因模块可安装就宣称 files/Shell/close 已有资格；E2B 不在本项新增范围。

## 边界与风险

- 已合入；反射及直接引用实现类型的消费者需迁移到新包/JAR/SPI，不能仍用旧 adapters 路径作为当前锚点。
- 不扩大 provider 原恢复/stop/执行权限；缺包拒绝、离线维护不启动和真实云资格都需独立证据。
