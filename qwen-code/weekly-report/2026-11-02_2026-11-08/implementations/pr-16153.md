> 规模：+2406 / -96，70 个文件

## 解决了什么问题

只按宿主模型目录选择 modelId，无法为单个 Session 固定协议、端点、密钥和采样参数；冷恢复若再次解析同名宿主配置，可能切换连接或使用错误凭证。直接把配置放进 journal/定义快照又会扩大秘密暴露范围。

## 最终实现方案

Public/WebShell 创建接收 model_config/modelConfig，Workspace 创建不能同时指定 modelId 与完整配置。SessionModelConfig 严格限制五个字段和四种协议（openai、openai-responses、anthropic、gemini），拒未知字段、控制字符、非 HTTP(S) 或含用户信息/query/fragment 的 URL；采样参数按各自范围/整数约束校验，canonical 配置最多 8192 UTF-8 字节。新准入要求启用 Session Store、可用 SecretProtector、精确 base URL allowlist 和 session-model-config/1 能力。

创建幂等语义只纳入摘要，原 receipt 回读先于可变能力/端点策略检查；同事务保存 Session 与加密配置，密文绑定 tenant/session 的加密上下文。读取必须核 expectedDigest、解密并重新计算摘要；缺记录、密钥或摘要不匹配 fail closed。子 Session 从原配置读取并在子身份下重新加密，不复制父密文作为新身份。配置 Session 不再宣传目录模型切换。

Harness create/load 和 managed-definition 只传/保存 modelConfigDigest；resident、冷恢复和快照恢复核同一摘要。实际连接由私有 model-config:query 按当前 tenant、Workspace、writer token/generation，以及普通或原 lifecycle authority 授权后读取，响应 no-store；HTTP reader 限 16 KiB，坏响应不回退宿主配置。legacy-close 仍走专门授权，不授权任意脱离原 Session 的秘密读取。

文本、workflow agent、压缩和模型 Hook 使用该连接；Config 清除同名 provider、环境连接和辅助模型/fallback 路由干扰，Gemini 显式关闭宿主 Vertex 模式，seed 进入原生成参数。Java SDK create/load 保留摘要和能力协商，load 的生命周期/副本转换不丢字段；生成 WebShell 类型不表示已有完整配置编辑 UI，也不表示 Python/TypeScript 公共 SDK 都有同等封装。

## 边界与风险

- V1 新增加密配置列并同步 CSI inventory，不提供旧 catalog 升级；有私有模型配置的 CSI 活动不能仅因表形状匹配就获准恢复。
- allowlist 与加密密钥是运行前提；撤回能力不允许新执行回退宿主配置，已提交 receipt 回读不等于重新获得执行资格。
- 本次未运行 Java/Node、CI、MySQL、实际模型或平台验收；未证明秘密轮换/旧 writer 混跑或所有协议参数均被远端接受。
