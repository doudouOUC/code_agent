# PR #16410 最终实现：native journal 快照写者不再争普通租户 guard

> PR: [perf(managed-agent): take native journal snapshots off the tenant guards](https://github.com/QwenLM/qwen-code/pull/16410)
> 状态：merged；最终 head `087eeeab6da1`，merge `c4f9899eeaaf`，对照 main `e5eb6a177560`。
> 规模：+168 / -2，4 个文件

## 解决了什么问题

每次 native journal snapshot 的多次 writer 检查都先争 placement 与 publication tenant guard，导致同租户不相干的绑定、回收和快照互相排队。简单把 build 事务首锁改成 root 又会堵住嵌套读取 lease。

## 最终实现方案

JournalWriterLifecycle.lockSnapshotWriter 复用 lockPublicationWriter 的 placement=false/publicationGuard=false 分支，普通 native snapshot 不再先取两类 tenant guard；原 credential、writer generation、ordinary admission 与 expected journal revision/sequence/digest 的比对保留。build 事务到达 Session root 前只持本次新建快照行，资源复制仍由读 lease 保护，root/head 串行 writer 检查。不能据此将整个 build 改成 root-first 长事务；已 pin 的 CSI continuation 仍取其专用 guard/身份围栏，不取消快照引用或回收保护。

2026-11-08 最新 main 复核：main 的 snapshot claim 先 FOR UPDATE 等待原 manifest 行，只有缺行才 upsert，build 只重试 deadlock victim，不重试 lock-wait timeout；这与本 PR 普通 writer 去 guard 是不同层，原资源/读 lease 仍保留。

## 关键代码路径

- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/JournalWriterLifecycle.java`：lockSnapshotWriter 的 guard-free 调用及原 head 比对。
