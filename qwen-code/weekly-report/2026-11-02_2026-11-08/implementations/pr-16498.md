## 解决了什么问题

已有 activity 证据不能准确测量实际执行耗时和原生文件增删行，journal 时间差包含等待，输出失败还可能掩盖已成功的文件副作用。

## 当前实现方案

当前 open diff 已重接最新 main，在 /internal/managed-runtime/v4/ execute/status/cancel/acknowledge 封装原 v2/v3，冻结原结果、managed-tool-measurements/1 和 canonical digest，再由 Broker 原 CAS 持久化后 ACK；不降级重跑已不明 v4 执行。执行单调时钟、原生 read/write/edit 模型提议与实际应用行数有界可空，Hook/审批改参使提议来源非 original 时不伪称有效模型行数。tool.measured 绑定原 outcome/execution/invocation，沿现有 activity reducer 原子合并，先于模型交付，幂等重放不重复计数；不新增 collector/domain/表。source event 推 storage floor/HTTP reader 5 与 managed-session/3，开关 QWEN_MANAGED_AGENT_RUNTIME_TOOL_MEASUREMENTS 默认 false，需新 attested ordinary capability；CSI /1–3 不扩执行方测量。#16475 已关闭、#16499 仍仅旧功能分支 merged；本项现复用已合入的 #16642 活动切片，目标 main，但 Tool v4/floor 5 仍未合入，不是 main 能力。
