## 解决了什么问题

RuntimeBrokerService 同时承担 Session、工具、绑定 provision/reconcile/recovery，类体过大，原失败与续租控制难以维护。

## 最终实现方案

新增同包 RuntimeBindingProvisioning，搬入 ensureBinding、durable provision/attest、bounded reconcile、lost cleanup 与受信任 maintenance recovery。RuntimeBrokerService 保公开入口、构造接线和 operation claim 的 BindingRenewal，协作者接原 repositories/registry/provisioner/transport/clock/scheduler/closed，不新建第二个运行时 owner。原 seed/lease/generation、deadline、failure handler 和停止证据保留；部分续租内类改包内可见以供该协作者使用，不改 wire/数据库。main 后续 size-ratchet 同步不等于新行为。

## 关键代码路径

- `packages/managed-agent-server/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/service/RuntimeBindingProvisioning.java`：绑定 provision/reconcile/recover 与 bounded cleanup。
- `packages/managed-agent-server/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/service/RuntimeBrokerService.java`：保 facade 和 BindingRenewal 接线。
