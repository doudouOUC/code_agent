# PR #16090 最终实现：保留事务入口的 Agent 与 Session Store 分片

> PR: [refactor(managed-agent): split Agent and Session stores](https://github.com/QwenLM/qwen-code/pull/16090)

> 规模：+14742 / -10773，86 个文件

## 解决了什么问题

两个大型 Store 同时承载准入、生命周期、事件、投影及 journal 资源逻辑，依赖和锁序难以局部核验。直接把公开入口、事务注解或调用者一起搬走，会改变 Spring 代理、同事务写入及恢复授权的边界。

## 最终实现方案

ManagedAgentStore 保留 AgentStateStore 和原公开入口/事务属性，构造十个包内 final 协作者：Rows、EventJournal、SessionQueries、MessageProjection、SessionPolicies、SessionCommands、LifecycleOperations、SessionAdmissions、TurnExecution、ExecutionOperations。SQL 和业务流程进入对应分片，依赖为 final、无 Spring stereotype、无新事务代理，也不反向持有 facade；入口仍先经过原事务代理，再在同线程调用普通对象。

ManagedSessionStore 同样保留 repository/事务入口，构造八个 Journal 分片，分别处理 Rows、Fencing、HistoryQueries、LifecycleAuthorization、ResourceReads、ResourceWrites、WriterLifecycle 和 Commit。commit 继续先核 credential/lifecycle/placement 与原 CSI 身份，原 command replay 仍校验原请求，资源/派生记录、journal 事务行和 head 更新仍处同一事务；MQ 通知仍在 afterCommit，重放不再通知。owner/native 读取的独立 TransactionTemplate、读 lease、原身份重验不改为长事务包住外部 I/O。

Session Store 将后置配置改为完整构造依赖；生命周期 execution/sessions 必须成对，否则都禁用。CSI binding 只接受与当前 JdbcTemplate 同 DataSource 的原 JdbcRuntimeBindingRepository，不能用非 JDBC/别库对象证明身份。standalone 简便构造保留其有限默认值，维护入口和 fixture 改传构造参数，不以反射注入生产依赖。Agent 的 required/nullable/lazy 回指约束延续原装配。后续 #16142 已清理分片默认重载与 ItemRow 中转，不倒算为本项新增。

最新 main 演进：#16256/#16268 继续保原 facade 事务，但普通 journal/inline 发布已改按 Session root 排队、storage alias/owner 共享准入；#16275 的 cleanup lane 仍先有界 placement 锁。不能把拆分时保留的锁集合当成所有当前入口仍持 tenant guard。

2026-11-06 最新 main 复核：#16335/#16354/#16370 又分别拆去普通 publication CAS、placement 与物理 storage 检查行锁；root/head/资源原子性和 cleanup 例外保留。

## 边界与风险

- 同 JVM、同 persistence 模块内拆分，不新增表、wire、服务或历史能力；main 仍为唯一 V1/38 业务表。
- 删除 Session Store 后置 setter/configure 需要手工构造消费者迁移；standalone 不等同真实 Spring/CSI 配置。
- 后续已合入 #16139 的运行时锁契约、#16143 的新 schema 与 #16153 的模型配置/新创建方法均独立归因；不再将本项入口清单当作 main 不变的 API 全集。
