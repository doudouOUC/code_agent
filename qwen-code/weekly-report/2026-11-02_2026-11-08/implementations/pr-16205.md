# PR #16205 最终实现：以存储成员 CAS 移除 Workspace 执行的租户锁竞争

> 规模：+1469 / -123，17 个文件

## 解决了什么问题

共享 Workspace 的执行成员准入/回收原先争用 tenant placement guard，并用范围扫描判定占用；不相关目录也可能互相等待。去锁若未同步维护、rewind 和 Broker 清理，会让物理操作绕过仍存活的执行成员。

## 最终实现方案

LOCAL/SSH_LOCAL 共享执行先只读取得原物理 storage key、READY mount revision 并做 mount 验证，再在短事务重验 alias、migration admission、binding generation/READY/drain 及原 Runtime Session/Harness 身份。MySQL binding 用 FOR SHARE，H2 因无该语法用更严格的 FOR UPDATE；只点锁自己的 Runtime Session，不拿 tenant guard 或成员范围锁。存储 owner 的 member_count 以 mount revision/无 holder、maintenance、exclusive 条件 CAS 加一，与 Session 的 execution_storage_key 一次提交；已有原成员重放不重复计数。

rewind 只有 member_count=1 才能 CAS 固定由 binding/generation/runtimeSession 摘要构成的 exclusive_member_key，同时标记原 Session；同一未确认 rewind 再入报 recovery_required，竞争成员不能进入。结束及正常/LOST/已停止回收按实际清除行数扣计数，并仅清除匹配的 exclusive key，失败回滚，不把计数当授权来源。maintenance/挂载 fence 看原物理 owner 的计数；operator preparation 保 directory-before-binding 锁序。Runtime retention 不删 execution_storage_key 仍非空的记录。

CSI/resident 路径保原专用权威，不泛化成无租户锁的所有操作；Broker 执行准入仍有自己的 placement/domain 围栏和共享存储重验。本项合入时上传仍占独占 holder、要求 member_count=0；最新 main 已由后续 #16212 改为上传与 Runtime/其他上传共享计数，独立归因，不倒算本项能力。

最新 main 演进：#16217 只把 resident claim/release 的只读分支移出 tenant guard；#16240 修正 Hosted 测试 owner 快照与 2→1→0 成员断言。#16283/#16312 分离只读文件/source 预检，不取消真正执行/上传/维护的原成员与身份 CAS。

2026-11-06 最新 main 复核：#16369 已替代单成员 exclusive rewind：每 Runtime Session pending 独立，邻居可执行/上传/rewind，未知仅阻原 Session，maintenance 仍需空闲；旧 exclusive_member_key 已删除。

## 边界与风险

- member_count 是维护占用事实，不替代原 binding/session/claim 身份，也不代表文件写冲突隔离或吞吐资格。
- 原地改 V1，无旧库升级/计数回填方案；旧 writer 不维护计数，不能混跑。
- 本次未跑 MySQL、Hosted、CSI、SSH 或真实挂载/恢复门禁。
