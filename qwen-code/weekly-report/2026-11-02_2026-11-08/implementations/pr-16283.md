# PR #16283 最终实现：Workspace 读取与持久受理分离

> PR: [perf(managed-agent): separate workspace reads from durable admission](https://github.com/QwenLM/qwen-code/pull/16283)
> 状态：merged；最终 head `36cd0574f40c`，merge `93fdebb8fb67`，对照 main `7d99e7d26ee4`。
> 规模：+1003 / -89，11 个文件

## 解决了什么问题

目录浏览、文件 query/read、上传预检和 worktree source 复用 resolveForCreation 的锁定事务，读请求等待 Workspace/ACL/Session 元数据写锁；外部 I/O 又不该持有数据库准入锁。

## 最终实现方案

Registry 显式区分 resolveForRead 与创建/OWNER ROOT 持久准入；读取使用独立 REPEATABLE READ 事务、不锁 Workspace/ACL/Session，仍核 actor/access、SSH、state、generation、cwd 和原 worktree。文件 I/O 前后各取新 scope/revision 比较，目录浏览完成后重验 binding；上传只把预检改 readScope，真正 admission 保原锁定重验/receipt/member CAS。SessionWorktree source 去 tenant guard，最终 admit 仍核原身份。最新 main 的 #16312 继续拆除内层 storage guard 隐式锁，并双快照重验 source，因此单靠本 PR 的外层 readScope 不等于全链路无锁。
