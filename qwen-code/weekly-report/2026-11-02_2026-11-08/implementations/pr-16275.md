# PR #16275 最终实现：Hosted cleanup 引用拒绝悬空原 binding

> PR: [fix(managed-agent): reject dangling Hosted cleanup references](https://github.com/QwenLM/qwen-code/pull/16275)
> 状态：merged；最终 head `90e4b39acc5d`，merge `98ef7b2cd31f`，对照 main `624d10532ab8`。
> 规模：+559 / -26，9 个文件

## 解决了什么问题

去掉普通 journal 租户锁后，retention 可在 cleanup 引用受理前收走原 Runtime binding；只写引用而不核原 binding 会留下悬空清理债务，或错误引用其他租户、Workspace、generation 的资源。

## 最终实现方案

JournalCommit 完成凭据/请求校验后检查记录是否含 hosted.cleanup；该 lane 在 Session root 之前有界锁 placement，跟 retention 的锁顺序一致。非 confirmed cleanup 对 ma_runtime_binding 按 binding_id 当前锁定读，核 tenant/Workspace/workspaceGeneration/runtimeGeneration；不存在或不匹配以 managed_session_cleanup_conflict 拒绝并回滚。confirmed 只结算原匹配引用，不要求已经完成清理的 binding 仍存在；不会自动修复旧悬空引用或重建 Runtime。

## 关键代码路径

- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/JournalCommit.java`：识别 cleanup lane 并恢复 retention 之前的有界锁序。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/HostedCleanupReferences.java`：非 confirmed 原 binding 当前读和身份拒绝。
