## 解决了什么问题

默认 files/1 缺 glob，shell/1 缺持久 todo_write；普通 read_file 执行已支持 PDF pages 但模型 schema 不声明，冷 load 还需验证 Todo 状态链。

## 最终实现方案

最终 diff 直接扩既有普通 profile：files/1 进入 search/glob，shell/1 复用 Session journal Todo；不新建 profile 版本或能力协商，create/load 用当前工具 schema，恢复拒绝旧 schema 而不降级剥 pages。普通 read_file 与只读 child 使用带 pages 的声明，复用 Core 的 1-based 闭区间/最多 20 页限制和现有执行；Resident/CSI 保原 restricted schema，SSH 保 foreground 限制。原生 glob 按 search profile 预批准，不让 MCP 同名工具继承；Todo 不做 Runtime 文件写且 Plan 不广告。Workspace restore 解析 managed-todo_state 并跟 previousRecordRef，坏数据/缺祖先在模型前拒绝；live/恢复的超限提示区分文本 offset/limit 与 PDF pages。并无 grep/LSP 或任意 daemon 工具全面对齐。

## 关键代码路径

- `packages/cli/src/serve/hosted-workspace-profiles.ts`：普通 files/1 search 判定。
- `packages/cli/src/serve/hosted-workspace-tool-turn.ts`：分型 schema/声明、Shell Todo 与超限提示。
- `packages/cli/src/serve/hosted-harness-session.ts`：cold restore 校验 Todo 链。
- `packages/cli/src/serve/hosted-runtime-recovery.ts`：恢复输出的 pages 提示。
