## 解决了什么问题

普通 inline 工具结果仍争两类 tenant guard；生命周期续租/失败/重试与只读 storage admission 过度串行。若忽略 claim mirror 当前读，旧事务还可能用已清理的 lifecycle claim 放行。

## 最终实现方案

普通 inline publication 先锁 Session，再读原 placement/CSI/head，缺失资源普通 probe/唯一键插入；lifecycle authority 和 CSI 保原 tenant 围栏。生命周期 claim/renew/fail/block/retry 使用 Session→operation→head 顺序，缺失 Session 不物化新 root；answered watermark 移除无关 placement 锁。普通 Turn/Session/journal 的 storage alias/owner 准入改共享当前读 FOR SHARE，H2 回退 FOR UPDATE；维护仍排斥这些读者。带 authority 的 Harness 检查对 claim mirror 同样保共享锁到事务结束。另去掉两个输出 collector tick 和 Kubernetes placement 查询上多余 Java monitor；不改变原 receipt、资源完整性、claim generation 或租约规则。

2026-11-06 最新 main 复核：#16329 补齐 Session 命令共享准入，#16370 对普通 journal/publication 进一步改不锁物理 storage 行；authority/CSI 与普通命令不是同一锁口径。
