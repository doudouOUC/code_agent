# PR #16354 最终实现：按原 binding 分类的 publication placement 去锁

> PR: [perf(managed-agent): take ordinary publication lanes off the placement guard](https://github.com/QwenLM/qwen-code/pull/16354)
> 状态：merged；最终 head `372dfb87f359`，merge `cf6b4270c657`，对照 main `a32684604a12`。
> 规模：+533 / -180，21 个文件

## 解决了什么问题

去掉 publication CAS 后普通工具 lane 仍等待 tenant placement；直接在 Session root 后锁 binding，又会与 binding→root 的拥有者形成死锁。

## 最终实现方案

ToolPublicationPlacement 仅对同 DataSource 原生 JDBC、非 CSI/Resident 且 workspace-class 或精确当前 Session isolation 的 binding 允许先锁 Session root，不拿 placement。workspace-class 在 root 后共享锁 binding；session-class 用仓库独立当前读，因为所有离开 READY 的写者须持该 root，operator recovery 同步补此锁。其他 binding/CSI/Resident 与 lifecycle-authority lane 保 placement-first。lockPublicationWriter 显式传 placement/publicationGuard，禁止 root 后再补 guard。receipt 明确禁止 hosted.cleanup，避免 common commit 反向取 placement；资源/receipt 原一致性不变。后续 #16370 只为普通 lane 再去 storage 检查行锁。

2026-11-07 最新 main 复核：#16415 的 execution control 去 guard 是独立切片：已有公共 Session root 才可省，admission drain placement 仍保，不能倒算所有执行均无锁。
