## 解决了什么问题

启动前本地容量拒绝若落入通用失败分支，会把没有启动的原 binding 写为 RECOVERY_BLOCKED；若只按错误码放开，又可能重放已启动且 attestation 失败的 Runtime。旧候选还混入已拆出的线程池方案。

## 最终实现方案

最终 diff 提取 RuntimeProvisionFailureHandler，在 ensureResource/provision 阶段记录 local-process、retryable 503/runtime_local_capacity 且原因为 RejectedExecutionException 的证据；attestation 后同码不算启动前拒绝。保同 binding/seed 重试，只在原无 handle、当前 PROVISIONING/无 lease/未 attested 且精确 synthetic v1 placeholder 时 CAS 清除；replacement owner CAS 失败则 fenced，真实 durable handle 保留。deferred map 的 null 在异步 stage 返回 400，SSH 清理日志仅暴露异常类名；本地生命周期 monitor 改 ReentrantLock，虚拟线程命名、常量/注释与 Java 约定同步，类大小棘轮的测试/资源保留，不引入 PMD。最终本项不新增 startup 32/HTTP 64 限制：线程池已由 #16330 独立合入，main 为 operation 16/reader 64/stop 4、HTTP 32+64 队列。warm 完成仍需 acquire，drain 不等于物理停止。

2026-11-08 最新 main 复核：#16501 将 binding provision/recovery 与 failure-handler 接线搬入 RuntimeBindingProvisioning，原精确容量拒绝、seed/generation 和证明边界不改变。
