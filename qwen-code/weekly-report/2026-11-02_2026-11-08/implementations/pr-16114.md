## 解决了什么问题

## 最终实现方案

仅 RELEASE_TAG=v0.26.5 时，在 CLI 构建前要求 SOURCE_SHA 恰为 `db0e4e24a0d89b211b2a15f4af2be22adac71dfc`，校验工具目录内补丁 SHA-256、要求 tracked checkout 相对 HEAD 干净，先 git apply --check 再应用。补丁只有 #16099 的 import 和范围转义，不改产品算法或原 tag；summary 记录产品 SHA、补丁 blob 和完整构建门禁仍开启。

脚本元测试建立原始输入 fixture，验证修复内容、产品文件不变、执行顺序，以及错误 SOURCE_SHA、补丁篡改或脏 checkout 均在应用前拒绝。最新 main 的后续 #16134 将此步骤扩为两份固定补丁共同预检/应用，第二份修复 profile 所有权；不能把当前完整步骤全归本项，也不以补丁可应用证明发行成功。
