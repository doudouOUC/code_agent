# PR #16370 最终实现：普通 journal/publication 物理存储检查不锁行

> PR: [perf(managed-agent): remove ordinary journal and publication storage locks](https://github.com/QwenLM/qwen-code/pull/16370)
> 状态：merged；最终 head `43544eb00c05`，merge `de940c41cb4e`，对照 main `e5eb6a177560`。
> 规模：+526 / -12，14 个文件

## 解决了什么问题

普通 journal/inline/publication 只读 alias/owner，却用共享或独占行锁，仍排在无关 member_count 更新之后；为 receipt 另开 bypass 又会扩大正确性契约。

## 最终实现方案

requirePhysicalOpenForRead/JournalFencing.requireSessionStorageOpenForRead 用空锁后缀复用原物理身份、registration/mount 状态检查；无 lifecycle authority/CSI continuation 的 journal 和 inline，以及 placement-free 非 CSI publication writer 使用它，其他保原锁。receipt 始终走共同 transactional commit，不新增 request flag/特例；原资源、writer、generation、root/head、receipt replay 与资源完整性保留。普通读只见当前事务 snapshot，不承诺刷新旧 ambient RR 或等待并发离线物理维护；FENCED/非法状态在快照前提交仍拒绝。物理维护的安全前提是按原 offline-confirmed 停止服务/准入/外部 writer，而非靠这些 journal 锁冻结文件系统。

2026-11-07 最新 main 复核：#16410 普通 snapshot writer 已使用 placement=false 路径，沿原物理 snapshot-read 检查；CSI/authority/cleanup 与 Session 命令准入仍按各自协议。
