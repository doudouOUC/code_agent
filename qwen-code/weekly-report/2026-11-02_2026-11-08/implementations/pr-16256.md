# PR #16256 最终实现：普通 journal commit 改按 Session 排队

> PR: [perf(managed-agent): queue journal commits on the Session row instead of the tenant lock](https://github.com/QwenLM/qwen-code/pull/16256)
> 状态：merged；最终 head `89565d65df99`，merge `651bd66b36ed`，对照 main `11f6163f0fd7`。
> 规模：+512 / -76，13 个文件

## 解决了什么问题

普通 journal commit 长时间占租户 placement guard，导致其他 Session 的 Turn/生命周期互相等待；简单改锁也会在缺失 resource/cleanup 索引上引入跨 Session gap-lock 死锁。

## 最终实现方案

普通 commit 先在真实同源事务中点锁 Session root，再做普通读取、原 writer/placement/CSI 和 head 检查；资源、派生记录、journal/head 与 afterCommit 仍在原事务语义下。资源和 HOSTED_CLEANUP 先普通 probe，已有行再锁定读，缺失插入以唯一键仲裁并核身份，避免锁空隙。生命周期 authority 与 CSI 路径仍有原 tenant 围栏；最新 main 的 #16268 给普通存储准入用共享锁，#16275 对含 hosted.cleanup 记录的 commit 在 Session 之前恢复有界 placement 锁并核原 binding，因此不是所有 commit 都无 tenant guard。

2026-11-06 最新 main 复核：#16370 已把无 lifecycle authority/CSI 的普通 commit 物理 storage 检查从共享锁改为普通 snapshot 读；cleanup placement/原 binding 仍保留，离线维护必须先停 writer。
