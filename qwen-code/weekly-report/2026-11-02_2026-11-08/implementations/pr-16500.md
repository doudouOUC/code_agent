## 解决了什么问题

原静态 Skills/扩展发布依赖 daemon 准备，Managed-only 缺少上传/表单、纯预览及幂等安装入口。

## 最终实现方案

最终实现已收窄为 archive/Skill/MCP 自助准备与安装。operator+部署 allowlist、selfServiceEnabled 和 Harness preparation capability 先检查，将有界输入交认证 Hosted 纯 prepare/preview/inspection，规范化 archive 后复用原发布/settings/config_install。预览不创建 revision、不启动 Runtime/模型/MCP/安装脚本；100 MiB 输入、并发/磁盘/截止/产物限额拒绝超量。更新保原包 namespace，显式 idle apply 仍核 expectedConfigRevision，其他 Session 保原 pin。MCP 表单秘密只引用声明 settings，不回读 archive/browser storage。Runtime Skill discovery/snapshot 已拆到 #16638，个人 OAuth/执行 actor/两张候选表已拆到 #16647；两者均曾以本分支为 base；#16638 已另行合入 main，#16647 已改目标 main 但仍 open。两者不属于本项最终合入 diff，不能把 OAuth 当作 main。

2026-11-10 最终复核：MCP 地址中的 settings 占位符必须完整且已声明，使用安全替代值再过 recipe 地址校验，拒绝混入 userinfo 等非法地址。安装器编辑/再发布保留原可选 timeout，限安全整数 1–600000；canApply 元数据与原 SHELL/MCP/FILES/READ 准入 profile 对齐，仍需 ACTIVE、非 child、无活动 Turn，不推广 FILES_V3。包来源 MCP 只有具备 canPublish/canApply、导入/预览/原操作 lookup 和 inspect 等能力才展示相应安装/编辑入口；不能打开包编辑器时保留独立 MCP 管理控件，不把 package-owned 状态当作无条件屏蔽原操作的依据。最终还严格要求 recipe type 为字符串枚举；无 Workspace 时查询指定 operation 返回 missing，不能返回空成功视图；静态 Skill 刷新失败保留上次有效清单并显式报错，复合包无法打开编辑器时恢复独立 MCP 控件。
