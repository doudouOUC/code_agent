## 解决了什么问题

每次本地 Workspace read/upload 都启动一次 CLI --help 子进程，重复支付能力握手开销；只按路径缓存又可能在 CLI 或 Node 被替换后误认能力。

## 最终实现方案

WorkspaceFileProcess 缓存最近一次成功 help 结果，身份同时绑定绝对配置路径、realPath、fileKey、size、创建/修改时间，探针前后身份必须相同。命中仍分别验证 read/upload 能力，并为每次实际操作启动原命令；相对路径、无法可靠 stat、文件更换或失败握手不据缓存放行。不缓存文件内容/访问权限，也不改 SSH 路径。

## 关键代码路径

- `packages/managed-agent-server/runtime-host/src/main/java/com/alibaba/qwen/code/runtimebroker/host/WorkspaceFileProcess.java`：文件身份、成功 capability 缓存及 read/upload 分别核验。

本次核对 PR diff、完整 changed files、相关测试源码及最新 main；未运行 Java/Maven、Node、CI、数据库、Hosted 或真实平台测试。 在源码匹配的 JDK 21/SDK 和隔离 Maven 仓库就绪后，从 packages/managed-agent-server 聚焦 `mvn -Dtest=WorkspaceFileProcessTest test checkstyle:check`。 覆盖多次读写只探针一次但各操作照常执行，替换 CLI/Node 后重探针，read-only 不推断 upload，相对路径和失败握手不复用。
