# PR #16288 最终实现：内嵌数据库逐物理连接启用严格模式

> PR: [fix(managed-agent): enforce strict SQL mode per embedded connection](https://github.com/QwenLM/qwen-code/pull/16288)
> 状态：merged；最终 head `9d83217e3d7f`，merge `26ed1a322bf1`，对照 main `e5eb6a177560`。
> 规模：+163 / -39，8 个文件

## 解决了什么问题

要求 DBA 把 GLOBAL.sql_mode 改严格会扩大部署权限与影响范围；只有校验连接严格又不能保证连接池后续物理连接都拒绝静默截断。

## 最终实现方案

内嵌 Druid DataSource 对 jdbc:mysql:/jdbc:mariadb: 设置 connectionInitSqls，每个新物理连接在原 SESSION sql_mode 上追加 STRICT_TRANS_TABLES，保留原模式且不改全局值。ManagedSchemaCatalog 在 DDL 前只查询当前 SESSION，要求精确 STRICT_TRANS_TABLES 或 STRICT_ALL_TABLES；取消对 GLOBAL 默认值的读取/要求。外部提供的 DataSource 仍需自行保证所有应用连接严格；schema 专用 catalog、列/索引/FK 和 MariaDB 其他检查不因此取消。

## 关键代码路径

- `packages/managed-agent-server/server/src/main/java/com/alibaba/qwen/code/managedagent/config/ManagedAgentPersistenceConfiguration.java`：每个物理连接的初始化 SQL。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/runtimebroker/managedschema/ManagedSchemaCatalog.java`：DDL 前仅核当前连接严格模式。
