# PR #16369 最终实现：rewind 按 Runtime Session 保未决而非目录排他

## 解决了什么问题

rewind 要求单成员并占 exclusive_member_key，会阻塞其他 Session/上传；丢失 rewind 回答还会把整目录锁死。mount handback 在事务外查状态也可能与新 rewind 竞态。

## 最终实现方案

beginRewind 在短事务核原 owned root/READY 成员，以 CAS 设置该 Runtime Session 的 is_rewind_pending，不要求 member_count=1、不安装物理独占 owner。transport 直接转原 worker；成功回调 endRewind 只清自己的 pending，异常/未知保留，邻居可执行/上传/rewind。原 Session 仍拒普通执行、重复 rewind 与 mount handback；handback 检查并入成员释放事务，和 rewind 只有一个赢家。confirmed stopped/LOST 仅清原成员并按实际行扣数，不动邻居。V1 原位重命名 is_execution_exclusive→is_rewind_pending，删除 exclusive_member_key/相关谓词，projection/boolean/CSI inventory 同步；仍 38 表，无旧库升级。
