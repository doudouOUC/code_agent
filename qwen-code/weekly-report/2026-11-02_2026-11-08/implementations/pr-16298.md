# PR #16298 最终实现：Git 先回收后代再终止父进程

> PR: [fix(managed): Reap Git descendants before terminating parents](https://github.com/QwenLM/qwen-code/pull/16298)
> 状态：merged；最终 head `8df025d3b4bf`，merge `572ee4f6ba64`，对照 main `11f6163f0fd7`。
> 规模：+193 / -16，6 个文件

## 解决了什么问题

先杀 Git 父进程会把子进程交给不回收它们的 PID 1，形成仍被 isAlive 观察到的 zombie，停止证明失败后 Workspace 维护必须保留。中断 checkout fixture 和 CSI HTTP collector 也有终止顺序问题。

## 最终实现方案

保留单次两秒清理预算：前 1.5 秒反复扫描根与已观察活父的后代，先杀当前叶子让父进程回收；保留所有曾观察 handle。最后 500 毫秒尝试所有已知后代和根的信号并等待退出，任何观察/信号失败或剩余存活都 STOP_UNVERIFIED。清理期间暂存中断并恢复，stopAttempted 防 finally 重新开始第二预算。fixture 以 worktree add --no-checkout 后直接中断 reset --hard 保留部分文件；CSI generator 先 server.close、立即 closeAllConnections 再 await，不改原 fixture 字节与退出期限。
