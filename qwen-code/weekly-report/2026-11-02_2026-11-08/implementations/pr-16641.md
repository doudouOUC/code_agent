## 解决了什么问题

## 最终实现方案

最终实现从关闭的 #16475 拆出模型诊断，base main，并复用 #16640 已合入的被动 UI/查询基础。Hosted prepared-request、main/hook/compression observation 生成有界统计和实际已提交请求上下文，通过 main/hook usage v2、maintenance v2 的 durable ref 沿原 journal/资源原子投影。snapshotRevision 单调、同 revision 不同内容拒绝，恢复保 legacy/unclosed/observation coverage gap 和原 output token 预算；累计 totals/sources 与近期样本不重复相加。SQL context/stats 查询以授权短只读 RR 事务返回 source/read revision、estimated/stale/partial/not_recorded，配置/输入/工具/压缩等提交使旧上下文 stale，未知不补零。本 PR 以 storage reader 2→3 与 CSI /2 合入；后续 #16642 已把最新 main 提升为 reader 4/CSI /3，不是 DDL migration；此切片无 activity、Tool v4 或资源健康探测。

2026-11-10 最终复核：contextWindowSize 字段必有、允许 null；非 null 必须在 1 到 MAX_SAFE 范围，不能像 inputTokens/cachedTokens 一样接受明确零。Java validator 与合入 OpenAPI 的 minimum=1 对齐；共享 producer fixture 补 zero-context-window 和 duplicate-coverage-gap 拒绝样本，Java/TypeScript 测试均消费同源 fixture。本次仅检查定义与代码，未执行这些产品测试；未知保持 null，不伪造零窗口。
