# PR #16415 最终实现：普通工具执行控制按已有 Session root 核 CSI

> PR: [perf(managed-agent): take tool execution control off the tenant guards](https://github.com/QwenLM/qwen-code/pull/16415)
> 状态：merged；最终 head `6fe51a65d6c8`，merge `6fb741642f12`，对照 main `45cde869985a`。
> 规模：+487 / -6，8 个文件

## 解决了什么问题

普通 session-class 工具 admit/dispatch 为证明没有 CSI pin，仍通过 lockBindingControl 锁两类 tenant guard 和整组 slot/binding；若缺 root 时贸然去锁，唯一键与主键查 binding 会死锁。

## 最终实现方案

新增 JdbcCsiFilesRetirementGuard.lockExecutionControl，非 CSI 且公共 Session root 确实已存在时先确认并锁 root，再核 pin/requestKey 和残留 CSI runtime marker，普通路径不在此 helper 拿 tenant guard 或整组 slot/binding。root 缺失只会得到 gap lock，不能序列化 control，所以仍走原 guarded 分支；CSI profile、pin 或残留 marker 不走普通无 guard 捷径。requireProvisionPin/lockManagedSession 改 root-before-slot/binding，与后续原 execution 行锁保持同序。JdbcCsiActivationAdmission.lockForExecution 接新入口；admission 的 Harness drain fence 仍需 placement，不能说 admit/dispatch 端到端完全无 tenant 锁。

## 关键代码路径

- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/runtimebroker/persistence/JdbcCsiFilesRetirementGuard.java`：执行专用 control、存在 root 判定与统一锁序。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/runtimebroker/persistence/JdbcCsiActivationAdmission.java`：执行准入接专用入口。
