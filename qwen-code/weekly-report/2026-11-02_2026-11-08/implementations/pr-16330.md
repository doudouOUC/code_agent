# PR #16330 最终实现：本地 Runtime 与 HTTP 线程池有界拒绝

> PR: [fix(managed-agent): bound runtime thread pools](https://github.com/QwenLM/qwen-code/pull/16330)
> 状态：merged；最终 head `d397ec1ed7b6`，merge `b9f4a9ee432b`，对照 main `11f6163f0fd7`。
> 规模：+698 / -50，8 个文件

## 解决了什么问题

无界本地操作、stdout reader、停止升级与 HTTP executor 可能耗尽宿主线程；仅限启动操作又会让长期 reader 排队或容量拒绝丢失原恢复身份。

## 最终实现方案

本地 provisioner 分为 daemon platform operation 16、reader 64、stop 4 的 SynchronousQueue/AbortPolicy 池，submit 捕获拒绝为异步 retryable 503/runtime_local_capacity。非 durable 启动先预留终身 stdout reader 再 spawn，持续排空；停止升级用独立池，饱和时立即 force，不依赖被占满的 operation 池，close 关闭三池。HTTP 为固定 32 platform worker 加 ArrayBlockingQueue 64，AbortPolicy 超额断连而不是 caller-runs 或无界排队，不保证 JSON 503。Broker 原恢复身份保留的最初分支随后由 #16318 收紧为阶段证据/placeholder CAS，不能只按错误码放行。最终 main 无旧候选的 32-startup semaphore 或虚拟本地控制线程。

## 边界与风险

- 16/64/4 是各池并发线程上限而非全局存活 Runtime 数；HTTP 64 是等待队列不是 dispatch 线程数，拒绝断连不保证结构化 503。
