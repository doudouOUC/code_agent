> 规模：+5606 / -455，119 个文件

## 解决了什么问题

Hosted 刻意关闭环境本地记忆，现有 Mem0 配置不能作为 tenant/actor 鉴权；跨 Session 个人记忆需要持久归属和不明写入保护。

## 最终实现方案

最终实现为每个认证 tenant+actor 幂等创建 Store，Session 显式 memory_store_id 绑定且不可变，省略关闭；SQL 保存 opaque namespace、条目归属/墓碑和 owner_only，Mem0 保存正文，认证头为 Token，v2 search 以 user_id 过滤、v1 add 使用 infer=false，get/delete 复核原 namespace；异步/不完整 ADD 或回读不符保 unknown，不把 2xx 当持久成功。私有 Session 的列表/历史/SSE/产物/修改/转发及子上下文执行 owner 检查，子 Session 不自动继承 Store，Workspace 文件仍共享。writer/generation 与 MEMORY receipt 在短事务受理，外部 HTTP 在事务外，结果持久后回放；丢失写结果保 unknown 不盲重试。真实用户输入做最多 512 字查询、5 条/4000 字上下文、5 秒 provider 截止的召回，作为不可信参考，后台不触发。四个 context_* 工具显式写/删、infer=false，删除核原 scope/完整内容并保存墓碑；纯记忆批次 runtime:null。配置默认 false、session-memory/1 capability 与 Session Store 均需支持。已在唯一 V1 加入 ma_memory_store/ma_memory_entry 和 Session 私有绑定列，主干现为 40 张业务表；不提供旧库升级。合入提交标题仍保留 Holo，但最终 provider 为 Mem0，不能据标题推断实现。

2026-11-09 head 增量：召回 query 先去 Shell 续行，再拒绝 MYSQL_PWD、curl 续行 user、redis-cli 紧邻 -a/--pass 等凭据形式，命中则不向 Mem0 发送召回查询；这是模式保护，不是任意秘密检测证明。
