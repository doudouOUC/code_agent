# PR #16212 最终实现：并发上传共享存储成员关系

> PR: [feat(managed-agent): allow concurrent workspace uploads](https://github.com/QwenLM/qwen-code/pull/16212)
> 状态：merged；最终 head `07d0a6c74213`，merge `da42e5714ad0`，对照 main `7d99e7d26ee4`。
> 规模：+523 / -81，10 个文件

## 解决了什么问题

变更前 main 上传以单一 holder 独占物理目录，阻止其他上传和已有 Runtime 成员，即使实际文件操作可以重叠。简单取消 holder 会让未知结果、并发同 ID receipt 或维护操作失去可靠占用事实。

## 最终实现方案

沿 #16205 的物理 member_count，把每个 RUNNING 上传计为共享成员，不再设置独占 holder；上传可与其他上传或 Runtime 共存，但 maintenance/holder/exclusive rewind/非 READY/挂载换代仍拒绝。WorkspaceFileStore.Scope 带 mountRevision，准入先重验原 scope/revision/migration，再按 alias、directory、operation 锁序点锁并 CAS 增计数，无 tenant guard。ma_operation 仍冻结原 actor、locator、path、digest 和进程目标，不持事务执行外部 I/O，也不将文件字节存入 SQL。

同 uploadId 并发以唯一 operation key 仲裁；duplicate/deadlock 异常后只读取已提交原 receipt，并重验 actor 和语义摘要，找不到原 receipt 不吞异常。pending 不重新提交变更；恢复只查询原进程目标。确定终态在 directory-before-operation 同事务内先返回已有结果，否则扣本上传的一次计数并 CAS RUNNING 结果；状态更新失败回滚计数。未知/坏响应保留成员，避免维护提前进入；不清除别人的 holder，也不把重启当释放依据。

V1 仅更新 member_count 注释说明上传也计入，不新增 schemaVersion/迁移。最终 head 已以 merge `da42e5714ad0` 合入，替代 main 之前的独占 holder 上传语义；未新增前端上传并发调度或同一路径写冲突解决协议。

最新 main 演进：#16283 将新上传的预检改为 readScope，body 在数据库事务外读取，最终上传受理仍锁定重验原 locator/mount/actor/receipt 并取得成员；#16312 进一步拆除只读 storage root 的隐式锁。#16229 只缓存本地成功 help 能力，不缓存上传结果或取消每次操作。

2026-11-06 最新 main 复核：#16369 已允许上传与邻居 rewind 共存，原上传 receipt/未知成员/一次结算不变；不再因 exclusive_member_key 拒绝，仍不解决同路径并发。

## 边界与风险

- 已合入不等于真实数据库/进程并发资格；计数共享不隔离文件内容竞争。
- 计数注释变化不等于旧 writer 兼容：旧 holder 语义与共享计数 writer 不能据相同 V1 混用。
- 不授予维护、rewind、迁移或路径越权；未知结果保持占用，需原目标证据后再结算。
