## 解决了什么问题

Workspace settings 服务凭据不能代表个人授权；共享运行环境、并发刷新或撤销可能串用 actor token，结果不明重试又会重复外部副作用。

## 当前实现方案

当前 open diff 从 #16500 拆出个人 HTTP MCP OAuth，base codex/managed-skills-mcp-self-service。默认 disabled，需显式 isolatedToolProfiles/provider 和 execution access；tenant+Workspace+actor 绑定加密 grant/attempt，PKCE S256、一次性 state、browser nonce、issuer/resource/scope/package pin 校验。callback 只记录授权 code，认证原 actor/browser complete 才交换；refresh lease 与原 generation CAS、不明交换 fail closed，revoke 先持久代际围栏，外部撤销失败不恢复旧 grant。config_install format v2 原子投影 personal execution actor 与 config revision；Runtime 按精确 server/credential generation/resource/config/actor 取 token，前后核有效 bundle，不把 token 放包、浏览器 storage 或 daemon 迁移。禁止 child/unattended 隐式委托，原 MCP 不明调用不盲重放。候选 V1 加 ma_mcp_oauth_attempt/ma_mcp_credential 及 Session actor/revision 列，无旧库迁移；本切片并非 #16500 当前内容或 main。

## 关键代码路径

- `packages/managed-agent-server/control-plane/src/main/java/com/alibaba/qwen/code/managedagent/extensions/ManagedMcpOAuthService.java`：PKCE/actor/grant/token 的操作与复核。
- `packages/managed-agent-server/control-plane/src/main/java/com/alibaba/qwen/code/managedagent/extensions/ManagedMcpOAuthClient.java`：显式 provider 元数据与外部交换。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/JdbcMcpOAuthRepository.java`：加密秘密、attempt/refresh lease 和 generation CAS。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/ManagedMcpOAuthAdmission.java`：Session 原锁下 config 与执行 actor 原子准入。
- `packages/cli/src/serve/managed-mcp-oauth.ts`：Runtime 取 token 的 HTTP transport。
- `packages/web-shell/client/components/managed/ManagedMcpOAuthPanel.tsx`：认证/完成/撤销与状态。
