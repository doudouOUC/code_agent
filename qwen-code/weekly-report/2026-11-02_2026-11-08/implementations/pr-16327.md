# PR #16327 最终实现：队列派发与 Workspace Session 创建缩小租户锁

> PR: [perf(managed-agent): narrow queue dispatch and workspace session creation locks](https://github.com/QwenLM/qwen-code/pull/16327)
> 状态：merged；最终 head `098c1cc81ac5`，merge `83248491cf3d`，对照 main `e5eb6a177560`。
> 规模：+465 / -70，12 个文件

## 解决了什么问题

startNext 与 Workspace Session 创建仍先持 tenant placement guard，让同租户不相干工作串行；迁移的旧 RR 快照也可能漏掉刚创建 Session 的完整恢复 profile。

## 最终实现方案

startNext 改先锁原 Session，在同事务 reconcile/claim 队列并调用 Turn 受理，Harness 派发仍在 commit 后。Workspace 创建在任何 consistent read 前锁所选 ma_workspace 行；ResidentWorkspaceCatalog.mayContain 按配置保守决定是否仍须先 tenant guard，原 receipt 唯一键、权限和存储 fence 不变。显式 Workspace 可缩到一行；默认选择保 tenant_id/is_default 的原扫描与默认切换锁序，并未改成 generated default_tenant 索引点查，仍可能锁同租户其他行。迁移锁源 alias 后用同一个独立 autocommit 连接检查 committed idle 与完整 Session/genesis/definition profile，避免外层旧快照且不反向锁 Session/head。team lead/child 创建保原 guard。
