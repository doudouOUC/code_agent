## 解决了什么问题

周期性的 available_commands_update 带完整 Skills 正文，旧 ring 与 compaction 长期引用每份大对象；仅按事件个数限流和出站脱敏不能阻止 daemon 堆随刷新次数增长。

## 最终实现方案

ACP Session 用串行 tail 构造/发送完整 wire snapshot 的 SHA-256，只记最后成功发送摘要；首帧和内容变化发送，失败可重试，held/disposed 复查，Workflow refresh 不因重复被略过。EventBus 以不可变投影仅移除 availableSkillDetails，ring/compaction 保存轻帧，单独保最新完整命令事件；live ACP 仍完整，重连只在原 matching ID 恢复正文，旧快照不充当 Skill 源码档案，SDK/浏览器继续脱敏。新增 --event-ring-max-bytes/eventRingMaxBytes（默认 8 MiB，正安全整数、最多 256 MiB、无 unlimited），轻 ring 字节加最新完整 slot 保守计费，按数量/字节删最旧连续前缀，但至少保最新一帧；单超大事件/完整 slot 是允许超预算的例外，并非严格 V8 heap 上限。seed/reset/close 清当前占用，evicted counters 保本 EventBus 生命周期累计；status 同步 count/bytes/earliest ID/eviction/snapshot bytes，原 epoch、resync 和 replay-burst budget 不混用。
