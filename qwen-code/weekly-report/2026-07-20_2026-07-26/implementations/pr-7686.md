## 解决了什么问题

ACP child cold start 的 static closure 仍急切带上 `iconv-lite`、`@xterm/headless` 和 `simple-git`。这三类依赖分别服务于非 UTF-8 编解码、PTY terminal replay 与 Git/worktree 操作，但多数 session 在 bootstrap、`channel.initialize` 或 `POST /session` 阶段并不会立即用到它们。旧路径因此把约 890 KiB 的直接包输入固定摊到每个冷启动 ACP child 上，也会增加模块解析、编译和 RSS 成本。

## 最终实现方案

最终实现为三类依赖分别建立 first-use dynamic loader：`load-iconv-lite.ts`、`load-xterm-headless.ts` 和 `load-simple-git.ts` 都采用模块级 promise 做 single-flight，并兼容 CommonJS default-only chunk 与具名导出差异；后续 review commit 还补了 shape validation，让坏 mock、缺失 chunk 或错误导出在首次使用点给出清晰失败，而不是静默拿到 `undefined`。

编码链路拆成两层：`sync-file-encoding.ts` 保留 package-root 同步 API，继续由静态 `iconv-lite` 支撑外部兼容；内部 file service、file utils 和 range reader 走 async lazy codec path。UTF-8、空文件、BOM 和 valid UTF-8 fast path 不加载 codec chunk，只有非 UTF-8 decode/encode 才第一次加载 `iconv-lite`。读取失败仍保持 UTF-8 replacement fallback 与 warning，写入编码失败仍 reject，不改变既有行为边界。

Shell/PTY 路径把 `@xterm/headless` 的 import 推迟到确认要走 PTY 之后。首次加载期间如果收到 abort，会在 async import 返回后再次检查 abort，并避免 spawn 真实进程；xterm chunk 加载或 terminal chunk 处理失败仍落回既有 child-process fallback 策略。Git 路径则让 `GitWorktreeService`、worktree cleanup 和 Git-backed extension helper 在构造阶段保持 side-effect-free，只在 repository detection、worktree create/diff/apply/cleanup 或扩展 Git 操作真正需要时加载 `simple-git`；带结构化失败返回的方法继续在原有 failure envelope 内返回错误。

为了让兼容入口不被 ACP child 闭包误保留，CLI 侧新增窄化的 deferred Core runtime entry（`serve/core-runtime.ts` 与 `utils/deferred-core-runtime.ts`），避免 namespace import 牵出 Core package root 的同步 encoding compatibility path。`esbuild.config.js` 增加定向 tree-shake 插件，只在 Core package root 被引入时把 `sync-file-encoding` 标为 side-effect-free；直接导入该兼容模块仍保留原行为。bundle guard 同时禁止 ACP runtime 到 `iconv-lite`、`@xterm/headless`、`simple-git` 的静态路径，但允许动态 chunk 存在。

## 关键代码路径

- `packages/core/src/utils/load-iconv-lite.ts`, `load-xterm-headless.ts`, `load-simple-git.ts`: 三个 first-use single-flight loader、CJS/default 归一化与 shape validation。
- `packages/core/src/utils/sync-file-encoding.ts`, `encoding.ts`, `iconvHelper.ts`: package-root 同步 encoding 兼容入口与 UTF-8 fast-path predicate 拆分。
- `packages/core/src/services/fileSystemService.ts`, `packages/core/src/utils/fileUtils.ts`, `read-text-range.ts`: 内部 read/write/range text path 改为 async lazy codec。
- `packages/core/src/services/shellExecutionService.ts`: PTY path 选中后才加载 xterm，并覆盖 first-load abort 不 spawn。
- `packages/core/src/services/gitWorktreeService.ts`, `worktreeCleanup.ts`, `extension/github.ts`: Git service 与 Git-backed extension 首次真实操作才加载 `simple-git`。
- `packages/cli/src/serve/core-runtime.ts`, `packages/cli/src/utils/deferred-core-runtime.ts`: ACP/serve 需要的窄 Core runtime exports，避免 namespace import 拉回同步兼容入口。
- `esbuild.config.js`: `syncFileEncodingTreeShakePlugin` 定向移除 ACP 静态闭包中的同步 encoding compatibility path。
- `scripts/check-serve-fast-path-bundle.js`, `scripts/tests/serve-fast-path-bundle-check.test.js`: ACP static closure guard 拒绝三类 first-use 依赖的静态路径。
- `docs/design/lazy-first-use-dependencies.md`: 目标、非目标、静态闭包结果、性能数据、风险与回滚边界。

## 验证方式

- bundle/build 后运行 serve fast-path bundle guard，确认从 ACP runtime 出发的静态闭包中 `iconv-lite`、`@xterm/headless`、`simple-git` 归因字节为 0，动态 chunk 仍允许存在。
- focused Core tests 覆盖 async codec loader、同步 compatibility API、file service UTF-8/non-UTF-8/BOM/fallback、simple-git loader mock 与 Git failure forms。
- focused CLI tests 覆盖 deferred Core runtime entry、serve workspace file-system path 与 bundle guard。
- shell execution tests 覆盖 PTY 路径、child-process fallback、xterm first-load abort 不 spawn。
