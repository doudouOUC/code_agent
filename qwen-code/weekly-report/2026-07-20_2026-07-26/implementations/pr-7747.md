## 解决了什么问题

settings 与 trusted-folders 写入路径原先依赖同步 `comment-json` 编辑器。ACP child 在回答 `channel.initialize` 前需要导入这些 writer，即使正常启动并不会写 settings 或 trusted-folders，也会把 `comment-json`、`esprima` 等旧 JSONC parser cluster 拉进 ACP static startup closure，增加冷启动模块解析、编译和 bundle 体积。

直接替换 parser 不能破坏用户配置文件的格式语义。settings/trusted-folders 写入需要继续保留注释、缩进、CRLF、final newline、UTF-8 BOM、merge/sync/exact-subtree 行为、trusted-folder lock、磁盘状态校验和 atomic write 保证。

## 最终实现方案

最终实现新增轻量 `jsonc-parser` path editor，删除旧的 `commentJson.ts`。编辑器先剥离 BOM 并用 `parseTree` 解析 JSONC，拒绝 parse error 或 root 非 object；读取出来的普通对象通过 JSON roundtrip 规避 prototype 风险。写入更新时，`applyUpdates()` 先根据 merge/sync/exact-subtree 语义构造目标对象，并跳过 `__proto__`、`constructor`、`prototype` 这类 prototype-named update key。

`updateJsoncContent()` 不用字符串拼接，而是以 JSON path 为单位调用 `jsonc-parser.modify()` 生成 edit，再用 `applyEdits()` 应用。它会根据原文件首个 key 推断 tab/space、缩进宽度、EOL 和 final newline；对重复 key 先做 normalized duplicate-property pass，让后续 path edit 命中最终生效的最后一个属性；删除属性时额外处理 trailing inline comment，避免留下悬空注释。写后再次 parse，并用 `isDeepStrictEqual()` 校验产物对象等于预期目标，失败则拒绝写入。

settings writer 继续保留同步 `updateSettingsFilePreservingFormat()` surface：新文件用 `JSON.stringify(updates, null, 2)` 创建，已有文件用 jsonc path editor 原地最小化编辑，解析失败或 root 非 object 时返回 false 并写 stderr，不覆盖原文件。trusted-folders 侧在原 lock 内使用同一个 editor，仍然重新读取磁盘状态、校验磁盘和拟写入状态、合并并发磁盘规则，并以 `0600` mode atomic write。

构建侧把 `jsonc-parser` 作为 CLI production dependency 引入，并在 esbuild 中把 public import 解析到 `jsonc-parser/lib/esm/main.js`，避免 bundle 误用 UMD build；未 bundle 的编译产物仍保留 Node-compatible public package entry。fast-path bundle guard 新增黑名单，拒绝 `comment-json`、`esprima` 和 `jsonc-parser/lib/umd` 回到 ACP static closure。

## 关键代码路径

- `packages/cli/src/utils/jsonc-editor.ts` / `jsonc-editor.test.ts`：新增 JSONC path editor、格式检测、duplicate key 归一、delete inline comment cleanup、parse/validate/write-back 保护。
- `packages/cli/src/utils/commentJson.ts`：删除旧 `comment-json` helper。
- `packages/cli/src/config/settings.ts` / `settings.test.ts`：settings 写入改用 `updateSettingsFilePreservingFormat()` 的新实现，并覆盖 malformed/non-object、comments、CRLF、tabs、BOM、final newline、prototype-named keys 与 no-op。
- `packages/cli/src/config/trustedFolders.ts` / `trustedFolders.test.ts`：trusted folders locked write 改用 jsonc editor，并保留 read-under-lock、validation、atomic write、failure cleanup。
- `packages/cli/package.json`、`package-lock.json`：移除 `comment-json`，加入 `jsonc-parser`。
- `esbuild.config.js`：bundle 中把 `jsonc-parser` 指向 ESM build。
- `scripts/check-serve-fast-path-bundle.js` / `scripts/tests/serve-fast-path-bundle-check.test.js`：扩展 ACP static closure guard，禁止旧 parser cluster 和 UMD build。
- `docs/design/lightweight-jsonc-settings-editor.md`：记录 parser replacement 设计和 benchmark。

## 验证方式

PR 验证包括 focused CLI tests、CLI typecheck、lint、clean CLI build、bundle、unbundled runtime smoke 和 fast-path bundle guard。配置兼容性覆盖前置/嵌套/行内/尾部注释、malformed root、尾逗号、重复 key、CRLF、tab、final newline、BOM、prototype-named key、字段删除和写失败。

性能证据：ACP exact static closure 从 12,449,869 bytes 降到 12,145,099 bytes，减少 304,770 bytes（2.45%）。在 2-vCPU Linux 主机 30 组交替冷启动中，`channel.initialize` P50 改善 35.39ms，process-to-first-session P50 改善 38.00ms，process-to-first-session-complete P50 改善 48.51ms；预热场景统计上持平。Windows 未做本地人工验证。
