## 解决了什么问题

Web Shell 的 session 已经可以运行在 secondary workspace 中，但 Voice 控件仍使用 primary workspace daemon 的 status、provider、settings、model 和 stream route。结果是 secondary composer 可能看到 primary workspace 的 Voice 配置，也可能把 primary runtime 生成的 transcript 插入到 secondary workspace 的输入框里。

这同时影响 split-view：两个 composer 看起来属于不同 workspace，但 Voice capture 生命周期、模型设置和最终 transcript 没有绑定到发起 capture 的 composer owner。workspace 切换、移除、untrust 或 draining 时，旧 owner 的 late callback 也可能落到新的输入框状态中。

## 最终实现方案

最终实现新增 `voice-workspace-target` 解析层。输入包括 daemon capabilities、composer intended cwd、session id/draft id 和 workspace 列表；输出是一个 legacy-primary target 或 workspace-qualified target。primary workspace 与旧单 workspace daemon 继续使用 legacy routes；trusted secondary workspace 必须能通过 canonical cwd 或唯一 workspace id 精确匹配，且 capability 支持 workspace-qualified Voice，才会使用 `/workspaces/:workspace/voice/...` 路由。未知、歧义、不可信、bootstrapping、draining 或 removed workspace fail closed，不回退 primary。

target 中包含稳定 owner key、workspace key、status/settings/model route 能力和 stream path。qualified target 优先使用唯一非空 workspace id，否则使用 cwd selector，并且只编码一次 stream path；status/provider response 如果返回 cwd mismatch 会被拒绝。`supportsVoiceCapture()` 和 `supportsVoiceModelSettings()` 分别 gate capture 与 model settings：legacy target 保持兼容，qualified target 需要 `workspace_qualified_voice`，settings/model 写入还需要 workspace-qualified REST core 与 workspace settings capability。

React 装配层把 owner-aware workspace 信息向下传递。`App`、`ChatPane`、`SplitView`、`ChatEditor` 把 main、locked、split-view composer 的 intended cwd、session id 和 merged workspace list 传给 Voice 层；`VoiceButton` 以 target workspace/owner/settings revision 作为 key 管理 status，pending/error/unsupported/mismatch 时隐藏或禁用，不从 unsafe secondary fallback 到 primary。

`useVoiceCapture` 以 capture generation snapshot owner。每次开始录音时固定 target 和 owner key，WebSocket URL 来自 target.streamPath；target、owner 或 gate 变化时会 abort capture，清理 mic、audio、timer、socket 和 stale callbacks。旧 generation 的 final transcript 或 error 会被忽略，避免切换 workspace 后污染当前 composer。`use-voice-workspace-settings` 同样按 target 隔离 provider/settings/model：user-scope revision 共享，workspace-scope revision 按 target 分开，qualified workspace 的 model 写入走 owning workspace client。

Vite dev proxy 增加 workspace-qualified Voice stream upgrade 规则，只转发 `/workspaces/<selector>/voice/stream` 这类 qualified WebSocket；legacy primary route 维持既有行为。

## 验证方式

PR 最终记录通过了 359 个 focused Vitest tests、Web Shell production build、library build、Web Shell typecheck、repository lint 和 whitespace validation。人工验证建议使用 primary + trusted secondary workspace：确认 primary composer 使用 legacy routes，secondary/split-view composer 使用 qualified routes；capture 后切换、移除、untrust 或 drain owner 时，录音停止、资源释放，旧 owner late transcript/error 不插入当前 composer。
