# PR #17072 最终实现：binding control 去 catalog probe 与重复 root 锁

> PR: [refactor(managed-agent): drop the catalog probe and repeated root lock from binding control](https://github.com/QwenLM/qwen-code/pull/17072)
> 状态：merged；最终 head `b01514966699`，merge `e0d28e7c4662` 已在 main；对照 main `7fab512f79d9`。
> 规模：+205 / -40，3 个文件

## 解决了什么问题

热路径反复查询数据库元数据并重复锁同一 Session root，既增加控制成本，也容易因同名异 schema 表改变控制判断。

## 最终实现方案

JdbcCsiFilesRetirementGuard.lockBindingControl 删除每次 hasTable/getTables 探测，依赖启动时校验的 Managed catalog。普通 execution control 先非锁定存在性探测，再由一次 lockRootPin 读取生成 is_csi_guard/tool_profile；root 消失、被 pin 或存在 CSI marker 都拒绝。生成列包含 request key pin 的表达式由启动 catalog 校验，不能将这一信任复制到未校验环境。

profile/readPin 路径一次完整 FOR UPDATE 同时取得 root 存在性和完整 pin，不再先做窄锁读再取全字段。非 execution、profile 或缺失 root 仍按原 placement/retention/Session 准入路径走；未删除 tenant authority、原 binding 身份或 retirement 拒绝。补 decoy schema、一次 root 锁及 request-key/leftover marker 拒绝测试。

## 关键代码路径
