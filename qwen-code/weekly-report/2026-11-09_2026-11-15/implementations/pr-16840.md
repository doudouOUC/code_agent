# PR #16840 最终实现：Tool Publication 只保留异步受理

> 规模：+621 / -527，34 个文件

## 解决了什么问题

同步和异步两条 publication 验证路径同时维护配置、header、SQL execution_mode 和客户端响应分支，容易让相同 operation 的恢复与最终回执口径分叉。

## 最终实现方案

删除 asyncVerificationEnabled、选择 header 和 ma_operation.execution_mode；segment/resource/seal/prefix/finish 统一先受理持久 operation，再由验证器推进状态。PENDING 返回 202，终态读取原 receipt；客户端不再把无 state 响应当同步成功，按原 operation 查询，轮询从 25 ms 退避到 250 ms。

原 publication token、binding digest、claim 与 request digest 校验保留，不因只剩异步而自动开启 Tool Publication。修改唯一 V1 baseline，并同步 CSI 投影、配置和测试；旧 catalog 需按当前 schema 策略重建，不提供在线迁移。

## 关键代码路径

- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/ToolPublicationDataStore.java`：统一 operation 受理、冻结验证请求和回执。
- `packages/managed-agent-server/server/src/main/java/com/alibaba/qwen/code/managedagent/api/ToolPublicationController.java`：移除模式选择，按状态返回 HTTP 响应。
- `packages/cli/src/serve/remote-shell-result-publication.ts`：原 operation 查询与自适应轮询。
