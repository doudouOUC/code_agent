## 解决了什么问题

worker 外层 allowlist 与 context worker 内部路由挂载各自推导 publisher、Workspace、resident 等组合，可能出现已挂载但外层未放行或不需要的结果/安装路径被放行，且组合行为难以系统验证。

## 最终实现方案

`resolveManagedShellPublisherMode` 集中 resident、requiresActivation、remotePublisher、publisher、installRoute 推导，context mount 与新 `resolveManagedRuntimeWorkerRoutePlan` 共享它。boot v1 仍只允许 owned routes 与 provider；v2 基于实际 capability 和 boot 配置组合 context、测量 v4、扩展、CSI、SSH、tool-result 和 publisher 路由，外层 gate 直接消费 plan.routes。publication 被算作已有 capture publisher，resident 不凭 requiresActivation 隐式创建远端 publisher 或 install 路由。

新组合测试比较 mode/plan 与实际 gate，不把 allowlist 存在当成执行授权。原 token、attestation、mount 内绑定/代际校验保留；本 PR 不新开测量、扩展或 CSI 功能。两份设计说明记录组合规则，产品事实以实际调用点和路由计划为准。

## 关键代码路径

- `packages/cli/src/serve/managed-runtime-worker-routes.ts`：按 boot/capability 生成统一路由计划。
- `packages/cli/src/serve/managed-workspace-activation.ts`：共享 Shell publisher 模式。
- `packages/cli/src/serve/managed-context-worker.ts`：按共享模式实例化 publisher 与 activation 门禁。
- `packages/cli/src/serve/managed-runtime-attestation-worker.ts`：外层 gate 消费 plan.routes。
- `packages/cli/src/serve/managed-runtime-worker-routes.test.ts`：publisher 组合和真实 gate 一致性回归。
