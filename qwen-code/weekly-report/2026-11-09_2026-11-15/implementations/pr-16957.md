# PR #16957 最终实现：删除未使用的 CSI snapshot 与日志读取器

## 解决了什么问题

已经没有生产调用的 checkpoint snapshot 与 Kubernetes 日志接口继续保留，会让维护者误以为它们参与当前恢复或应用证据读取。

## 最终实现方案

删除 WorkspaceCsiCheckpointSnapshotStore 及专属单测/MySQL IT、KubernetesCsiLogReader 及专属测试，并移除 KubernetesRuntimeClient/MaintenanceClient 与 HTTP 实现中的闲置日志读取接口。同步 runtime-broker 设计和残留类清单断言。

这是无调用路径清理，不删除 schema 或现行 CSI admission/activation/retirement authority；WorkspaceCsiApplicationStore、JdbcCsiActivationAdmission 和生产 Kubernetes HTTP 客户端仍在。删除 snapshot reader 后，其他直接读取 record_bytes 的 CSI 路径仍需单独处理，不能由删类推导 pack 删除已安全。

## 关键代码路径

- `packages/managed-agent-server/runtime-kubernetes/src/main/java/com/alibaba/qwen/code/runtimebroker/provisioning/kubernetes/KubernetesHttpRuntimeClient.java`：保留现行 Kubernetes 操作，移除闲置日志 API。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/WorkspaceCsiApplicationStore.java`：仍在使用的原 Session 应用证据路径。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/runtimebroker/persistence/JdbcCsiActivationAdmission.java`：保留实际 activation admission。
