# PR #17074 最终实现：同步 rename 不再取 tenant placement guard

> PR: [fix(managed-agent): drop the stale tenant guard from synchronous rename settlement](https://github.com/QwenLM/qwen-code/pull/17074)
> 状态：merged；最终 head `47b45143ac93`，merge `5fe83c8368c7` 已在 main；对照 main `7fab512f79d9`。
> 规模：+97 / -43，6 个文件

## 解决了什么问题

rename 已不写 delivery row，却仍沿用旧 operation-range 防护的 tenant guard，使一个 Session 的事务阻塞同 tenant 其他 Session 的首次改名。

## 最终实现方案

AgentSessionCommands.settleRenameSync 删除 WorkspaceMigrationAdmission.lockTenant，先锁目标 Session，再做不带锁的原 receipt 查询；同键异 Session 竞争由 command receipt 唯一键仲裁。actor、Session/digest 幂等、title_revision 和提交后 Harness 通知边界均保留，不恢复 delivery operation。

新增参数化 H2 测试：持住第一次 rename 的事务，在同 tenant 或另一 tenant 的另一 Session 上首次 rename，要求独立结算出 revision 1。设计页同步把旧 beginSessionRename guard 标为被同步重设计替代；其他 admission/lifecycle guard 不因本 PR 删除。

- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/AgentSessionCommands.java`：Session-first 同步结算与非锁定 replay probe。
