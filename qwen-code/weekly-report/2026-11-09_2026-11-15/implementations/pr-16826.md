## 解决了什么问题

多处只识别紧邻的 `"code":"`，带空白或截断的 Harness 错误体可能丢失原错误分类。异常吞因和 stdout 线程池选择也影响定位与等待行为。早期 diff 的终态取消键回收已从当前 head 撤去，现标题也已收敛到错误解析、host reader 与异常原因，不登记取消泄漏修复。

## 当前实现方案

共享 `HarnessConflictCodes.bodyCode` 用容忍冒号两侧空白的正则提取首个 code 字段，允许完整 code 之后的 JSON 截断；AutomationScanner、Channel 优先使用结构化 getErrorCode，再用 body 回退，缺失时仍使用各自默认错误码。ManagedAutomationService 对已存 lastError 使用同一提取器。当前 diff 不修改 HarnessCoordinator 或取消键生命周期。

diff 还保留 Session Skills、CSI ACK 的原异常 cause，缩窄 child relay 的 JSON IOException 捕获，并将 `HostCommandRunner` stdout 读取放到显式虚拟线程执行器。它不是任意 JSON 解析器，也没有新增重试或放宽未知操作屏障；main 尚无这些改动。
