## 解决了什么问题

扩展包只支持平台本地归档，业务系统无法按明确资源版本提供 Skill/Extension；若把业务地址或凭据直接下发 Harness，还会绕过 actor 授权和固定内容校验。

## 最终实现方案

增加 ManagedExtensionSource（resolve/open）和 ExtensionArchiveStorage（不可变 put/open），前者用 tenant/actor/Workspace/request/deadline 上下文解析精确 provider/kind/resourceId/revision，拒绝 latest 和未知字段，不把 archiveId 暴露为 URL 或凭据。Spring 注入来源列表并拒重复 ID；归档存储可由业务 bean 替换，默认目录实现仅在未提供自定义实现时配置。

importSource 在 SQL 事务外 resolve/open，限定并发与 deadline、暂存并核 digest，再调用 Harness prepare，沿现有持久幂等 operation 发布归档和 source provenance。source-bound 包不能由普通上传覆盖；list/get/settings/选择阶段重新检查来源权限。Session 受理前形成完整 selection 授权快照，事务内核对 pin、package 与有效期，不在持锁时远调来源。归档下载先获得可关闭的已校验临时文件 lease，再交给 Harness，失败仍拒绝而非重取 latest。同步 OpenAPI、Java SDK、生成类型与既有客户端。

## 边界与风险

- SPI 不自带任意业务 provider；业务适配器须兑现每次授权、有限超时、同 revision 字节不变与未知写不重放。多副本必须共享持久归档，不可依赖每台机器各自目录。
