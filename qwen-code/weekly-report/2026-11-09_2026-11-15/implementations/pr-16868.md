## 解决了什么问题

inline 资源上限阻断较大 Session 资源，长期原始 journal BLOB 占 SQL；直接删除正文又会破坏回放、恢复、列表与工具详情等读路径。

## 最终实现方案

复用 ToolPublicationObjectStore，为超过 kind inline 上限的资源增加 allocate/upload/finalize；writer token、generation 和 Workspace 授权仍在 Controller，原 resourceId 对应 SQL locator，上传后读回核长度与 digest，再由 PUBLISHED 转入原引用流程。TS 客户端外置成功后只提交资源元数据，不再重复携带 inline bytes。finalize 的隔离事务保留 digest mismatch quarantine。这里并非 #16837 的通用 SPI/UNKNOWN 账本方案，upload/finalize 仍有事务内对象 IO。

JdbcJournalPacks 将连续 journal revision 逐事务 gzip 并索引到不可变 pack；BUILDING 先独立提交，事务外构建/PUT/回读，JournalPackTransactions 原子发布 manifest、catalog 与 head watermark。超过宽限后可清空被覆盖 SQL record_bytes，读取仍按 SQL digest/长度从 pack range 解析，EVICTED 仍可读；retirement 与 orphan 回收另行处理。同步 checkpoint、工具结果、队列版本和 Session preview 等消费者，不能只修主回放。

sessionResources.enabled、packJobEnabled、deletionEnabled 默认 false，pack 目标 16 MiB、最多 4096 笔、删除宽限 72 小时。当前 main 唯一 V1/44 表、reader 5，新增 ma_journal_pack；不是候选 HOT/COLD 补热状态机，也不是数据库备份或兼容证明。
