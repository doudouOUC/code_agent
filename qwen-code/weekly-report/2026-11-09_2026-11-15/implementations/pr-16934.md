## 解决了什么问题

公共 proof 的 canonicalBase64 先调用短文本读取，导致不同调用方声明的正文上限被隐式压到约 3072 字节；历史终态 record 的读取也使用过大的通用历史预算。

## 最终实现方案

直接要求 JSON 字段是非空 textual，再按调用方 limit 检查编码长度、解码长度和 canonical 重编码，不再经过 4096 字符 text helper。JdbcCsiActivationAdmission 对历史 terminal recordBytesBase64 明确限 128 KiB，移除 JdbcCsiExecutionAdmission 的孤立 import。新增超过旧阈值可读和超声明预算拒绝的回归，原 digest/身份检查不变。

## 关键代码路径

- `packages/managed-agent-server/contracts/src/main/java/com/alibaba/qwen/code/runtimebroker/CsiNativeActivationProof.java`：canonicalBase64 按声明 limit 解码。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/runtimebroker/persistence/JdbcCsiActivationAdmission.java`：历史 terminal record 的独立 128 KiB 限额。
