## 解决了什么问题

对象每次读取重复探测 bucket versioning，存储 bean 还耦合 publication 开关；多个启动入口的连接池默认值与绑定顺序容易漂移。

## 最终实现方案

最终实现让 AliyunToolPublicationObjectStore.open/openRange 不再每次 validateConfiguration；写入/删除仍探测 versioning，读者原长度/digest 校验不取消。存储自动配置改由独立 object-storage.enabled（默认 false）控制，不再依赖 tool-publication.enabled 或其配置 bean。

ManagedDataSourceDefaults.applyMySqlDefaults 在 URL/属性绑定后统一 mysql/mariadb strict SQL mode 与 MySqlStatementCache.fillDefaults，接入嵌入式、独立 persistence 和恢复入口，并修 Druid 绑定顺序。删除闲置 KubernetesRuntimeProvisioner 草稿及专属 fake/test，不概括为删除生产 CSI/resident provider。此 diff 未修改 JdbcSessionResourceObjects，不能宣称关闭开关后所有旧资源仍可读。

最终实现还为 sessionWorktreeScheduler 补 defaultCandidate=false，避免嵌入宿主的按类型调度器注入选中 Managed 专用池；#17139 随后补遍历实际调度器的回归。MaintenanceObjectStores.settingsOss 仍按 publication 开关构造，独立对象存储 bean 条件不能自动代表所有 operator 入口。

## 关键代码路径

- `packages/managed-agent-server/adapters/src/main/java/com/alibaba/qwen/code/managedagent/adapters/artifact/AliyunToolPublicationObjectStore.java`：读热路径移除重复配置探测。
- `packages/managed-agent-server/server/src/main/java/com/alibaba/qwen/code/managedagent/config/AliyunToolPublicationStorageAutoConfiguration.java`：独立默认关闭的对象存储 bean 条件。
