## 解决了什么问题

重命名依赖持久 delivery operation、Harness 可用性与旧 journal 标题，可能使展示标题受运行时故障影响或让两个 authority 分叉。

## 最终实现方案

SessionAdmissionStore.settleRenameSync 在原 tenant/Session 锁、actor 与幂等 digest 条件下，同一 SQL 事务修改 ma_session.title、递增 title_revision、写 mutation/command receipt；不再创建 RENAME operation/claim/lease。COMPLETED replay 返回当前持久标题且 revision 为 0，删除后的原授权重放仍保留既有 last-visible 语义。移除 SessionRenameCoordinator、RenameEvidence 及旧 reconciliation/drain 分支。

ManagedAgentService 在 SQL 成功后仅 best-effort 通知支持 fenced titles 的 Harness，不为 rename 启动 Runtime，不因通知异常撤销 SQL 成功。public/WebShell 读取 SQL 标题，不增加响应字段；主干后续 #17043 以 revision>0 而非 !replayed 判定通知，覆盖旧 FAILED/PENDING 键重新结算。WebShell renameSupported 仍受 Harness available/supportsFencedTitles 门禁，不能概括为 UI 总是可点。
