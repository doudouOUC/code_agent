## 解决了什么问题

journal pack 发布并删除 SQL 正文后，activation lease 和 CSI saved/history 仍直接读 record_bytes，可能把合法已外置记录当损坏。

## 最终实现方案

最终实现增加包内 CsiPackRecords：优先 inline，否则调用共享 JdbcJournalPacks.resolveBytes；即使 inline 也核 SQL 长度/sha，缺少 pack、字节或摘要不符均返回失败，由调用者 fail closed。JournalStoreRows.activationLeaseRow 读取 byte_length 并接对象存储/pack 依赖。

activation/execution admission、retirement saved/history 与 binding/execution repository 读路径通过构造和 RuntimeBrokerConfiguration 共享 pack 解析，维护入口与 SideQueryStore 同步接线。新增 pack-only/损坏场景测试；main 已有该 helper，但删除资格不能仅凭测试定义认定通过。

最终 diff 还增加 JdbcJournalPacks.hasObjectStore，storeless bundle 不抛通用 501，而由 reader 的 null 结果触发自身准入拒绝；JournalCommit、writer lifecycle/native head 及非 Spring 维护入口补齐 pack 接线。MaintenanceObjectStores 为 K2/W1 环境和 settings 构建可关闭客户端，无配置返回 null；settingsOss 目前仍受 tool-publication.enabled 限制，不能概括为所有维护入口都使用 #17058 的独立开关。真实对象 IO 异常仍沿调用链拒绝。
