# PR #16953 最终实现：退役 InMemory Broker repository

> PR: [refactor(managed-agent): retire the InMemory runtime broker repositories](https://github.com/QwenLM/qwen-code/pull/16953)
> 状态：merged；最终 head `3d1d5ded00f3`，merge `80f95252e7f4` 已在 main；对照 main `19c6af15b730`。
> 规模：+2512 / -4155，56 个文件

## 解决了什么问题

内存 binding/session/execution repository 与 JDBC 两套语义长期漂移，测试可能只证明内存行为而未走实际 schema、CAS 与持久恢复路径。

## 最终实现方案

最终实现删除三套 InMemoryRuntimeBindingRepository、InMemoryRuntimeSessionRepository、InMemoryToolExecutionRepository 以及专用测试；将大批 Broker/provisioner/recovery fixture 改为初始化 ManagedSchema 的 H2 MySQL mode 与 Jdbc repository，binding secret 用测试 AES-GCM protector。跨实例恢复改依赖数据库共享事实，而非持有内存对象。

测试侧 RuntimeBrokerTestAccess 增加少量可控 fixture 入口，明确绕过不属于单测目标的 CSI admission，同时保执行 identity/version/dispatch CAS 条件；这些入口只在 verification，不是生产准入后门。部分仅测内存持久形状的断言被移除或调整，应区分保留行为与实际删去的覆盖。main 已删除三套 InMemory 类，生产仍沿原 JDBC wiring；测试迁移不是新增生产存储能力。

## 关键代码路径

- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/runtimebroker/persistence/JdbcRuntimeBindingRepository.java`：现有生产持久 binding 实现，JDBC/H2 fixture 复用。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/runtimebroker/persistence/JdbcRuntimeSessionRepository.java`：现有持久 Session 实现。
- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/runtimebroker/persistence/JdbcToolExecutionRepository.java`：现有 execution CAS 与 durable 状态。
- `packages/managed-agent-server/verification/src/test/java/com/alibaba/qwen/code/runtimebroker/persistence/RuntimeBrokerTestAccess.java`：测试 fixture 专用入口，不是生产 API。
