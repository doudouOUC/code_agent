# PR #16723 最终实现：Managed Web 接受非空短浏览器 token

> PR: [fix(managed): Allow short browser tokens in Web gateway](https://github.com/QwenLM/qwen-code/pull/16723)
> 状态：merged；最终 head `ee21a655bd3f`，merge `030fc8bac8e0` 已在 main；对照 main `74b8cde46612`。
> 规模：+37 / -32，5 个文件

## 解决了什么问题

独立 Managed Web 网关将浏览器 bearer token 与服务端签名密钥同时要求至少 32 字节，短而非空、且独立于签名密钥的 token 也会在监听前被拒绝。浏览器认证凭据与 Java 请求签名密钥用途不同，放宽前者不应削弱后者或移除认证。

## 最终实现方案

`runManagedWebServe` 继续通过 `resolveServeToken` 先选显式 `--token`、否则选 `QWEN_SERVER_TOKEN`，再 trim；显式空白参数仍遮蔽环境变量并被拒绝。最终 diff 只删除浏览器 token 的 `Buffer.byteLength(token) < 32` 判断，保留 token 非空、签名密钥至少 32 个 UTF-8 字节、token 不等于原始或 trim 后签名密钥的检查；失败仍发生在创建监听器之前。

静态资源继续公开，`/managed/boot`、`/health`、`/capabilities` 等动态路径仍经 `bearerAuth`，原 Host/Origin 限制、固定 tenant/actor 签名代理和 daemon 路由隔离不变。CLI 的 managed-web 帮助与 Kubernetes 中英文 Secret 说明改为非空独立浏览器 token；本 PR 没有修改 Helm 模板或其他密钥下限。

## 关键代码路径

- `packages/cli/src/serve/managed-web-serve.ts`：启动前分离浏览器 token 与签名密钥校验，保留原中间件顺序。
- `packages/cli/src/serve/serve-token.ts`：复用原参数优先级和空白规范化；不是本 PR 新增解析器。
- `packages/cli/src/commands/serve.ts`：对齐 managed-web 参数帮助。
- `packages/cli/src/serve/managed-web-serve.test.ts`：用短 token 覆盖成功启动、动态认证及缺失/空白/共用密钥拒绝。
- `deploy/kubernetes/README.md` 与 `deploy/kubernetes/README.zh-CN.md`：对齐外置 Secret 的浏览器凭据说明。

## 边界与风险

- 接受非空短 token 不代表弱 token 安全；公网部署仍应使用高熵独立 token 和 HTTPS。32 字节要求仍适用于签名密钥，不能把二者混写。
- 本项只放宽独立 Managed Web 网关的浏览器 token 检查，不证明 Helm 渲染、线上升级或业务链路验收完成。
