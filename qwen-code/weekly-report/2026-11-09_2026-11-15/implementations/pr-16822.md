# PR #16822 最终实现：移除未使用构造器与辅助转发

> PR: [chore(managed-agent): remove unused constructors and helpers](https://github.com/QwenLM/qwen-code/pull/16822)
> 状态：merged；最终 head `bc44c9852deb`，merge `b1c6ba120798` 已在 main；对照 main `19c6af15b730`。
> 规模：+4 / -168，6 个文件

## 解决了什么问题

API record 保留了多个仓内不再调用的缩参构造器，服务也残留只转发或未使用的 helper，使读者误以为仍有旧调用契约，增加维护和搜索噪音。

## 最终实现方案

删除 `ApiModels` 中未使用的便捷构造器，保留 record 字段及使用中的构造路径；移除 `ManagedAgentService` 对规范化 helper 的冗余转发、`WorkspaceFileProcess.requireCapability` 的单参数转发和 preflight 未使用的 isLoopback。Unicode 回归直接测试 `ManagedUserMessagePolicy.replaceLoneSurrogates`，仅为已删 isLoopback 服务的测试同步删除。没有改变 HTTP/JSON schema、校验策略、监听地址或数据库协议，不能把 Java 缩参构造器删除解释成公网 API 字段删除。

## 关键代码路径

- `packages/managed-agent-server/contracts/src/main/java/com/alibaba/qwen/code/managedagent/model/ApiModels.java`：移除闲置 record 构造器。
- `packages/managed-agent-server/control-plane/src/main/java/com/alibaba/qwen/code/managedagent/session/ManagedAgentService.java`：去除无调用的规范化转发。
- `packages/managed-agent-server/runtime-host/src/main/java/com/alibaba/qwen/code/runtimebroker/host/WorkspaceFileProcess.java`：保留带 upload 参数的实际能力校验入口。
- `packages/managed-agent-server/server/src/main/java/com/alibaba/qwen/code/managedagent/preflight/ManagedAgentPreflight.java`：删除未使用 loopback helper，而非放宽当前网络准入。

## 验证方式

本次核对六文件 diff、main 调用点和测试定义，未运行 Java/CI。Java 从 `packages/managed-agent-server` 执行 `mvn -Dtest=ManagedAgentApiContractTest,ManagedAgentPreflightTest,ManagedAgentServiceWorkflowChildTest test checkstyle:check`，需 JDK 21、匹配 SDK；完整编译应发现仍使用旧缩参构造器的仓内消费者。仓外 Java 源码若直接依赖被删构造器需独立迁移，wire schema 未改不能保证源码兼容。
