## 解决了什么问题

Managed Session 缺少不打断主任务的私有追问和离开后回顾；仅依赖浏览器内存无法跨刷新恢复，直接复用主会话执行又会污染历史、共享其他 actor 的旁路内容或意外启动工具。冷 Session 也需要从已有持久事实生成回顾，而不是要求原 Runtime 常驻。

## 最终实现方案

新增 `ManagedSideQueries` 账本和 `ma_side_query`，以 tenant、Session、actor 隔离列表、问题与结果。受理锁定原 Session，冻结 journal revision/sequence/digest、已完成对话边界、私有 BTW 历史和原模型配置 digest；原幂等键重放，不把旁路问答写入主对话。`SideQueryConversation` 在原 `ma_session_record` 中维护对话版本而非再建一张 conversation 表；合入时唯一 V1 为 42 张业务表，同周存储/来源变更后为 44 表，2026-11-14 当前 main 为 46 表，不提供旧 catalog 升级链。

服务选择 Hosted Harness 后以 instance/boot/generation/token claim 绑定一次执行，读取有期限的原前缀及有归属的资源，先冻结并校验完整模型输入，再通过 running CAS 调用模型。Core 仅采纳成功完成的主对话，BTW 可带最近 20 组本人私有跟进，Recap 过滤为真实用户对话并裁取近期内容；按窗口和 32 MiB 总预算裁剪，不开放工具或 Workspace 执行，也不恢复主 Runtime。流式进度持久为单调 resultRevision；取消、权限丢失、Session 关闭、claim/deadline 失效使结果终止，状态不明不重新派发模型请求，清理资源引用和读 lease。

WebShell 增加 `/btw`、`/recap`、侧栏历史与取消，原 intent/queryId 按 provider/actor/Session 恢复；未知提交沿原键确认。服务端 `sideQueriesEnabled` 与浏览器自动 Recap 均默认关闭。自动模式仅在离开至少 5 分钟后、前台交互且主任务 idle 时尝试，服务端校验 contentVersion/mainInputBoundary 和轮数门槛；同内容自动尝试去重，迟到结果不强行弹窗。Java Hosted 客户端与 OpenAPI/生成类型同步。

## 边界与风险

- 已合入不等于部署开启；服务开关、SessionStore、Harness side-query capability、原 actor 权限和显式模型配置共同约束生成。
- 自动 Recap 是前端返回触发，不是后台计划任务；正文和用量属于旁路查询，不计作主对话继续执行。
