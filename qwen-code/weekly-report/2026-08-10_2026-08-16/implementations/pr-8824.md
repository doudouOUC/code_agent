## 解决了什么问题

大型 persisted session 的 load/resume 可能慢于一次普通交互。旧 WebUI 在目标 restore 完成前就 detach 当前 session、停止 source SSE、清空 transcript/prompt state 并切换 workspace metadata；目标 404、504、网络失败或被新点击替换时，用户会看到空白或错误 target，而健康的 source 已经不可继续使用。

## 最终实现方案

#8824 是事务化 WebUI session switching 的安全完整 draft。它把普通 load、resume、reload、full-resync 和 live-journal repair 都改成 source 保持 visible owner、target 在离屏 staging store 中完成 restore/replay，最后通过 generation/deadline 检查后同步 commit。Provider 暴露 preparing/queued/failed transition 状态，普通 restore RPC 串行化，相同请求 coalesce，后续只保留 latest target；迟到 event/completion 按捕获的 owner identity 隔离，废弃 candidate 用 daemon 实际返回 identity 做 best-effort detach。

WebShell 侧分离 desired 与 committed session/workspace identity，不 remount 当前 App；sidebar、overview、resume、dialog 和 scheduled-task open 复用事务 helper。新写入在 optimistic UI side effect 前 gate，git/model/mode/recap metadata 按 committed owner 归属，scheduled-run 30s timer 延后到 restore commit 后开始。

该 draft 最终没有直接合入。代码深读显示它被拆成两个更小边界：#8833 先合入 same-id attachment stale work fencing；#8882 当前 open diff 继续推进 cross-session transactional switching。#8824 中 branch restored-payload adoption、branch-specific SDK timeout、global attachment scheduler、cleanup registry、daemon-wide A+1 guarantee 等内容未作为本 PR 落地。
