# PR #8911 最终实现：daemon ACP NDJSON 帧与 decoded queue 有界化

> PR: [feat(serve): bound daemon ACP NDJSON buffers](https://github.com/QwenLM/qwen-code/pull/8911)
> 状态：merged，已合入 `main`。
> 规模：+758 / -36，7 个文件

## 解决了什么问题

daemon 与 ACP child 之间的 `ndJsonStream` 会保留未终止 chunk，且 decoded `ReadableStream` 没有 count/byte 上限。失控 child 可以发送超大未终止 frame 或大量 notification，在 ACP SDK 消费前持续增加 daemon root 内存；既有 large-frame observer 只是 post-decode observability。

## 最终实现方案

#8911 为 daemon-owned ACP child 启用 bounded NDJSON stream。入站/出站 frame limit 固定为 64 MiB（含 newline）；入站 decoded queue limit 为 256 条与 64 MiB retained wire bytes，并使用 `max(frameBytes, ceil(64MiB/256))` 的 conservative charge，防止小消息绕过 byte cap。

admission 在 decode/parse 前完成。超限、queue saturation 或 unterminated EOF 会报告 typed transport cause，cancel input，正常关闭 decoded stream，并终止精确 tracked child；这样 ACP SDK receive loop 不会因 rejected stream 出现 unhandled rejection。bounded parse failure 日志只包含 error kind、byte length、SHA-256 digest 和 payloadOmitted，不记录 child-controlled payload。

## 关键代码路径

- `packages/acp-bridge/src/ndJsonStream.ts`：frame/decoded queue limit、typed limit error、metadata-only parse failure。
- `packages/acp-bridge/src/spawnChannel.ts`：spawn channel 传入 bounded stream options。
- `packages/cli/src/serve/run-qwen-serve.ts`：所有 `qwen serve` ACP child 使用固定 bounds。
- `docs/design/2026-07-31-daemon-capacity-model-and-memory-bounds.md`：capacity model 中的生产接入说明。

## 验证方式

PR 运行 57 个 ACP bridge focused tests、243 个 daemon runtime tests、build/typecheck/lint，并用 GC/memory probes 验证：96MiB input 在约 65MiB 取消，40k messages 截在 256 条，invalid 2MiB frame 只记录 digest，ACP SDK receive loop 没有 unhandled rejection。

## feature 文档处理

已同步到 ACP bridge 权限文档、resource budgeting 和 daemon 总览，作为已合入的 daemon-owned ACP NDJSON resource bound。

## 边界与风险

- bounds 只自动应用到 `qwen serve` daemon-owned ACP child；公开/standalone ACP streams 仍需显式 opt-in。
- #8911 不限制 ACP SDK 内部 handler/outbound/pending-response 队列；这些已由后续 #8947 merged diff 继续补。
