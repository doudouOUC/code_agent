# PR #9007 当前实现观察：ACP HTTP pre-attach buffer byte bounds

> PR: [fix(serve): Bound ACP HTTP pre-attach buffers by bytes](https://github.com/QwenLM/qwen-code/pull/9007)
> 状态：open，未合入 `main`。
> 规模：+3785 / -492，27 个文件

## 解决了什么问题

ACP HTTP pre-attach 缓冲原本主要按 frame 数限制，无法约束少量超大 JSON-RPC reply、多动态 workspace connection 或已 attach 但 stalled 的 SSE/WebSocket writer。旧行为还可能静默淘汰旧 frame，尤其对无 id reply 会让客户端永久等待。session/new/load/resume/fork 也会在 reply 本地投递前记录 ownership；如果连接关闭或 overflow，daemon 可能遗留客户端根本不知道 id 的 fresh session、persisted fork 或 client attachment。

## 当前实现方案

#9007 的 open diff 为 daemon-owned ACP HTTP pre-attach buffer 增加 serialized byte budget。buffered reply 只 `JSON.stringify` 一次并保存 UTF-8 Buffer；admission 同时检查 per-stream 256 frames、per-connection 1024 frames/64 MiB payload，以及 process-global 4096 frames/256 MiB payload。primary 与 dynamic workspace mounts 共享同一个 global budget；stalled SSE/WS delivery 会继续持有 lease，直到 write callback/close/failure 释放。

拒绝资源时不再 silent eviction，而是关闭精确 session 或 logical connection；共享 WebSocket resource failure 用 1013。`session/new`、`session/load`、`session/resume`、`session/fork` 的 ownership grant 变成 provisional receipt：只有 JSON-RPC reply 本地 delivery 成功才 commit；teardown、overflow、serialization failure 或 delivery failure 会 rollback fresh session、persisted fork 和新增 attachment，不撤销已经存在的 ownership。notification 形式的 ownership-granting method 不再 mutate state。

daemon status 与 TS SDK surface 暴露 effective pre-attach limits、current/high-water frames/bytes、pending delivery ownership、guard failure、per-mount attribution 和 per-connection owned frames/bytes。该 diff 还修正 ACP prepared-response JSON string byte estimation，计入 escaping、UTF-8 和 surrogate。
