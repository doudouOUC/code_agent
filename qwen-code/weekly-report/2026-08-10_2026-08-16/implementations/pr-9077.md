# PR #9077 最终实现：daemon 多会话 OTel session ownership

> PR: [fix(core): Preserve OTel session ownership in daemons](https://github.com/QwenLM/qwen-code/pull/9077)
> 状态：merged，已合入 `main`。
> 规模：+1039 / -209，15 个文件

## 解决了什么问题

一个 daemon/ACP child 可以在同一进程承载多个 session，但 telemetry 初始化只有一个 process-global session。generation、forked query 等 standalone 模型请求可能让 native LLM span 归到 bootstrap session，而 API logs 使用真实 routed session，导致同一次模型请求在 AgentLoop/OTel 后端被拆成两个 conversation。

## 最终实现方案

#9077 给每次模型请求建立 immutable request-scoped OTel session identity。优先级为：显式 interaction/tool/subagent 逻辑父级；content generator 拥有的 request session；scoped OTel Context；request-local Context；最后才是 process-global CLI session 兼容 fallback。最终 session identity 同时写入 native LLM span、instrumented HTTP child spans、API request/response/error log records，并在 async stream iteration 期间保持不变。

automatic spans 与 log-to-span bridge 先读取 scoped identity，再走旧 fallback，且不覆盖已有显式 session attributes。`LoggingContentGenerator` 创建 LLM span 时绑定 context；streaming generator 通过 context-bound async generator 保持后续 response/error log 的 owner 不变。interaction、tool、subagent、daemon callback context 都携带 owning session，单会话 CLI 仍可使用 process-global fallback。

## 关键代码路径

- `packages/core/src/telemetry/session-context.ts`：session id Context key、set/get helper。
- `packages/core/src/telemetry/session-tracing.ts`：LLM/tool/subagent span session ownership resolution。
- `packages/core/src/core/loggingContentGenerator/loggingContentGenerator.ts`：request-scoped LLM span 与 async stream context binding。
- `packages/core/src/telemetry/loggers.ts` / `log-to-span-processor.ts`：API logs 与 log bridge session attribution。
- `packages/core/src/telemetry/daemon-tracing.ts`：daemon routed session context 传播。
- `packages/core/src/telemetry/sdk-impl.ts`：SessionIdSpanProcessor fallback 顺序。
