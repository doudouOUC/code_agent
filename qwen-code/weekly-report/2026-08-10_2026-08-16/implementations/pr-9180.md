# PR #9180 当前实现观察：Web Shell composer text file attachments

> PR: [feat(web-shell): support text file attachments in the composer](https://github.com/QwenLM/qwen-code/pull/9180)
> 状态：open，未合入 `main`。
> 规模：+1675 / -169，40 个文件

## 解决了什么问题

Web Shell 的 paste/drop 通道原本只接受图片。用户把 `.log`、`.txt`、`.md`、`.json`、`.csv` 或源码文件拖进 composer 时会被当作“不支持的 image file”跳过；在浏览器与 daemon 不在同一机器时，`@path` mention 也无法引用只存在于本地浏览器侧的日志或文本片段。

## 当前实现方案

#9180 当前 open diff 把 image ingestion 泛化为 file ingestion：保留图片路径的 8 MiB 预算，同时新增 text attachment 分类、读取、命名和生命周期。文本文件按 `text/*`、受控 `application/*` MIME、扩展名和常见文件名 fallback 识别；总文本内容预算为 512 KiB，解码后含 NUL byte 的文件按 binary/unsupported 拒绝。附件名在 ingestion 阶段一次性规范化，去掉控制字符、替换 token 不安全字符，并给重名文件追加后缀，保证 chip label、`attachment:///` URI 与正文 token 完全一致。

Composer 状态新增 `PromptFile` 集合，并和图片一样参与 submit gating、clear-on-commit、remove chip、restore-on-edit、queued prompt、Ctrl+Y retry、failed-send retry 与 unknown-admission restore。带图片或文件的 prompt 不参与 mid-turn 注入，只排队到下一轮自然发送；dedup 逻辑也不会把 attachment prompt 当作 text-only mid-turn 消耗掉。

发送到 daemon 时，`toDaemonPromptContent()` 会在普通文本末尾追加 `@attachment:///<name>` token 行，再附加 ACP `resource` content block，内容为 `{uri,mimeType,text}`。slash/shell command path 和图片一样丢弃 attachment block 并省略 token，避免 daemon 侧出现悬空引用。乐观 user bubble 通过 SDK/WebUI 本地 metadata 展示 file chips；session reload 或 peer client 只能看到 transcript 中的 token 文本，这是当前 daemon transcript 只持久化 text block 的预期降级。

## 关键代码路径

- `packages/web-shell/client/utils/imageIngestion.ts`：`extractFileTransfer`、文本 MIME/扩展名分类、512 KiB budget、UTF-8 读取、binary 检测和安全命名。
- `packages/web-shell/client/hooks/useComposerCore.ts`：文件附件状态、abort readers、restore/clear/remove、submit payload 组装。
- `packages/web-shell/client/components/ChatEditor.tsx` / `ChatEditor.module.css`：文本附件 chip、文件图标、大小和删除按钮。
- `packages/web-shell/client/hooks/useQueuedPrompts.ts` / `midTurnDedup.ts`：带文件 prompt 的排队、恢复与 mid-turn 去重边界。
- `packages/webui/src/daemon/session/promptContent.ts`：正文 token 与 ACP `resource` block 的生成规则。
- `packages/sdk-typescript/src/daemon/ui/types.ts` / `transcript.ts` / `store.ts`：本地 UI transcript 的 file metadata。
- `packages/cli/src/acp-integration/session/Session.test.ts`：daemon resource prompt projection 的端到端断言。

PR 当前声明 `packages/web-shell` 3094 项测试、`packages/webui` 467 项测试、`packages/sdk-typescript` 1502 项测试，以及 CLI Session focused 561 项测试通过。新增覆盖包括 ingestion/classification、composer chip/queue/dedup、daemon prompt resource block、SDK 本地 metadata、retry restoration 和 `File: attachment:///app.log` prompt 注入。浏览器级手工 E2E 尚未执行，PR 中记录了可复现验证步骤。

## feature 文档处理

已在 WebUI/transport 与 SDK 口径中登记为 open diff：它主要是 Web Shell composer 到 daemon prompt resource 的客户端侧能力，不改变 daemon 生产路由或 transcript 持久化格式。

## 边界与风险

- 当前未合入，不能作为 `main` 行为承诺。
- 512 KiB 是浏览器侧文本附件聚合预算，不是通用 daemon resource budget。
- reload/peer client 只看到 `@attachment:///...` token，不恢复原始 file chip metadata。
- slash/shell command 不携带附件 block，避免产生无效 attachment reference。
