# PR #8893 最终实现：非交互会话 OpenAI API 日志清理

> PR: [feat(cli): clean up OpenAI logs in non-interactive sessions](https://github.com/QwenLM/qwen-code/pull/8893)
> 状态：merged，已合入 `main`。
> 规模：+1028 / -86，14 个文件

## 解决了什么问题

#8862 只把 OpenAI API log retention 接入 interactive housekeeping。headless `-p`、stream-json SDK 和 ACP sessions 同样可能启用 `model.enableOpenAILogging`，但短进程或无 TUI 流程不会触发 interactive scheduler，日志仍会长期累积。

## 最终实现方案

#8893 在 housekeeping scheduler 中增加非交互队列：`startNonInteractiveOpenAILogHousekeeping(config, settings)` 按日志目录去重，FIFO 串行扫描，复用 #8862 的 retention、marker、writer-owned 文件名和自定义目录策略。非交互 CLI、stream-json 和 ACP lifecycle 都在启动时注册 log dir。

退出时 `stopNonInteractiveOpenAILogHousekeeping()` 会拒绝新任务、丢弃等待队列、abort 当前 scan，并最多等待 250ms 让文件操作或 lock 释放；异常终止仍依赖一小时 stale lock recovery。`cleanupOldOpenAILogs` 增加 `AbortSignal` 与细粒度 cancellation checks，保证长目录扫描可被退出流程打断。

## 关键代码路径

- `packages/cli/src/utils/housekeeping/scheduler.ts`：non-interactive queue、dedupe、FIFO、retry、stop/abort。
- `packages/cli/src/utils/housekeeping/cleanup.ts`：`cleanupOldOpenAILogs` 的 signal-aware result。
- `packages/cli/src/utils/throttledOnce.ts`：per-dir marker 与 throttle 支撑。
- `packages/cli/src/gemini.tsx`、`packages/cli/src/acpAgent.ts`：non-interactive/ACP lifecycle hook。
- `docs/design/openai-log-retention.md` 与 settings schema：清理模式与配置说明。

## 验证方式

测试覆盖 writer-owned 文件名识别、lookalike 不删除、cutoff、cancellation、自定义目录、retention 0/默认/超大、per-dir throttling、settings fallback、root scan failure、marker catch-up，以及 non-interactive queue 的 dedupe/FIFO/retry/graceful stop/CLI+ACP hooks。

## feature 文档处理

已更新 telemetry/auth-provider 文档，把 #8862 的“interactive only”限制改成 #8862/#8893 的 interactive + non-interactive best-effort retention。

## 边界与风险

- 非交互清理仍是 best-effort，不是写入路径同步删除；极短进程可能在 250ms stop 预算前未完成 scan。
- 自定义共享日志目录仍只接受 user/system 级单一策略，避免 workspace-scoped retention 删除他人日志。
