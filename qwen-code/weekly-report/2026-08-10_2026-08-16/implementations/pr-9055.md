# PR #9055 最终实现：selective daemon session restore

> PR: [perf(serve): Restore large sessions selectively](https://github.com/QwenLM/qwen-code/pull/9055)
> 状态：merged，已合入 `main`。
> 规模：+7504 / -1216，44 个文件

## 解决了什么问题

大型 persisted session 即使只请求最近历史，旧 cold restore 仍会先完整 materialize JSONL transcript，再按 `historyPageSize` 裁剪；writer-lease activation 还可能再次全量读取。这让 restore latency 和 peak allocation 随完整 transcript 增长，并可能拖慢同一 ACP child 中的 sibling session。

## 最终实现方案

#9055 实现 #8743 设计的 selective daemon session restore contract。cold `loadSession` / `resumeSession` 先构建一次 transcript index，只读取恢复模型/runtime state 和目标 replay projection 需要的 records；projection 保留 compressed/legacy model history、record ancestry、interrupted turns、FileHistory、artifacts、Goals/checkpoint evidence、attribution、telemetry、cumulative usage、source metadata 和 background notifications 的 active-chain 语义。

显式 `historyPageSize` 的 response-mode load 在读取 payload 前选择 bounded recent replay，返回 `historyHasMore` / `historyAnchorRecordId` 等分页 metadata，并在 Session 发布前拒绝超过 32 MiB 或 10,000 updates 的 transformed replay envelope。省略 `historyPageSize` 的 load 保持 full visible replay 兼容；channel 与 scheduled-task resume 改走 no-history resume path。writer-lease restore 在 ownership 建立后获取权威 projection，live-session refresh 在 recorder barrier 下复用窄 projection；runtime hydration、response build、Session publication、rollback，以及 Goal/FileHistory/attribution activation 仍在既有事务边界之后。

冷索引设置 256 MiB source-byte ceiling，并在 record 边界 cooperative yield。hidden inherited Goal 会为 runtime correctness 恢复，但被 fence 在 client presentation 之外，直到出现 visible replacement。

## feature 文档处理

已把 #8743 从 docs-only design 推进为 #9055 merged runtime 实现，更新 daemon session lifecycle、protocol/SDK、WebUI/transport、roadmap、resource/telemetry 口径。后续 durable checkpoint、worker-thread parsing、streaming JSON parse 和 sidecar restore 仍未落地。

## 边界与风险

- explicit recent load 现在可能返回已记录的 transcript/replay limit error，而不是无上限分配响应。
- legacy transcript 仍需完整扫描一次；cooperative yielding 无法抢占单条大型 JSON parse。
- 不新增 public success schema 或 caller migration；省略 `historyPageSize` 的客户端保持 full visible replay。
