# PR #9012 当前实现观察：Headless tool_result content projection

> PR: [fix(cli): Bound headless tool result content](https://github.com/QwenLM/qwen-code/pull/9012)
> 状态：open，未合入 `main`。
> 规模：+723 / -158，14 个文件

## 解决了什么问题

Headless JSON、stream-json、persistent stream-json/SDK、subagent adapter 和 Dual Output 会把大型文本工具展示完整序列化到 `tool_result.content`。一个 499,999 字节 fake-MCP 结果会产生约 500KB stdout/JSONL/sidecar，并在 Text 模式内部保留完整 tool result，即使文本输出只显示最终答案。这是 field-level wire 放大和内存驻留问题，不等同于模型上下文 finalizer 或完整 frame/backpressure 限制。

## 当前实现方案

#9012 的 open diff 在 shared Headless adapter 边界对文本 `tool_result.content` 做 JSON string byte projection。预算为 `JSON.stringify(content)` 后最多 65,536 UTF-8 bytes；超限时生成 deterministic 20/80 head-tail preview，并插入传输截断 marker。投影只作用于 transport/display 字段，语义选择、model-facing response、canonical recording 和 producer artifact 保持原样。

新增 `json-string-byte-projection` primitive，按 JSON string payload 规则处理 escaping、UTF-8、多 code unit surrogate 和预算选择；`projectHeadlessToolResultContent` 在 Base JSON adapter 统一调用，因此覆盖 JSON、stream-JSON、persistent stream-JSON/SDK sessions、subagent result、Text-mode retention 和 Dual Output。ACP 侧复用 surrogate-safe truncation primitive，但不迁移 ACP multi-block allocation 或 A2UI 行为。Dual Output protocol version 从 1 提升到 2，因为消费者可观察到 `tool_result.content` 从完整文本变成带 marker 的有界预览。

## 关键代码路径

- `packages/cli/src/utils/json-string-byte-projection.ts`：JSON string byte accounting、prefix/suffix selection、surrogate-safe truncation。
- `packages/cli/src/nonInteractive/io/headless-tool-result-text-projection.ts`：65,536 byte budget 与 marker。
- `packages/cli/src/nonInteractive/io/BaseJsonOutputAdapter.ts`：shared adapter boundary projection。
- `packages/cli/src/nonInteractive/io/JsonOutputAdapter.test.ts` / `StreamJsonOutputAdapter.test.ts`：JSON/stream-json coverage。
- `packages/cli/src/dualOutput/DualOutputBridge.ts`：protocol version 2 与 sidecar projection。
- `docs/users/features/headless.md` / `dual-output.md`：用户可见字段语义。

## 验证方式

PR 声明 268 个 focused CLI tests、build 与 typecheck 通过，并给出 deterministic 499,999 ASCII bytes 前后对比：JSON、stream-json、SDK/subagent/Dual Output 都把 content 序列化限制到 65,536 bytes 左右，Text stdout 仍只含最终答案，producer artifact SHA-256 不变。

## 边界与风险

- 当前未合入，不能作为 `main` 行为承诺。
- 消费者不能再假设 Headless `tool_result.content` 总是完整文本；带 marker 时是预览。
- 不限制完整 JSONL frame、累积 session、tool input、partial message、replay container 或 backpressure。
