# PR #9084 最终实现：daemon logs OpenTelemetry correlation

> PR: [feat(cli): Correlate daemon logs with OpenTelemetry spans](https://github.com/QwenLM/qwen-code/pull/9084)
> 状态：merged，已合入 `main`。
> 规模：+321 / -13，7 个文件

## 解决了什么问题

daemon request/lifecycle 日志即使在 active request span 内输出，也没有 trace context。排障时只能从日志看到 route/status/runId，无法可靠跳转到对应分布式 trace；但直接把所有日志绑定 ambient context 又可能误关联 long-lived child-process raw output 或跨请求 suppression summary。

## 最终实现方案

#9084 给 daemon caller logs 增加可选 OTel correlation fields。`info`、`warn`、`error` 在日志调用时只捕获一次 active span；只有 span recording、context valid 且 sampled 时，stderr 与 daemon file 同时输出 `trace_id` 和 `span_id`。caller-supplied correlation keys 不能伪造或覆盖保留字段，public formatter 仍 deterministic，file log 保留原有 `[DAEMON] runId=... pid=...` prefix。

长期 child-process `raw` records、boot records、file-drop summaries 和 multi-request access-log suppression summaries 明确不关联。access suppression summary 在 OTel root context 里运行，避免吞掉后续当前请求的 context；后续 `request completed` record 会恢复自己的 active request span。

## 关键代码路径

- `packages/cli/src/serve/daemon-logger.ts`：active span capture、reserved key filtering、stderr/file formatter。
- `packages/cli/src/serve/server/access-log.ts`：access log suppression summary root context 隔离。
- `docs/developers/daemon/19-observability.md`：daemon log/trace correlation 文档。
- `packages/cli/package.json` / `package-lock.json`：引入轻量 `@opentelemetry/api` 依赖路径。

## 验证方式

PR 声明 daemon logger、access logger 和 telemetry focused tests 共 117 项通过，覆盖 sampled/recording matrix、malformed context、OTel lookup failure、单次 capture、reserved key filtering、raw/boot/drop-summary exclusion、access suppression、truncation、queueing 与 rotation；还验证 fast-path graph 只依赖轻量 OTel API，以及 always-on sampler + file exporter 的真实 provider 场景。

## feature 文档处理

已在 telemetry/observability 的 trace↔daemon log correlation 章节登记为已合入实现；它只增加日志关联字段，不改变 trace sampling、export、propagation 或业务 request id。

## 边界与风险

- 不处理日志平台索引规则、metric labels、采样策略或业务 request id。
- 只自动关联 caller `info`/`warn`/`error`；raw/boot/drop-summary/suppression summary 仍保持 legacy format。
