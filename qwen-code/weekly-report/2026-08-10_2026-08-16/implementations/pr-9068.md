## 解决了什么问题

Direct External Context 已有 Generic HTTP adapter，但它是 Qwen 维护的私有兼容实现，不适合作为每个 provider 的长期接入方式。没有可移植 profile 时，新 provider 要么需要改 Qwen Core，要么自定义不兼容 MCP shape，且可能把 endpoint、corpus、credential 等选择权暴露给模型。

## 当前实现方案

#9068 当前 draft open diff 定义 External Context Provider Extension Profile v1：provider 团队通过现有 Qwen Extension + MCP 边界独立交付检索集成，manifest 只 allowlist `context_search`。profile 发布 language-neutral input/output JSON schema 与 test vectors；input 只有严格 `query` 字段，undeclared selector/tenant/filter/credential/metadata 在调用 provider 前拒绝。

参考 MCP 工具对齐 schema，同时返回语义一致的 text result 和 `structuredContent`。输出最多 5 条，每条 content 1000 code points，整体 rendered envelope 4000 code units；text output 转义 literal angle brackets，structured output 保留原始内容。diff 还提供 provider-owned remote OAuth 示例和 self-contained local REST adapter 示例：local adapter 从管理员绑定的环境变量读取 base URL/token，对 loopback REST provider 发一次 normalized fixed-limit request，并用 1 MiB bounded body 读取响应。

## 关键代码路径

- `integrations/external-context/contracts/v1/*.schema.json` / `test-vectors.json`：profile v1 语言无关契约。
- `integrations/external-context/src/provider-profile.ts`：runtime schema、query normalization、bounded result rendering。
- `integrations/external-context/src/mcp.ts`：参考 `context_search` MCP tool 的严格输入与 structured/text output。
- `integrations/external-context/examples/provider-extension-local/*`：本地 REST-to-MCP adapter 示例。
- `integrations/external-context/examples/provider-extension-remote/*`：远端 OAuth provider extension manifest 示例。
- `docs/design/external-context-provider-extensions.md`：ownership/auth/output sanitization/trust/rollout 边界。
