## 解决了什么问题

#8911 限制了 raw NDJSON frame 和 decoded readable queue，但 ACP SDK 会继续把消息分发到 handler、pending response、outbound operation 和 outstanding request 等私有队列。失控 child 仍可能通过慢 handler、停止读 stdin、对小请求返回大响应或永不回答 daemon 请求来绕过 stream watermark。

## 当前实现方案

#8947 的 open diff 在 daemon-owned channel 上新增 envelope admission 和 transport guard。消息进入 ACP SDK 前先做 bounded JSON-RPC envelope 验证；active handlers、prepared responses、pre-SDK outbound operations、outstanding request IDs 都按 count 和 conservative bytes 计账，并在 handler response delivery、outbound notification local delivery 或 request settlement 时释放。

fatal protocol、serialization、EOF 或 admission failure 会立即标记精确 workspace channel generation unavailable，终止 tracked child，并阻止 initialize/create/restore/attach/prompt/status 复用该 channel。已经在 fatal 前完整 admitted 的 frame 保持有序可交付。日志和 client error 只使用 metadata-only inspection，不记录 child-controlled payload。

## 关键代码路径

- `packages/acp-bridge/src/bridge.ts`：inbound handler admission、channel generation failure、session ownership rollback。
- `packages/acp-bridge/src/bridgeClient.ts` / guarded connection helpers：outbound guard、request settlement 与 log-safe errors。
- `packages/acp-bridge/src/ndJsonStream.ts` / `spawnChannel.ts` tests：与 #8911 bounds 的组合验证。
- `docs/design/2026-07-31-daemon-capacity-model-and-memory-bounds.md`：资源 guard follow-up 设计。
