# PR #8947 最终实现：daemon ACP transport resource guard 补强

> PR: [fix(serve): Close daemon ACP resource guard gaps](https://github.com/QwenLM/qwen-code/pull/8947)
> 状态：merged，已合入 `main`。
> 规模：+2756 / -177，10 个文件

## 解决了什么问题

#8911 限制了 daemon-owned ACP child 的 raw NDJSON frame 与 decoded readable queue，但 ACP SDK 会继续把消息 drain 到 handler、prepared response、write queue 和 pending response/outstanding request 等私有状态。异常 child 仍可通过慢 handler、停止读 stdin、小 request 大 response、未知 response id 或永不回复 daemon request 来绕过原始 stream watermark。transport failure 也可能在 child 退出前关闭 SDK connection，而 bridge 仍把该 generation 视为可复用。

## 最终实现方案

#8947 在 daemon-owned channel 上新增 bounded JSON-RPC envelope admission 和 transport guard。消息进入 ACP SDK 前先校验 JSON-RPC shape、known-method params、method/id/error 字段 byte 上限、JSON depth/node/array 上限，以及 request/response ownership；active handler、prepared response、pre-SDK outbound operation 和 outstanding request ID 都按 count 与 conservative bytes 计账。

release 点绑定真实生命周期：handler response delivery 后释放 inbound handler budget；outbound notification 本地投递后释放 outbound op；outbound request 在 response/失败/teardown 后释放 outstanding request。fatal protocol、serialization、unexpected EOF、clean EOF、schema violation 或 admission failure 会立刻把精确 workspace channel generation 标记 unavailable，终止 tracked child，并阻止 initialize/create/restore/attach/prompt/status 复用该 generation。fatal 前已完整 admitted 的 frame 仍保持有序可交付。日志和 client error 使用 metadata-only inspection，不记录 child-controlled payload。

public/standalone ACP stream 未提供 limits/guard 时保留 legacy queue、EOF、parse log 与 error response shape。

## 关键代码路径

- `packages/acp-bridge/src/ndJsonStream.ts`：bounded JSON-RPC validator、inbound/outstanding ledgers、低敏 invalid message logging。
- `packages/acp-bridge/src/spawnChannel.ts`：daemon NDJSON limits、prepared response/outbound operation budget、known-method param validator。
- `packages/acp-bridge/src/bridge.ts`：log-safe request errors、guarded client/connection、exact generation unavailable、session ownership rollback。
- `packages/acp-bridge/src/channel.ts`：`AcpChannelTransportGuard` contract。
- `packages/cli/src/acp-integration/acpAgent*.test.ts`：daemon runtime 竞态回归。

## 验证方式

PR 声明 727 个 ACP bridge focused tests、243 个 daemon runtime tests、full build/typecheck/lint、Prettier、diff check、直接 SDK backpressure probes 与多轮 correctness/compat/resource-bound review 通过。验证重点是 handler saturation、outbound backpressure、malformed params、unknown response id、EOF、initialize/new/load/attach/prompt/status racing teardown 都不留下 lease、session ownership 或可复用 dead generation。

## feature 文档处理

已在 ACP bridge 权限文档和 resource budgeting 中把 #8947 从 open 观察改为已合入 guard。

## 边界与风险

- 只有 `qwen serve` daemon-owned ACP channel opt in；公共/standalone ACP 默认不变。
- guard 使用 conservative byte charge，可能早于理论独立 count/byte 同时满时回收 channel。
- 仍不覆盖跨 workspace stream aggregate quota、EventBus/replay bounds 或 outbound allocation 前 canonical encoder。
