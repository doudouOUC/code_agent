## 解决了什么问题

WebUI 收到 event epoch 或 replay ring gap 后，旧 state resync 会先清空 transcript、session reference、cursor 和 source stream，再发起 replacement load。restore 延迟或失败时，用户会看到空白或混合 owner 状态；live-journal repair 也复用 destructive reload path，可能打断原本健康的 source stream。

## 当前实现方案

#9048 的最终关闭 diff 把 authoritative state resync 和 live-journal repair 纳入现有 provider-local restore coordinator。发生 gap 时，provider park 已知 gapped source stream，但保留最后合法 transcript 和 attachment，以 read-only recovery state 展示；完整 replacement snapshot 在离屏 candidate 中恢复，复用 committed stable client id，并在 commit 前校验 session/workspace ownership、replay completeness、epoch/watermark、prompt terminal consistency 和 lifecycle freshness。

live-journal repair 不再 destructive reload：healthy source SSE 保持 attached，同时 staging full snapshot，并捕获 bounded same-epoch source tail；commit 时用 repaired suffix + tail 原子替换 truncation marker。历史 replay 不重新发布 notice、workspace event 或 pending/mid-turn event，只在 post-commit 做一次 side-channel reconciliation。WebShell main view、split panes、queued prompts 与 action layer 在 recovery preparing 或真实 gap 未解除时统一阻断 session mutation，但允许只读查看与导航。
