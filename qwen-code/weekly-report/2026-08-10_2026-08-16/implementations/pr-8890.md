## 解决了什么问题

standalone/projectless sessions 需要复用现有 Conversations runtime，但旧代码把 Conversations workspace、source helper 和 runtime publication 嵌在 Live Voice 绑定路径里。这样未来无项目会话若要复用 runtime，容易被迫启用 Live、重复创建第二套 projectless runtime，或绕过 Live 已有的 strict ownership、one-flight publication、失败重试和 handler teardown 语义。

## 最终实现方案

#8890 最终实现 standalone daemon sessions 设计中的 PR0 基础设施，而不是直接上线 standalone session API。它把 `conversation-workspace`、`session-source` 等 helper 从 `serve/live` 移到 `serve/conversations`，保留既有 `live-conversation` provenance、storage layout、relocation token、metadata、capability 与用户可见 Live 语义。

新增 `ConversationRuntimeManager` 作为 daemon 内部单例 runtime manager：并发 ensure 只做一次 publication；每次 reuse 都重新校验 Conversations root；已有 active owned runtime 可被 adopt；invalid、draining、blocked、removed、generation replaced 或 root 不精确的 runtime 都 fail closed，不发布替代 runtime，也不 fallback primary。ensure runtime 只注册 runtime 和 bridge，不触发 ACP preheat、provider probe 或 native Host 初始化。

Live Voice 变成 adapter：在共享 Conversations runtime 上事务式安装三个 bridge handler，部分绑定失败会清除全部 handler，后续可复用已发布 runtime 重试；shutdown 等待 in-flight binding、清理 handler，runtime/bridge dispose 继续交给 workspace lifecycle。

## 关键代码路径

- `packages/cli/src/serve/conversations/conversation-runtime-manager.ts`：single-flight publication、adopt/revalidate/fail-closed 规则。
- `packages/cli/src/serve/conversations/conversation-workspace.ts`：Conversations root 创建、realpath/revalidate、exact-root identity。
- `packages/cli/src/serve/conversations/session-source.ts`：shared session source parsing/formatting。
- `packages/cli/src/serve/server.ts` / `run-qwen-serve.ts`：Conversations manager 注入与 Live handler binding。
- `packages/cli/src/serve/live/*`：Live 专属调用迁移到 shared conversations helpers。
