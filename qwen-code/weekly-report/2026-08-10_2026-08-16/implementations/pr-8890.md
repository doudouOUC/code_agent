## 解决了什么问题

当前 daemon session creation 如果没有明确 `cwd`，仍容易隐式绑定 primary workspace。顶层聊天、临时任务或 workspace 被移动/删除后的继续会话，都可能被误解为“项目内 session”，从而继承错误的路径、trust、文件系统和清理语义。

## 当前实现方案

#8890 只新增设计文档，不改变 runtime 行为。方案把 standalone session 定义为 daemon-managed 资源：会话有独立私有 work dir，生命周期由 daemon 创建、恢复、删除和故障恢复；请求必须显式区分 standalone、workspace 和 Live context，不能在缺少 `cwd` 时 fallback primary workspace。

文档还规定了事务边界：create/delete 失败需要 rollback；managed dir 缺失、被移动或疑似 compromised 时要有确定错误和恢复策略；旧客户端通过 capability gate 继续按 workspace 语义运行。设计把 SDK/REST route shape、session catalog 展示、archive/export、cleanup 和测试验收矩阵先冻结，方便后续实现按小 PR 落地。
