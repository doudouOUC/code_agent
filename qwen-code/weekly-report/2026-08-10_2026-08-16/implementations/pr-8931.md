# PR #8931 最终实现：prompt-safe session navigation

> PR: [fix(web-shell): Enforce prompt-safe session navigation](https://github.com/QwenLM/qwen-code/pull/8931)
> 状态：merged，已合入 `main`。
> 规模：+636 / -0，7 个文件

## 解决了什么问题

transactional switching 让 source 在 target 准备期间继续可见，但 write gate 可能已经关闭。一个 prompt submission 若在 navigation 前启动 async host `onSubmitBefore` hook，hook 返回后可能绕过旧检查，清空 composer/follow-up 或提交 draft，再在更底层 action 失败，造成用户输入丢失。

## 最终实现方案

#8931 在 direct prompt 和 queued prompt 的 async admission hook 返回后，再次读取 session write gate。若当前 session navigation 已进入 queued/preparing/transition 状态，submission 直接停止：不清 follow-up、不 commit composer、不分配新 session、不发送 prompt、不 enqueue。

文档同时固定 prompt-safe navigation contract：session navigation 本身不得生成 cancel、continuation、prompt replay 或 mid-turn 请求。这样切换期间的 UI 可见状态和执行 side effect 分离，用户草稿保留在 source owner。

## 关键代码路径

- `packages/web-shell/client/App.tsx`：host submission gate 与 navigation interaction。
- `packages/webui/src/daemon/session/actions.ts` / Provider tests：queued/direct prompt 二次 gate。
- `docs/design/2026-08-11-prompt-safe-session-navigation.md`：navigation 不产生 prompt-like side effects 的契约。
- real-daemon integration tests：request ledger 验证 navigation 不生成额外 execution request。

## 验证方式

PR focused race regressions、297 个 WebUI provider/action tests、4 个 real daemon session-switching tests 通过。关键断言是旧 source prompt 只出现一次，切换本身不产生 cancel/continuation/prompt replay/mid-turn 请求，draft 在 write gate 关闭后仍保留。

## feature 文档处理

已更新 WebUI/transport 文档，作为 #8882/#8939 事务切换链路里的 prompt write-gate hardening。

## 边界与风险

- 新增 prompt submission path 必须在 async hook 后复用同一 write gate 检查。
- 该 PR 不解决 restore shape coalescing 或 same-session refresh，这些分别由 #8933/#8939 处理。
