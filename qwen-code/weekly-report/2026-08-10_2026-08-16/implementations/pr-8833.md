# PR #8833 最终实现：按 attachment identity 隔离 WebUI stale session work

> PR: [fix(webui): Fence stale session work by attachment identity](https://github.com/QwenLM/qwen-code/pull/8833)
> 状态：merged，已合入 `main`。
> 规模：+724 / -95，4 个文件

## 解决了什么问题

WebUI Provider 过去把 `sessionId` 当作会话异步工作的充分 owner identity。同一个 persisted session reload/reattach 后，新旧 attachment 共享同一个 `sessionId`，但 `clientId`、SSE stream、runner、metadata 请求和 cleanup 都已不同。旧 attachment 的迟到 metadata、SSE output、`session_closed`、heartbeat 410 或 cleanup 可能覆盖新 attachment，造成错误断连、stale transcript 或把 replacement session detach 掉。

## 最终实现方案

#8833 把 WebUI session-owned async continuation 的 guard 从 `sessionId` 提升为精确 attachment 对象/`clientId`。`DaemonSessionProvider` 的 SSE runner 在应用 streamed events、terminal frame、heartbeat failure、transcript batch、runner cleanup 前，都验证当前 provider 仍拥有启动该 runner 时捕获的 session attachment；被同 id replacement 替换后，旧 runner 只能自我收尾，不能写共享 connection/transcript 状态，也不能 detach 新 owner。

same-session reload handoff 的 cleanup 也改为精确 retire：source attachment 与 replacement attachment 分别记录，成功 reload 后只 detach 应回收的 source；Provider unmount 发生在 replacement load settle 前时，source 和 replacement 会各自最多 retire 一次。actions 层的 model、approval mode、supported commands、context refresh 等 late completion 同样在写 state 前读取当前 session ref，发现 attachment 已替换就丢弃结果。

该 PR 保留原有 detach-first session switching 行为，不做可见状态事务化；跨 session restore pending 期间保留 source UI、WebShell coordination、resync/repair staging 和 branch adoption 留给后续 #8882 等 PR。

## 关键代码路径

- `packages/webui/src/daemon/session/DaemonSessionProvider.tsx`：runner/session ownership guard、heartbeat failure guard、same-session reload cleanup 与 unmount settlement。
- `packages/webui/src/daemon/session/actions.ts`：`setModel`、`setApprovalMode`、`refreshCommands`、`getContext` 等 action completion 的 stale attachment fence。
- `packages/webui/src/daemon/session/DaemonSessionProvider.test.tsx`：same-id stale SSE、`session_closed`、heartbeat 410、reload cleanup 和 unmount replacement 回归。
- `packages/webui/src/daemon/session/actions.test.ts`：late metadata/action completion 不覆盖 replacement attachment。

## 验证方式

PR 声明运行 `cd packages/webui && npx vitest run src/daemon/session/actions.test.ts src/daemon/session/DaemonSessionProvider.test.tsx`，250 个 WebUI 单测通过；并运行 `npm run typecheck && npm run lint && npm run build`。聚焦回归用两个相同 `sessionId`、不同 `clientId` 的 attachment 确定性复现旧 metadata/SSE/session_closed/heartbeat 污染，修复后 replacement 保持 connected 且内容不变。

## 边界与风险

- guard 依赖 attachment 对象身份；未来新增 session-owned async path 必须复用同一 ownership 检查。
- 该 PR 不改变 restore performance、daemon wire protocol、SDK public API 或 WebShell host coordination。
- Windows/Linux 未在本地验证，跨平台依赖 CI。
