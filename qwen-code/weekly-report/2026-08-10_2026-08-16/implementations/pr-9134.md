# PR #9134 最终实现：active-work close authorization follow-up

> PR: [fix(daemon): Preserve sessions when active-work close is refused](https://github.com/QwenLM/qwen-code/pull/9134)
> 状态：已合入 `main`（2026-08-16）。
> 规模：+515 / -31，5 个文件

## 解决了什么问题

#9042 合入后，active-work close 仍有多条 post-merge 生命周期竞态。第一，conditional close 可能在 running turn 还没登记 shell hold 前先取消 cron、Goal、notification 等 queued work，随后 running turn settle 出 shell hold，close 被拒绝，但保留下来的 Session 已经被破坏。第二，spawn-owner kill 在还有其它 attacher 时被延后后，如果 child 只协商 legacy `agent`/`notification` 类别而没有 `shell`，最后一个 attacher detach 后可能因为 reporting coverage incomplete 而一直不执行 kill。第三，deferred kill 若撞上 conditional-close probe、force close 或 child 内部 close gate（如 cd/restore），旧逻辑会把明确拒绝也升级为 channel kill，连同同 channel sibling sessions 一起杀掉。

## 当前实现方案

#9134 最终把 automatic active-work close authorization 改成非破坏性两阶段。child 收到 `onlyIfUnheld` close 时先读取已有 holds；如果已有 hold，立即返回 `closed:false`，不等待、不取消队列、不 dispose Session。若初始为空，则在 close gate 下让 already-running turn 自然 settle，再次读取 holds；只有第二次仍为空，才进入破坏性取消 pending prompt、flush recorder、dispose Session 的 teardown。成功路径通过 invocation order 测试固定为先 settle/复查，再 abort active generation。

两个 drain 阶段共享同一个 child-side deadline。daemon 用 `sessionCloseDrainBudgetMs()` 从实际 outer wait（含 `opts.timeoutMs`）推导 child `drainTimeoutMs`，branch restore cleanup 也补上传参；child 第一个自然 settle 阶段用掉的时间会从第二个 destructive drain 与 history mutation wait 预算里扣除，timeout message 仍报告共享总预算，避免 oncall 被剩余 1ms 之类的内部残值误导。

daemon 侧也调整 detached cleanup 顺序和失败语义：如果存在 deferred spawn-owner kill，并且最后一个 attacher 已离开，先确认 entry 仍是当前对象且没有 close/authorization in-flight，再执行 force kill 并输出一条低敏 stderr；否则让现有 close/probe settle 后再处理。`killSession` 遇到 definitive ACP `RequestError`（child 表示 close 已在进行）会复位 `entry.closing` 并返回 `false`，而不是 SIGTERM 整个 channel。这样显式 spawn-owner kill 继续保持强制语义，但不会因 close gate/refusal 误杀 sibling sessions；quarantined channel detached reap 也继续强制。

## feature 文档处理

已在 daemon session lifecycle、ACP bridge 和 daemon 总览中作为 #9042 merged follow-up 登记：#9042 已合入 shell activeWork retention，#9134 只修 automatic close 授权拒绝时的非破坏性、deferred spawn-owner kill 回收顺序和 close refusal/close gate 竞态。

## 边界与风险

- automatic cleanup 现在会在有界预算内等待 running child turn 自然 settle；若 turn 卡死，授权失败并保留 Session 是预期 fail-closed 行为。
- child 明确拒绝 close 时 daemon 选择保留 entry 并等待下一次 settle/retry；这避免误杀 sibling sessions，但也意味着真正卡住的 child 仍依赖后续 watchdog、operator kill 或 channel exit。
- channel liveness、Agent watchdog、shell stall detection、公开 health 字段、持久化格式和协议版本不在本 PR 内。
