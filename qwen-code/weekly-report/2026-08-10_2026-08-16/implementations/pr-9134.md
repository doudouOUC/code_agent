# PR #9134 当前实现观察：active-work close authorization follow-up

> PR: [fix(daemon): Preserve sessions when active-work close is refused](https://github.com/QwenLM/qwen-code/pull/9134)
> 状态：open，未合入 `main`。
> 规模：+141 / -27，4 个文件

## 解决了什么问题

#9042 合入后，active-work close 仍有两个 post-merge 生命周期竞态。第一，conditional close 可能在 running turn 还没登记 shell hold 前先取消 cron、Goal、notification 等 queued work，随后 running turn settle 出 shell hold，close 被拒绝，但保留下来的 Session 已经被破坏。第二，spawn-owner kill 在还有其它 attacher 时被延后后，如果 child 只协商 legacy `agent`/`notification` 类别而没有 `shell`，最后一个 attacher detach 后可能因为 reporting coverage incomplete 而一直不执行 kill。

## 当前实现方案

#9134 当前 open diff 把 automatic active-work close authorization 改成非破坏性两阶段。child 收到 `onlyIfUnheld` close 时先读取已有 holds；如果已有 hold，立即返回 `closed:false`，不等待、不取消队列、不 dispose Session。若初始为空，则在 close gate 下让 already-running turn 自然 settle，再次读取 holds；只有第二次仍为空，才进入破坏性取消 pending prompt、flush recorder、dispose Session 的 teardown。

两个 drain 阶段共享同一个 child-side deadline。daemon 在既有 10 秒 active-work close round-trip timeout 内传入 8 秒 `drainTimeoutMs`，child 第一个自然 settle 阶段用掉的时间会从第二个 destructive drain 预算里扣除，避免总等待超过 daemon deadline。

daemon 侧也调整 detached cleanup 顺序：如果存在 deferred spawn-owner kill，并且最后一个 attacher 已离开，先执行 force kill，再判断是否 ordinary automatic close candidate。这样显式 spawn-owner kill 继续保持强制语义，即使旧 child active-work reporting 只有 legacy category，仍不会被普通 cleanup 的 partial coverage guard 永久挡住；quarantined channel detached reap 也继续强制。

## 关键代码路径

- `packages/cli/src/acp-integration/acpAgent.ts`：`closeSession` 的 only-if-unheld early hold check、natural-settle drain、remaining budget 计算和 destructive teardown 排序。
- `packages/acp-bridge/src/bridge.ts`：daemon active-work close 调用传入 8 秒 child drain budget，并在 detached cleanup 前处理 deferred spawn-owner kill。
- `packages/cli/src/acp-integration/acpAgent.test.ts`：conditional close 不破坏 queued work、共享 timeout budget 的 child 测试。
- `packages/acp-bridge/src/bridge.test.ts`：legacy category child、deferred spawn-owner kill、quarantine reap 与 incomplete reporting cleanup guard 回归。

## feature 文档处理

已在 daemon session lifecycle 和 daemon 总览中作为 #9042 follow-up open diff 登记：#9042 已合入 shell activeWork retention，#9134 只修 automatic close 授权拒绝时的非破坏性和 deferred spawn-owner kill 回收顺序。

## 边界与风险

- 当前未合入，不能作为 `main` 行为承诺。
- automatic cleanup 现在会在有界预算内等待 running child turn 自然 settle；若 turn 卡死，授权失败并保留 Session 是预期 fail-closed 行为。
- channel liveness、Agent watchdog、shell stall detection、retry 行为、公开 health 字段、持久化格式和协议版本不在本 PR 内。
