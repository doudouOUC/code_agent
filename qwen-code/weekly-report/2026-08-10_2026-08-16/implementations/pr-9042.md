# PR #9042 最终实现：background shell activeWork retention

> PR: [feat(daemon): Track background shells in activeWork](https://github.com/QwenLM/qwen-code/pull/9042)
> 状态：merged，已合入 `main`。
> 规模：+728 / -50，16 个文件

## 解决了什么问题

Prompt 启动长时间后台 shell 后可以立即 settle。旧 `activeWork` 只覆盖 accepted prompt、background Agent 和 Agent terminal notification；deep health 可能在 shell 仍 running 时报告 `activePrompts:0`、`activeWork:false`、`activeWorkReporting:"full"`，让重启或 idle cleanup 误判 session 空闲并清理掉后续 shell terminal notification。

## 最终实现方案

#9042 将 Session-managed background shell 纳入 activeWork retention fact。child Session 本地 collector 在任意已登记 shell running、shell terminal notification queued，或该 notification 正在驱动父 continuation 时返回一个 bounded `shell` hold；详细 shell 状态仍保留在 task/status surface，activeWork wire 只上报一个聚合类别。

active-work v1 handshake 改为显式协商 `agent`、`notification`、`shell` 三类。新 daemon 遇到缺少 `shell` 类别的旧 v1 child 时报告 partial coverage，并禁止该 session 的普通自动 cleanup；新 child 连接旧 daemon 时 wire 上只发 legacy 类别，但本地 conditional close 仍会在 shell work 存在时拒绝。显式 close、kill、shutdown、channel exit 和 condemned restore cleanup 保持强制语义。

## 关键代码路径

- `packages/acp-bridge/src/bridgeTypes.ts` / `bridge.ts`：activeWork hold category 协商与 compatibility 语义。
- `packages/cli/src/acp-integration/active-work-reporter.ts`：按对端协商类别过滤快照。
- `packages/cli/src/acp-integration/acpAgent.ts`：child initialize activeWork capability 与 snapshot 上报。
- `packages/cli/src/acp-integration/session/Session.ts`：Session collector 汇总 shell running/notification/continuation holds。
- `packages/core/src/services/backgroundShellRegistry.ts`：background shell registry 的 active hold 源。

## 边界与风险

- 长时间运行的开发服务器会有意保持 `activeWork:true`。
- PID 探测、shell stall detection、进程恢复、Monitor、workflow、cron、follow-up work 与外部 detached process 不在本 PR 内。
- #9134 merged follow-up 继续修复 automatic active-work close 授权在 refused close 前不应破坏 queued work、deferred kill 不应撞进 close/probe in-flight，以及 child definitive refusal 不应误升级 channel kill 的后续竞态。
