## 解决了什么问题

`GET /workspaces/:workspace/sessions` 是 persisted catalog 查询，会按请求形状扫描 JSONL、读取 organization/worktree sidecar、过滤分页，并合并 bridge live state。把它当成高频 active/waiting/client-count 探针，会让轻量 volatile status 刷新反复触发最重的 catalog 路径，大型或慢 session store 下容易把 sidebar/status polling 变成 timeout 风险。

## 最终实现方案

#9261 最终实现新增 `workspace_session_live_state` capability 与 trusted-only、memory-only `GET /workspaces/:workspace/sessions/live-state`。route 仅从 selected trusted workspace runtime 的 bridge 内存读取，返回 `v:1`、`catalogVersion:{generation,revision}` 与完整 live session volatile snapshot：`clientCount`、`hasActivePrompt`、permission/user-question 等等待标志。它不读取 storage、settings、commands 或 ACP child，不接受 query，不 fallback primary；untrusted workspace 在 bridge read 前返回 403，unknown selector 返回 400，transitioning generation 返回 503 + `Retry-After`。

catalog version 是 daemon-local equality token。bridge 提供 `getSessionCatalogVersion()` 和 `markSessionCatalogChanged()`，`generation` 随 bridge 重建变化，`revision` 只在当前 generation 内单调递增；客户端只能比较整对 token 是否相等，不能做 revision arithmetic。revision 覆盖 live registration/removal、display name、worktree summary、persisted branch/fork commit、archive/delete/organization/group 等 daemon-observed catalog membership/static metadata 变化；普通 prompt/transcript activity、attach/detach/permission wait 等 volatile state 不递增，而由 live-state response 直接携带。

route 维护 last-exposed version。首次或变更后暴露新 version 前，会同步失效 active 与 archived persisted catalog cache，避免客户端看到新 token 后又命中旧 catalog snapshot。REST/ACP catalog mutation 共用 invalidate-then-mark helper，保留 no-op mutation 的精确语义；live lifecycle mark 通过 `emitSessionLifecycle` 收口。客户端 handshake 是 `live A -> full sessions -> session groups(如启用) -> live B`，只有 A/B 相等且资源请求在 A 之后启动并成功，才能接受 bundle；版本驱动 reload 需要 coalesce 和 backoff。

TypeScript SDK 新增 `DaemonSessionCatalogVersion`、`DaemonSessionLiveState`、`DaemonWorkspaceSessionLiveState`，并提供 `DaemonClient.getWorkspaceSessionLiveState()` / `WorkspaceDaemonClient.getSessionLiveState()`。SDK helper 走 native REST，正确编码 workspace selector，不对每次 poll 做 capability preflight；旧 daemon 缺 capability 时客户端应回退原 catalog path。

## 边界与风险

- 导出的 `AcpSessionBridge` 接口新增 `getSessionCatalogVersion()` / `markSessionCatalogChanged()`，对外部 structural bridge implementation 或完整 typed test fake 是源码级契约变化。
- 该协议不观察其它 daemon、TUI 或外部进程直接写入的 persisted store；停止全量 catalog polling 后，这些变化没有有界发现时间。
- 普通 turn activity 不递增 catalog version，跨 controller 的 ordering/updatedAt 可能到下一次 catalog reload 才刷新。
- 保守的额外 revision increment 是协议允许的；真正危险的是在失效旧 catalog cache 前暴露新 revision，或遗漏 daemon-owned writer 的 mutation mark。
