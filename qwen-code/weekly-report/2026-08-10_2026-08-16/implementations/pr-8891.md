# PR #8891 最终实现：Web Shell 共享 session catalog 调度

> PR: [feat(web-shell): Share session catalog scheduling](https://github.com/QwenLM/qwen-code/pull/8891)
> 状态：merged，已合入 `main`。
> 规模：+4486 / -808，32 个文件

## 解决了什么问题

Web Shell 的 sidebar、overview、split picker、dialogs 和 command lookup 会独立拉取 session catalog。相同 daemon client 和相同查询会重复 polling、重复 pagination，并让慢响应或 mutation 后的旧数据覆盖较新的 UI 状态。

## 最终实现方案

#8891 引入 page-scoped `SessionCatalogStore`。同一个 `DaemonClient` 通过 WeakMap 复用 store；相同 query 共享 cached page 和 in-flight request。调度器对 client-wide list 请求限流：总并发 2，background 并发 1，显式用户动作保留可用 slot。

store 保留 legacy route 与 workspace-qualified route 的 owner 语义，不改变 public hook API。订阅者归零后 entry 保留 30 秒，避免频繁 mount/unmount 立刻冷启动。hidden page 暂停 pending automatic work，visible 后只补 overdue active queries；transient error 保留 last success，retry floor 为 30 秒。session create/close/delete/archive/unarchive、metadata 和 organization mutation 会 invalidate 或保守 patch owning workspace，避免 stale catalog 扩散。

## 关键代码路径

- `packages/web-shell/client/session-catalog/session-catalog-store.ts`：`SessionCatalogStore`、query key、in-flight/cached page、scheduler 与 mutation invalidation。

## 验证方式

PR 覆盖 focused WebShell unit tests、dialog/Vite tests、Playwright smoke、lint、format、typecheck、prod/lib build。回归重点是相同 query 只发一次请求、mutation 后 owning workspace 刷新、hidden/visible 调度、错误保留 last success 和 route ownership 不串。

## feature 文档处理

已同步到 daemon WebUI/transport 文档和 daemon 总览，作为已合入的 WebShell shared session catalog 能力。

## 边界与风险

- store 只共享同一 `DaemonClient` 范围内的 catalog，不跨 baseUrl/token/client 实例。
- background refresh 仍是 best-effort；显式用户动作才拥有更高调度优先级。
- 新增 catalog consumer 必须走 shared hooks，否则会重新引入重复 polling。
