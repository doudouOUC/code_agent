# PR #8852 最终实现：已授权外部 built-in text write 的 same-host 写入闭环

> PR: [fix(serve): Allow approved external built-in text writes](https://github.com/QwenLM/qwen-code/pull/8852)
> 状态：merged，已合入 `main`。
> 规模：+1495 / -56，31 个文件

## 解决了什么问题

#8620 让 same-host daemon-owned bridge 的 direct text read/pre-read 回到 ACP child 本地权限系统，但最终 text write 仍委派给 daemon `WorkspaceFileSystem`。用户批准内置 `write_file`、edit、notebook edit 或 controlled shell sed edit 写 workspace 外路径后，core permission 已通过，最终 ACP `writeTextFile` 仍会被 WFS workspace boundary 拒绝为 `path_outside_workspace`。这会让工具失败，并可能诱导模型转用 shell fallback 做同一写入。

## 最终实现方案

#8852 为 core built-in write 请求增加严格的内部 provenance。`packages/core/src/services/tool-write-origin.ts` 定义 `qwen-code/tool-write-origin` `_meta` 标记，source 只允许 `write_file`、`edit`、`notebook_edit`、`shell_sed_edit` 等受支持来源，格式带版本且只允许单个 marker key。`AcpFileSystemService` 只有在请求来自 trusted core origin 时才构造该 marker，并会剥离 caller-supplied provenance，避免普通 ACP/HTTP 调用伪造。

serve 侧 `BridgeFileSystemAdapter` 在处理 `writeText` 时先用 workspace resolver 判断目标是否仍在 workspace 内；workspace 内写入继续走原 WFS path，保持既有审计和边界。workspace 外写入只有在 adapter 显式 opt-in、runtime trusted、generation live、marker 合法且来源受支持时，才调用 `WorkspaceFileSystemFactory.writeSameHostToolText`。缺 marker、marker 格式错误、factory 不支持、untrusted runtime、stale generation 或通用 ACP/HTTP 路径全部 fail closed。

host writer 对 workspace 外文件做 canonical target 校验与 per-path lock：新文件要求 parent realpath 可解析且为目录；已有文件要求 canonical target 是普通文件；leaf symlink、dangling symlink、目录、socket/特殊文件、TOCTOU leaf replacement 和 closed generation 均拒绝并记录一次 denied audit。写入使用 `atomicWriteTextResolvedFile`，保留已有 mode，新文件使用 `0600`，支持 BOM/encoding/lineEnding 元数据，并在编码后 enforce 5 MiB 上限。

## 关键代码路径

- `packages/core/src/services/tool-write-origin.ts`：内部 provenance marker 的 build/parse/sanitize。
- `packages/core/src/services/fileSystemService.ts`：`CoreWriteTextFileRequest` 携带 `toolWriteOrigin`。
- `packages/core/src/tools/write-file.ts` / `edit.ts` / `notebook-edit.ts` / `shell.ts`：内置工具调用写文件时标记真实来源。
- `packages/cli/src/acp-integration/service/filesystem.ts`：trusted core origin 才序列化 marker，外部请求无法伪造。
- `packages/cli/src/serve/bridge-file-system-adapter.ts`：workspace 内外路由分流、metadata sanitization 和 fail-closed 检查。
- `packages/cli/src/serve/fs/workspace-file-system.ts`：`writeSameHostToolTextOutsideWorkspace`、canonical path lock、symlink/regular-file/generation guard、atomic write 和 audit。
- `integration-tests/cli/qwen-serve-streaming.test.ts`：真实 daemon/fake model 覆盖 approve/reject/YOLO 外部写入，无 shell fallback。

## feature 文档处理

已同步更新 daemon 文件系统边界与 ACP bridge 权限文档，把 #8852 记录为 #8620 之后补齐的 approved external built-in text write host route。文档明确 HTTP `/file`、通用 ACP 和 caller-injected bridge 没有放宽 workspace 边界。

## 边界与风险

- 安全性依赖内部 provenance marker 不可由外部 caller 注入；相关 sanitize/parse 测试需随 wire 字段演进保持同步。
- 普通 shell redirection 仍走 shell 权限系统，不属于该 host writer。
- 预读内存压力、批准前 external diff fan-out、local-read opt-out 和模型在 policy rejection 后继续重试仍是后续问题。
