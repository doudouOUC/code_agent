# PR #8892 最终实现：persisted session catalog 短 TTL single-flight 缓存

> PR: [perf(cli): Cache persisted session catalogs](https://github.com/QwenLM/qwen-code/pull/8892)
> 状态：merged，已合入 `main`。
> 规模：+1683 / -116，12 个文件

## 解决了什么问题

organized、pinned、source-filtered、archived 和 LiveTask 相关 session list 会反复扫描 persisted JSONL 与 worktree sidecar。并发查询、多个 workspace 视图或 WebShell polling 会放大磁盘扫描，session 数量上来后造成 route 延迟和 event-loop lag。

## 最终实现方案

#8892 新增 process-local `PersistedSessionListCache`，TTL 为 2 秒。缓存 key 由 resolved runtime root、精确 workspace identity 和 active/archive state 构成；同 key 并发扫描走 single-flight。缓存内容只包含 persisted JSONL summary 与 worktree sidecar catalog。

Live bridge state、organization metadata、filter/sort/pagination 仍在每个请求中独立计算，确保短 TTL 不冻结动态状态。REST/ACP metadata、close、delete、archive、unarchive 等 mutation 会在响应前失效对应 active/archive catalog。telemetry/status 上能区分 `scan`、`cache_hit` 和 `single_flight`，便于后续判断缓存收益和等待者数量。

## 关键代码路径

- `packages/cli/src/serve/server/persisted-session-list-cache.ts`：缓存 key、snapshot、TTL、single-flight 与 invalidation。
- `packages/cli/src/serve/routes/session.ts` / session list helpers：把 persisted scan 接入 cache。
- `packages/cli/src/serve/server.test.ts`：并发查询、mutation invalidation、runtime-root isolation 和 cache status telemetry。
- `docs/design/session-list-persisted-catalog-cache.md`：缓存边界与 non-cached dynamic state。

PR 聚焦测试覆盖多查询并发、warm cache、Live/org freshness、mutation invalidation、runtime root 隔离和 cache status。全仓 build/typecheck 在当时受既有 Ink selection 与 WebShell generated declarations 问题阻塞，未作为该 PR 的通过信号。

## feature 文档处理

已同步到 daemon session lifecycle，强调缓存只覆盖 persisted catalog，不改变 Live bridge、organization、过滤排序和分页语义。

## 边界与风险

- TTL 很短，目标是削峰而非长期 cache；调用方不能把它当作强一致存储。
- 每个 mutation path 都必须记得 invalidation，否则 2 秒窗口内可能看见旧 catalog。
- cache key 必须保留 runtime root/workspace/archive 维度，避免 multi-workspace 串读。
