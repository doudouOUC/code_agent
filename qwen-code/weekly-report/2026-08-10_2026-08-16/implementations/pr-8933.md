# PR #8933 最终实现：restore request shape-aware coalescing

> PR: [fix(serve): Keep restore request shapes distinct](https://github.com/QwenLM/qwen-code/pull/8933)
> 状态：merged，已合入 `main`。
> 规模：+902 / -26，7 个文件

## 解决了什么问题

restore coalescing 只看 target session/workspace 时，会把不同 replay 语义的请求错误合并：`load` 可能满足 `resume`，`load/recent(100)` 可能共享 `load/recent(500)` 或 `load/all`，导致 WebUI staging 拿到错误 replay 页面。该问题会直接破坏 #8882/#8939 的事务切换前提。

## 最终实现方案

#8933 在 ACP bridge 和 WebUI Provider 两端引入 restore request shape identity。restore intent 不再只由 session/workspace 决定，而是包含 replay kind：`resume/none`、`load/all` 或 `load/recent(N)`。只有完全相同 shape 才能 coalesce；非等价 restore 要么串行等待，要么按 transition/lifecycle fence 明确冲突。

WebUI 侧把 raw restore result 和待提交 target 绑定到 shape identity，superseded 或 stale result 即使稍后返回，也不能 commit 到当前 owner。ACP bridge 侧在 restore admission 前校验 effective page，确保 daemon 返回的 replay 模式与请求语义一致。

## 关键代码路径

- `packages/acp-bridge/src/bridge.ts` / `bridgeTypes.ts`：restore state identity、load/resume/recent/all 区分与 conflict/coalesce 语义。
- `packages/webui/src/daemon/session/DaemonSessionProvider.tsx`：Provider restore coordinator 使用 shape identity fence raw result。
- `integration-tests/cli/qwen-serve-webui-session-switching.test.ts`：切换与 restore shape 组合回归。
- `docs/design/2026-08-10-transactional-webui-session-switching.md`：设计契约补充。

## 验证方式

PR 声明通过 bridge/WebUI focused tests 与真实 daemon session-switching integration。验证重点是 `resume` 不被 `load` 满足、`recent(N)` 不被不同 `N` 或 `all` 复用、被 supersede 的 restore result 不能覆盖最新 owner。

## feature 文档处理

已把 session lifecycle 和 WebUI/transport 文档中该 PR 从 open 观察改为已合入实现，并作为 #8939 same-session refresh 的前置不变量。

## 边界与风险

- 该 PR 不改变 selective JSONL 读取策略，只修复现有 restore response 的 coalescing 语义。
- 新增 shape 必须保持 additive；旧 daemon/旧客户端仍按既有 full/recent/resume 兼容路径工作。
