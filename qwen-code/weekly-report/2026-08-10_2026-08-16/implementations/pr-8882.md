# PR #8882 当前实现观察：WebUI cross-session switching 事务化

> PR: [fix(webui): Make cross-session switching transactional](https://github.com/QwenLM/qwen-code/pull/8882)
> 状态：open，尚未合入 `main`。
> 规模：+5210 / -459，21 个文件

## 解决了什么问题

#8691 已让 daemon restore timeout、late cleanup 和 quarantine 安全可观测；#8833 已阻止 stale same-id attachment 异步工作污染 replacement。但 WebUI 切换到另一个 logical session 时，旧行为仍会在目标 restore 成功前 detach source、停止 stream、清空 transcript 并发布 target/loading。大型会话超时或目标失败后，用户会丢掉本来可用的 source。

## 当前实现方案

#8882 当前 open diff 将现代 WebUI load/resume cross-session switching 做成客户端事务。source session 在 target restore 和 replay staging 期间保持 visible owner；target session 在隔离 transcript store 中有界 reducer batch replay，只有完整 staged target 仍通过 lifecycle/deadline/owner 仲裁时才 commit。失败、超时、被替换、malformed 或 stale target 会被丢弃并 best-effort detach，不清空 source transcript、不停止 source event stream、不替换 source connection state。

Provider 引入 `CrossSessionIntent`、`StagedCrossSession`、`beginCrossSessionTransition`、`pumpCrossSessionTransition` 和 `commitCrossSession`。普通 restore 同时只允许一个 raw RPC；相同 target coalesce，后续请求只保留 latest queued target；late raw result 必须匹配当前 intent、attachment 与 environment identity 才能进入 staging/commit。commit 是同步所有权交接：flush source legal buffered events，安装 target transcript/history/session/workspace/client refs、connection state、staged notices、mid-turn/pending prompt side channels，settle source-local prompt waiters，然后才 resolve public load promise并启动 prepared target runner，不二次 restore。

WebShell 侧 `WorkspaceSessionProvider` 保持现代 Provider mounted，区分 desired target 与 committed target；workspace 解析未完成或失败时继续显示 committed App，并用 once-only rollback 通知 host。`App.tsx` 与 hooks 引入 owner guard/write gate，queued prompts、background tasks、artifacts、metadata、model/mode/recap、git intent 和 scheduled-run catch-up 均绑定当前 owner；目标 pending/failed 时保留 source metadata，新写入在 UI side effect 前被阻断，scheduled-run 30s catch-up timer 延后到 restore commit 后开始。明确缺少 `client_identity` 的 legacy daemon 保留 detach-first keyed path；未知 capability 或 malformed modern target fail closed。
