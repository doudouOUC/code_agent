> 规模：+6554 / -660，23 个文件

## 解决了什么问题

WebUI 切到另一个 logical session 时，旧实现会先 detach 当前 session、停止 SSE、清空 transcript，再等待目标 restore。大型 session restore 超时、结构化 504、workspace target 解析失败或被后续目标替换时，用户会停在空白/错误目标上，而原本健康的 source session 也已经被中断。#8691 只让 restore timeout 安全可观察，#8833 只隔离 stale attachment；缺少的是客户端可见状态的事务边界。

## 最终实现方案

#8882 让现代 daemon（明确支持 `client_identity`）的 cross-session `load`/`resume` 变成两阶段提交。source session 继续作为 visible owner，保持 transcript、event stream、metadata、control 和 side channel 可用；target 在独立、有界 staging store 中完成 restore replay。restore coordinator 同时只允许一个普通 restore RPC，相同 target 合并，只保留最新 queued target，并用精确 attachment、workspace/environment identity 和 deadline fence 丢弃 stale result。

commit 阶段一次同步 handoff 安装 target transcript、session/client/workspace refs、connection state、staged notices、recap/BTW/artifact/background-task 等 side channels，再启动 prepared runner，不再发第二次 restore。失败、超时、malformed、superseded target 被 best-effort detach，不影响 source。旧 daemon 明确缺 `client_identity` 时保留 keyed detach-first legacy 行为；capability 未知或 ownership shape 不合法时 fail closed。

## 关键代码路径

- `packages/webui/src/daemon/session/DaemonSessionProvider.tsx`：target staging、restore arbitration、commit handoff、prepared runner。
- `packages/webui/src/daemon/session/actions.ts`：source-bound operation 与 restore transition 的互斥/阻塞。
- `packages/web-shell/client/components/WorkspaceSessionProvider.tsx`：受控 session/workspace prop 与 committed target 分离，现代 provider 不 remount。
- `packages/web-shell/client/App.tsx`：session owner guard、write block、metadata/recap/BTW/artifact/queued prompt side effects 的 owner fencing。
- `integration-tests/cli/qwen-serve-webui-session-switching.test.ts`：真实 daemon delayed-success 与 structured 504 覆盖。

## 验证方式

PR 声明 focused WebUI action/provider tests、WebShell affected tests、真实 daemon integration、build、typecheck、bundle 与 focused ESLint。验证重点是：B restore 被暂停时 A 仍 connected 且能接收 live event；B 504 或被 supersede 时 A 仍可用；controlled workspace target 失败只回滚一次且不重试循环。

## 边界与风险

- staging 期间会短暂同时持有 source store 与 target replay。
- source/stale target detach 是 best-effort，失败时不可见 client ref 依赖既有 reaper 回收。
- same-logical-session refresh、clientId-only rebind、ring resync 和 live-journal repair 不在本 PR 内，由 #8939/#8990 等后续收口。
