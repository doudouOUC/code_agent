# PR #8939 当前实现观察：same-session refresh 事务化

> 规模：+2992 / -351，9 个文件

## 解决了什么问题

same logical session 的 load/reload/resume/clientId rebind 仍可能走 destructive runner path：先 abort source SSE、detach attachment、清 prompt/transcript，再等待 target restore。慢 restore、失败 restore、partial replay 或 stale result 都可能中断健康 source session，并丢失 live tail。

## 当前实现方案

#8939 的 draft diff 把同 session refresh/rebind 做成事务候选。source attachment、transcript、event stream、prompt state、metadata 和 controls 保持活动；candidate restore 在后台运行。commit 前校验 restore epoch、cursor、replay completeness、ownership 和 bounded live tail，成功后原子替换 owner；失败、超时、malformed、superseded 或 stale candidate 只 retire 自己，不改变 source。

restore coordinator 复用 #8933 的 exact replay shape 区分，并串行普通 restore RPC，避免 cross-session 与 same-session intent 互相采用错误 raw result。full load 会 stage replay 加 source contiguous tail，不重复 replay arrays；resume/clientId rebind 保留 transcript，只更新 owner 与 pagination owner。TS SDK 侧补 restore epoch 和 partial replay diagnostics 类型。

## 关键代码路径

- `packages/sdk-typescript/src/daemon/DaemonSessionClient.ts` 与 types/tests：restore epoch 与 partial replay diagnostics。
