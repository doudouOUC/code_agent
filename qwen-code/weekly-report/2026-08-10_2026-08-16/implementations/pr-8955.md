## 解决了什么问题

#8882/#8939 让 source session 在 navigation/refresh 准备期间保持可见，但 WebShell 的 prompt submission 还有多个异步点：host `onSubmitBefore` admission、lazy session preparation、queued prompt approval、failed-prompt retry 和 turn-error retry restoration。它们可能在 A→B 或 A→B→A 后才返回，继续提交 stale draft、清 follow-up、enqueue 错误 session，或把重放后复用的 reducer-local block id 当成同一个可重试 payload。

## 最终实现方案

#8955 把 direct/queued submission 的 owner 校验扩展到异步返回之后。提交前重新检查 App lifetime、logical session owner、composer source、write-gate generation 和 current owner guard；不匹配时停止副作用，保留源 draft/follow-up，不 send、不 enqueue、不 commit composer。queued prompt 也在 approval 后重校 owner，避免批准结果晚到写入替换后的 session。

retry 生命周期改为 source-owned。被 navigation 取消的 failed-prompt retry 与 turn-error retry 缓存在其 logical owner 上，只在导航 settled 且当前 transcript 有稳定 identity match 时恢复。恢复优先使用 persisted user record identity 或 stable prompt/event identity，拒绝只靠 reducer-local block id；同 owner workspace 后续变为可用时可以 enrichment/migration，owner/workspace/attachment 改变时 fail closed。并发 admission out-of-order settle 时保留更新的 retry，防止旧 retry 覆盖新状态。
