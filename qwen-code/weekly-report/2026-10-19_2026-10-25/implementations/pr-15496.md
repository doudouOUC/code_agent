# PR #15496 最终实现：避免 Managed 输入框因重复 key 重建

> 规模：+43 / -1，2 个文件

## 解决了什么问题

权限规则 dialog 与 composer 使用相同 provider/Session key，React 在规则查询重渲染时可能错误复用或重建兄弟组件，造成重复输入框和草稿丢失。

## 最终实现方案

只给 ManagedPermissionRulesDialog 的 key 增加 permission-rules 前缀，与原 composer 的 provider/Session 身份区分；没有把规则内容、revision 或忙状态加入 composer key。回归先输入草稿、同 Session 连续重渲染，断言只有一个 composer、原 textarea 对象和值均保留；切换 s2 后仍一个 composer，且 DOM 身份更新。生产变更仅一行，不改变后端审批协议。

- `packages/web-shell/client/components/managed/ManagedSessionsPage.tsx`：dialog 的独立 React key。
- `packages/web-shell/client/components/managed/ManagedSessionsPage.test.tsx`：单输入框、草稿和跨 Session 对照。
