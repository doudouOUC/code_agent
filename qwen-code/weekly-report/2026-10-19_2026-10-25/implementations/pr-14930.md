## 解决了什么问题

Managed 输入框原来只能使用已发布定义里的 Skills，用户当前 daemon Workspace 已启用的 Skills 无法带入新 Session；若运行时重扫宿主，又会让重试和恢复读到不同指令。

## 最终实现方案

创建 UI 从显式选择的 daemon/Workspace 来源懒加载目录；真正提交时重新取完整快照并核对同一来源实例，将 structuredClone 与原 idempotencyKey 一并保存 pending，未知结果重试不重新扫描。已有 Session 不随后来的本地配置变化。

Workspace-qualified snapshot 路由只接可信 active generation，发现失败或任一非 ok 状态拒绝整个快照；await 后重验 trust/generation/cwd，不回退 primary。只导入 name/description/body 与 model_invocable/user_invocable，不复制目录、assets、脚本或宿主 base_directory。

Java 在 SESSION_CREATE_ACTOR receipt result_json 同事务保存 version1/语义摘要的不可变快照。只有 additions 非空才与 pinned definition Skills 合并，名称重复拒绝；最多 256 项、每 body 512 KiB、合计 2 MiB，旧发布定义的 16 项/32 KiB/48 KiB 限制不变。子 Session 继承原快照；损坏版本、字段或摘要拒绝，旧 Session 无快照仍读原定义。

非空快照必须协商 session-skills/2；Connector 发布 managed-agent-skills 资源，将同一 sessionSkillsRef 穿过 create/load/stop/lifecycle，Hosted admission/recovery 核对原 identity/ref/digest，优先原 Session 快照。Workspace recovery fingerprint 纳入 skillsDigest，CSI 库存核验 receipt；没有新增 SQL migration。

模型声明/指令过滤 model_invocable=false；菜单和用户 slash 过滤 user_invocable=false。clientInitiatedSkills 写入原记录，恢复保留调用来源。Skill 必须独立完整批次，混合/非法成员整批拒绝；原 PreToolUse Hook 与拒绝摘要保持。保存给模型的结果前统一执行 toolOutputBudget，恢复对原响应使用相同预算，防止大指令突破上下文预算。

当前 main 中 ManagedSessionSkills、准入、catalog 和 SDK 请求 blob 与最终 diff 一致；后续 #14987/#15061 改 Controller/UI，但保留原创建快照和重试流程，不把执行 Workspace 自动当作 Skills 来源。
