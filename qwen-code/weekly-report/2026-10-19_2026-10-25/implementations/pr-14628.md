# PR #14628 最终实现：附件编码输入预算提升至 8 MiB

> 规模：+805 / -110，39 个文件

## 解决了什么问题

48 KiB 的附件输入预算容不下常见截图；只改上传校验会在持久化、模型请求、恢复或浏览器 pending 存储处再次失败。

## 最终实现方案

Java、Hosted 和 WebShell 将含附件的完整规范化编码输入上限设为 8 MiB，包含文字和 base64 开销，不是每个文件 8 MiB。managed-input 为 8 MiB、hosted-model-request 为 32 MiB；后续 #15094 将 checkpoint 单独提升到 1 MiB，#15170 增加已结算历史分页，普通 inline resource 默认仍 64 KiB，Skills 另有 2 MiB 预算。Java inline transaction 为 40 MiB，恢复快照累计为 128 MiB。按 ref kind 解析恢复，保持原请求/摘要及字节验证。

Jackson 只为内部 CommitTransactionRequest 注册复制的 mapper，放宽对应 base64 字符串长度，不改全局 JSON 约束。浏览器 pending 超过 128 KiB 写 IndexedDB，sessionStorage 只留引用；先可靠保存再发送，按原 client/key 恢复和删除，不因配额失败换新幂等键或丢失新草稿。
