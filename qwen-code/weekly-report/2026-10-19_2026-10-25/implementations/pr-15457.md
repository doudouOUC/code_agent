## 当前实现方案

完整 diff 只有双语范围决定、部署和显式退役说明，没有 Java/SQL/测试改动。候选将完整 CSI 审计移出首版前置，不新增回收服务、证据入口或空开关。撤出记录的历史基准 7ab5a95c61d5 与后续 S1 pin 2c0c9fa8dc4a 分开，旧本地证据实现/测试仅为历史；不能把文档中的撤出操作文字当作本 PR 正在改变生产文件。

保留已有同 tenant/Workspace/generation、同健康原 Pod/PVC 的文件 Session handoff：前一 close 成功后释放逻辑 Runtime Session，但 binding READY、物理 owner RESERVED。原显式 idle retirement 只保存 DRAINING、原 slot/reservation/history，按 UID/resourceVersion 发最多有界 DELETE 尝试；RETURNED 只是完整 HTTP 响应（包括非 2xx），不是进程终止/卸载，UNKNOWN 不释放，不删 PVC/PV/Secret/保护对象，保留资源继续计费。

新 S1 资格、S2 平台完成/异常隔离/数据策略设计、S3 原子释放与重复复用分开。平台托管回收未来必须明确原身份关联、正常完成与失节点/强删隔离、重启/丢答 readback 和同事务 owner 变更；Pod 缺失、DELETE 返回、VolumeAttachment 消失或单一云盘状态不能单独释放。Shell/MCP/Hooks、活会话强排空、自动替换与跨租户复用仍不在该首版范围。不是完整 K2、CSI LOST 恢复或生产安全验收通过。

最新候选追加原生 S1 pin 2c0c9fa8dc4a 的阻塞记录：一个 resident binding DRAINING 后，同 tenant 的不同注册磁盘/存储新 Workspace 仍可能被公共 /workspace canonical path 的放置围栏拒绝为 runtime_placement_recovery_required。已有独立 binding 可用不能证明冷准入无影响，另一个测试 tenant 的通过也不能冲销；必须先解决并验证 S1，再推进 S2。这里记录候选报告，不声称本次复跑原生现场。
