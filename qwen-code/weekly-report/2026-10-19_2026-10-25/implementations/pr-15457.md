# PR #15457 最终实现：独立常驻 Workspace 放置与工具准入

> PR: [fix(runtime): unblock independent resident workspaces and tool admission](https://github.com/QwenLM/qwen-code/pull/15457)
> 状态：merged；最终 head `02624f3069cd`，merge `33e80fc1aa49`，对照 main `b3ab3ec64c81`。原文档候选已演进为运行时修复，原生资格仍单独验证。
> 规模：+933 / -30，35 个文件

## 解决了什么问题

同 tenant 的独立 resident 容器都使用 /workspace，旧放置围栏把不同注册存储当作同目录而阻塞冷准入；公共文件 profile 又声明 resident worker 不支持的 web_fetch，已 dispatch 的拒绝可能留 SQL UNKNOWN 并卡住 Workspace。原完整 CSI 审计前置还混淆首版交接与未来物理回收。

## 最终实现方案

最终内存与 JDBC 围栏仅在双方均为精确 resident capability、kubernetes-workspace provisioner、Workspace isolation 时忽略相同 canonical cwd。相同 tenant/Workspace、storage identity、缺 managed storage 的独立阻塞分支仍在；非 resident 请求保持原路径规则，不把不同 alias 当作物理卷安全复用证明。无 schema 改动。

文件 profile 构建声明前，共享一次 /runtimes:capabilities 请求，按原 Harness Session/admission resolver 和 Broker/lifecycle 凭据只解析 scope，不创建 binding/Pod/Runtime Session/存储 reservation，不返回 endpoint 或 worker 凭据。成功缓存、失败清 promise；不接受调用方指定 Workspace 或 primary fallback。明确非 resident profile 不做该探测；旧无 profile 的纯文件路径也遵守边界。仅 HTTP 404 回退等待已经发出的原 warm，503/鉴权/传输/错 scope 不降级，也不另发 warm。

精确 resident catalog 仅 Read/Write/Edit，公开 Plan 活跃时仅 Read 和 Harness 本地 exit_plan_mode；伪造不支持调用在 acquire/prepare/dispatch 前整批持久拒绝。旧 Harness/直接 Broker 客户端的有效但不支持 payload，仅在原 identity/version/PREPARED 仍匹配时由 settlePrepared 保存 not_started、空 responseParts、capture:null 和 resident_tool_unsupported；dispatch generation 仍零，不调用 worker。竞争、已 dispatch 或 UNKNOWN 返回原记录，不能改成确定未执行。

双语范围决定与部署/退役说明同步，将完整 CSI 审计移出首版前置，不新增回收服务、证据入口或空开关。历史 withdrawal 基准和 S1 pin 2c0c9fa8dc4a 分开，文档中的本地撤出记录不是本 PR 删除生产文件的证据。

保留已有同 tenant/Workspace/generation、同健康原 Pod/PVC 的文件 Session handoff：前一 close 成功后释放逻辑 Runtime Session，但 binding READY、物理 owner RESERVED。原显式 idle retirement 只保存 DRAINING、原 slot/reservation/history，按 UID/resourceVersion 发最多有界 DELETE 尝试；RETURNED 只是完整 HTTP 响应（包括非 2xx），不是进程终止/卸载，UNKNOWN 不释放，不删 PVC/PV/Secret/保护对象，保留资源继续计费。

S1 资格、S2 平台完成/异常隔离/数据策略设计、S3 原子释放与重复复用分开。平台托管回收未来必须明确原身份关联、正常完成与失节点/强删隔离、重启/丢答 readback 和同事务 owner 变更；Pod 缺失、DELETE 返回、VolumeAttachment 消失或单一云盘状态不能单独释放。Shell/MCP/Hooks、活会话强排空、自动替换与跨租户复用仍不在 resident 首版范围。不是完整 K2、CSI LOST 恢复或生产安全验收通过。

保留 S1 pin 2c0c9fa8dc4a 的两项原生失败记录：不同存储冷准入被 runtime_placement_recovery_required 拒绝，以及不支持的 web_fetch 已派发后进入 UNKNOWN/workspace_busy。以上源码修复不能追溯清除此历史失败或原 UNKNOWN；需在修复版本重新验证，不以另一 tenant 或既有 binding 可用冲销。
