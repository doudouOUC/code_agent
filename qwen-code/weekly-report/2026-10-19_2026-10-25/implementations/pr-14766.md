## 解决了什么问题

原生工具返回媒体时，完整 functionResponse/history/checkpoint 可能引用相同摘要的资源；需要证明退役 GC 不会误删另一 Session 的同字节结果，或破坏 reader/recovery 引用。

## 最终实现方案

最终 diff 无生产逻辑变更。Node generator 使用实际 Core authority/sink 与 HostedWorkspaceToolTurn 产生 inlineData outcome、工具历史、checkpoint/ref 闭包，仅替换外部 Broker 返回；Java 通过真实 ManagedSessionStore 提交并比对原字节，损坏资源必须拒绝。

测试区分 seal 与 retire、默认关闭与显式 GC、reader/recovery blocker；退役收集保留 tombstone/账本且重复运行不再累计。两个 Session 相同 ref/摘要仍有不同 scoped resource key，一个被收集另一个仍可读；手工插入 foreign RECOVERY pin 验证防御性保护，不据此发明公开跨 Session 共享生产者。
