## 解决了什么问题

单一应用中的 service/store 混入多种职责，业务与持久化反向依赖 HTTP api，Broker 供应器和传输协议也难区分。

## 最终实现方案

api 保留 HTTP 控制器与错误映射，共享 ApiModels/TenantContext/RequestDigests/异常移到 model/exception；Session、Workspace/runtime、artifact、catalog、event、automation/channel 各归其职责。共享锁与事务辅助类集中 persistence，不为业务标签公开内部事务。Broker 供应器、transport、security 与仓储核心分层，只扩大真实跨包消费者必需的既有访问点，测试夹具跟随内部归属。

Spring 应用根包与独立 maintenance 扫描边界保持；pom 的可执行入口、脚本、设计/README 路径和测试 import 同步更新。没有拆 Maven artifact 或部署，diff 不改 SQL/OpenAPI 资源；不能把文件数和 package/import 变化解释为新增恢复能力。
