## 解决了什么问题

monitor/child/workflow wake 崩溃后只结算旧 attempt，会把通知消费掉而没有后续模型处理；简单重放原输入又可能重复副作用。

## 最终实现方案

仅 monitor 和 child notification 两类源（child_agent/workflow）在原 Runtime 结算后、旧 Turn settle 前，以 interruptedTurnId 的 SHA-256 派生 wake-recovery 键提交 managed-input/admission；重复调用复用同键。continuation 可再次崩溃并延续，但始终保存最初 notificationTurnId，校验来源与原 accepted input，不生成假 user 消息。

后继 Turn 读取原通知文本和已提交历史/结果，使用 system turn_attempt 表示，提示未知不等于未执行；其自身成功后才按原 notification ID 标记 child consumed。call-key 对 continuation 固定摘要，避免多次恢复身份无限增长。

## 关键代码路径
