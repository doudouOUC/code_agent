## 解决了什么问题

Session 已关闭或活动 holder 消失后，Hosted cleanup 仍可能 owed/blocked；只看活执行会过早回收原 Runtime 或清掉完成 cleanup 必需的描述符。

## 最终实现方案

V13 给 ma_session_head 加 cleanup_head_revision，ma_resource_ref 增 runtime_binding_key 和 HOSTED_CLEANUP owner/索引。提交已验证 hosted.cleanup 时，在同事务为原 descriptorRef、binding/generation 保存引用；只有相同 cleanupId 与原身份的 confirmed 才删除，身份变化拒绝。

Runtime retention 同时检查原 binding/generation 欠账和未覆盖当前 journal revision 的历史；nullable/滞后的旧 head 不按没有债务处理。按 Session isolation 或共享 Runtime Session 找原 Harness，阻止原绑定清理。资源退役分批处理 cleanup refs 仍受既有生命周期/保留保护；CSI inventory 同步新列，不绕过 schema 校验。

后续 #15026 将普通 LOCAL/SSH_LOCAL 的活执行判断改为原 ma_runtime_session.execution_storage_key 成员，不再把普通单 storage holder 当权威；本 PR 的 cleanup debt/未覆盖历史屏障仍独立保留，不能因成员已 handback 或 Session 已 close 免除原清理债务。

2026-10-24 复核：#15263 已将有效 V13 结构折叠到唯一 V1/32 表，并删除旧 migration 文件；这里的 V13 是合入时历史编号，原 cleanup 引用与保留屏障仍在，不维护旧目录升级链。
