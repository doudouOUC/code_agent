## 解决了什么问题

释放 MCP 连接与删除 Session 数据是不同生命周期；缺少贯穿 catalog/参数/结果资源的验证时，容易误以为断开连接可以回收仍被历史或恢复引用的字节。

## 最终实现方案

最终 diff 只增加测试和双语说明。测试经真实 ExtensionRecordJournal/ManagedSessionStore 提交配置与 resource_read/prompt_get 的 intent、dispatch、settled 记录；缺 catalog/response 原子拒绝，重开后核对完整记录及 blob/text 结果。连接 releasing→drained→released 不删除记录资源。

Session 未退役或 GC 默认关闭时 collector 不变；SEALED/失租并完成退役后，显式开启 collector 才分批删除 owner/ref、清 inline bytes 并保留 COLLECTED tombstone。核对账本字节与重复扫描不重复计费，原资源读取返回 retired 拒绝。
