## 解决了什么问题

WebShell 缺少 close/archive/delete 的完整交互与丢响应恢复；会话只能在线阅读，直接导出当前 UI 或原始私有存储会漏分页、误带 authority 或把工具摘要误作完整结果。

## 最终实现方案

复用已有生命周期 API 与 durable operation：可读权限只允许阅读/导出，变更能力仍要求对应 owner/Workspace OPERATOR。UI 在发送前将 provider/client/Session 隔离的原 intent/requestId/idempotencyKey 写 sessionStorage；写不成功不发送。未知响应保留原键；拿到 operationId 后只查询原操作，校验 Session、类型和 ID。pending/running/recovery_blocked 持续观察，不把 202 当完成。

close_archive 是明确两段：原 close 确认完成后才以保存的独立 archive 键提交，archive 失败保留第二段意图。服务端列表附活动操作摘要，原页面消失也可恢复观察；archive all/unarchived/archived 在 SQL 过滤，immutable gmt_create keyset 的 v2 cursor 固定过滤条件，旧 cursor 只适用于 all。

reading export 经受授权的 sessions/export/query 读已有不可变 snapshot。客户端固定初始 lastSequence，最多等待 30 秒让快照追齐，再以固定 watermark 收集所有页面；拒绝异 Session、重复 item/cursor、越界 sequence，收集和渲染均限 32 MiB。HTML 使用静态 ReactMarkdown，不执行 raw HTML，并限制 CSP；外链图片和 Markdown 图片用占位，已有内联附件才可嵌入。公开 reasoning 可导出，工具只带明确标注的 preview，不含调用参数或完整私有 Artifact。

2026-10-24 当前 main 的 #15330 默认公开 Shell/1 lifecycle v2，拒旧 Shell/2；仍需原 close proof/可靠 stop，活 Turn/approval 拒绝，unarchive 仍 CLOSED。#15331 仅统一归档呈现，#15263 统一 operation/强协议，不以 UI 或 phase 猜原操作终态。
