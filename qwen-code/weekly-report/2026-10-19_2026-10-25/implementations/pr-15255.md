## 解决了什么问题

单 Harness 地址不能随 Kubernetes 副本扩缩容；随机负载均衡会把同一 Session 发给非原 writer，Pod 滚动退出又可能丢掉未释放的 Hook/MCP/工具资源。发现服务不可达不能充当释放或接管证据。

## 最终实现方案

池开关关闭仍走单 Harness；开启要求 SessionStore 与绑定凭据、协议 digest/能力匹配，远端 HTTPS/mTLS，Kubernetes 模式强制 mTLS。EndpointSlice list/watch 固定 namespace、Service name/UID、Pod namespace/UID 和 TCP port，只把 Ready 且非 terminating 的字面 IP 当候选；每轮最多 256 slices/endpoints、响应 2 MiB，发现不确定时不提供新候选，重列带退避。Kubernetes API 使用 HTTPS、禁重定向并逐请求重读 projected token。

当前 V1 在 ma_session 保存 instanceId/bootId/placementEpoch 与 UNASSIGNED/ACTIVE/QUIESCING/RELEASED，仍 32 表。按 tenant/Session 锁分配并拒绝全局 control ID 冲突，后续 RPC 粘原 owner/epoch，不轮询随机选址。`qwp1_` HMAC token 绑定 tenant/Workspace/Session/instance/boot/epoch；SQL writer acquire/renew/commit、publication 和 lifecycle 重验 placement，不能拿 bootstrap token 绕过。

接管只接受数据库时间证明原 writer 与 activation 都已过期、且 head 可验证，或原 head 已 seal 并保存 durable release receipt。Endpoint 下线、NotReady、HTTP 错误均不足以接管。原实例 ACCEPTING→QUIESCING→DRAINED；drain 按原 boot/operation 幂等，拒新 load/submit/wake，允许完成与 cleanup。attached/opening/未知 opening、mutation、Hook/MCP/monitor/child、文件 undo/cleanup debt 和未结算 attempt 都参与阻塞，不能把断连计为 drained。

空闲 Session 的释放先持久 quiesce，再提交 released activation/prefix proof；SQL 原子核对原 epoch/writerGeneration/head revision/sequence/hash，保存 hosted_harness_release 记录与资源并 seal/置 RELEASED，最后才移除本地 attachment。丢回包读原 receipt；未知保持占用。owner subscription 按真实 attachment 的 writer boot+tenant 分组，生命周期走原 operation claim 而非普通准入。部署清单含 Envoy mTLS、headless Service/RBAC/NetworkPolicy/PDB/HPA；preStop 最长 90 秒而 Pod grace 120 秒，探针必须观察实际 DRAINED，不伪造释放。后续 #15448 将 Auto/规则能力检查委派到池，原归属与释放条件不变。
