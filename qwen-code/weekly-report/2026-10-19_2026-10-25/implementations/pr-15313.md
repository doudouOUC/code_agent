## 解决了什么问题

Workspace 模型不能经原工具链抓取网页；让浏览器或 Java 直接代取会绕开 Runtime、原审批和恢复账本，任意 URL/重定向还可能访问内网或泄漏凭据。

## 最终实现方案

files 与 Shell profile 暴露 web_fetch，由 Runtime executor 实例化 WebFetchTool(config, 'managed')；只读 snapshot child 仍只有 read_file/glob。参数限定非空 url/prompt 与 auto/markdown/html/text 格式，只接受无凭据 HTTPS。GitHub blob 在审批前规范为实际 raw host，default/auto-edit 的出站请求需询问，yolo 沿既有策略；原 NATIVE_TOOLS、Turn/prepare/start/query、receipt/history 与审批续接保留，Java 只识别动作与 lifecycle 验证，不执行网络请求。

Managed 路径复用 Core 内容提取但不发辅助模型请求、不用宿主 URL cache、不下载二进制或写 Workspace 文件、不降级 HTTP。llmContent、returnDisplay 和错误各自按 JSON 编码字符串限制 16 KiB，保留截断标记且不割裂 surrogate；有界结果不是全文 Artifact 承诺。

网络请求仅 Node：每次使用独立 undici Agent，把 DNS lookup 固定到本次校验的公网 IP，强制 TLS certificate 校验，不继承全局代理 dispatcher。所有 DNS answers 必须公网，拒私网、环回、link-local、CGNAT、multicast/reserved 及映射 IPv4/受限 IPv6。每跳重新解析/固定；手动 redirect 仅同 origin（host/scheme/port）可跟随，跨 origin 返回 redirect，由新工具调用重新走审批。响应预算 10 MiB、最多 10 次 redirect，原 timeout/retry 控制仍在。

## 关键代码路径

- `packages/core/src/tools/web-fetch.ts`：Managed 无辅助模型/缓存的提取与结果预算。
- `packages/core/src/utils/fetch.ts`：独立 dispatcher、固定 DNS 与 redirect 检查。
- `packages/core/src/utils/network-policy.ts`：共用公网地址判定。
- `packages/cli/src/serve/hosted-workspace-tool-turn.ts`：公开 profile、参数与审批入口。
- `packages/cli/src/serve/managed-runtime-tool-executor.ts`：原 Runtime 工具执行。
- `packages/cli/src/serve/hosted-approval-continuation.ts`：同原 Turn 审批后续接。

## 边界与风险

- 不是任意 URL 代理、二进制下载或辅助 LLM 总结服务；应用地址校验不能替代网络层 egress 策略。
- 不扩大只读 snapshot child、MCP 或 CSI 平台资格；取消/回执遵循原执行证据，不因页面已返回就推断物理停止。
