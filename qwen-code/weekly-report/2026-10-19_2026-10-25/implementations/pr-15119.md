## 解决了什么问题

已有 Session 只能查看已保存的 MCP catalog；更新服务器选择必须重建 Session，直接改 definition 或发送原始 command/env 又会破坏不可变准入、凭据隔离与丢响应幂等。

## 最终实现方案

管理的是独立持久 Session 选择，不修改原 definition。仅 ACTIVE bound 的精确 SHELL/1 或 MCP profile、files/shell gate、当前可读 OPERATOR 且 Plan off/空闲时准入；排除 SSH、resident、child，Turn/Action/维护/rename/pending command 会阻止新选择。Session 行与锁定读取避免在旧一致性快照上误判 idle，原已提交 operation 仍可回读。

UI 只能选择管理员已发布 serverId/revision/digest/transport pin，不接受命令、环境变量或 secret。tenant/actor/Session/幂等键派生原 operation UUID，expectedRevision 与完整命令共同校验。config_install 的 hosted-mcp-settings 以前一 ref 串链、revision+1；最多 32 个保留选择、16 个 enabled，禁止降低 pin revision。add/edit/remove/enable/disable/reload/restart 先提交选择再做物理动作，未知操作只允许原 operation 继续。

HostedMcpSession.manage 先拒绝 pending invocation，清该 server 缓存，按原 Runtime/配置 drain 旧连接；disabled/removed 不重建，enabled 按同一 operationId configure/discover，持久 release/configuration/operation 证据仍保留。原 MCP/Hook Broker 可复用，无则只用经证明的 inventory Broker，不接受公开 body 指定 Runtime。原 owner/grant/binding/generation fence 贯穿恢复与 cleanup。

浏览器按 provider.storageScope/client/Workspace/Session 保存原命令、请求键与 operationId；响应验证 action/server/revision，切换 abort，不凭无关 catalog 清原 pending。retry 读原 operation 后才允许原命令 resume；错误对外有界且脱敏，不返回 daemon 配置秘密。无需新增 SQL 表或 migration。

## 边界与风险

- 不是任意 MCP 安装或秘密编辑 API；管理选择不授予执行工具权限。连接释放不删除原 catalog/参数/结果/receipt，失败或 UNKNOWN 不能切新 owner 冒充恢复完成。
