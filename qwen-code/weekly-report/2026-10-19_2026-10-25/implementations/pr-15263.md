# PR #15263 最终实现：移除预发布兼容分支并统一 V1 基线

> 规模：+2431 / -10542，168 个文件

## 解决了什么问题

尚未正式发布的 Managed 协议积累了 admission profile、旧 cursor、可缺省 checkpoint 和工具发布回填等兼容路径；同一状态存在两套解释，既增加恢复歧义，也让旧 writer 在新目录中被误认为安全。

## 最终实现方案

删除 V2–V17 文件并将有效字段、索引与约束折叠到唯一 V1，仍 32 业务表。ManagedSchema 只读取 V1、验证 schema version 1 与实际 catalog；Spring 对已填充目录做结构校验，不能通过 Flyway history repair 或旧 migration chain 升级。首个正式版本前只维护当前新库基线，开发目录重建；旧环境先停写和保全证据，不能将 schema 不变推断为混版本兼容。

删除 JavaDurableAdmission/config/feature flag 与 admissionProfile 参数，submit/cancel 统一返回原 operationId/admissionStage/deliveryState，不再广告 durable_operations。WebShell 校验 Session/Turn/operation 身份，取消必须支持 queryCancelOperation 并保留原键，仅原操作终态才清 pending，不用摘要或 phase 猜成功。删除 environmentId、旧 workspaceCwd/provider-kind 别名与日期字符串/当前时间回退，工具投影必须有 itemId。

列表只发 v3 cursor，绑定 archiveState/titleQuery digest；旧无版本/v2 cursor 与 include_archived 别名不继续适配。LocalManagedSessionAuthority.open 强制持久 journal handle；checkpoint 写出 agentWait/commandWait/commandLock，即使为 null，缺字段输入拒绝，不能混用旧 writer。

删除旧本地 Runtime provider/包装器，保留独立 ManagedRuntimeBrokerClient 与类型化错误。客户端检查协议和执行身份、成功/错误响应均限 8 MiB，prepare 只以相同确定键和 body 对可重试传输/5xx 再试一次，不给其他控制操作增加盲重放。MCP release 必须原 drain receipt；tool publication 强制原 journal head/activation revision、身份和租约授权，移除开关、legacy journal 扫描/回填和 O3 backfill 列。原 GC、retention/read lease、确定结果与 cleanup 权威没有被删除。

## 边界与风险

- 这是有意移除预发布兼容，不提供旧数据库/旧 checkpoint/旧客户端的自动迁移或回滚保证。Server/Broker/Harness/SDK/外部 writer 必须匹配升级并隔离旧 writer。
- V1 重建不得对有未知运行或待清理原资源的环境直接删库；先保全与结算旧证据，不手清 owner 换取准入。
