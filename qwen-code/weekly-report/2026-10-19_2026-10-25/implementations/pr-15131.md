## 解决了什么问题

只显示 recovery_blocked 不能说明何时可发下一轮；SQL 已终态但原 Harness 尚未 inputSettled/cleanup 时，直接继续或重发原请求会重复副作用，冷取消也可能误停另一个 prompt。

## 最终实现方案

公共恢复 query 返回 recovering/awaiting_evidence/cleanup_pending/ready/operator_required、原因、精确 Turn 与 nextTurnAllowed/actions。查询要求可读，recheck 要当前 OPERATOR 并重验原 target，前后检查 latest Turn 未变化。初始无 Turn 也必须证明完整原 journal genesis/header/resources、连续 revision/sequence/hash 与稳定 head，不能只凭 SQL 空行认定 ready。

Hosted readonly status 使用同一 committedSequence，结合原 accepted/settled 输入、checkpoint、before_model 与所有待决工具/attempt/runtime/approval/agentWait/commandWait/cleanup/file undo。ready 必须没有 pending input/event/恢复债务且 settled input 已覆盖；证据缺失、变化或不支持扩展时 fail closed，不重放 UNKNOWN。

Workspace 终态失败先保存恢复意图，再取消精确原 prompt；原 inputSettled 与 continuationReady 证明提交后才退休旧 driver，已提交原事件可重建公开投影，但不重新运行模型/工具。显式 recheck 仅走原取消、parked Runtime 或终态 cleanup；#15094 的 HARNESS_RECOVERY_BLOCKED 自动观察并非所有情况下都开放手动重试。

cleanup-only 冷 load 绑定精确 prompt、原 lease/file history 与债务，不执行新模型/工具；缺 Hook/MCP 冷支持拒绝，普通执行必须重新授权打开。取消只接受当前 pending 或最近 settled prompt，释放 held lease 也必须匹配 prompt，迟到请求不能停止新 Turn。

UI 可见时每 5 秒观察，切 Session/provider abort，目标 Turn 变化不套用旧结果。无法恢复时生成最多 32 KiB 的可审阅 handoff 草稿，带原 Workspace/cwd/agent、最后用户输入及已确认完成的文本并标注不确定性/截断；不自动执行，不迁移私有 checkpoint。
