# PR #14875 最终实现：Hosted MySQL IT 的逐类隔离

## 解决了什么问题

Hosted IT 在同一 fork 中共享 MySQL，前一个类留下 ma_* 行会让后续用例读到外来身份/状态并产生不稳定故障。

## 最终实现方案

仅 hosted-harness-mysql 的 Failsafe 配置启用 JUnit extension 自动发现和 qwen.hosted.mysql.isolation，单 fork、禁并行。BeforeAll 只处理顶层类，强制 disposable mysql.url/user、校验 application catalog，再在同一连接暂关 FK、TRUNCATE 全部 ma_* 基表并 finally 恢复；不删除 Flyway history/表结构或其它表。

Launcher activation 测试验证服务发现/开关真正生效；独立 MySQL IT 验证下一类干净而结构/非 ma_ 表保留。本 PR 合入时 CI/meta-test 将 fork/step/job 预算分别同步为 10178 秒/180 分钟/283 分钟；本次提交前复核的最新 main 因后续故障用例调整为 10462 秒/185 分钟/288 分钟，不把后续增量归入本 PR。
