## 解决了什么问题

已有 MCP stream/fault gate 缺少经公开发布定义、连续两个 Turn 复用原本地连接，再公开关闭并核对原进程/SQL 的完整正常路径，容易把请求返回当作实际释放。

## 当前实现方案

当前 diff 给 HostedMcpStreamGapIT 增 publishedMcpReusesTheLocalRuntimeAndClosesOnMySql：真实 stdio MCP、packaged Harness、durable worker 和 disposable MySQL，受控 loopback 模型驱动 EXT_FIRST/SECOND 两个独立 Turn。

两轮必须保持同一配置/Runtime Session、server/config/catalog revisions、connectionGeneration/catalogRef 与 worker registration，MCP 只 start/initialize 一次而 tools/call 两次。逐项检查原 cwd 的物理效果及 decoy 不存在，SQL 原 binding/generation/Runtime Session 的 SETTLED success 与公开输出对应。

公开 catalog GET 与 WebShell POST 一致，读 catalog 不产生新 MCP 请求，不泄露 token、私有路径、digest 或 Runtime Session ID。公开 close 要 operation complete、Session CLOSED、配置释放、session-isolated binding RELEASED/drain receipt、无活 Runtime Session/storage owner，并确认原 worker/MCP 退出后才 teardown。

本地证据写入 target/fg12-cases/fg12f 的请求/进程和 local-acceptance.json。没有生产代码变化；fixture 是 session-isolated 的本地 MCP-only 路径，不将其绑定释放断言推广到 workspace-shared 或 resident CSI。
