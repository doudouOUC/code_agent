## 解决了什么问题

单独 Managed 试用前门与普通 daemon UI 割裂，用户要切换执行模式和 Workspace；一次把启动器、签名前门、本地导入与 UI 导航合入又扩大集成和审计边界。

## 关闭前方案

关闭前 head stacked 于 codex/managed-local-serve，不是 main 增量。它把当时 open #14928 的专用前门改成 runQwenServe 托管的 authenticated loopback 普通 daemon，新增 installSignalHandlers=false 与 managedLocalWeb 依赖，由父 launcher 统一信号和退出，ACP 延迟启动。

managed 路由只允许 primary listener，前门仍有白名单与签名/私密内部路由拒绝；/managed/boot 构造 Java provider 后交给普通 StandaloneApp，清除旧 Local URL context，避免恢复串后端。候选同时调整 signed 本机导入门禁，不可套用 merged #14970 的 OPEN 条件。

UI 候选在同 sidebar 展 daemon/Managed Workspace，按原 provider 分组、显式执行 selector，包含 pending 创建和未知结果恢复。关闭后独立 #15061 已合入其中纯 WebShell 导航切片；其 main blob 与本关闭候选不等价，更不表示 launcher/signature/boot 集成全部合入。

当前 main 后续已由 #14928 的最终实现交付 managed-local 启动器、普通 daemon/boot 集成和 signed loopback 导入；本关闭观察仍保留原 base/head 与依赖，不把相似能力后续落地改写为本 PR merged，也不沿关闭 head 证明最终实现。
