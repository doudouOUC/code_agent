## 解决了什么问题

现有物理退役 seal 不能证明 SQL 应用、原 worker 文件历史和所有资源已闭合；提前清理会失去恢复证据或误释放原挂载。

## 最终实现方案

新增内部 freeze/cut/finalize/status 与原 worker-authority 入口，按原 writer token、retirement/binding/generation/registration/lease 认定同源 authority。V12 扩原 ma_operation 的版本化进度与 frozen/cut/receipt 字节及摘要、唯一目标约束。库存按声明表和原引用扫描，schema drift、未知/不支持记录、超过 4096 行或 32 MiB 都阻塞，不用空结果证明无义务。

freeze 先预检原 terminal commit、SQL baseline 与 boot6 worker 的 QUIESCENT 文件/执行库存，RPC 不持 SQL 锁，返回后重新锁定核一致才保存 FROZEN。CUT 在事务中提交原 terminal 字节和 cut 证明；finalize 只在原 worker 独立回验已保存 CUT 后关闭准入、join 原操作、文件 backend/mount/root fd 并生成完整 cleanup receipt，Java 再验并存 DRAINED。原请求/摘要重试必须一致；保存的历史按原库存/资源关系核验，不采用新 writer 的当前观察替代。

后续主干 #14764 将 V13 cleanup 引用列纳入库存；#14765 的 V14 空闲常驻 Workspace 维护是独立路径，不能把这里私有应用 DRAINED 当作其准入或物理释放证明。#15026 的 V15 为普通执行添加成员列，当前私有 CSI 库存/checkpoint 明确要求 execution_storage_key 为 null、execution_exclusive 为 false，不将普通并发引入此路径。原 head 与最终合入 diff 一致。
