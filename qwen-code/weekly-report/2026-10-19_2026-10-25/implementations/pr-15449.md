## 解决了什么问题

活 Turn 时只能等待或取消，用户无法耐久追加更正；若只在浏览器缓存，刷新会丢消息，或把尚未交给模型的文字当成已消费。重试、失败后自动启动和 cwd 改变还可能误用旧输入。

## 当前实现方案

候选广告 user-message-queue/1，新增公共及 WebShell query/command 路由。复用 submitter role、可见性/Workspace facts 与 ACTIVE 校验，不将 tenant header 当权限。submit 保存规范化文本/文本文件，拒图片；每 Session queued/claimed/recovery_blocked 合计最多 32。原 actor+key 摘要记录 command result，重放不同 payload 冲突；edit 只 queued、withdraw 仅 queued 或无 Turn 的 blocked，均要求原 revision。

在 V1 增 ma_user_message_queue、ma_user_message、ma_user_message_command，候选合计 35 业务表，main 仍 32。序号、context revision、paused/resumedTurn、消息 revision/状态及原 Turn/prompt 持久保存；不是 V2 migration。每秒 dispatcher 取最多 32 个空闲 Session，以原 actor、user-queue:messageId 和原输入经 submitTurn 开新 Turn，事务提交后才派发。队列未清时拒绕过它的新普通提交，保留单活 Turn。

活 Turn 由原 writer token/generation 授权 claim，在模型下一轮前加入消息，而非打断在途模型/工具。已准备的恢复请求先保留原字节，不中途注入；claim 丢回包返回同原 prompt 已认领项。UserPromptSubmit Hook 可以改正文/补上下文或阻塞，消息以 umsg_id:revision/原 prompt 的 user record 提交，SQL 只有在已提交 message.committed 捕获时标 consumed。临近正常结束仍有消息时，先保存 assistant 再写追加输入并继续，受原轮数/取消预算；不伪造工具终态。

context revision 不匹配将 queued 标 recovery_blocked 并暂停；失败/取消/取消中/恢复阻塞暂停，不自动跑下一条。claimed 在原 Turn 结束仍未证实消费时保持 blocked，resume 不能越过未解决 blocked；关闭 Session 撤回尚未认领项。当前投影 item.input.added 主要抽取文本，不提供完整附件导出承诺。

WebShell 在已查询支持后将忙时输入路由到队列，pending 保存 queued 标记和原 key，不能改成普通发送重试；每秒查询、按 provider/Session/请求序号隔离迟到响应，展示 queued/claimed/blocked、编辑/撤回/恢复。图片仍要求空闲，排队不是取消或即时执行。候选 base 早于当前 Auto 规则增量，不能据当前主干能力推断该分支已完成组合契约对齐。
