# PR #15171 最终实现：默认公开子 Agent 的受限准入与原快照

> 规模：+3655 / -366，74 个文件

## 解决了什么问题

公共 root Session 缺少可用委派入口；直接开放内部 H4 会同时暴露多层/team/任意隔离，并让子会话模型、审批和 Skills 随配置变化，取消后还可能继续拉起新工作。

## 最终实现方案

workspace-child-agents-enabled 默认 true，但有效条件仍为 shell enabled、durable local-process、local-process provisioner、bound-session-isolation-class=session。仅新建 builtin qwen-code root、无 published definition、精确 SHELL/1、非 foregroundOnly、无 MCP/Hooks/SSH/resident/child Workspace/snapshot 且满足 capability 才记录 version1。合入时 V17 给 ma_session 增 public_child_agents_version，默认 0、约束 0..1，旧会话不追溯开启；当前 main 的 #15263 已折叠到唯一 V1/32 表并删除 V17 文件，开发目录重建，不维护旧升级链。

复用原 H4 funnel，公开只 root depth0→child depth1，禁止嵌套、team/workflow/send_message/member 命令和用户隔离参数。子与父共享原 Workspace/cwd 可变文件，并非文件系统隔离。准入冻结八字段 publicLaunch：version=1、sourcePromptId、approvalMode、approvalRevision、modelId、modelRevision、modelRoute、skillsRef；分别固定当前批准模式、实际 prepared model 和原 Skills。modelRoute 保存 authType/endpoint digest/provider pin，fallback 保留实际 origin。

原 childRun input resource 持久保存 launch snapshot，relay 按原 owner actor 和已提交 Skills resource 创建；不重扫宿主、不嵌入凭据。load 必须匹配保存模型/auth/endpoint/provider pin，不默默替换为默认模型。子会话禁止手动 Turn、改模型/审批/Plan/cwd；只读 child view 与父级聚合审批保留，action 指向实际 childSessionId 并逐项授权。

取消先持久 source cancel fence 再 abort，串行 fence 阻止后续 launch，标记同源未终态 child stopRequested；抑制被取消源的 completion/blocked 通知与 continuation，但不伪造 child terminal/kill 证明。全局开关撤回只拒绝新 launch，原 funnel cleanup 继续。任务明细展示 childSessionId/stopRequested/approvalMode，activeChildCount 从 SQL 计算，子 action 分页 cursor 绑定 tenant/root。
