## 解决了什么问题

服务端已有受 fencing 保护的改名命令，WebShell 却没有入口或能力标记；仅改列表文案会在刷新后丢失，并可能让迟到响应污染别的会话。

## 最终实现方案

新增 POST /sessions/rename adapter，强制复用原 service.renameSession 的 tenant/actor、幂等键、requestId 与 fenced title delivery，返回存储后的标题和 replay 标记，不另建本地标题权威。可见 ACTIVE 且 Harness available/title protocol 可用的会话才广告 canRename；bound Session 还要求 maySubmit。

原服务端 creator/当前 OPERATOR 及 recorded-command replay 授权门禁保持；原命令固定 Session/title 摘要和单调 renameRevision，Harness 确认后提交。改名不必等 Turn 空闲，但不改运行输入/模型上下文，也不绕过原 title 验证。

UI 使用同一个 SessionRenameDialog，trim 后非空且最多 256、IME Enter 不提交、busy 防重复。useManagedSessionRename 在未知结果时保留同标题原键；改标题才换键。provider/clientId/Session lifetime 更换时 abort 并清旧编辑状态，迟到结果不更新新会话。

成功用服务端返回标题更新当前 summary/列表/Recents；canRename 不根据 canSend 推断，非 interactive 或 provider 无方法不提供命令。OpenAPI/生成 types/provider/client 与投影同步；后续统一导航、生命周期和子视图继续演进这些文件，但保留同一 fenced 改名路径，不据整份 UI 文件相同与否判断该行为。
