## 解决了什么问题

共享池实现与模板不能证明实际镜像来源、Pod/Service 归属、公共权限和物理效果；直接把预检或 synthetic HTTP 成功当作扩缩容/故障验收，会遗漏真正的 writer 与 release 证明。

## 最终实现方案

镜像脚本默认只生成计划；显式 execute 才 git archive 精确 40 位源码构建 linux/amd64 的 Harness、Java 和 Java+worker 镜像，显式 push 仅发布 Harness/worker。报告校验 source label 与 registry repository digest，不把本地 image ID 或构建计划当可部署 digest。派生 worker 保留真实 machine-id/proc 和分离私有目录要求，不证明 Pod 替换可恢复。

renderer 只读 operator 提供的 Node inventory，要求两个明确、不同 hostname domain 的现有 Ready 业务节点，拒系统/保留/污点/压力节点。生成精确 node affinity、非抢占 PriorityClass、最多三 Pod quota、零 PVC/LoadBalancer/NodePort，不创建付费资源、应用 YAML 或启用 HPA；rollout 的实际空闲容量需另验。mTLS、Pod IP SAN、原 Store/Broker/publication 凭据和真实 HTTPS 目的地由部署方提供，Harness 不挂租户卷或 host volume。

read-only preflight 显式核 kube-system UID、run namespace/priority 所有权、当前 Deployment/ReplicaSet/generation、恰好两个 Ready 原 Pod/节点、实际镜像/探针/sidecar，以及 Service-owned EndpointSlice 的 Pod UID/IP/端口。只执行有界 kubectl get，不读 Secret、不 exec/scale/delete，executionAcceptance 固定 NOT_RUN；annotation 不是构建来源证明。

公共 runner 固定两 tenant 各两 actor，创建四 Workspace、八个 files/Shell Session。验证签名/篡改拒绝、同 tenant 非 owner 与跨 tenant 404、同键受理回执、实际 Write/Read/Edit 内容和下一 Turn 历史；Shell 只批准完整 preview 中精确前台命令，检查 Allow 一次效果/Deny 无效果、Action 重放原 operation、SSE 真断线/续游标、前台取消无重复效果和 close 原 operation 完成。HTTP/body/SSE/等待有界，报告只存身份、阶段和效果摘要；失败保留原 key/ID，不能新 run 重试未知副作用。成功关闭 Session，但保留 Workspace/测试文件供原范围清理。

PUBLIC_SCENARIOS_PASSED 仅描述被访问服务的这些公共场景，placement/fault/capacityAcceptance 仍 NOT_RUN，scaleInEnabled=false。两真实 Harness Pod/boot 的执行放置、SQL fencing、idle release receipts、忙/崩溃/丢 ACK/未知效果和 HPA 必须独立证明，不是脚本绿灯即完成池验收。
