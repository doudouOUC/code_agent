## 解决了什么问题

Managed 输入框无 Session MCP 菜单，用户看不到持久 catalog 的服务与发现状态；直接复用 daemon 目录又可能跨服务端或 Session 读到别的配置。

## 最终实现方案

新增 WebShell POST session-mcp/query，强制当前 actor，复用可读 Session 的 ManagedMcpCatalogService 与持久 mcp_configuration/catalogRef，而非现场发现。结果展示 tools/resources/prompts 数量及 complete/partial/failed/stale，已释放连接仍按 stale，空状态不冒充连接成功。

provider/useManagedMcp 绑定 provider/client/Session scope，懒加载并用 AbortController 丢弃切换后的响应，核 session_id。复用 composer AddMenu，菜单只列目录，不 connect/refresh/调用 resource_read 或 prompt_get，也不注入 legacy daemon 工具。partial tool discovery 的模型描述携带 JSON 转义原 serverId/toolName，名字/参数 schema 不变。

后续 #15119 已在此只读 catalog 之上增加独立 Session MCP 管理：空闲授权 OPERATOR 选择管理员已发布 pin，先保存原命令/revision 再 drain/configure，未知结果沿原键恢复。本 PR 菜单读取本身仍不执行 MCP；不能把原切片的只读范围误作当前 main 完全没有管理入口。
