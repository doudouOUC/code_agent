## 解决了什么问题

缺少可审阅的 Managed 实验部署入口，直接把 daemon、浏览器凭据和 Java 签名密钥混在一起，可能暴露本地执行面或在 retained PVC 仍存在时意外重生成原密钥。

## 当前实现方案

新增 Helm chart：单副本 Recreate 应用 Pod 内 colocate Java/Hosted Harness，可选独立 web 容器；MySQL 8.4 单副本 StatefulSet 持久化。内部 Store/Harness/Broker 仍走同 Pod loopback，不等于跨 Pod 共享 Harness 池。默认不启用 Runtime 和 web，无 HPA/HA、自动跨节点接管或 CSI 回收。

可选 Runtime 用匹配 Java+CLI 派生镜像，由 Java 在同容器启动 durable local-process worker；明确绑定可信 nodeName，Workspace 和 Runtime 状态分别 RWO PVC，真实 machine-id 只读挂载，trusted reboot recovery=false，默认关闭子 Agent/publication。启动脚本拒软链、非本 UID 和非普通文件，修复私有状态权限。相同 Node/Pod/boot 的身份条件不等于 Pod 替换后自动恢复，不能为跑通而关闭身份检查。

最新启动分支仅在 broker 明确为 false 且两个 Runtime 私有路径均未配置时跳过目录检查，允许组合镜像只跑 Java；其他配置继续要求完整私有路径和原 UID/类型/权限，不因缺目录静默开启非耐久模式。

Secret 首次生成后 keep，升级复用；已有数据库/Runtime PVC 缺原 Secret 时拒绝，不静默换密钥。web token 与 Java signing key 独立，均至少 32 bytes。`qwen serve --managed-web-config` 只接受网关配置与 hostname/port/origin/auth 参数，拒与 daemon、Managed local/workspace 模式混用；API 目标仅无凭据 loopback HTTP origin，绝对 signingKeyFile 和固定 tenant/actor。复用 Host/CORS/Bearer/签名代理，静态页可加载但数据路由需鉴权，未知路径 404、WebSocket upgrade 关闭；不挂 daemon 路由。

模板对 tenant/actor 和模型 key 增 toString/trim/required 校验，补 0/123、null/空值/空白的渲染断言；不是本次确认 Helm 渲染通过。CLI 长选项检查不再把单横线开头的 token 值误判为另一个长选项。

managedOnly boot 直接展示 Managed WebShell，Session 导航保存 managedSession 并隔离 Local history；仅 URL 真正改变才 push history，保留其他 query/hash。smoke 使用真实签名验证 unsigned 401、原 Session 历史/新 Turn、assistant marker 和 close operation；历史查找沿编码后的原 cursor 分页，不能只查第一页或用旧 assistant 代替新 marker，耗尽仍未见目标则失败。可保留 Session 后验证重启历史，但不覆盖 Runtime 物理工具或集群故障。chart/template 测试和烟测脚本存在不证明集群已部署。

## 边界与风险

- 不是生产参考架构或完整恢复承诺；可信 Node 约束、持久卷和原密钥保留不能简化为无状态重建。
- 原生集群、升级/备份、Runtime 替换和跨网络访问仍需独立验收；main 的共享池工具不能证明该 open chart 已通过。
