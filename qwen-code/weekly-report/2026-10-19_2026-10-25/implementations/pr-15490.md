## 解决了什么问题

仅导入静态 Skills 或分别配置 MCP/Hook，无法固定整个扩展的来源、包内容、settings 修订和 Session 生效版本；直接热载宿主目录又可能扩大权限、影响其他 Session，或在丢回包后重复执行未知命令。

## 当前实现方案

候选以默认关闭的发布/执行配置和部署 allowedActors 为前置。Workspace 读权、OPERATOR、ACTIVE 与原 actor/key/请求摘要分别校验，公共和 WebShell 路由同步。原始 git/npm/release/目录/archive 来源经过显式同意、目标 platform/arch 编译和有界准备，不直接发布已安装目录中的凭据；剥离私有文件，拒软链/越界路径、动态 Skill 权限/Hook/model/path 和不支持的 LSP/channel/workflow/executor 声明。产物为带 SHA-256 的不可变 tar.gz，不依赖源目录 watcher。

发布先持久 PREPARING/原 operation，再有界流式验摘要、fsync 文件/目录并建立不可覆盖 archive，最后提交 PUBLISHED/settled；最大 100 MiB。签名覆盖实际上传 bytes，复用原认证，不拿租户 header 授权。settings 以原 scope/revision 加密保存，读回只给已配置键，CAS 和原值重放校验；8 KiB/128 项预算。Workspace catalog 最多 256 个扩展，单 Session 最多 32 个精确 extensionId/packageRevision/packageDigest/settingsRevision pin。

V1 增 ma_extension_package、ma_extension_settings、ma_extension_operation；该 head 共 38 业务表，main 的 35 表不包含这三表。开发 catalog 重建，不增加 V2 migration。初始 pin 必须在持久 Session/创建 receipt 前通过已协商 lifecycle 的 Shell/MCP profile 校验；Files/Read 或缺协议拒绝，不在创建后补救已受理失败。初始化只能沿原创建选择、首次模型提交前的受限路径，不能借 bootstrap 绕过后续空闲检查。

安装沿 Session 原 config_install 链：preparing→prepared→committed→active，保存原 Runtime binding/generation/Workspace generation、不可变 effective bundle 和两端 stage/enable ACK。commit 同时改变唯一 config binding；Runtime prepare 校验包、目标、settings、组件预算和可解析依赖，再排空变更组件、激活并回读，Harness 才启用对应视图。独立 MCP 的未变精确 pin 可复用，不全局清空其他 Session；配置操作与 Turn/待批/未结算 child 共享准入屏障。

commit 后激活/ACK 未知保持 recovery_required，拒新工作；继续只查询/推进原 operation 和原 Runtime，不透明替换。显式恢复旧内容先要求原 operation 的 stopped receipts，再以更新 configRevision/补偿 operation 安装旧 bundle，不回退代数，不将未知原命令重新 execute。普通查询读取已提交配置记录，不通过查询自动提交工作。

七类贡献包含静态 Skills、commands、agents、context、MCP、Hooks 和 settings，权限仍受 Session 基础工具/审批/Plan 限制。command 的文件/Shell 预处理逐步保存 tool_stage 的原输入、权限、Hook、Action 和结果；恢复走原 status/cancel，不把输入展开当无副作用字符串操作。包 agent 使用已提交 bundle 和受限 launch snapshot 校验工具/模型，不开放 agent 私有 MCP/Hook 或自定义 executor。私有资产用 extension URI 在原 Runtime 读，不把真实宿主路径当公共标识。

执行 profile 显式区分 Linux delegated cgroup 与 macOS developer process-group，capability digest 必须一致；原 Session/configRevision 的 owner journal 和停止回执保留。Linux 要求已加入进程树并确认空，macOS 依原 ledger 证明登记组消失，unknown 不删除原 owner；process-group 不是 Linux 进程树或整机恢复证明。WebShell 管理页、创建选择和 Java/TS SDK 同步；确定 revision 冲突可刷新解锁，未知结果保留原请求键。

## 关键代码路径

- `packages/core/src/extension/managed-package.ts`：原始来源准备、封闭编译范围、目标和 archive 摘要。
- `packages/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/extensions/ManagedExtensionPackageService.java`：发布/加密 settings、原权限与 pin。
- `packages/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/extensions/ManagedExtensionArchiveStore.java`：耐久 archive 写入与读取校验。

- `packages/cli/src/serve/managed-extension-runtime.ts`：原 Runtime prepare/activate/status/reconcile 和资产读取。

## 边界与风险

- 多副本发布要求共享耐久 archive 和匹配密钥/consumer；不能以本地 cache、包版本名称或相同表数证明可恢复或兼容。
- 完整平台/故障矩阵、真实 MySQL 与 CI 门禁仍需独立验证；未合入包管理不能被写成现行 main 能力，预检也不证明动态命令一定可执行。
