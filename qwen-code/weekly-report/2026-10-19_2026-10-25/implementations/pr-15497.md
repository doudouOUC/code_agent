## 解决了什么问题

模型声明包含 monitor 或 Shell 的 is_background，但原 Session 没有 publication/领域 funnel，执行时才拒绝；模型会反复生成根本无法执行的调用，测试还把这些失败计入正常公共流程。

## 最终实现方案

用共同 helper 统一声明与执行准入：后台 Shell 需要 publication、childRuns 和 childRunAdmissionsEnabled；Monitor 需要 monitors、publication 和 monitorRunAdmissionsEnabled。缺 Monitor 条件时不声明，缺后台条件时从克隆的 Shell schema 移除 is_background，改为准确前台说明并保留文件修改无备份的警示。开关撤回立即收窄声明，不增加后台权限。

执行仍使用相同条件；强塞未声明 monitor 按 profile 拒绝，测试断言不 acquire/prepare。前台普通公共 Shell、SSH foreground-only 与已有正向后台/Monitor 切片分开；公共 Java/fake model 断言更新为只请求实际可用工具，不再要求先触发两次无意义拒绝。
