## 解决了什么问题

公开 Shell 分成 /1、/2 且默认不支持完整关闭/归档；本地启动器又覆盖 lifecycle 广告，容易出现 UI 可见能力、实际工具与 Server/Harness 协议不一致。

## 最终实现方案

只保留精确 hosted-workspace-shell/1；Shell/2 从 TS profile 和 Java 公共 Shell 判定删除，definition compiler/create/load 明确拒绝旧 Shell/2，不自动迁移旧定义。Shell/1 原生 glob 纳入搜索工具集合并在 default/auto-edit 沿原 profile 预批准；不是同名 MCP 工具或任意 profile 的 blanket allow。read-only snapshot 仍只读工具，内部 team-lead 不因本变更获得 glob。

lifecycleV2Profiles 默认 Shell/1，显式空值禁用，自定义列表全量替代。local launcher 使用相同 contract/env，不再硬编码另一份；readiness 对列表精确核对。Shell close 和活动 delete 走原生命周期 v2/可靠 stop；archive/unarchive 需 completed close proof，unarchive 恢复 CLOSED 而非重新打开。活跃/取消中的前台 Turn 或 pending approval 返回 turn_active。

begin protocol2 后普通 renew 被 fence，但仅为仍活的原 writer lease 用 GREATEST 延长至配置期限，绑定原 operation/tenant/head LIFECYCLE_ONLY/ACTIVE。不会复活已过期 writer，也不允许重试不断刷新失效 owner；close 仍依赖原 worker 的终态与资源证明。后续 #15313 加入 web_fetch 不改变这里的原 lifecycle 身份。

2026-10-26 后续 #15497 进一步让模型声明与真实 publication/领域 owner/开关准入一致：无后台 lane 时不声明 monitor/is_background，只保留前台 Shell；不因统一 Shell/1 或默认 lifecycle v2 自动获得后台能力。

## 边界与风险

- 默认生命周期不是绕过当前租约、审批或原 Runtime stop 的权限；没有 idle/keep-warm/CSI 自动退役承诺。
- 旧 Shell/2 不是静默别名，部署与已保存定义需要人工核查；本次未验证真实升级与回滚。
