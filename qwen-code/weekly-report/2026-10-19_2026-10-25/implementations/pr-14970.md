## 解决了什么问题

首页只能新建受控目录或复用已登记 Workspace，本机已有项目需要人工注册；直接接受客户端绝对路径则可能暴露服务端私有状态、重复登记或让重试指向另一目录。

## 最终实现方案

默认关闭 local-directory-import-enabled；启动配置要求 auth OPEN、公开监听 loopback、非空 trusted actor header，且 Workspace files/durable local-process/verified recovery 均启用。它限定可信单用户本机部署，不是 signed profile 或远程多租户任意目录导入。

localPath 与 sourceWorkspaceId/cwdRelative 互斥，controller 强制 actor。路径要求绝对、无控制字符、末端非 symlink，toRealPath 后可读可遍历目录；ancestor symlink 可被 canonical 解析，不承诺逐层都无 symlink。拒绝 .git/.qwen-child-workspaces 段和私有 runtime/creation roots，导入根也不能包住私有根。

默认登记项目父目录；发现祖先 .git 时将根移到最外层仓库之外，根不可是文件系统根且需可写，使维护 marker 留在仓库外，cwdRelative 指回所选项目。不复制项目。目录浏览空路径从 user.home 开始，最多扫描 1024/返回 100 个直接非 symlink 子目录。

只复用当前 actor OWNER、ACTIVE ROOT、已验证 LOCAL 且包含项目的 Workspace，不借用外人/SSH/CSI alias。WORKSPACE_CREATE receipt 固定原 localPath/name 和 native host/device/inode/birth、逻辑 Workspace/storage 身份；pending 与最终事务重验原目录及授权，必要时安全复用并发已导入根。

新登记使用预期物理 identity，最终事务原子写 Workspace/OWNER/completed receipt；重试原 key/body，改路径冲突，不因重放恢复已撤销权限。无新 schema migration。当前 main 保留目录校验/创建身份边界，后续 #15061 将同一流程接入统一入口；#14928 现已合入 signed loopback 导入，认证门禁为 signed 或 OPEN+trusted actor，仍拒绝远端 listener。原切片的 OPEN-only 不再代表当前 main。
