## 解决了什么问题

普通 LOCAL/SSH_LOCAL 的单 holder 将整个存储串行化，一个 UNKNOWN 工具就阻塞其它独立 Session；简单去掉锁又会让释放、undo、维护和恢复误清别人的执行权。

## 最终实现方案

V15 在原 ma_runtime_session 加 execution_storage_key、execution_exclusive 与 physical-key 索引，仍为 32 业务表。普通 LOCAL/SSH_LOCAL 在 tenant storage domain/alias、原 binding/physical mapping 和 owner 行锁下登记每个精确 Runtime Session 成员；可并存多个非独占成员，不再以单 ma_storage_owner holder 作为普通执行 authority。

准入仍拒绝 legacy holder/maintenance 和既有 LOST/DRAINING/OPERATOR_RECOVERY/attested RECOVERY_BLOCKED placement 屏障。isHeld 要求无旧 holder/维护及自身原成员，release 只清自身 binding/generation/runtimeSession/Harness 对应的 execution 字段。READY 上 UNKNOWN 保留原成员/禁止重放，但不排斥另一普通 Session。

undo 先验证原成员；有其它当前成员则返回 snapshot/conflict 而不改文件。仅自身时置 exclusive，短暂拒绝新 acquire；正常响应清独占，错误/未知保留 sticky exclusive，execute/release 返回 recovery_required/writer_unproven，不靠 lease 超时抹掉。文件级历史检查仍保留，过去曾并发本身不永久禁用 undo。

登记/fence/迁移/维护和 child Workspace 准入仍需全部成员 drain。停止/丢失原 binding 的清理在原 operation lease/fence、无未结算工作证明后只清原成员，保留别人。operator recovery 只接受精确唯一原 LOCAL 成员，歧义拒绝；保留策略查成员及 cleanup debt。

resident/private CSI 不使用普通 execution membership，字段须 null/false，原 CSI RESERVED/single unfinished Session 与库存/checkpoint 约束保持；不能把普通并发写成 CSI 并发或物理释放。

原切片在 V1–V14→V15 时要求 drained cutover：旧版本停止新 Turn，完成/恢复并释放所有普通 holder，停止旧 Server/Broker/Harness/worker/外部 writer，核查无非维护 LOCAL/SSH holder。2026-10-24 当前 main 的 #15263 已折叠为唯一 V1/32 表、删除旧 V15 文件；开发目录重建，不再提供逐版本升级链。UNKNOWN cleanup 未证实留旧环境，不手清 ownership；无 singleton 自动转换/回退 authority，不支持混版本滚动升级。原执行成员与独占维护边界保留；#15171 的公开子委派仍要求 session isolation，不能从普通并发推出 shared Runtime 子委派支持。
