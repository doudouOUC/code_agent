## 解决了什么问题

Managed 只有粗粒度审批模式，用户不能为当前 Session 保存明确的 allow/ask/deny 规则；直接复用普通 CLI 设置或分类器历史，会读取 Harness 宿主路径，或把工具输出/Agent 消息当成真实用户授权。

## 最终实现方案

在现有 approval-selection/1 上分别协商 permission-rules/1、auto-approval/1，Java Connector/池、SDK、HTTP store 和 WebShell 同步。合资格公共 bound Session 沿原 owner/OPERATOR、expected revision、原 actor/key/摘要 receipt 修改；规则变更要求无活 Turn/待批/未结算 operation，模式仍可按原 live 能力修改。省略规则保留原值，显式三个空列表清除；确认需结果及原 revision 回读一致，冲突不覆盖。能力撤回拒执行，不静默回退。

唯一 V1 给 ma_session/ma_turn 增 permission_rules_json 和 CHECK，模式增加 auto，仍 32 表。Turn 准入冻结规则/模式/revision；持久 Action 增 requiresHumanDecision=true，只接受 true，恢复和 live poll 都保留人工下限。规则更新不能中途改变原 Turn；live reader 拒缺失、倒退或规则变化。后台 wake 缺用户 admission 时读当前授权选择，Auto 分类器无法证明当前真实用户输入则转人工；公开 child launch 将父 auto 收窄为 default，不扩大原八字段快照。

三端闭合语法为 allow/ask/deny：每类最多 32、合计 64，单条 UTF-8≤512 bytes、编码对象≤8192 bytes，同类重复/控制字符/首尾空白拒绝。仅工具名、Shell 命令、WebFetch domain、MCP server/tool pattern，不支持宿主文件路径规则。使用既有 PermissionManager，deny 优先 ask 再 allow；以固定远端上下文和 Shell sandbox 判定，不读取 Harness 文件系统或 settings。MCP 用保存目录中的真实 server/tool 身份，不靠易混淆的展示名。

工具资格/参数/Plan 和 Hook 仍先约束执行。规则 deny 形成未执行拒绝，显式 ask、Hook ask、exit_plan_mode 写人工 Action，不能由 yolo/live 切换自动放行。其余先按规则/原 profile 决定，Auto 只对需要审批的原生工具调用既有 classifyAction；分类 unavailable 转人工，明确 block 拒绝，MCP 不交分类器。分类上下文只从最多最近 40 个已接受原用户输入读原 bytes，结合模型 function calls，不把 Agent/工具输出当用户文本；使用当前已选模型配置与取消信号。

WebShell 提供三类规则编辑、清空、stale revision 重载与原键 pending 恢复，忙 Session 禁改规则；新建 Shell 的初始策略限制仍在，Auto 通过后续授权选择，不是把公开创建默认改为 Auto。

2026-10-26 后续 #15449 已增队列三表，当前 V1 共 35 表；本 PR 本身只增规则列。#15496 为 dialog key 增独立前缀，避免与 composer 冲突，不改变规则/审批 wire。

## 边界与风险

- Auto 是分类决策，不是确定安全或物理停止证明；不会绕过 Runtime、Plan、Hook、MCP 人工下限或原权限。规则 allow 也不授予未注册工具和宿主访问。
- 当前 V1 原地更新须重建开发 catalog，旧 Server/SDK/Harness writer 必须隔离匹配升级；本次没有运行新旧协议或数据库切换验收。
