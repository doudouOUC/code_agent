## 解决了什么问题

事件消费者、公有分发与 wake 各自重复维护线程池和关闭行为，canonical JSON 递归构建中间字符串；维护时容易让协议校验和资源边界漂移。

## 最终实现方案

复用 TransportExecutors 的固定线程/有界队列/AbortPolicy 和两秒关闭等待，保留各角色容量及拒绝后 SQL 恢复。WakeFence.open 与 wake kind 归一，不改变 ACTIVE Session/ACTIVE-or-SEALED head 与持久水位门槛。

ManagedEventEnvelopes 合并 exact keys、UTF-16 surrogate 与数字/摘要检查，用单 StringBuilder 输出规范 JSON；安全整数采用等价 fast path，其余仍按 ECMAScript 数字格式。公有 row 先核封闭字段再在原 list-depth 中求 digest，不改变 wire/顺序/SQL 权威或 MQ 的非权威定位。
