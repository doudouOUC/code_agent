## 解决了什么问题

Managed 会话缺少子 Agent 的独立状态、时间线、产物与取消恢复入口。把一次取消 HTTP 成功显示成任务 cancelled，会掩盖仍运行的原任务；超时换幂等键、页面切换或刷新又可能重复提交取消。

## 最终实现方案

Java provider 复用已有 `/tasks/query`、`/tasks/get`、`/tasks/events/query`、`/tasks/cancel` 与 operation query，不增加服务端 API/schema。当前容器宽度达到 1100px 时用 360px 侧栏，否则用 Dialog，关闭后回原触发按钮。列表按服务器原分页读取，再过滤 `child_agent`；Shell/Monitor 等混合页可能显示空页但仍可翻页，不扫描全库或伪造总数。

`useManagedTasks` 仅在面板打开且页面可见时每 3 秒轮询；每请求校验 Session/task 身份，以 owner、generation 和 AbortController 隔离切换后的旧结果。已观察终态不回退到 running；events 按 cursor 去重、逐页读取，cursor_expired 清掉旧游标并显示历史缺口。面板展示 task state/runtimeState、起止时间、输出和 artifactRefs，不把时间线或输出片段冒充公共最终结果。产物沿既有授权 reader/`ManagedArtifactContent` 读取，复核 Session/artifact ID。

取消需显式 productScope 身份、当前 capability 和 `child_agent`。hook 在 POST 前向按 provider.storageKey/Session 分区的 sessionStorage 保存原 task/key；保存失败不发送。已拿到 operationId 后优先查询原操作，未知 ID 的意图由用户恢复原键提交。operation 必须为同 Session/task 的 task_cancel，已接受的 operation 不能换 ID 或状态倒退。

确认窗口 30 秒，轮询间隔 1/2/3 秒。operation completed 只表示停止请求已接受，还须 GET 任务实际终态才清理意图；任务自然完成仍保持 completed。未知结果、超时和 recovery_blocked 保留 stopping/unconfirmed，重放拒绝不证明原请求未受理。首次确定性的 400/403/404/409 或 operation failed 才按对应路径结束意图。capability 撤销后仍保留已保存取消的恢复入口，不以取消过程新增聊天发送锁。

## 边界与风险

- 当前仅 child_agent 可展示/取消；混合任务原分页没有 child 总数，空页不是没有任务。
- sessionStorage 是当前浏览器会话的恢复线索，不是服务端执行权威。身份变更必须更换 productScope/provider，token 同身份刷新不能制造新业务键。
- 最终公开结果不由该面板新增；取消接受、任务终态和真实物理停止仍是不同证据。
