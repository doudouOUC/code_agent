## 解决了什么问题

HTTP Managed Session adapter 没有收集私有 file-history preparation 内的 input、tool definition 与 intent refs。SQL 要求这些 candidate 在原 journal 事务闭合，缺引用会使 live native grant→worker→retained history 链路无法准入；不能用手工塞授权或 stub 结果绕过缺口。

## 最终实现方案

`collectNestedResourceRefs` 将 managed-file_history 纳入 reference container，仅 schemaVersion 2 且 profile 为 csi-files-retirement/1 时解析并收集 preparation 的嵌套 refs；同一 helper 服务 commit、resource-read、只读 snapshot。只遍历 preparation，不直接遍历顶层 previousRecordRef；prepared 记录的 preparation.intentRef 与 predecessor 相同，SQL activation proof 要求它在当前事务重新准入，因此仍进入 candidate。bind/result 的旧 predecessor 不被泛化重纳入。畸形 JSON/null 明确拒绝；普通 snapshot、其它版本/profile 保持既有行为。

新增显式 MySQL IT 与 Node producer/worker 装置，使用生产 Core authority、HTTP adapter、Broker/JDBC/native read 和 worker composer。SQL dispatch 生成真实 grant，不向成功路径插入 native_authorization_json；限定原 writer/activation 下消费 write/edit/read 结果与 retained backup，再继续原输入。断言两个完成 Turn、四条 settled native execution、writer generation 1、原 first activation revision 与完整 bytes，同时检查错误凭证/owner/context/未授权 execution 在效果前拒绝。

Fixture 明确映射 Pod endpoint 到自有 loopback worker，所有平台均映射 mount/proc-fd 来源，不依赖宿主暴露 /proc/self/fd；真实 inode/file handle 与生产认证/结果/history 不被 stub。finally 先对各 Node/listener/client 清理，再统一断言退出，避免首个断言失败跳过其余释放。新增 ESLint Node fixture 路径豁免不开放生产路由或公共能力。
