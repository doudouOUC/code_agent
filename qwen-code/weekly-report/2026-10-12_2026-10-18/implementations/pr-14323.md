## 解决了什么问题

Shell 不能显式选择 Full Access，已创建 Session 也无法调整下一回合审批。只改 UI 或可变 Session 值，会使重试、冷恢复及在途工具沿不同审批策略执行。

## 最终实现方案

仅内置、public、bound Workspace 的 qwen-code Session 可选择 default/auto-edit/yolo，固定 AgentDefinition 仍固定。创建可显式选择 Shell yolo，但部署默认继续 default/auto-edit。只有原 Session owner 且当前具备 Workspace OPERATOR 的 actor 能改策略；活动 Turn、可决 Action、未结 operation、retained Runtime 或恢复状态阻止变更。

原 approval_mode 保留不可变定义；V6 新增 selected_approval_mode/approval_revision，并给 Turn 加原策略快照。Session 锁内校验 expected revision、actor 幂等回执、更新及 session.approval.changed 原子提交；同键不同内容或旧 revision 拒绝。下一 Turn 在同锁固定 effective mode/revision，恢复只读原 admission，不读当前策略。

SDK/Harness 协商 `approval-selection/1`。revision 0 省略在线字段，以原定义维持同 prompt 重试摘要；非零快照缺能力拒绝新的执行附件，但不堵取消/生命周期清理。yolo 跳过普通审批，仍服从显式 Hook deny/ask 和 Action 边界。切换保留配置的审批超时，旧缺省为十分钟。

WebShell 使用专用 query/change 接口，不增加公共 REST 面。发送前保存原键/意图，未确认期间阻止输入及模型/cwd/审批交错操作；响应后以至少该 revision 的读回解除 pending。初始策略与当前策略分开投影，旧摘要不能回退新状态。

## 边界与风险

- 不支持运行中改策略、固定定义 override 或全局默认 Full Access。V6 顺序接 V4/V5，不改写初始策略。
- Linux 原生、持久 whole-JVM 恢复、未知效果及真实上游模型仍需独立验收，HTTP 接受不证明工具已停止。
