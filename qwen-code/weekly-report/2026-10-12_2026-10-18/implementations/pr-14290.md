## 解决了什么问题

Hosted Workspace 缺少受控 grep/目录列表，直接注册普通 CLI 后备实现会超出保存的 Session 目录、失去取消/期限/输出上限，甚至扫描其它已安装 Session 的私有子目录。

## 当前实现方案

新增 files/3、shell/3 profile，纳入 glob、grep_search、list_directory。`QWEN_MANAGED_AGENT_WORKSPACE_SEARCH_ENABLED` 默认 false，只影响内置 Agent 的新建 Workspace Session；已有 Session、原幂等请求与固定 AgentDefinition 不被开关重写。生命周期、冷恢复、审批 continuation、迁移和 SDK/生成类型显式识别新 profile，/1、/2 工具集保持原样。

复用 Core Glob/RipGrep/LS，向内部调用传 Session containmentRoot 和五秒期限。Harness 在 acquire 前拒绝绝对/遍历路径；worker realpath 和 ownership 双重检查，在扫描前拒绝包含其它 Session 私有子目录的搜索根，对全部收集结果检查后才展示切片。grep 只启动随包 rg，禁配置/跟链，不走 shell 或主机后备实现，取消/超限等待真实进程退出。目录枚举使用可终止 worker，最多扫描 1000 项、展示 100 项；grep 默认 200、最大 1000 个结果，原始输出超 1 MiB 失败。

Core 和 executor 分别按实际 JSON/UTF-8 将 worker 结果限制为 48 KiB，Harness 仍守 64 KiB outcome/工具消息总预算；保留状态和明确截断提示，不替换匹配正文中的物理目录字符串。复用 prepare/dispatch/status/cancel/持久结果链路；丢响应只观察原 execution，不通过再次搜索补恢复。搜索命中不等于 read-before-write，原生预批准不能授权同名 MCP。

## 关键代码路径

- `packages/core/src/tools/bounded-search.ts`：目录包含关系及结果字节上限。
- `packages/core/src/tools/ls-search-worker.ts`：有界直接子项扫描与排序。
- `packages/core/src/utils/ripgrepUtils.ts`：随包 rg、进程取消/输出限制。
- `packages/cli/src/serve/managed-runtime-tool-executor.ts`：独立 ownership、工具注册和终态结果裁剪。
- `packages/cli/src/serve/hosted-workspace-profiles.ts`：精确 /3、只读与生命周期分类。
- `packages/sdk-java/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/store/WorkspaceToolProfiles.java`：服务端 profile 与生命周期读取点。
