## 解决了什么问题

消费者虽注入 ToolPublicationObjectStore，Spring 却总初始化 OSS，错误分类也直接依赖 OSSException，导致应用提供其他存储仍需要 OSS 配置及凭据。

## 最终实现方案

保留单一字节存储接口，将 requireUnversioned 改为 validateConfiguration；接口约束私有/持久/不可变、原子 no-overwrite create、准确 key 删除和原字节读取。物理 create 不自动重放；每次新读取及重试前检查授权/lease guard，失败流不因此可重放。SQL 仍是 publication 身份、归属、操作账本权威，消费者不自行挑后端。

OSS 适配器在边界把服务端/客户端错误转为 ToolPublicationStorageException 的 ACCESS_DENIED/FAILURE，保留 cause、有界读取重试与写入策略。API/异步校验只依赖通用分类，拒绝仍为 403 managed_tool_publication_storage_denied，不泄漏后端消息或对象位置。

默认 OSS 客户端/Bean 移入注册的 Boot 自动配置，仅在通用发布配置存在、功能开启且无自定义 ToolPublicationObjectStore 时装配。应用 Bean 先于该配置被观察，关闭/maintenance-only context 不启动 OSS。默认仍校验固定区域 HTTPS、V4、私有且未版本化 bucket，使用自己专用 client。自定义存储免 OSS 配置，但仍需通用服务 URL/容量/期限，并实现发布失败清理所需 delete。

一个部署和同 SQL 的全部实例必须共享同一存储；SQL key 没有 provider 身份，换 Bean 不迁移旧对象。独立 WorkspaceRecoveryMain/WorkspaceCsiWorkerAckMain 仍是 OSS 专用启动器，自定义部署须另接同一实现。

## 边界与风险

- 不实现 S3/MinIO/生产文件系统、后端路由、运行时插件或对象迁移；服务仍打包 OSS SDK。
- 自定义实现须重新编译并满足 guard/no-overwrite/delete；不能用空 validateConfiguration 代替生产保证，旧对象缺失继续阻塞，不回退其他存储。
