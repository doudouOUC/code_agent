## 解决了什么问题

瞬态续租耗尽后调度可能永久停止；丢 admission 响应的输入在 writer 过期后无从取消；恢复失败只做普通 cancel，又无法结清 parked 原执行。公开 FAILED 或进程退出本身没有原生 receipt，现有 close 正确地继续阻断。

## 最终实现方案

HTTP writer 健康频率不变，传输/可重试 5xx 预算耗尽仅在原 grant 有效时一秒重排；拒绝/过期/seal 停止，绝不换 grant。activation heartbeat 三次后可在提交开始时原 lease 内用同事务身份/字节/摘要继续，普通事务仍三次、tenant contention 不重开预算，并保留并发续租较晚期限。不可恢复 append 失败停后台保活，不清写失败锁存。

缺 epoch 不等于未 admission。持有效 dispatch claim 的 owner 锁 Session/head，要求 writer sealed/过期、完整未压缩 idle journal 且查不到该 prompt 的 input.accepted，才在同事务撤回 submission 标记并取消。最终版直接使用 requireIdleJournal 按锁定 head/revision 扫描返回的 accepted 集合，避免另一次普通查询落入 MySQL RR 旧快照；沿原 profile v1/v2 monitor 规则判断 idle。缺失/异属/已接纳证据继续拒绝。恢复 blocked 的终态前先以原 checkpoint/activation/prompt 做取消接管；内部授权限定具体已接纳 RUNNING Turn 与有效 owner，用户并发 CANCELLING 不被失败终态覆盖，工作区原取消未结算则保留重试。

await_runtime 的 UNKNOWN 只允许尝试 cancel 原 execution，不允许 continue/execute 重放；仍要观察停止结果或保留 abandoned/unobserved。前台 Shell publisher 仅连接失败的 cause.code=ECONNREFUSED，且有原 sink 的 aborted、非后台真实结果、有效匹配启动 PID 与 POSIX 原进程组 gone，才能保留 cancelled。finalize 丢失给 unavailable/producer_lost/null manifest/blocked；accept 丢失保留已完成 manifest、delivery blocked。其它网络/HTTP/protocol 错误不得伪装 publisher_lost；错误文本按有效 UTF-8 有界。相同对象及同停止证据才有本地四字段 ACK，不伪造 durable outcomeRef；Windows/未知/仍活/权限拒绝不适用。

当前 writer 从 Broker 只读原已结算 Shell 结果，核对 checkpoint/intent/参数/Runtime 映射及原 activation，复用 manifest/seal/digest 验证后写唯一 tool.receipt/outcome 投影，再解除等待。原执行精确 404 或合法 legacy 无 capture 不获得补回执资格；仅 cancelled 且 delivery blocked 的 publication 结果进入该恢复路径，其他结算不被改写。已有 receipt 复用原 ref；capture 丢失 resultRef 为空、不关联产物，完整结果需全量核验。本地 v1 lost-cancellation receipt 的 pending/blocked 形状单独核验，不把它当 durable publication；并未削弱 requireIdleJournal 或物理 close 门禁。

## 边界与风险

- 不启用 Full Access，不恢复过期 writer 自动续聊，不用 HTTP 202/超时/lease 过期认定已停止。
- 永久不可达原 Runtime 仍可阻塞清理；未知 agent/command 等待不自动获得取消资格。跨 SDK/Java/Harness 必须同版本资格验证。
