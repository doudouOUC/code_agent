## 解决了什么问题

配置准入和模拟 Runtime 响应不能证明真实 MCP/Hook 已执行、没有重放且已清理。静态扩展 #14319 的 Skill 恢复证据也不足以证明 Linux 原进程生命周期。

## 最终实现方案

新增仅 Linux 的 HostedExtensionsIT，复用 hosted-harness-mysql profile、原 Spring/SQL Session Store/内嵌 Broker，运行打包 Hosted Harness、原生 Workspace worker、真实 stdio MCP 与 command Hook。模型确定性选择工具；manifest 由管理员 fixture 配方计算摘要，公开定义只给 pin，不声称 Runtime 自行重算配方。

正常用例核对模型声明、精确 Skill 正文、MCP cwd/一次 fsync 追加、Hook allow/deny。发布 revision 2 后 SIGKILL 并以新 home 替换 Harness，旧 Session 仍为 revision 1，新 Session 才使用新定义。取消带存活后代的 Hook 后断言进程退出、cgroup 空、无 MCP 效果且可继续；lifecycle v2 close 再核对原 worker/MCP 退出、SQL drain receipt 和 holder 释放，并保护独立 canary。

负向用例在 MCP fsync 效果后、响应前退出，保留原 worker/SQL 并替换 Harness。断言原普通 ma_tool_execution 持续 UNKNOWN、无结算结果/第二次调用，实际 load 出现 hosted_turn_recovery_required/runtime_broker_execution_unknown，Turn 保持 RUNNING，新输入和 close 均 409 turn_active。此组不装可选 Hook catalog，避免用不支持的在途 Hook takeover 混淆普通工具边界。

强制测试收尾前保存模型、进程、日志与 SQL 摘要到 failsafe-reports/hosted-extension-evidence。清理 fixture 不作为产品 close 成功证据；未实现 MCP 方法返回 JSON-RPC -32601。
