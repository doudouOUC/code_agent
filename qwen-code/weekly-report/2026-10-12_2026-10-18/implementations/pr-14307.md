## 解决了什么问题

库复用后仍有手写 XML 三字符 escape、LF 行切分和 Artifact byte range 算术。直接采用更宽松的库 parser 或全 XML encoder 会改变既有 ASCII 错误分类、控制字符/引号保留与响应区间。

## 最终实现方案

ChildResultRelay 用 StringUtils.replaceEach 一次替换 &、<、>，保持引号、控制字符和代理项原样；已编码 ampersand 仍按原行为再次 escape。ChildWorktreeGit 用 StringUtils.split(text, '\n') 忽略空 LF 行，保留 CR，不改成平台换行解析。

Artifact 保留先拒绝逗号为 unsupported_range、再按旧 regex 校验精确 ASCII 语法的门禁，之后才委托 Spring HttpRange 计算 suffix/open-ended/上界裁剪。parse 溢出/倒序仍映射 invalid_range，空内容或不相交映射 416 range_not_satisfiable；既有大小限制保持，不能开放多区间或 Unicode/符号数字。测试补充 Long 极值、空制品、逗号、内空白和 Unicode 等价性。

## 关键代码路径

- `packages/sdk-java/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/service/ChildResultRelay.java`：限定三字符 escape。
- `packages/sdk-java/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/service/ChildWorktreeGit.java`：只按 LF 去空行。
- `packages/sdk-java/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/service/ManagedArtifactService.java`：旧语法门禁后复用 HttpRange。
