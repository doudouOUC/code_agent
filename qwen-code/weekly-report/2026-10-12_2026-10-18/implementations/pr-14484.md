## 解决了什么问题

保存 AgentDefinition 的已有会话不能像内置会话切换下一 Turn 审批策略。只开放菜单会绕过 Turn 快照、固定定义、Actions 和旧 Harness 能力边界，可能以错误策略执行或恢复。

## 最终实现方案

扩展资格到绑定 Workspace、有效已保存 definition digest 的精确 files/1、shell/1、shell/2，会话 owner 还须当前 OPERATOR/OWNER；不开放 files/2、CSI、MCP、team-lead 或未知 profile。复用 V6 的 Session selected_approval_mode/revision、锁内 expected revision、actor 回执和不可变 Turn 快照，无新增 schema。改策在原锁下与新用户 Turn 准入互斥，活动回合/Action/操作、未释放 Runtime owner、迁移或恢复阻塞均拒绝。

原 definition/初始 approval_mode/创建 digest 不改，自定义创建仍不能覆盖编译初始策略；Shell 定义仍不能以 yolo 初建。授权同键重放先返回原回执，不二次递增或倒退当前策略；新变更才检查执行能力和忙碌。yolo 只跳过普通已准入文件/Shell 审批，Hook 明确 ask/deny 及 Workspace/Runtime 约束保留。

新增 `agent-definition-approval-selection/1`，自定义会话正 revision 执行须同时有旧 approval-selection/1；Connector 按不可变 Session 事实做额外协商，不给 SDK 请求增加 Session-kind 标记。旧 Harness 可继续未覆盖的初始策略，覆盖后能力丢失则拒绝执行，即使又切回初始模式。list/get/query、Actions 和 attach/submit/recovery 对齐资格，读回、授权旧回执及既有取消/清理不被误当成新执行。

每个新合资格用户 Turn 冻结选择；revision 0 仍不发 wire 字段，旧 null 快照且零 revision 沿原身份执行，正 revision 缺快照保留 approval_snapshot_missing。恢复/continue 用原 admission，不用会话最新覆盖；终态回执重放不能重跑。创建/既有会话 UI 保留各自 options 语义，复用原先持久意图、原键确认和 draft/model/history；只修改不支持策略提示。

- schema 未变不等于旧 Java writer 兼容：提交自定义覆盖前必须升级/隔离全部共享 catalog 的旧 Java/Broker 端；不能清 revision 或改历史回滚。
- 不新增公共 REST 改策接口，不扩工具或平台能力；缺新能力时保持阻塞，不静默回到定义初始策略。
