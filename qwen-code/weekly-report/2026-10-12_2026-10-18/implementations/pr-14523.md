## 解决了什么问题

文件效果和完整 receipt 已持久化，但原 Hosted 进程在 tool_result/checkpoint 补齐前退出时，SQL 与 caller 仍只接受首代 writer。重新运行文件工具可能重复修改，恢复必须消费原证据而不是重建效果。

## 当前实现方案

在原连接、原锁序和数据库时间下资格化 ACTIVE/READY、未压缩的原 journal。只接受一个无 deadline 用户输入、一个原文件批次、全部成员 SETTLED 且有授权 dispatch、完整 success/error outcome 和唯一原 receipt；原 writer/activation 两个 lease 都必须过期。保留原 READY Runtime Session、binding、mount、worker 与 retained history。缺回执、取消、PREPARED/执行中/UNKNOWN/abandoned、外来成员、流式/最终模型输出已提交或不支持的尾部均拒绝。

新 Hosted boot 取得递增 writer generation，安装恰好下一 activation epoch；writer claim 与 activation 仍是分离事务，未安装 claim 不能冒充有效 writer。再次接管过期的未安装 claim 不跳过已安装 activation，原 SQL reader 按 writer/activation 分段验证 journal，不放宽跨身份提交。

recoverHostedCsiReceipts 先核对原 input 字节、assistant Parts/ordinal 和 checkpoint，再为整个批次预检全部 receipt、outcome、消息 ID/时间/model/父链及既有 history 前缀。只补缺失的原 tool_result 与 checkpoint resolution；需要时读取原 worker history 快照并保存 preparation=null 的闭合记录，随后用保存响应进入模型 continuation。修复阶段不 allocate、prepare、dispatch 或重执行文件工具；不新提交 input，不复制新 definition/root。

冷准入必须在原 pending batch 被最后一次 checkpoint resolution 清掉前发生；已安装 successor 上的重试可观察 results_ready，不等于任意 results_ready 尾部都能冷接管。错误先阻塞 owner，原 bytes/receipt/未消费义务保留。
