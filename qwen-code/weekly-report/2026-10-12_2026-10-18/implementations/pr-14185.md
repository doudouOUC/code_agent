## 解决了什么问题

32 表 catalog 混用 DATETIME、BIGINT 和 created_at/updated_at，JDBC driver 对 unsigned/boolean/大字段的 getObject 返回类型不同。隐式窄化或时区转换会影响 lease、排序、幂等完成时间和 query mapper；SELECT * 与原始 Map 拼接还使范围、字段和容量行为难以核对。

## 最终实现方案

直接调整 canonical V1 的时间字段为非负 epoch-millisecond BIGINT UNSIGNED，创建/修改时间统一 gmt_create/gmt_modified，lease/deadline/完成/retirement 时间保持毫秒单位；API 的 Instant/Timestamp/公开 DTO 不改名。`ManagedSchemaTime` 使用数据库秒加毫秒余数计算 SQL_NOW，读 null 不变，负数拒绝；Broker setInstant 写 BIGINT、拒绝负数/溢出，databaseNowPrecise 截到毫秒，不沿用 DATETIME/Calendar。

`ManagedSchemaJdbcTemplate` 为 Timestamp 单列 query 和参数接上毫秒转换。`ManagedSchemaRows` 按 JDBC type 显式读 Long/Int/BigDecimal/bytes/text/null，封闭 boolean 列规整 TINYINT，仍只解码已声明 UTF-8 identity，避免改所有任意 bytes。Catalog 验证 MySQL/MariaDB 的 BIGINT signedness，H2 不冒充 native unsigned。

新增封闭 `ManagedSchemaProjection` 列清单和固定 alias，多个 store/relay/collector 用显式列替 SELECT *，删除不必要的重新装配 Map/中间查询；不加通用 SQL 重写器。Automation command settle 同时推进 gmt_modified，错误 actor 或已完成重试不改原结果/时间；回归还覆盖 timestamp/null、receipt 与 query budget。

最终 head `010664ddba0e` 保留 typed receipt 的 actor_id 字节身份，Session 列表沿 immutable 创建时间 keyset 改为 gmt_create，并同步 V3 索引。终态 publication/resource collector 使用 NEVER_DUE_MILLIS=9007199254740991（JavaScript 精确整数上限）代替负哨兵或零，避免 UNSIGNED 越界或终态任务再次到期；lease 统一从 epoch millis 读取，不再做 DATETIME 时区往返。已合入 main `5af87595f346`，不等于这些行为已通过本次运行验收。

## 边界与风险

- 最终 diff 直接改 V1/V3，不提供已存在 DATETIME/created_at catalog 的版本化升级；合入不意味着现有库可原地启动，部署需选择新库或补齐迁移/回滚，不得以 Flyway repair 绕过 checksum/catalog 拒绝。
- Java 时间范围仍受 signed long/Instant 约束，SQL UNSIGNED 不表示接受任意 64 位无符号时间。
- 跨 store/collector 的改动需要有真实锁序、lease、分页、query budget 与拒绝语义验收；本次未执行。
