## 解决了什么问题

32 表基线中的 storage alias 与 physical owner 不是同一个旧 tenant/storage hash。Hosted fault probe 直接查旧 hash 会读错 holder 或错报缺失；同一文件系统 tick 内 birth time/mtime 相同还会误触生产 mount identity 的防歧义拒绝。

## 关闭前方案

新增测试 helper `HostedProbeStorageOwners.owner`，以 canonical storageAliasKey 及原 tenant/storage 查询 ma_storage，沿 physical_key JOIN ma_storage_owner；不查旧 hash，也不回退 decoy owner。Cancellation、provider control、Shell output、SSE gap 四类 probe 共用该查询。测试同时放置 physical 与 legacy decoy，覆盖原字节身份不一致和 physical owner 缺失。

Process crash、public Workspace、Shell lifecycle、team-lead 装置在注册前将自有 Workspace 根目录 mtime 固定为 1ms，使其与真实 birth time 可区分；不修改生产 identity reader 或削弱 mount 核验。这是测试装置方案，不是新的 Runtime 恢复能力。最新 main 已有同类测试修正，但不能据重叠代码认定此 closed PR 合入或推断关闭原因。
