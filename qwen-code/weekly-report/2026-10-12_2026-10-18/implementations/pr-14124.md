## 解决了什么问题

Harness 已支持 captureBytes 选择 remote publication，但 Java SDK/Connector 未传该字段。即使打开 tool-publication，Shell 仍使用 inline producer，可能执行/取消成功却没有 OSS publication，公开结果显示 unsupported_receipt_producer；不能依赖测试 relay 替生产请求补预算。

## 最终实现方案

`CreateHarnessSession.Builder.captureBytes(long)` 增加可选字段，只在提供时序列化，校验闭区间 `[1, 2^41]`，旧 SDK 请求不改变形状。Connector 解析一次 profile，在 publication enabled 且为公共 Shell/1、Shell/2 或内部 team-lead Shell family 时传既有 execution-bytes；Files/MCP/无工具 profile 不传。公共 Shell 的 child-agent 抑制仍独立，不改变内部 team-lead 准入。

该预算仅为原始 capture 上限，producer/admission 开销仍计入既有 Session/tenant 聚合容量，不截低预算或绕过 quota。Harness 持久保存原 definition；Java load 不传当前部署预算，冷/常驻恢复沿用原值，原 inline Session 不随配置改变自动转换，显式冲突预算仍拒绝。

回归 fixture 改用 remote producer，跨 Spring SIGKILL 的对象存储使用自有根目录不可变文件，核验原输出长度/SHA-256、SQL 收集与物理对象消失；不改变生产 storage identity 或 GC 调度。源码设计记录的历史真实 OSS 与 rebase 后本地对象装置是不同证据，本次没有复跑这些验收。
