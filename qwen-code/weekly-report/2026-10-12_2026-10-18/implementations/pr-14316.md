## 解决了什么问题

Managed 已复用聊天组件但仍困在独立管理面板，首页新任务走 daemon、重复历史列表；用户也不能自助创建可执行工作区、选择真实审批策略或在同会话切换模型/观察有效上下文。只加控件而不固定服务端意图会产生跨后端请求和不确定重试。

## 最终实现方案

App 保留本地/托管两种模式与独立 URL/草稿归属，通过 sidebar portal 展示 ManagedSessionsPage 原导航，停用隐藏 daemon catalog 查询。Managed 状态隐藏时保留挂载但不接管键盘/输入；模式切换不发送草稿或取消后台任务，Java ID 不进入 daemon API。

WorkspaceCreationStore 在原 actor 范围的 WORKSPACE_CREATE 回执中先固定目录/registration 身份，SQL 事务外注册物理存储，最终事务原子创建 ACTIVE ROOT Workspace、OWNER 和 COMPLETED。受控 creation root 默认关闭，动态解析只允许 completed receipt 进入执行；pending 重试沿原身份，completed 回放重验当前记录/权限，不恢复撤权或删除对象。

审批选项来自服务端 Agent/profile 解析，显式选择进入创建摘要及原 pending intent，已存 AgentDefinition 不被 UI 覆盖。本 PR 合入时 auto/plan 拒绝、Shell 不允许 yolo；后续已合入 #14323 才允许内置 bound Session 显式 Shell yolo 和空闲审批切换，不可继续将原限制描述为当前 main。已有会话切模型只允许服务端目录、空闲与预期 revision；actor 幂等重放保留原结果，Turn 在同锁事务固定 model ID/revision，SDK/Harness 的 model-selection/1 和 managed-admission 资源沿原输入恢复，不用会话当前值改写在途回合。最终合入版本已对齐 typed receipt 与 gmt 毫秒列。

主模型 output_committed 事件才投影已核验的 usage resource 到现有 ma_session_record 私有 hosted_context_usage/latest；白名单输出最近 promptTokenCount/contextWindowSize/实际 model，非法或缺失保持未知，不用累计计费补齐。切换模型原子清 projection/ref，防止 A→B→A 复活旧用量。V4 扩回执 namespace、V5 增 Session/Turn model 快照；不是“只有 UI、没有 schema 改动”。
