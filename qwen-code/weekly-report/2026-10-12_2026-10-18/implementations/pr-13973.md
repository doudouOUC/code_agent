## 解决了什么问题

Managed 独立输入框、空白创建表单和主题布局与标准 WebShell 不一致。创建后再另发第一条输入可能拆开原受理意图；简单成功清草稿还会在 A→B→A 或跨会话重试时删除用户的新内容。

## 最终实现方案

`ManagedAgentWebShell` 复用 App.module.css 的明暗主题与 frame；`ManagedSessionsPage` 复用 WelcomeHeader、MessageList、ChatEditor。新 Session 使用标准 model/Workspace selector，模型选项仅来自宿主发布的 agentId/label presets，选择的是创建时 AgentDefinition，不给已有 Session 热切模型。

provider 的 `createSession` 将初始 input_text 与 Workspace/cwd、原 idempotencyKey 放在一次既有创建 API 请求中，要求返回 Session/Turn admission 身份，不另行 prompt。兼容只提供 createEmpty 的 provider。WorkspaceBindingCreator 在请求前持久原 agent/workspace/cwd/input/client/key；未知提交恢复同一 payload/key，已取得 sessionId 后读回失败只重读，不再次创建。摘要需匹配原 agent/Workspace，服务端规范化 cwd 按读回记录显示。

标准 composer onSubmit 返回 false，只有确认原请求受理后才调用对应 commit。PendingPrompt 还记录原 draftText；成功时按原 provider/Session 的 draft storage key 清理，且内容仍与原 draft/text 相等才清空当前 editor，跨会话重试或更新后的不同草稿不被删除。未确认请求继续保留重试和明确放弃入口，放弃不代表服务器一定未创建。

`useComposerCore` 提交文本沿用标准 trim；带前后空白的原 editor draft 另存为 draftText，用于成功后的精确匹配清理，不声称提交 payload 原样保留所有空白。

最终版本仅在 pending 且不 busy 时展示未知创建的恢复行。明确放弃恢复原 initial input、清理本地 pending/commit callback，并由 onAbandoned 刷新 Session 列表，使服务器可能已创建但丢响应的 Session 可重新发现；含初始输入与空创建显示不同风险提示。放弃只是解除本地重试意图，不表示原输入一定未运行。

Managed 显式关闭 shellMode、附件、Workspace daemon 特性、slash commands 与宽度切换；`!`、无快捷键 handler 的 `?` 作为字面输入，不去消费 daemon Shell history。保留既有进度、审批、cwd 屏障与取消入口，不因为标准视觉组件而引入 daemon 执行权限。新建页 selector 保持可见，窄容器中进度与停止操作仍沿现有布局呈现。

## 边界与风险

- 标准组件复用不等于 daemon Shell/附件/slash command 已迁移；模型 selector 不是已有会话的在线模型变更。
- client 草稿与 pending record 只保护原请求身份，不能凭放弃、网络错误或本地状态断言服务端未受理。
- 真实宿主 identity/model presets、浏览器构建与部署仍需门禁，本次未执行。
