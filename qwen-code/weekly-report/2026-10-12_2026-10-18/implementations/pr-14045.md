# PR #14045 最终实现：Shell profile 中原生文件调用的关闭核验

> 规模：+114 / -9，8 个文件

## 解决了什么问题

Shell profile 可包含原生 read_file/write_file/edit/glob。它们通过 deferred 文件路径结算，不一定生成 Shell publication；生命周期若对每条 execution 都要求 Shell result source，会将已结算的合法文件调用错误阻塞。反过来直接忽略所有缺输出记录又会放过真实 Shell/MCP 的未闭合资源。

## 最终实现方案

`WorkspaceProfileLifecycleVerifier` 在原 tenant/Session 范围锁定 REFERENCED managed-tool-input，通过资源存储校验原 bytes/ref，要求原 harnessSessionId、runtimeSessionId 和 payloadJson。payload 只能有 toolName/input 两项且 input 为对象，toolName 仅允许四种原生文件工具；以原 runtimeSessionId 与实际 UTF-8 payload SHA-256 建立 input key。

只有 execution 已结算、没有 result source、dispatchMode 为 deferred、runtimeProtocol 与 publicationId 均为空，并且原 runtimeSessionId/requestDigest 匹配已验证 input 时，才免除不适用的 Shell publication 检查。真实 Shell/MCP/protocol/publication 执行仍验证原输出与资源闭包，Runtime Session owner 的关闭证明也不取消。
