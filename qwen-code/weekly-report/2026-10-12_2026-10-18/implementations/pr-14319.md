## 解决了什么问题

AgentDefinition 能保存扩展字段，却不能把非空 Skill/MCP 配置可靠带入 Hosted Session。依赖当前宿主发现或最新定义恢复，会改变原会话指令、扩展权限及 Hook 决策。

## 最终实现方案

Java 编译器核验静态 Skill 的 name/description/body/可选 base_directory，发布不可变内容引用，并随定义 revision/digest 固定。最多 16 项、目录 JSON 48 KiB、单 body 32 KiB；目录只能是规范相对 POSIX 路径，重复名、坏 Unicode 和越界拒绝。Harness 只从保存的目录声明并处理 `skill`，正文逐字返回并进入普通工具历史，不调用宿主 SkillManager、读取本地 Skill 文件或运行脚本。

MCP 仅接受管理员 manifest 的 server_id/revision/definition_digest pin；Hook 仅接受独立 catalog_id/revision/digest pin。MCP profile 必须有非空 pin，非 MCP profile 不能夹带；Hook 需要 bound Workspace。create/load/cleanup 均用原定义的 pin，不把端点、凭证或进程配方交给公开定义。HTTP store 对嵌套指令/Skill ref 做有界资源闭包，Java 继续核验 scope/schema/digest/长度。

Skill 只能独立工具批次执行；混合 Workspace 批次在审批/Action/派发前拒绝。恢复保留原 PreToolUse 汇总 deny、effective input 与体积拒绝摘要；无 marker 记未执行拒绝，有 marker 无结算则阻塞，ask 不自动授权。不会为补齐历史重跑 Hook 或工具。缺失/损坏原 ref 拒绝恢复。
