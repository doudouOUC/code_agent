## 解决了什么问题

现有 placement 依赖本地挂载，不能在管理员预配的远端已有目录执行普通工具。简单 SSH 启进程无法回答丢启动响应、控制面重启、隧道变化或关闭时原 worker/进程组是否已停止，不能据此换进程重放 UNKNOWN。

## 当前实现方案

新增受 tenant/actor 白名单管理的静态节点和 SSH_LOCAL storage 登记，路由仅从可信 storage 元数据选择 ssh-process，后续按持久化 kind/seed/handle 分派，未知身份不回退本地。WebShell 提供节点/目录探测/幂等登记 operation 和读回入口；预览不授权，网络在 SQL 事务外，提交前重新核验 claim、授权、原物理 owner 及重叠目录。V4 扩 operation/storage 契约，不增加 worker 池表。

私有 stdin JSON bootstrap 提供 probe/register/ensure/observe/stop。先 ensure launch=false 固定原 generation intent，SQL 保存 immutable handle 后才 launch=true；启动 claim/私有记录 fsync 并原子发布，重复 ensure 返回原 PID，模糊启动不再 spawn，retired 拒绝迟到启动。Broker 观察原启动最多 60 秒，经原 seed/lease attestation 后 READY。

SshConnectionManager 强制 host-key 校验和 loopback 双向转发，HTTP transport 只重解发送地址，不改持久化远端 lease；稳定本地控制状态/OS 锁允许同控制面主机接管原 master。断线只重连/attest 原 worker，死亡、重启或身份不符保持 blocked，不跨机器替换。

严格 close 先结清原执行/结果/ACK、释放 Runtime Session，再以匹配 generation/seed/retirement/cleanProof 和原进程已退出生成 RuntimeDrainReceipt。no-start capture:null 的 v3 Shell 先关闭原 SQL publication，再按原 direct/deferred 身份补 ACK。worker 要求 POSIX ledger，每次前台 Shell 结算前确认本调用进程组退出；ledger/退出证据失败永久取消该 incarnation 的 clean proof 资格，UNKNOWN 保留 holder。kill/空 holder/超时都不是 stop proof。

SSH 仅接受 files/1、shell/1，foregroundOnly 在 Harness 定义中固定并在冷/驻留 load 核对；禁止后台/Monitor/MCP/Hook/child Workspace。默认禁用新准入不阻断原 operation、结算/关闭，节点定义须保留至原 Session 退役。不依赖共享隔离/idle 常驻提案。
