## 解决了什么问题

#14081 已接入私有 CSI 文本，但模型仍不能调用原 worker 的文件工具。直接挂普通工具会绕过原批次、备份历史和 SQL authority，或在丢响应后重复修改文件。

## 当前实现方案

在原认证 attach/text/history 入口安装 HostedCsiToolTurn，仅声明 read_file、write_file、edit；保持 writer generation 1、activation epoch 1 和原 READY Runtime binding。attach 先绑定原 worker 的空 retained history，持久化初始 file_history 后才暴露会话，不回退本地工具或其它 Runtime。

先提交完整 assistant Parts，保留 function ID、partIndex、ordinal、输入与声明字节；非法、根路径或超限输入在 reservation 前产生准确拒绝消息。全部接受成员完成 prepare/read-batch 身份核对后，修改类调用按 history intent→原 worker 备份准备→prepared observation→tool.intent→await_runtime checkpoint 顺序授权；只读调用不伪造修改准备。prepare 丢响应或取消后，独立回读原成员一次，上限 5 秒；回读失败或身份不符仍保留原 preparation/取消错误，不换 ID 或授权再次派发。

经原 Broker 执行后，只接受封闭 schema 的完整 success/error outcome：校验 error 的非空 message/可选 type，Part 限 text 或完整 inlineData/fileData，拒绝未知字段及外部 functionResponse/functionCall，转换后再核原 call ID/工具名。非法结果不发布 receipt，保留 await_runtime 和未消费原工作。合法结果保存原生 receipt、固定 UUID/时间的 tool_result 和修改后 history，再返回模型。原结果实际被消费后才标 consumed。最终 assistant 与成功 model.attempt 同事务提交，保留原流式消息 ID/Parts，不重复写 assistant；checkpoint 的命令键/摘要在 authority 队列内依据最终字节与 covered sequence 生成，避免续租推进 journal 后摘要错位。

原生 SQL reader 按原 function 精确验证无派发拒绝、批次身份及已准入工作的 receipt，不以无副作用拒绝替代真实执行证明。完整输入、outcome、message 和 history envelope 均受持久资源预算限制；部分结果、超限或未知操作阻塞 owner 并保留义务。
