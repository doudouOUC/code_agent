## 解决了什么问题

托管 composer 缺少可恢复的 Plan 审批和输入附件。只改变菜单或 prompt 无法保证工具只读，也不能在重启后保持原计划、用户输入字节和执行权限。

## 最终实现方案

Plan 是独立 planMode 布尔状态，不替换 default/auto-edit/yolo。创建/空闲改策保留 owner+当前 OPERATOR、expected revision、幂等回执和固定定义；只允许合资格根 public files/1、shell/1,/2 且无 Hook，不扩 CSI/MCP/child profile。V10 给 Session/Turn 加 plan_enabled 及约束，新用户 Turn 与原审批模式/revision 一起冻结；Connector/SDK 协商 plan-mode/1，恢复使用原 Turn 快照。

Hosted planning 只声明并准入 read_file、glob 和单独一项 exit_plan_mode；Shell、写文件及混合退出批次在执行前拒绝。exit 要求非空且最多 24000 字符 Markdown，保存原 v3 Action/continuation，yolo 也不能跳过计划批准。只有 Session owner 且当前 OPERATOR 可批准；同批原 action/call/input/Turn 核验后解除本 Turn planning，仍按原 execution permission 执行。Java 按匹配 revision 同步关闭 Session 的 Plan 并递增 revision，避免覆盖更晚选择；拒绝不解除只读。

附件复用公共 input_file/input_image→私有 resource/image inline blocks，图片仅 canonical base64 且签名匹配 PNG/JPEG/WebP，文本只允许安全单文件名与 UTF-8/MIME/扩展白名单。含附件的全部规范化 input 编码不超过 48 KiB、最多 100 blocks；拒绝 URL、宿主路径、PDF/Office/音视频，不上传 Workspace 文件。Java 与 Hosted 再校验，原 input resource/请求 digest/Item metadata 保存完整附件，恢复从原 accepted input 读取；文本以有界附件段进入模型，图片保持 inlineData，所选模型不支持 image 则明确失败。

input-attachments/1 独立广告。WebShell 复用原 composer，创建/发送/pending 恢复保存原附件、键和 payload；不在未知受理后重新编码另一份输入，也不覆盖已有较新附件。历史投影恢复附件，审批与 Plan 状态由服务端读回。OpenAPI、生成类型与 Java SDK 同步，revision 0 不发送新增审批字段的旧 wire 规则保留。

## 边界与风险

- 非完整上传/Workspace 导入，不支持任意图片格式或大文件；内联附件仍占原日志/请求预算。
- Plan 不授权绕过普通审批、扩大 profile 或改变在途策略；必须升级相关 Java writer/Harness，旧零快照兼容不代表正 revision 可降级执行。
- 当前 catalog 为 V1–V10，仍无旧 DATETIME 表形状的通用迁移，不得 repair 历史规避验证。
