## 解决了什么问题

server 重复实现字符串截断、空白/数字判断、SHA-256/HMAC，并在请求路径重复构造 mapper。统一时若改变编码、canonical JSON 或异常映射，会破坏已持久化摘要、幂等键或签名校验。

## 最终实现方案

pom 直接声明 commons-lang3/commons-codec，沿用 Spring Boot 版本管理。普通 UTF-16 截断和 null-safe blank 判断委托 StringUtils；标题含 NBSP/BOM 的专用 unicodeBlank 及 ASCII-only 协议校验保留，原来允许 Unicode 数字的后缀使用 isNumeric。

原始 SHA-256 委托 DigestUtils，流式摘要保留字段长度前缀、容量和心跳；HmacUtils 每次新建，保留原输入字节、Base64/hex、恒定时间比较与异常分类。`RequestDigests` 仍用固定 canonical mapper 产出相同 sha256: 字符串，注入既有 Spring 组件；协议 mapper 不改用可变应用配置。AGENTS 和双语设计固化这些约束。
