# PR #14599 当前实现观察：共享 Workspace Session 创建预热

> 规模：+304 / -33，8 个文件

## 解决了什么问题

#14435 让绑定会话共享原 worker，但空 Session 创建后仍等首 Turn 才 warm。若对 Session isolation 一并预热，会为每个未使用会话常驻一个 worker，并破坏 never-initialized close 资格。

## 当前实现方案

新增默认 false 的 `qwen.managed-agent.runtime-broker.session-create-warm`，开启时必须 bound-session-isolation-class=workspace 且没有配置 SSH nodes；既有 durable local-process/child Workspace 限制不变。Session isolation 或 SSH 组合启动即拒绝，不改变全局 isolation 默认。

createWorkspaceSession 的原创建/幂等读回完成后，仅 admission.turnId=null 的无输入创建调用 coordinator.warmSession；有输入创建沿原首 Turn 并行 warm，不重复加一路。Coordinator 再检查开关、runtimeWarmer enabled 和 Workspace files availability，投递到既有 dispatch executor，不在请求线程等待文件系统/placement 完成。

复用原 Session resolver 授权及 warm(sessionId)，只做 placement/确认原 READY worker，不 acquire Runtime Session、不装 context、不执行工具、不写新 Turn 或公开 environment 事件。任务体及返回 future 失败记录告警，不新增自动重试，首 Turn 仍走既有 warm。原共享 binding 和 never-initialized close 不因这一 placement-only 请求改为 Session-isolated 资源清理。
