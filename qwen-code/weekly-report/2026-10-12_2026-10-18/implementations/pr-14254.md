## 解决了什么问题

server 多处直接比较 local-process 字符串，Workspace 的 Session 隔离规则分散在配置、解析、停止和 release 路径。后续隔离演进容易漏掉消费者；把 kind 身份改成泛化 capability 又可能将不属于该 provisioner 的资源误接管。

## 最终实现方案

将 `LocalProcessRuntimeProvisioner.KIND` 公开，配置默认值、worker 恢复候选、storage/placement、原资源恢复等身份判断统一引用它。仍使用已有 kind()/supportsDrainedStop()/supportsStartupRecovery(handle)，不新增一套重复 capability。

新增 `WorkspaceExecutionProfile.admitsIsolationClass`，配置准入、Workspace resolver、canStopDrained、RuntimeAdmission 与 local stopDrained 共用；实现严格只允许小写 session，workspace、Session 与 null 均拒绝。child Workspace 的独立 durable/session 约束保留。双语常驻设计同步切片顺序和预算要求，不新增共享隔离或 idle 行为。

## 关键代码路径

- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/LocalProcessRuntimeProvisioner.java`：公开持久化 kind，停止仍核验原资源。
- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/WorkspaceExecutionProfile.java`：唯一 Session 隔离准入策略。
- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/RuntimeAdmission.java`：stopped release 消费同一策略，原 isolation key/owner 条件不放松。
- `packages/sdk-java/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/service/WorkspaceRuntimeResolver.java`：挂载解析准入。

## 边界与风险

- 无 API/schema/默认隔离变更；不能据这一 helper 开启 workspace isolation、共享 close、warm 或 idle retirement。
- kind 仍是持久身份，不是任意支持 stop 的 provider 可替代原资源的许可。
