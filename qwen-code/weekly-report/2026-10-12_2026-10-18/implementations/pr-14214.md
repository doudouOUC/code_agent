## 解决了什么问题

当前 worker 虽可跨 Turn 保留，但绑定 Workspace 的 Session 仍按 Session 隔离，没有提前预热、空闲退役或代际容量预算。直接让多个 Harness Session 共享 worker 会破坏按 isolation key 推导 owner 的关闭和恢复路径，不能只改一个配置值。

## 最终实现方案

新增双语设计，区分 binding generation、Runtime Session 与 Harness Session；保留 SQL storage holder 串行化工具 Turn。提出按原 generation 的 stop evidence 退役、受限共享、预热等切片，UNKNOWN 不自动换进程重跑。

最新 main 的后续 #14254 修订把顺序收敛为：先统一 kind/隔离策略，再交付默认关闭的 idle retirement，然后在硬 generation budget 与逐条 Harness owner 核验下开放 Workspace isolation，最后做创建时 warm；keep-warm 推后。只有 kind/策略重构已实现，不能把修订后的其余章节记为已交付。共享 Session 的 close 证据、预算与真实 Linux/MySQL 竞态仍是准入条件。
