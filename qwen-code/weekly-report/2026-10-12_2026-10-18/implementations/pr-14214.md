## 解决了什么问题

当前 worker 虽可跨 Turn 保留，但绑定 Workspace 的 Session 仍按 Session 隔离，没有提前预热、空闲退役或代际容量预算。直接让多个 Harness Session 共享 worker 会破坏按 isolation key 推导 owner 的关闭和恢复路径，不能只改一个配置值。

## 最终实现方案

新增双语设计，区分 binding generation、Runtime Session 与 Harness Session；保留 SQL storage holder 串行化工具 Turn。提出按原 generation 的 stop evidence 退役、受限共享、预热等切片，UNKNOWN 不自动换进程重跑。

后续 #14254 曾将切片收敛为身份策略、idle、硬预算共享与创建 warm，keep-warm 推后。当前 main 已合入 #14339 的逐 Runtime Session Harness owner 检查，以及独立 #14340 的显式 CSI/files 单未完成 Session 常驻交接。#14435 进一步为 durable local-process 的 bound Session 增加显式 workspace 隔离配置和原 Harness Session 的逻辑 close，默认仍 session、child Workspace 不适用；共享 worker/binding 保持 READY，物理退役仍需 storage fence。这些不等于本设计全部交付：idle timer、硬预算调度、创建预热和 keep-warm 仍未实现，真实 Linux/MySQL 共享关闭与竞态仍需独立门禁。

创建预热的后续 #14599 当前仍 open：只在显式 workspace isolation/no SSH、无输入创建后异步 placement-only warm，不属于本设计 PR 或当前 main 已交付能力。
