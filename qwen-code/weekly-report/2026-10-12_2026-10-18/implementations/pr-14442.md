## 解决了什么问题

已验证 LOCAL Workspace 和 durable local-process 依赖 Linux machine-id、namespace 与可靠 birth time，macOS 原生调试无法注册/重接。简单放开平台检查会把被替换目录或 reboot 后进程误认成原资源。

## 最终实现方案

MacOsHostIdentity 用绝对路径 ioreg 读取唯一非零 IOPlatformUUID、sysctl 读取 bootsessionuuid；storage birth time 通过 stat 的 device/inode/纳秒值交叉核验，不采用 mtime 的近似值。原探测受五秒/64 KiB 限制，失败、歧义、零值或身份改变拒绝；marker 保留硬件 UUID 字节形式，Runtime hostId 则规范为原契约的 32 位小写形式。

WorkspaceStorageGuard 允许 Linux/macOS，继续要求 canonical 非符号链接 root、原 marker、mount/device/inode/birth 身份。新建 owned root 只在非 macOS 路径调整 mtime，不修改 macOS 原生 birth 证据。目录选择因此可在授权 macOS 执行宿主使用，仍不提供任意客户端目录导入。

LocalRuntimeStore.HostIdentity.current 在 macOS 使用配对 macos namespace 标签和原 boot UUID；同 host/boot 下按原私有 state/handle/进程身份接回原 worker。macOS 不进入可信整机 reboot 清理，trusted-local-reboot-recovery=true 明确拒绝启动，需显式设 false。boot/host 变化返回 UNKNOWN，不能 adopt/attest/stop 原 worker 或自动换代；Linux 原路径保留。

## 边界与风险

- macOS 支持不等于具备 Linux cgroup/MCP/Hook、CSI 或整机 reboot 清理资格。
- 新平台身份不迁移旧私有 state，也不授权跨主机或启动新 worker 替代 UNKNOWN。
