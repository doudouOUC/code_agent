> 规模：+1180 / -1093，878 个文件

## 解决了什么问题

Broker 目前只被 Managed server 消费，却作为 SDK 同级独立 Maven 模块发布和安装。两套资源、测试及 CI 链路增加构建和维护成本，单纯移动源码会遗漏 classpath schema、故障门禁或 contract guard。

## 最终实现方案

把 server 与 Broker 的 Java package、资源和测试统一放入 `packages/managed-agent-server`，保留 `com.alibaba.qwen.code.managedagent` / runtimebroker 包名，删除独立 Broker pom 和主/测试 jar 依赖。统一 server pom 保留 SDK 依赖，迁入 Broker 直接依赖、JaCoCo、fault-gates 和测试选择；两种 Checkstyle 规则以包过滤及命名 execution 分开，不能因此声称全服务同一规则。

同步 Docker、开发/打包/验证脚本、CI/CodeQL/发布入口与文档路径。OpenAPI 版本检查在 rename 场景通过 previous_filename 取 base 文档，防止移动文件绕过兼容检查；Flyway 扫描、Failsafe 覆盖核对继续包含 Broker 资源/测试。最终 878 个 changed files 大部分为 rename，不代表新增同等规模业务逻辑。当前 main 已使用统一目录，SDK 仍留 packages/sdk-java/qwencode。

## 关键代码路径

- `packages/managed-agent-server/pom.xml`：合并后的依赖、资源、检查和测试 profile。
- `packages/managed-agent-server/Dockerfile`：只先安装 SDK，再构建统一应用。
- `.github/workflows/sdk-java.yml`：迁移测试、MySQL/Hosted/fault lane 与报告路径。
- `.github/workflows/ci.yml`：Flyway/重命名合约版本门禁。

## 验证方式

本次独立对照最终 rename inventory、非零生产 diff、pom、workflow 和 main tree，未执行 Maven/容器/CI。在 `packages/managed-agent-server` 先执行 `mvn -f ../sdk-java/qwencode/pom.xml -DskipTests -Dgpg.skip=true install`，再运行 `mvn verify`、Broker 定向测试与 `mvn checkstyle:check checkstyle:check@runtime-broker-checkstyle`；还需真实 MySQL、Hosted/fault profile、脚本元测试与 Docker/分发检查。本周已合入条目的关键路径及命令按本次 rename 映射更新；历史 diff 原路径不变。
