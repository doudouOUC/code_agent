# PR #12923 当前实现观察：Session 附件 512 KiB 分块上传

> PR: [fix(serve): upload session attachments in 512 KiB chunks](https://github.com/QwenLM/qwen-code/pull/12923)
> 状态：open；仅记录 head `3f282a9fc10d` 的当前 diff，不代表 `main` 已支持分块。
> 规模：+3181 / -33，28 个文件

## 解决了什么问题

现有一次性附件 POST 在代理约 1 MiB 的 body 限制下会 413；客户端虽然允许较大附件，实际链路可能在 daemon 前就被拒绝，无法可靠提交。

## 当前实现方案

当前 diff 在 daemon/ACP bridge 增加 create、chunk、complete、cancel 路由。上传以 512 KiB 固定块和 offset 顺序写入预分配内存，精确重复块幂等，乱序或内容冲突拒绝；完整接收后才经原 Session 附件提交路径发布引用。临时数据按 Session/client 归属、五分钟过期和全局/单 Session 容量上限受控。TS SDK 对大于 512 KiB 的附件先查询 capability，支持时分块并处理错误/取消；小附件及旧 daemon 仍走原 POST，旧代理限制仍可能影响降级路径。

## 关键代码路径

- `packages/acp-bridge/src/session-attachment-uploads.ts`：上传状态、offset 幂等与容量/过期管理。
- `packages/cli/src/serve/routes/session.ts`：受 owner/mutation 守卫的上传 HTTP 路由。
- `packages/sdk-typescript/src/daemon/DaemonClient.ts`：capability 探测、分块发送和旧路径回退。
- `packages/acp-bridge/src/session-attachment-uploads.test.ts`：上传状态与错误回归。
- `packages/sdk-typescript/test/unit/DaemonClient.attachments.test.ts`：SDK 兼容分支。

## 边界与风险

- 分块临时缓冲仍占 daemon 内存；过期、重启和跨进程迁移不能视为持久续传。旧 daemon 回退单次 POST 仍受代理 body 限制。
