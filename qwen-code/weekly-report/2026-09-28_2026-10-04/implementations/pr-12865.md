## 解决了什么问题

现有本地进程 provisioner 只认本 JVM 启动的 worker。Broker 重启后即使进程仍存活，也无法凭持久身份安全地接管；盲目重启会增加重复执行风险。

## 当前实现方案

当前 diff 加入显式开关的 Linux 同宿主持久模式。`EmbeddedRuntimeBroker` 校验 state directory 位于 Workspace 根之外，再构造 durable provisioner；默认仍走非持久路径。`LocalRuntimeStore` 以本机/boot/process 起始身份和原 seed、handle 保存启动意图及 READY 记录。provisioner 在锁内登记、启动、核对 ready 和 attest 后采用；进程身份不明或记录冲突时阻塞，不凭 PID 单独接管。durable 模式的普通 Broker close 不终止仍需恢复的 worker。

## 关键代码路径

- `packages/sdk-java/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/service/EmbeddedRuntimeBroker.java`：开关与存储目录边界。
- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/LocalRuntimeStore.java`：持久登记、宿主/进程身份和锁。
- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/LocalProcessRuntimeProvisioner.java`：启动、观察、attest 和接管。
- `packages/sdk-java/runtime-broker/src/test/java/com/alibaba/qwen/code/runtimebroker/DurableLocalProcessRuntimeProvisionerTest.java`：持久模式回归。
