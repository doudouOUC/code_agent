## 解决了什么问题

宿主重启后，旧 Runtime 进程已消失，但数据库里的 binding、execution 与 Workspace holder 仍可能占用原工作区。只清理进程登记不能证明旧副作用停止，也不能安全释放 holder 供新 generation 使用。

## 最终实现方案

最终增量用可信同宿主 reboot 证据区分进程确已消失与身份未知。Broker 维护扫描按小批量枚举本地 binding，使用原 generation 的 operation claim 做 reconcile；具备 loss/stop 证据后终结 LOST，先确认无活跃 Tool Execution，再用行锁及 binding/session/holder 身份校验释放原 Workspace holder。证据不完整、lease 过期或代际不匹配时拒绝替换。此 PR 依赖 #12865 的 durable worker 登记，39 文件统计不重复计算其 base diff。

## 关键代码路径

- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/RuntimeBrokerService.java`：按旧 generation 恢复、LOST 清理和 operation fencing。
- `packages/sdk-java/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/LocalRuntimeStore.java`：同宿主 boot ID 变化判断。
- `packages/sdk-java/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/service/RuntimeRecoveryCoordinator.java`：有界维护扫描。
- `packages/sdk-java/managed-agent-server/src/main/java/com/alibaba/qwen/code/managedagent/store/WorkspaceExecutionStore.java`：事务性 holder 核对与释放。
