## 解决了什么问题

Hosted Tool Runtime 的 Shell 输出若只留在进程缓冲、裁剪后模型消息或一次 HTTP 回复中，失联后无法证明完整 stdout/stderr 是否已保存，重试还可能重复物理执行或把不完整结果当成功。

## 最终实现方案

最终合入 diff 定义 `managed-tool-publication/1` 的原始执行/Session writer/activation 绑定及容量准入。Java 端用 JDBC admission、publication 与 operation 记录约束 reserve/renew/fence、租户/Session 归属、分段上传和封存；对象存储适配器负责持久 bytes。Broker 在原执行 dispatch 前核验 grant，并把结果引用与结算挂回 execution ledger。Runtime 侧在 Shell 进程管道处捕获原始输出，通过带 operation ID 的 publisher 上传、查询不确定操作、seal 和读取前缀；Hosted Harness 把执行意图、结果引用与模型实际消费的有界回执按原调用关联，失败/未知结果不回退到另一个 Runtime 重放。
