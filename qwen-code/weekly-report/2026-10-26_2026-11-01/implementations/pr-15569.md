## 解决了什么问题

公共消息 snapshot 不能恢复 native Session 的执行链、checkpoint 与资源依赖。需要可验证的原提交前缀镜像，既可供 HTTP consumer 恢复，又不能通过普通资源发布伪造快照、越过原 writer 或提前回收原资源。

## 最终实现方案

ManagedNativeJournalSnapshots 定义 qwen-managed-native-session-snapshot/1、committed-prefix-v1。发布请求绑定原 tenant/Workspace/Session、writerId/generation、snapshotId 与 expected revision/sequence/digest；先以原 writer/placement/ACTIVE/READY 准入保存读保护，再扫描未 compact 的原提交链。每个 journal revision 一页，校验 genesis、连续 revision/sequence、previous commit、activation 和 checkpoint；页及单批 bytes 上限 16 MiB、批量最多 100 页。

manifest 保存覆盖位置、storageVersion、checkpoint、资源数量与末页摘要。资源 census 来自原 JOURNAL 引用，检查原资源字节、类型/版本/长度/摘要及嵌套依赖；发布结束再次核原 writer/head，页、manifest 和资源引用以 NATIVE_SNAPSHOT owner 固定。snapshotId 的确定请求可重放，内容或覆盖冲突拒绝；普通 journal commit、工具资源发布和普通资源读路由不能伪装成 snapshot 通道。

唯一 V1 只扩 ma_resource_ref 的 owner CHECK，仍 38 业务表，不增 V2 migration。新快照 pins 由永久退休后的有界 collector 显式移除，完成检查拒遗留 pins；不是创建快照就可删除 journal 或解除 retention。快照读路径不以坏对象修复/隔离动作改写历史。

最终 diff 同时包含 HTTP native snapshot 消费：restore 可选携带 descriptor，客户端先验证 scope、manifest/page 元数据、页链、事务 bytes 与资源闭包，再从覆盖位置读取尾部，最后校验完整逻辑 journal 和原 head。该部分与先合入的 #15599 聚焦接线重叠，规模不是去重 main 增量；不能把两份 PR 统计解释为两套恢复实现。

## 边界与风险

- 仍是完整 committed prefix 镜像，不是折叠为常量状态；恢复仍验证前缀、资源与尾部，不证明常数内存或固定延迟。
- 不授权未知工具重放、历史修复、旧 journal 删除或资源 GC；混版本 writer 和真实故障/数据库验收仍需独立核对。
