## 解决了什么问题

旧验收 fixture 把普通 Shell lifecycle v2 的后台能力与早期前台-only 契约混用，并仍断言 35 表，导致正确的新契约被测试自身误判。

## 最终实现方案

HostedPublicWorkspaceIT 按 shellLifecycleV2 决定期望工具集：v2 加 monitor，并要求 run_shell_command.is_background 与该条件一致；旧 profile 仍不声明后台字段。WorkspaceMigrationMySqlIT 将新库结构期望从 35 改为 38 表，仍检查无多余 GC authority。

上述数字是本项最终 diff 的当时基线。最新 main 已合入 #15745 worktree 和 #15870 公共快照删除，当前为 38 业务表；该 MySQL fixture 已按 ManagedSchemaContract.TABLES.size() 校验全部契约表，不再硬编码 38，单 GC authority 断言保留。不能把历史 fixture 数字当最新 DDL。

仅调整两份测试的预期，不修改生产 Runtime、工具准入、SQL DDL 或退役行为。原生 S1 或平台场景过去的失败，不会因修改 fixture 自动变为通过。
