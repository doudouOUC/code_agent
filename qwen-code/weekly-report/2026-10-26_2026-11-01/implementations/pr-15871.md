## 解决了什么问题

单个 Server artifact 同时容纳契约、控制面、Broker、JDBC、SDK/OSS/MQ/进程适配和 Boot 装配，编译依赖难约束，也容易让嵌入宿主的 DataSource/ObjectMapper 或测试路径误入产品依赖。

## 当前实现方案

根 POM 改 qwen-managed-agent-parent reactor，包含 contracts、control-plane、runtime-broker、persistence、adapters、server 六个生产模块及 verification。contracts 为共享模型/端口；中间四模块各只依赖 contracts，JDBC 实现落 persistence，SDK/OSS/MQ/HTTP/原生进程落 adapters；server 依赖各模块负责 Spring 配置、API 和维护入口。不是独立服务拆分，也不移交 SQL/lifecycle/Runtime 所有权。

包移动配套窄接口和 factory，适配实现不再由控制面直接反向引用。ArchUnit 从实际编译 classes 检查无重复类/拆包、允许依赖矩阵；contracts/Broker 不依赖 Spring，控制面/契约/Broker 不直接依赖 JDBC，SDK/OSS/MQ 不进入非适配逻辑或 Boot 装配代码。命名 managedAgentDataSource/managedJdbcTemplate/transactionManager/ObjectMapper 用 qualifier 和 defaultCandidate=false 隔离宿主默认 bean。

最新 head 将 ManagedAgentSettings 限为 server 外实际消费的只读视图，认证/内部监听/服务账号/可信头和凭据加载状态留在 server；Broker 契约也去掉无模块外消费者的便利重载，实现类仍保留。业务服务直接调用原 inputPolicy，保留授权、原 key replay 与新工作事实检查的顺序。Harness 装配回归通过建 Session、发布 skills/继承扩展资源和捕获最终 SDK 请求验证，不再检查连接器私有字段；新增回归尚不能据定义判通过。

verification 集中原测试/fixtures 和所有 profile/report/coverage，设置 install/deploy skip；生产模块不靠添加 test source 来编译。完整源码报告 guard 跟随迁移且空测试源报错。server 保持原公开 artifactId，主 library JAR 不携 application 配置，exec/操作工具 classifier 携独立配置；运行产物转 server/target，CI、Docker、launcher/打包脚本和 release 旧 tag fallback 随迁。Flyway/schema 与 OpenAPI 资源分别落 persistence/contracts，baseline SQL 与当前 main 字节相同，仍 39 业务表，无新迁移。

1219 个 changed files 包含 1049 个 Git 识别 rename，以及新接口/装配/测试和路径调整；规模按 PR diff 记录，不是同等新业务逻辑量。main 仍单模块目录，其他 open 查询/快照分支不得按这里的新路径解释为已集成。

## 关键代码路径

- `packages/managed-agent-server/pom.xml`：parent、模块顺序和公共插件/依赖管理。
- `packages/managed-agent-server/contracts/pom.xml`：共享契约资源和依赖边界。
- `packages/managed-agent-server/contracts/src/main/java/com/alibaba/qwen/code/managedagent/settings/ManagedAgentSettings.java`：仅跨模块实际消费的只读配置视图。
- `packages/managed-agent-server/contracts/src/main/java/com/alibaba/qwen/code/runtimebroker/RuntimeBrokerOperations.java`：模块外 Broker 操作契约。
- `packages/managed-agent-server/persistence/pom.xml`：JDBC/事务实现依赖。
- `packages/managed-agent-server/adapters/pom.xml`：SDK、OSS/MQ 与平台适配依赖。
- `packages/managed-agent-server/server/pom.xml`：Boot assembly、library/exec/维护 classifier。
- `packages/managed-agent-server/server/src/main/java/com/alibaba/qwen/code/managedagent/config/ManagedAgentPersistenceConfiguration.java`：原命名 bean 和宿主隔离。
- `packages/managed-agent-server/verification/pom.xml`：验证 profile、报告与禁止安装/发布。
- `packages/managed-agent-server/verification/src/test/java/com/alibaba/qwen/code/managedagent/architecture/ModuleArchitectureTest.java`：实际 classes 的模块依赖与 split-package 检查。
- `scripts/check-failsafe-reports.js`：新 verification 源目录的全量报告覆盖。

## 验证方式

本次核对 1219 项清单/rename 分类、最新 head 的 10 文件增量、关键 POM/源码/脚本与 main，未运行 Maven、编译、容器、发布或嵌入宿主。按候选目录用 Java 21/匹配 SDK/隔离仓库，聚焦入口 `mvn -pl verification -am -Dtest=ModuleArchitectureTest,ManagedAgentEmbeddingTest,HarnessConfigurationTest test checkstyle:check`；先编译齐六模块，不能只测试空目录。完整 reactor verify/SpotBugs、MySQL/Hosted/fault profile、ManagedAgentPackagingIT 和独立 embedding-host 安装路径仍需 CI/相应真实证据，受模块共享十分钟本地预算约束。

脚本元测试入口 `npx vitest run --config scripts/tests/vitest.config.ts scripts/tests/sdk-java-workflow.test.js scripts/tests/check-failsafe-reports.test.js scripts/tests/managed-runtime-release.test.js`；packaging 需核 library 不夹带默认配置、exec/维护入口含配置及匹配 runtime 启动。未运行即不标通过，也不以 ArchUnit 规则存在证明依赖闭环已被接受。
