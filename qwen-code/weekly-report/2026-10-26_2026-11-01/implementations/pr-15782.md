# PR #15782 最终实现：runtime 分发与 Maven Central 发布解耦

> PR: [fix(ci): Decouple managed runtime distribution from Maven Central](https://github.com/QwenLM/qwen-code/pull/15782)
> 状态：merged；最终 head `8eee05ed58ff`，merge `db88f2da5ed0`，对照 main `57d9a8fb50f4`。
> 规模：+144 / -161，7 个文件

## 解决了什么问题

安装器从版本化 OSS/GitHub 下载可执行 runtime，但原发行先要求 Central 签名发布和同步。Central 组织权限、GPG 或同步失败会阻塞根本不消费该 Maven 坐标的安装渠道；重试也容易把渠道身份和 Maven 产物混淆。

## 最终实现方案

受保护 release workflow 删除 Central 存在性/部分发布检查、签名凭据加载、mvn deploy 和等待 Central 可用步骤。runtime 分发只需 GitHub release 权限和 OSS 凭据，仍从已公开 CLI tag 固定源码/版本/构建时间戳，工具脚本来自 workflow revision；手动入口限定 main，默认 dry-run，不绕过 production-release environment。

同源码 CLI build/typecheck/bundle、SDK clean install、server 完整 clean verify -Pcentral-release 保留，包含 #15676 的单 fork/不复用和验证阶段跳签名。构建优先选 -exec.jar，旧 tag 回退主 JAR，核 Spring Boot Main-Class 后暂存为原公开版本名和 sha256。profile 名称不表示 verify 会发布；独立签名 Maven 发布仍可单独使用该 profile，普通 Maven 依赖解析也未取消。

生产上传前重验 tag 未移动和 Release 非 draft，分别把 GitHub/OSS 原版本 JAR/checksum 与暂存 bytes 核对，只上传缺失文件，已有不同内容拒绝覆盖。最后两个公开下载渠道均须与暂存原 bytes 一致。dry-run 只构建、验证和保留 workflow artifact；删除 Central 依赖不等于已有公开产物或首次安装成功。

测试同步删除 Central 前置断言，固定无 Central/GPG 发布凭据、无 deploy、保留完整验证及 exec/旧 tag 选择，并覆盖 Central 不可用且凭据为空时仍准备两渠道、任一渠道字节核验错误都终止。设计、用户发行说明和 server README 双语边界同步。

- `scripts/tests/managed-runtime-release.test.js`：无 Central/GPG 依赖、原验证保留和渠道错误拒绝的结构/脚本测试。

## 边界与风险

- 不取消 Java 编译、正常依赖解析或完整 verify，也不自动完成生产上传；OSS 权限、GitHub release 和原版本不可变性仍须核验。
- Central 产物不再参与此流程的分发准入，但 Maven 使用者的独立签名发布与 runtime 消费资格仍各自验证。
