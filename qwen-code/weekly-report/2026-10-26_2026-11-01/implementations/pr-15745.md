# PR #15745 当前实现观察：Managed 主 Session 独立 worktree

> PR: [feat(managed): add independent worktrees for main sessions](https://github.com/QwenLM/qwen-code/pull/15745)
> 状态：open；当前 head `e8e80328de20`，对照 main `dda006c237ee`；以下仅为当前 diff 观察，不能作为 main 能力承诺。
> 规模：+7043 / -265，98 个文件

## 解决了什么问题

多个主 Session 在同目录修改文件会相互干扰；若直接创建 checkout 再建会话，重试可能改用新的 HEAD、重复分支，崩溃后也无法判定谁拥有目录。清理聊天即删 worktree 还可能丢未提交文件、未完成 Git 操作或仍在运行的子任务。

## 当前实现方案

首版仅支持 LOCAL、非 Windows/UTF-8 文件名环境、durable local-process 且 bound Session isolation 为 session。部署开关默认关闭，受控本地 launcher 在非 Windows 开启，仍需服务端全部条件和 Git/layout 检查；SSH/CSI、运行中切换、重开关闭会话及自动合并不覆盖。worktree 只隔离编辑目录，不隔离宿主权限或共享 Git refs。

创建省略 worktree 保持当前目录；空对象选 HEAD，API 可给现有本地 baseRef（公开字段 base_ref）。先按 actor/key/请求语义回原 create receipt，再只读 preflight 解析 commit，冻结原 storage/root/common-directory 身份和源码子目录 offset。一次 SQL 事务重验并创建带最终 target binding 的 Session、ma_session_worktree、SESSION_WORKTREE operation、可选首 Turn 和 receipt；后续重复不重新解析 HEAD 或分配身份。

服务端分配 `.qwen-managed-worktrees/<id>` 与 `worktree-managed-<id>`，保存原 offset，tracked 文件按冻结 commit 检出，不额外复制源目录 dirty 文件或 ignored 配置/环境/依赖。目标 cwd 提供项目指令，模型/审批/Skills/MCP/扩展仍用原 Session pin。Git common directory 和 metadata 必须位于授权 storage；选定 commit 中子目录必须存在，拒 submodule 和非法 ref。claim worker 持整个物理 storage 的维护 hold 后从冻结 commit 非强制 add，落盘所有权 marker 与独立 completion receipt，再核原 checkout/gitfile/gitdir/common identity 才 READY。只看到现成目录不能补猜完成；缺失/损坏 completion 或目标身份变化进入 BLOCKED，不重置文件或回退源目录。

PREPARING/READY/FAILED/BLOCKED/REMOVING/REMOVED 与 Session 生命周期正交。未 ready 禁 warm、attach、dispatch、新输入和文件访问；取消和排空仍允许，准备期间关闭不会迟到启动 Runtime，已知准备失败结算未派发首 Turn。storage busy 延后、不消耗失败次数；未知 Git 停止保留 maintenance hold，只有既有独立 stop 证据才重开原操作，claim 过期不证明物理已停，不新增 macOS JVM 被杀的自动回收保证。

close/archive/delete 保留 checkout。显式 cleanup 需记录 owner、当前 Workspace create 权限、终态 Session、Runtime/children/uploads 排空；维护 hold 下重验身份、tracked/untracked/ignored 脏文件、Git 锁/未完成操作、index flags、nested repo/submodule 和 HEAD 保留引用。只非 force worktree remove，不删除分支；拒绝则保留目录，遗留 worktree 阻止物理存储迁移/删除。

文件 API 恰选 Session locator 或 Workspace+cwd，前者解析原耐久 target 并把 Session/worktree revision 纳入 scope。只有可信 Java→Node 私有 stdin 能传 sessionFileScope，核原 target dev/inode；普通相对 path 验证仍保留，Workspace 浏览不能进入私有目录。上传保存原 Session/目标/scope 和原 uploadId，对账不重写新目标。WebShell 当前实现是 composer 内“当前目录/worktree”切换、当前分支显示和管理入口，提交 worktree:{}；API 支持 baseRef 不等于本版界面已有任意 ref 选择器。创建 composer 选 worktree 时暂停目录引用/上传，普通输入附件按原能力保留；创建后的 Session 在 ready 前禁附件和目录访问，ready 后按 Session target 恢复，过期引用需重选但保留文字草稿。

同一 diff 将新导入项目标为 imported- storage，marker 放服务 stateDirectory/imported-projects 下，不向共享用户目录声明排他所有权；共享导入拒绝 exclusive fence/recovery/migration/rewind。新增 ma_session_worktree 和 operation CHECK，当前候选 V1 为 39 表，不是 main 的 38 表，也不能把另一 open #15696 的 40 表当已集成基线。OpenAPI、严格 schema/CSI inventory 与生成 WebShell 类型随改，不新增 V2 升级链。

## 边界与风险

- 尚未合入；不能承诺 main 已有独立主 Session worktree、任意 ref UI、SSH/CSI 或安全沙箱。
- 目录与 Git refs 共享宿主权限；prepare/cleanup 的 whole-storage maintenance 会等待其他执行。未知停止/完成证据不足时保留占用，不以重建、force 或删分支绕过。
