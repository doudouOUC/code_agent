## 解决了什么问题

快照首屏可能读取整段消息或落后于实时投影；简单拼接 Item 页与 SSE 会重复文本/工具内容，序号相同的多个 Item 还可能互相覆盖。导出也不能把可变化的实时正文标成冻结快照。

## 最终实现方案

本项合入时 transcript/query、transcript/items/query 和 sessions/export/query 增可选 view=messages，Java provider 显式使用；省略仍走已有快照路径。每页在同一 REPEATABLE_READ 事务内读 ma_message 与投影进度，limit 1–100，按 first_sequence/item_id 的稳定 keyset 翻页；先以 limit+1 个长度候选选择至多 8 MiB 正文，再取选中 rows/parts。向旧页按 Item 所属 Turn 补至多每种状态一个相关生命周期事件，合计字节也受限。projection 低于 replay floor 或正向首次导出尚未追平 head 返回 message_projection_pending，不伪装空结果；既有 CSI legacy guard 保留。

Base64 消息游标绑定 Session scope、方向、projection version、初始 through 和位置，错 scope/方向拒绝、投影换代要求重载；它不是 #15839 的签名保留快照游标。firstSequence 固定导出范围，但已在范围内的 Item 正文可继续变化；exportConsistency=live 显式标记，不承诺 as-of snapshot。

provider 以 coveredSequence 作为 SSE 接续点并标记 history=items。consumer 按原 itemId 记录覆盖，旧页替换其覆盖范围内的旧内容、保留之后的 stream event；合并键含 sequence/itemId，并按 UTF-8 bytes 排同序号 Item。resync 重建页和 coverage，避免保留被撤销内容。审批、任务和当前运行状态仍走既有接口/stream，不靠旧 Item 页推断。

当前 main 后续 #15870 已删除默认公共快照和 view 选择，统一 live 消息页；原 coveredSequence/Item 去重与 live 导出边界保留，旧 cursor/limit 的升级拒绝见该项最终实现。

## 边界与风险

- 本项本身不删快照；后续已合入 #15870 删除公共消息快照，native journal 快照仍保留。
- keyset 限定成员范围不冻结内容；页面/stream 必须匹配升级，不能把 coverage 当完整实时控制状态。
