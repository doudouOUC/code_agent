## 解决了什么问题

Hosted Session 身份由耐久 store 管理，却仍受到本地 transcript 占用检查、分支恢复和 PR 状态扫描影响；同时已经协商后台能力的 Shell 会误拒显式前台参数，实际执行与声明不一致。

## 最终实现方案

Hosted 文本、Hook、workflow 和压缩模型配置在 `chatRecording:false` 下传内部 `sessionIdGenerated:true`，复用已有跳过本地占用扫描的入口。它表示原 Session 身份由 Hosted store 持有，不是重新生成 ID 或跳过 store 的租户、writer、幂等检查。普通用户提供的本地 ID 仍检查大小写占用。

`run-qwen-serve` 在普通及延迟启动路径均按 `profile !== 'hosted-harness'` 执行本地 worktree preparation 恢复；Hosted 也不加载 Session PR refresh timer。普通 profile 保留扫描及 chunk 加载失败时的降级，不把本地服务整体移除。

Shell 按实际后台准入决定是否接受 `is_background`；有能力时显式 false（包括既有布尔归一化接受的字符串）传给 Broker 为真正 boolean false，省略时保留省略。没有该能力时仍拒显式后台字段，畸形值在有能力时提示参数错误，不误报整个功能不可用。不放宽 publisher、领域 owner 或工具准入。

Java 侧只修验证 fixture：Skills mock 在创建时安装可变能力答案，避免后台线程与 Mockito 重设竞争；异步 verifier 的查询预算先计量再等待原操作成功；attestation 故障覆盖一次有界 EOF 重试的两个请求。

## 关键代码路径

- `packages/cli/src/config/config.ts:loadCliConfig`：保留普通 ID 占用检查，Hosted 内部调用显式跳过本地 transcript 检查。
