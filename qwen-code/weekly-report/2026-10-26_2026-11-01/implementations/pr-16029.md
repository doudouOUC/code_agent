## 解决了什么问题

RuntimeBrokerService 同时管理进程内路由、执行 CAS、UNKNOWN 查询、恢复扫描、取消和生命周期，边界与并发顺序难以单独验证。把这些 Map 当持久权威或在拆分时改变原 claim/receipt 顺序，又会错误重放执行或释放资源。

## 最终实现方案

新增 package-private RuntimeBindingRegistry 集中 live binding、binding reservation 和 Runtime Session future；SQL Repository 仍是权威。可路由性必须同时匹配持久 generation 及本进程已核验的 runtime instance、endpoint、token、lease ID、epoch。持久 READY 不自动等于本进程可用，缺本地原路由要求 adoption/reconciliation；需要向原物理 Runtime 查询的未决执行只能使用同 generation 的 READY/DRAINING binding，退休或换代返回不可重试的 evidence-unavailable。已持久终态核原 ownership 后可读，不要求活进程；原 durable publication 也有独立的证据读取路径，不能混同物理路由。

登记表按原 future 比较删除 reservation，迟到清理不移除替代者；失效先撤本地路由，再 claim/CAS 持久 LOST，finally 只释放原 operation generation，不能因持久写失败恢复旧路由。SessionContext 用原 ReentrantLock 管 controls、release/attempt、mount claim 和后台索引，不把锁换成阻塞 virtual-thread carrier 的 monitor。

RuntimeExecutionState 集中 owner/dispatch generation、identity/authorization 校验、最多 16 次 CAS 的 settle/UNKNOWN 与后台 sibling 结算。UNKNOWN 不因普通 settle 改终态；失效 claim 仍由 Repository 时钟/takeover fence 判断。RuntimeExecutionReconciler 只向原 Runtime 查询一次，或读取原 durable publication，得到可验证 settled result 才 resolve；未知、坏状态及失败不变成 not_started，也不重新 execute。保留单 execution 共享 in-flight lookup、超时，以及先写 observation cooldown 再移除 reservation 的次序；新增竞态测试固定成功/失败两条路径，顺序并非本项新发明。

RuntimeExecutionRecovery 按原 Session/generation 每页 100 条扫描未结算执行，并从 durable hold rows 补回后台索引。普通 release 只观察，drain 才对原 Shell/Monitor 做 status→stop→status；只有原 owner 的 exited 证据结算 hold，失答继续占用。RuntimeExecutionCancellation 保原 ownership、prepared-provider 取消确认、CSI 拒绝条件及 UNKNOWN 不伪造终态；DISPATCHING 仍通过 facade 传入的 callback 派发，不包含后续独立 dispatcher 候选。

RuntimeBrokerSupport 收拢共享 failure/status/scope 工具，其中 mapStoreFailure 仅将 StoreFailureException 映射 retryable store-unavailable，输入/永久不变量/JVM 错误不统一变可重试。facade 构造各协作者并共享 closed/scheduler，仍拥有 scheduler、renewal scheduler 和 provisioner 的关闭；取消本地待完成 future 本身不是物理停止证明。HTTP/公共 facade、SQL/V1、wire 和部署拓扑未被改写；main 仍 38 业务表。

## 边界与风险

- 这是同 JVM、同 Maven 模块内拆分，不是新服务、协议、状态机或数据库迁移；本地 registry 不能取代 durable authority。
- main 仍在 facade 持有 dispatches/invocations 及派发实现；开放的后续提取不能视作本项已交付。
