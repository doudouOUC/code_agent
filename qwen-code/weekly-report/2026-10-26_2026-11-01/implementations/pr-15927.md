## 解决了什么问题

caller-cancellation 探针在 HTTP 响应开始前就取消，不能稳定观测对端流关闭；多模块 reactor 测试也不能替代作为普通依赖的独立 Maven 宿主装配证据。

## 当前实现方案

HttpRuntimeTransportTest 增 responseStarted latch，首个字节 flush 后才取消，核 future 未完成、cancel 成功及已取消状态；handler 全范围捕 IOException，finally 关闭 exchange，测试停止自建 executor。原 deadline 300 ms、caller timeout 10 s 与对端 2 s close 断言保留；只改探针，不改生产 HTTP 取消。

mysql-integration 在原依赖/完整验证之后，用相同 job-local Maven settings/toolchains/repository 解析 reactor version，仅 install parent/server 及其生产依赖，再分别运行独立 embedding-host 的普通 EmbeddingHostTest 和显式 embedded profile 的 EnabledHostTest，均 failIfNoTests=true。宿主 POM 用 managed-agent.version 参数匹配本次产物，故障报告收集包含宿主目录；workflow 元测试固定顺序、选择、仓库和报告，不以空选择或完整验证前的 fixture 证明装配。

最新 head 将上述版本解析、安装与宿主命令移入独立 verify-managed-agent-embedding.sh，workflow 在原工作目录/环境调用它；元测试同时审计调用及脚本内容，并明确两条宿主 test 命令不能带 skipTests。提取不改验证顺序，也不扩占原 SDK CI lock。

设计文档补合入后证据分层，但其旧 CI 数字不是本次重新运行的结果；新增宿主作业和修后 macOS 探针仍须对应 head 的实际运行。本项不发布、部署或修改生产 Spring/网络实现，也不证明 OSS/云环境资格。
