## 解决了什么问题

caller-cancellation 探针在 HTTP 响应开始前就取消，不能稳定观测对端流关闭；多模块 reactor 测试也不能替代作为普通依赖的独立 Maven 宿主装配证据。拆分后的 SDK 边界还把空闲流异常抹平成一般 transport failure，丢失类型和超时信息；部分 Hosted fixture 仍假设旧目录/连接器形状或将投影暂未就绪误判失败。

## 最终实现方案

HttpRuntimeTransportTest 增 responseStarted latch，首个字节 flush 后才取消，核 future 未完成、cancel 成功及已取消状态；handler 全范围捕 IOException，finally 关闭 exchange，测试停止自建 executor。原 deadline 300 ms、caller timeout 10 s 与对端 2 s close 断言保留；只改探针，不改生产 HTTP 取消。

mysql-integration 在原依赖/完整验证之后，用相同 job-local Maven settings/toolchains/repository 解析 reactor version，仅 install parent/server 及其生产依赖，再分别运行独立 embedding-host 的普通 EmbeddingHostTest 和显式 embedded profile 的 EnabledHostTest，均 failIfNoTests=true。宿主 POM 用 managed-agent.version 参数匹配本次产物，故障报告收集包含宿主目录；workflow 元测试固定顺序、选择、仓库和报告，不以空选择或完整验证前的 fixture 证明装配。

最终将上述版本解析、安装与宿主命令移入独立 verify-managed-agent-embedding.sh，workflow 在原工作目录/环境调用它；元测试同时审计调用及脚本内容，并明确两条宿主 test 命令不能带 skipTests。提取不改验证顺序，也不扩占原 SDK CI lock。

最终生产增量在一般 DaemonTransportException 映射之前识别 HostedHarnessStreamIdleException，转换为保留 idleTimeout、消息和 cause 的 HarnessStreamIdleFailure；该类型继承 HarnessTransportFailure，递归 cause/suppressed/stack 映射规则保留。SdkHarnessBoundary 已有的延迟 stream/observeStream next 包装也使用该映射，因此 Hosted 的空闲告警/重试可保类型，不把空闲当作 Turn 已结算。Broker 对未分类内部错误新增服务端 ERROR 日志，公开 500 code/message 不变；不改生产 caller-cancel 算法。

Hosted reader fixture 向父目录查找实际 TypeScript reader，不再固定退两层；attachment 测试覆盖裸 connector 与 SdkHarnessBoundary。进程故障驱动只在等待 FOLLOW_UP_OK 的消息页轮询允许精确 503/message_projection_pending，继续原等待，不吞其他响应。liveness/coordinator fixture 改用新异常类型。设计文档的旧 CI 数字不是本次重跑结果；合入、检查定义、发行与云环境验收仍分开。
