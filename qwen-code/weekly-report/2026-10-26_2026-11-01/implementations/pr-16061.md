## 解决了什么问题

ManagedAgentStore 的协作者通过字段/setter 分次注入，直接构造后再配置的 fixture 与 Spring 装配可能不同，遗漏依赖也难以在创建阶段发现。简单改成必需构造参数又会破坏原可选能力和 configRecords→Session Store 的事务代理回引用。

## 最终实现方案

最终生产 diff 仅修改 ManagedAgentStore 的构造与依赖字段：worktreeFiles、creationSkills、extensionPackages、lifecycle、definitions、sessionWorktrees、journalEventTransport、configRecords 共八个引用变 final，移除原字段和 setter 注入。唯一 @Autowired 完整构造器保 managed JDBC/ObjectMapper/Clock qualifiers；Spring 仍必须提供 WorktreeFiles、ManagedSessionSkills、ExtensionPackages，缺少即启动失败，不通过退选简易构造器掩盖。

原可选 lifecycle/definitions/sessionWorktrees/journal transport 使用 @Nullable；configRecords 另外保 @Lazy @Nullable 代理，延迟解析其回指的已完成 ManagedAgentStore 事务代理，不启用 circular references。注意 lazy 引用本身可以非 null，即使目标 bean 尚不存在/未实例化；启动成功不保证首次调用可用，也不是变成全局必需依赖。既有业务使用处的 null/功能拒绝分支不被重写。

保留未注解的七参数手工构造器，沿旧 standalone 语义创建基础 ManagedSessionSkills，并把其他能力留空；它不等于完整生产装配。大量直接构造测试改为明确传依赖的 VerificationFixtures factory；三个 Spring @Bean 测试工厂也显式保留必需/可选参数和 lazy records，不能用无依赖 factory 替代真实注入。lifecycle resume 等 fixture 在构造前准备原生命周期依赖，不再事后 setter。

新增 wiring 测试关闭 circular references，检查必需缺失、可选缺失、final/no-setter、AOP 事务代理与 lazy back-reference，并参数化复核 actions/close/retention 三工厂。未改业务 SQL、锁序、原准入/回执、wire、schema 或 SDK 请求；83 文件不表示 83 个生产行为变更。
