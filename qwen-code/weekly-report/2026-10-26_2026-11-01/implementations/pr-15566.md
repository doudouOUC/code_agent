## 解决了什么问题

activation 或 inbox 已完成后，同一原身份的重复请求仍需得到一致终态，不能重新入队或因重启丢掉幂等结果；同时不能让派生索引替代原 journal，或把索引故障变成终态写入的前置依赖。

## 最终实现方案

FileManagedActivationStore.readTerminal 仅查询已 released 的原 activation；FileManagedSessionInbox.readTerminal 仅查询已 finished 的原 message。调用时复制身份，再串行排在已有 mutation 后读取。终态 duplicate admission 返回同一原结果，active/missing/orphan 身份不靠索引变成 terminal；身份复用但载荷不同仍拒绝。

FileManagedTerminalIdentityStore 在 journal 旁按 tenant/Session/activation 或 message 三元身份的 SHA-256 建索引。保存 kind、完整身份、journal 提供的终态与内容摘要；私有目录/0600 临时文件 fsync 后 hard-link 不覆盖发布，再同步目录。读时 no-follow、精确长度与完整 bytes 比较；缺索引可由已验证 journal 终态重建，冲突或损坏拒绝，不静默修复覆盖。

索引只在终态查回时物化；终态 mutation 不依赖索引成功，也不追加第二份 journal。scheduler 只在新 journal 写入时重置暂态失败计数，终态 duplicate 的派生读成功不能清掉原故障连续性。当前仍加载原状态与 journal，不由此获得 bounded memory、淘汰或历史删除能力。

## 关键代码路径

- `packages/core/src/managed-runtime/managed-terminal-identity-store.ts`：派生身份索引的耐久发布、读取与冲突拒绝。
- `packages/core/src/managed-runtime/managed-activation-store.ts`：released 查回与 duplicate admission。
- `packages/core/src/managed-runtime/managed-session-inbox.ts`：finished 查回、原消息幂等与串行身份捕获。
- `packages/core/src/managed-runtime/embedded-harness-scheduler.ts`：只以新 journal 写入重置故障计数。

## 边界与风险

- 不做 terminal eviction、journal 删除或压缩；已有索引不能使不存在的 journal 身份获得执行或恢复权限。
- 本地文件索引不是跨主机恢复或外置 MySQL 状态证明；并发文件系统、磁盘故障和适用 CI 仍需单独证据。
