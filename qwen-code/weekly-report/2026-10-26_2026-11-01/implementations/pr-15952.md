## 解决了什么问题

Public 与 WebShell 各维护一份 replay/live、心跳、权限复查及结束循环，相同修复容易只改一侧；直接统一消息投影又会破坏两端的时间单位和 resync 类型。

## 最终实现方案

两个入口仍同步校验原 tenant/actor/Session 的可读权限，再把事件转换函数和各自的 resync 构造函数传入一个私有 stream 循环，不增加公共抽象。正常帧的 SSE ID、event name、推进序号与 session.deleted 判断直接使用原 EventRecord；Public 的 createdAt 为秒，WebShell 仍为毫秒，各自 payload 类型不混用。

保留先订阅后分页补读，再等待 live delivery 的次序；满页继续补读，队列 overflow 回 SQL reconcile，不把丢失通知当作完整历史。空等待触发重查与原 keepalive 调度；原 read-grant interval 的缓存复查位置不变，权限撤销不是每帧即时查库保证。删除事件送达后立即结束，中断仍恢复线程标志并完成错误回调，subscription 随 try-with-resources 释放。

ReplayCursorExpired 仍投递各端 resync payload，带原 floorSequence/snapshotThroughSequence 与 reload_snapshot action，但帧不携带 SSE ID，随后结束，不能让重连游标跳过尚未读取的事件。该既有命名不恢复已删除的公共 ma_snapshot。

最终 diff 只含共享循环、回归断言和双语设计文档。SessionCreationCommand/builder 和单创建入口在此基线已由上游提供，未被本 PR 修改；不把先前创建重构、SQL/锁序、仓库角色或恢复改造记为本项新增。
