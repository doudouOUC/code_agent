# PR #15713 最终实现：跨 job 重试固定 canonical artifact 身份

> PR: [fix(ci): Preserve canonical artifacts across job retries](https://github.com/QwenLM/qwen-code/pull/15713)
> 状态：merged；最终 head `265f451d257f`，merge `dee6ace9d8f8`，对照 main `eaafba5d140b`。
> 规模：+12 / -5，2 个文件

## 解决了什么问题

只重试下游 job 时，生产 artifact 的上游 job 未重跑。用当前 `run_attempt` 拼名字下载会查找一份并不存在的新 artifact，而非已验证的 canonical 产物。

## 最终实现方案

`installed-npm` 上传步骤命名为 canonical，把 upload-artifact 返回的 artifact-id 作为 job output；下游 download-artifact 通过 `needs.installed-npm.outputs.canonical-artifact-id` 按不可变 ID 下载，不再按当前 attempt 重造名字。上传仍只在成功时发生，名称仍含原 run/attempt，后续仍 bind 到当前 checkout 再做产品路径验收。

元测试固定 step ID、job output 和按 ID 下载，拒绝回到按名字选择。只改变跨 job 产物传递，不重新构建 canonical 包、不证明包已发布，也不改变验收本身。

## 关键代码路径

- `.github/workflows/tui-parity.yml`：canonical upload ID 的 job output 与下游消费。
- `scripts/tests/e2e-workflow.test.js`：上下游必须绑定同一 artifact 的结构断言。

## 验证方式

本次核对最终 diff 和 main，未重跑 workflow。仓库根目录入口 `npx vitest run --config scripts/tests/vitest.config.ts scripts/tests/e2e-workflow.test.js`；真实验证需分别重试仅下游、重试全部 job，核对下载 ID 与上游成功 upload 的 ID 一致，并保留 checkout/artifact 绑定和验收结果。结构测试不代替 installed npm 验收。

## 边界与风险

- 没有上游成功 artifact/output 时不能回退其他版本；存储过期或权限失败仍需明确处理。
- artifact ID 只证明选择同一产物，不能单独证明安全、发布成功或真实平台行为正确。
