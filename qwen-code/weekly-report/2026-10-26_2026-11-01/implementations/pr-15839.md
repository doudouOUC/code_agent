# PR #15839 最终实现：有界 SQL 原事务查询与已发布消息倒序页

> 规模：+752 / -4，23 个文件

## 解决了什么问题

查询最近原事务或一个旧 command 不应恢复整段历史；WebShell 读取最近已发布 Item 也不应先顺序导出全部快照。两者的权威、游标和覆盖水位不能混为一谈。

## 最终实现方案

内部 transactions:recent 和 transactions:lookup 继续原 writer token/Workspace/Session 读授权，不获取 writer 或调用 Harness。READ_COMMITTED 查询捕获 throughRevision，拒超当前 head、被 compact 的前缀或缺失边界；recent 用 beforeRevision 向旧事务翻页，先按 revision/byte_length 看 limit+1 个候选，再读选中的正文并核连续性、Workspace、长度/digest，页内按时间正序返回，limit 1–100 且总原事务字节受既有 16 MiB 限制。lookup 复用 command_key_hash 唯一索引，在捕获前缀内命中后复核 operation/commandId 和原事务，不能把坏正文当未执行。返回前再次核读权限。

另增 WebShell transcript/items/query，按原 Session 当前读权限，从最新已发布快照的最后一页向旧 Item 翻页；签名 version2 游标固定原 root/version/projection/expiry，与正向导出的 version1 互斥，继续读 lease 和保留期。没有发布快照可返回覆盖 0 的空页，不能据此证明 Session 空；它不包含 live tail/审批/任务，也不触发 journal replay、writer 或进程 cache。

main 后续 #15865 在同路由增加显式 view=messages 的实时 ma_message 分支；本项默认已发布快照分支仍在 main。这里的 SQL 原事务查询不是 open #15696 的完整派生历史/异步消费者方案，不新增表或改写 canonical journal。
