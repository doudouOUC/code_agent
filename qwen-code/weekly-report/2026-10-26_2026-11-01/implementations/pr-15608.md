# PR #15608 最终实现：只读 attestation 的一次 EOF 重试

> PR: [fix(managed-agent): retry read-only attestation after EOF](https://github.com/QwenLM/qwen-code/pull/15608)

> 规模：+119 / -5，2 个文件

## 解决了什么问题

只读 Runtime context attestation 可能与空闲 SSH HTTP 连接关闭竞争，收到 EOF 后直接判 Runtime 不可用。无条件重试所有 HTTP 操作则会把安装/执行等可能已产生副作用的请求重新派发。

## 最终实现方案

HttpRuntimeTransport.attest 先冻结原 endpoint/path、encoded body、原 lease/token 和期望 gateway incarnation。仅异常 cause 链含 EOFException，且原 requestTimeout 仍有剩余时，使用完全相同请求再 post 一次；重试使用剩余 Duration，不重新获得一整段超时预算。

重试不包含递归重试器，第二次 EOF 正常失败。通用 post 只增加可传 timeout 的重载；installContext 等 mutation 仍走原单次请求，不因 EOF 获得重放权。响应继续经过原 attestation 身份/协议验证，不放宽原 Runtime 归属。

## 关键代码路径

- `packages/managed-agent-server/verification/src/test/java/com/alibaba/qwen/code/runtimebroker/adapter/HttpRuntimeTransportTest.java`：一次 EOF 成功、第二次拒绝、共享超时及 mutation 不重试。

## 边界与风险

- 不是所有网络错误、协议错误或非 EOF 异常的重试策略，也不扩大 install/execute/cancel 等操作的幂等保证。
- 不换 lease、Runtime、boot 或 incarnation；剩余预算耗尽和未知 mutation 仍准确失败。
