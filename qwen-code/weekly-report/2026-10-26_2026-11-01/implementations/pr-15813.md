# PR #15813 最终实现：有界 activation 续租而非追加心跳历史

> PR: [perf(managed): Bound activation renewal journal growth](https://github.com/QwenLM/qwen-code/pull/15813)

> 规模：+856 / -18，18 个文件

## 解决了什么问题

HTTP activation 每次心跳追加 journal 事务，会让长期空闲会话的恢复字节和事务数持续增长；丢响应后盲目重试又可能错误延长租约或放行下一次写入。

## 最终实现方案

journal handle 增可选 renewActivation，HTTP 按 writer grant 的 activationLeaseRenewal 能力使用原 writers:renew；没有能力的 store 仍走原事件式续租，本地 JSONL 不被强制换协议。Java 在原 writer/Workspace/lifecycle/CSI 围栏与行锁下核当前 active activation、worker/epoch 和 head，一次只接受原 renewalSeq 重放或加一。同序号回原 expiry，不再次延长；新序号更新原 activation 事务的两个 lease 列及 head expiry，不改 journal bytes、revision、sequence 或 digest。

restore 返回经原事件 bytes/digest 和 head 核验的 activationLease，HTTP 只在完整前缀恢复后覆盖匹配 active 身份，拒退序或倒退 expiry。authority 串行保存未知续租请求，下一操作先用同一序号结算；已知拒绝不冒充成功，未知不放行写入，非不确定错误停止 writer。release 也不能绕过未结算续租或释放换代后的 activation。

CSI 原生 admission/proof 与 typed inventory 同步读取这两个字段，只允许原 active 事件上的单调续租；其他事务和 genesis 不接受伪造 lease 元数据。V1 原表加列/CHECK、本项不新增表；后续公共快照删除使当前 main 为 38 业务表，不增加 V2，也不保证旧 writer 或旧 catalog 混跑。
