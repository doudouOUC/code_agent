# PR #15676 最终实现：隔离 Managed runtime 发布测试进程

> PR: [fix(ci): Isolate Managed runtime release test classes](https://github.com/QwenLM/qwen-code/pull/15676)
> 状态：merged；最终 head `0ef0554b52b3`，merge `34769f9d41a1`，对照 main `eaafba5d140b`。
> 规模：+14 / -1，2 个文件

## 解决了什么问题

发布校验复用测试 JVM 时，跨测试类的状态可能相互影响。通过过滤失败类或跳过测试让发行继续，会失去对实际可执行 JAR 的验证。

## 最终实现方案

Managed runtime release workflow 的原 `clean verify -Pcentral-release` 增加 `-DforkCount=1 -DreuseForks=false`：单并发 fork，不复用测试类进程。保留签名跳过和固定构建时间戳的既有用途，后续仍从这次校验的 JAR 生成 runtime/checksum。没有添加测试选择器、失败忽略、重试掩盖或覆盖 argLine。

workflow 元测试同时固定两个 fork 参数、原完整 verify/profile，并拒绝过滤、skip、failure.ignore 和替换 argLine。变化仅在发布校验进程隔离，不改变运行时协议、业务表或应用线程行为。

最新 main 的后续 #15782 已删除 runtime 分发的 Central 发布前置，但保留这里的完整 verify/profile 和 fork 隔离；不能再把 Central 发布权限当作 OSS/GitHub runtime 分发的必需 gate。

## 关键代码路径

- `.github/workflows/release-managed-runtime.yml`：可执行 JAR 与发布 profile 的完整校验命令。
- `scripts/tests/managed-runtime-release.test.js`：发布 gate 不被过滤或绕过的结构断言。

## 验证方式

本次核对两文件 diff 和 main，未重跑发布工作流或 Maven。仓库根目录可按脚本测试配置运行 `npx vitest run --config scripts/tests/vitest.config.ts scripts/tests/managed-runtime-release.test.js`，并检查实际 release job 的测试报告、JAR/checksum 和发布 readback；元测试通过不能证明发行成功或 Maven Central 权限齐备。
