# PR #15827 最终实现：移除 MariaDB 全量集成 CI 承诺

> PR: [ci(java): remove MariaDB full integration lane](https://github.com/QwenLM/qwen-code/pull/15827)

> 规模：+133 / -155，15 个文件

## 解决了什么问题

Java 全量集成仍通过数据库矩阵对 MariaDB 承担持续兼容验证，与当前支持 MySQL 的边界不一致；删除一个服务而留下矩阵、报告名或完整测试源检查也会产生错误证据。

## 最终实现方案

mysql-integration 删除 MySQL/MariaDB 矩阵，固定 MySQL 8.4.6、mysqladmin/mysql 客户端与 MySQL 报告名。保留原非 fast 条件、两 fork 各自随机端口/独立容器、tmpfs、禁 native AIO/二进制日志、128 MiB max_allowed_packet、原全量非 Hosted IT 与失败报告门禁，不改为挑选少数测试。

相关 workflow 元测试、文档和 failsafe 源目录覆盖说明同步。MariaDB 不再有 CI lane 或持续兼容保证；已有方言代码未移除，不新增连接拒绝、业务 schema 迁移或 MySQL 运行通过声明。Hosted/原其他验证职责不由本次替代。

## 关键代码路径

- `.github/workflows/sdk-java.yml`：单 MySQL 集成作业及独立 fork 数据库。
- `scripts/check-failsafe-reports.js`：保留完整测试源与报告覆盖审计。
- `packages/managed-agent-server/README.md`：数据库支持和资格边界。

## 验证方式

本次核对 15 个 changed files、最终 workflow/元测试与 main，未运行源码、Docker 或 CI。根目录聚焦入口 `npx vitest run --config scripts/tests/vitest.config.ts scripts/tests/sdk-java-workflow.test.js scripts/tests/check-failsafe-reports.test.js`；真正 MySQL 资格仍需对应 Java 21/full mysql-integration 作业与两 fork 报告。文档或结构测试不能替代数据库运行证据。
