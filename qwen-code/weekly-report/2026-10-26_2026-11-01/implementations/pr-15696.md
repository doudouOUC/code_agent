## 解决了什么问题

只压缩 journal 布局或删除一个 events 数组，仍会把完成命令、回执、checkpoint、Hook/领域版本和去重身份留在其他 Map/Set 或恢复大数组中。直接淘汰它们又会破坏旧 key replay、冲突判定和未知操作恢复。

## 当前实现方案

历史权威仍是完整 canonical journal，新增查询视图绑定原 tenant/Workspace/Session、committed sequence/digest；HTTP 还绑定 journalRevision，文件还绑定物理 generation。历史点查、事件页、extension 和 checkpoint 读取异步化，读者一次捕获固定前缀，不混用后续 head。默认事件页 100、上限 256；最近事件常驻至多 1,024 项/8 MiB，共享历史 cache 至多 2,048 项/4 MiB。活跃输入、未决 Action 和仍有效的领域定义另按生命周期保留，不承诺活跃工作也固定大小。

文件 adapter 以 64 KiB 页内容寻址 hash-trie、源事务 block/locator、摘要保护的 identity catalog 支撑冷查，fork/snapshot 共享 owner cache。每次打开从本次验证的 canonical prefix 建新 generation；空分支才可证明不存在，缺页/坏页不能返回空。缺失或损坏派生页触发串行重建，读者仍固定原前缀，源损坏/换代显式失败。close 拒新查询、等待在途工作并分批清私有 scratch，不删除 transcript、snapshot 或资源；scratch 空间和关闭时间仍随历史增长。

Java/JDBC 增 `ma_session_history_state`/`ma_session_history_fact`，查询是原 writer token 与 Workspace/Session 授权内的 `history:query`、`history:backfill`，restore 显式请求 `includeNativeHistory` 才回能力。新 facts 随 canonical commit 同事务写入；旧数据每批至多 100 事务补齐连续覆盖，256 identity-hash bucket 计数防缺行伪装不存在。每个命中校验 locator/ordinal/digest/metadata 和原事务，Core 另与独立重建事实比较；repair 用 expectedGeneration CAS，旧派生代每批至多删 256 行。视图未覆盖、不可用或损坏不是空结果。

提交先验证并构造候选状态，再提交原 journal，已知成功才公布查询视图和可见状态。派生 view 落盘失败时保留至多一个事务 overlay 和原成功回执，修复前阻止新写；未知 append 仍只能由原 `settleAppend()` 结算，不能靠索引不存在推断未执行。

本次 head 增量把 READ_COMMITTED 来源分页的长度候选和正文都限定在本次捕获的 head revision，防并发新提交混进 lookahead 误报损坏。native query/backfill/来源读取只核现有 read grant，不先续普通 writer，允许关闭普通写准入后的合法 lifecycle cleanup 读取；本地 stopped/sealed 与服务端 token/lease 校验不变，未知 append 仍拒 native 视图。恢复状态的 pending/input/terminal 证据读取统一 fail-closed，历史不可用时等待证据而非 HTTP500 或“输入不存在”。故障取证固定初始 restore revision/sequence/digest，后续 canonical 读取另验，不扩大冷恢复水位。

managed-local Java launcher 与规模 fork 加 `-Djdk.nio.maxCachedBufferSize=1048576`，只限制 JDK 每个临时 direct buffer 缓存到 1 MiB，不是进程 direct/RSS 上界、不改 H2 同步持久化或 canonical 事务大小。外部文件 H2 JVM 需自行加相同启动参数。规模证据另记录 direct/mapped pool，并断言 GC 后 direct-buffer 增量；修正后的 H2 10k/100k 和完整门禁仍待独立资格。

恢复 scanner 按完整事务流式校验，HTTP snapshot+tail、本地布局转换和 activation/inbox v2 snapshot 不再整体拼接。旧命令/首个 execution receipt/Hook 唯一键保留原答案；checkpoint 工具和 binding 改为固定视图懒读。CLI 的审批、取消、原 CSI、Hook/automation/channel/child/team、transcript、Goal 和 ACP consumer 同步迁移。message-only iterator 不把终态 UUID 当消息父节点；模型仅投影当前分支/有效压缩后上下文，完整历史仍可流式读。ACP bulk 超既有 bytes/update 限额显式 `HistoryReplayLimitError`，不是静默短响应。

当前 diff 将唯一 V1 从 main 的 38 表扩为 40 表，并同步 CSI typed inventory/契约与测试；没有 V2 升级链，不证明旧 catalog 或外部 writer 可混跑。它是 #15566、#15569/#15599、#15626 后续的常驻/读取改造，不因前四项已 merged 就视为本项已落地。
