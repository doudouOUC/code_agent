# PR #15870 最终实现：移除持久化公共消息快照

> PR: [refactor(managed): Remove persisted public message snapshots](https://github.com/QwenLM/qwen-code/pull/15870)
> 状态：merged；最终 head `2193d519765d`，merge `619a601b3965`，对照 main `eaafba5d140b`。
> 规模：+1318 / -2823，61 个文件

## 解决了什么问题

既有 ma_message 投影之外再持久发布全部公共 Item 快照，会增加重写、保留、读 lease 和回收链复杂度；实时消息页已提供有界读取，但不能因此误删 native recovery 快照或降低 replay 安全边界。

## 最终实现方案

删除 ManagedSnapshotStore、ma_snapshot、公共 snapshot manifest/page 专用列/索引、SNAPSHOT resource owner 和 stream 的 snapshot 指针/stale 标记。投影事务继续维护 ma_message、parts/resource refs 和 covered_sequence，读路径不再构建公共快照；默认 Public Item、WebShell transcript/export/recent Item 均转现有 live message keyset，去掉 view 选择。首请求 numeric afterSequence 只限制 firstSequence 大于边界，不是正文最后修改时间过滤。

公开兼容响应的 snapshotThroughSequence 等旧字段名保留，但明确是 live 成员范围，不是冻结内容；旧签名快照/数字 transcript cursor 不再被当新消息游标。当前消费者 live/item coverage 语义保留，schema/OpenAPI/生成类型及 typed CSI inventory 同步收窄。

最终接口将默认 transcript 的 limit 从事件页 1–1000 收窄为消息页 1–100，默认仍 100；旧十进制 transcript cursor 返回 400 invalid_message_cursor，需丢弃并重载首个消息页。Public Items 数字 after 和 SSE afterSequence 保留原数字语义，移除 view 后不另设全局未知字段拒绝。409 message_projection_changed 要重载，503 message_projection_pending 可等待重试；413 message_page_too_large 不是请求体 payload_too_large，单个超大 Item 即使 limit=1 也不可由该分页器返回。

replay floor 改由 message projection coverage 支撑，继续保留活跃 Turn 起点前的证据；低于 floor 的读要求 resync，投影低于 floor 时返回等待/503，而不是回放已过期内容。floor 自动推进仍需部署显式开启，本项不物理删除原事件。projection GC 只处理已释放的 message-parts 并继续等待读 lease/原资源引用，Session retirement 不再有公共 snapshot owner 批次。

NATIVE_SNAPSHOT、原 journal/checkpoint/工具捕获和制品 owner 均保留。main V1 已从 39 减为 38 业务表；随后 #15871 移到 Maven 模块目录，没有再改成另一套 schema。开发 catalog 重建，无 V2/旧目录原地迁移；已关闭未合入的 #15696 方案保留旧公共 snapshot/41 表，不能当作当前 main 的整合版本。

## 边界与风险

- 已合入只删除公共消息快照，不能把所有 snapshot 都称为已删除；完整 CI、MySQL 和真实恢复资格需独立证据。
- live 页不是 as-of 内容快照；旧游标/catalog/消费者不能仅凭 schemaVersion 相同混用，floor 与 GC 也不是未知执行或物理 Runtime 释放证明。
