# PR #8508 最终实现：daemon 子进程堆分区建模

> PR: [refactor(serve): model a per-child heap partition of the daemon budget](https://github.com/QwenLM/qwen-code/pull/8508)
> 状态：merged，2026-08-04 合入。

## 解决了什么问题

daemon 每个 workspace 会派生一个 ACP child，但旧的 `getAcpMemoryArgs()` 从 host memory 算出一个 heap ceiling 后会把同一个值发给每个 child。最多 25 个 workspace 时，32GB 主机可能被授权为 25 × 16GB 的 child heap，总授权远超 daemon memory budget。

PR 早期版本尝试按派生时刻的 live child 数动态分摊 heap share，但评审发现这不是总量约束：V8 不能降低已经运行 child 的 ceiling，因此授权会按 `P + P/2 + P/3 + ...` 累积。另一个缺陷是零 child pool 被建模为 `--max-old-space-size=0`，而 V8 中 0 表示默认 heap，不是零上限。

## 最终怎么实现

#8508 改为只建模、不应用。新增 `--child-heap-mode off|observe`，默认 `observe`；`enforce` 不再是合法取值。status 新增 `limits.memory.childHeap`：

- `mode`：当前 child heap 建模模式。
- `maxConcurrentChildren`：按模型可容纳的最大 child 数。
- `perChildCeilingMb`：每个 child 的恒定建模 old-space ceiling；当 child pool 连一个 512MB floor child 都容不下时为 `null`。
- `refusals`：观察模式下真实 spawn 会超出建模 child 上限的次数，只表示 admission pressure，不表示 ceiling 足够或 enforcement 安全。

核心模型改为固定分区：所有 child 共享同一个恒定 ceiling，并让 `maxConcurrentChildren * perChildCeilingMb <= modeled.childPoolMb` 作为不变量。这样不会再出现按派生时刻分摊导致的 harmonic overcommit。512MB host 等零池场景不再产生 `perChildCeilingMb:0`，而是报告 `maxConcurrentChildren:0`、`perChildCeilingMb:null`。

spawn path 保持不变。ACP child 仍使用 host-derived `--max-old-space-size`，不会使用 `perChildCeilingMb`，也不会因模型超限被拒绝。`limits.memory.enforced` 仍是 required literal `false`；早期版本中的 `getAcpMemoryArgs(explicitMb?)`、`ChildHeapPoolExhaustedError` 和 transport error mapping 都被移除，避免发布不可达的 enforcement 机制。

## 关键代码路径

- `packages/acp-bridge/src/child-heap-policy.ts`：计算 child pool、恒定 per-child ceiling、admission 上限和 refusal 计数。
- `packages/acp-bridge/src/spawnChannel.ts`：在不改变 child argv 的前提下询问 policy，用于真实统计 observe refusal。
- `packages/acp-bridge/src/process-registry.ts`：配合 child lifecycle 记录 live child 数与 policy observation。
- `packages/cli/src/commands/serve.ts`、`packages/cli/src/serve/run-qwen-serve.ts`、`packages/cli/src/serve/fast-path.ts`：接入 `--child-heap-mode off|observe`，并在 yargs 与 fast path 拒绝 `enforce`。
- `packages/cli/src/serve/daemon-status.ts`、`routes/daemon-status.ts`、`server.ts`、`types.ts`：把 `limits.memory.childHeap` 接到 `/daemon/status` wire payload，并保持 `limits.memory.enforced:false`。
- `packages/sdk-typescript/src/daemon/types.ts`：同步 SDK daemon status 类型。
- `docs/design/2026-07-31-daemon-capacity-model-and-memory-bounds.md`、`docs/developers/daemon/*`、`docs/users/qwen-serve.md`、`docs/developers/qwen-serve-protocol.md`：删除“refusals=0 可作为 enforce 信号”的表述，改成 observe-only capacity planning 口径。

## 验证方式

PR 声明已在 Linux 本地完成 48 个 acp-bridge 测试、175 个 cli 测试、prettier、eslint，以及 `acp-bridge`、`cli`、`sdk-typescript` 的 `tsc`。重点断言包括：2/8/32/256GB host 下 `maxConcurrentChildren * perChildCeilingMb <= childPoolMb`；8GB host 建模为 7 个 child、每个 526MB，32GB host 建模为 25 个 child、每个 614MB；`observe` 与 `off` 下 child argv byte-identical；yargs 和 fast path 均拒绝 `--child-heap-mode enforce`；`limits.memory.enforced` 仍是字面量 `false`。

评审手工验证可以读取：

```bash
curl -s 'http://127.0.0.1:4170/daemon/status' | jq '.limits.memory.childHeap'
curl -s 'http://127.0.0.1:4170/daemon/status' | jq '.limits.memory.enforced'
```

并对比 `--child-heap-mode observe` 与 `off` 下 `qwen --acp` child argv 中的 `--max-old-space-size`，确认没有应用建模 ceiling。

## 边界与风险

- #8508 没有关闭 #8182 的实际 overcommit；它只发布用于评审和容量规划的分区模型。
- `refusals:0` 不能证明分区可安全 enforce，因为当前没有按 child 采集 peak old-space 的测量链。
- `--max-old-space-size` 只限制 V8 old space，不覆盖 Buffer、native allocation、MCP descendant、channel worker 或完整 RSS。
- `limits.memory.childHeap` 是 additive；`limits.memory.enforced` 保持 `false`，因此客户端契约不变。
