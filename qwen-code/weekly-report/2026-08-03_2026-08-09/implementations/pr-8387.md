# PR #8387 · fix(core): Avoid replaying unsafe MCP tool calls

链接：https://github.com/QwenLM/qwen-code/pull/8387
状态：merged
规模：+492 / -21，7 个文件

## 解决了什么问题

MCP 工具执行期间如果连接断开，旧实现会尝试重连并重放同一次工具调用。对读请求或幂等请求这有价值，但对写入、外部副作用或未声明语义的工具，自动 replay 可能造成重复操作，而且会把“可能已经完成”的事实包装成一次普通 retry。

## 最终实现方案

`DiscoveredMCPTool` 新增安全 replay 判定。自动重放必须同时满足：server 被标记为 trusted、当前 workspace 仍 trusted、工具声明了 annotations，且 annotations 证明调用可安全重放。安全条件只接受 `idempotentHint:true` 或没有 destructive 冲突的 `readOnlyHint:true`；`idempotentHint:false`、缺失 annotations、untrusted server、untrusted workspace 都拒绝。

连接恢复后不会信任旧 tool object，而是重新 discover tool，并用新 tool 的 trust、annotations 与当前 workspace trust 再校验一次。只要 rediscovered tool 丢失 annotation、失去 trust 或 workspace trust 被撤销，就不 replay。无法安全 replay 时抛出固定错误，明确提示调用可能已经完成、不要自动重试，应该先验证结果。

## 关键代码路径

- `packages/core/src/tools/mcp-tool.ts`：新增 unsafe replay 错误文案、安全 replay 判定和 reconnect 后二次校验。
- `packages/core/src/tools/mcp-tool.test.ts`：覆盖缺失 annotation、非幂等、readOnly/destructive 冲突、untrusted server/workspace、rediscovery 降级、abort、protocol `isError` 与 reconnect failure。
- `docs/design/mcp-safe-replay.md`、MCP 用户/开发文档和 CLI add help：说明 trust 仅在 trusted workspace 内生效，以及 connection-loss replay 策略。

## 验证方式

PR diff 中补充了 MCP tool focused tests，断言只有 idempotent 或一致 read-only 工具在 trusted workspace 下会 reconnect/retry；所有无法证明安全的连接断开都返回 stable unsafe replay error。
