## 解决了什么问题

REST、ACP、SDK 调用方需要把 qwen-code session 与自己的 thread/session 体系对齐，因此希望传入 caller-supplied session id。直接接受该字段会带来多类冲突：与 live session 重名、与同一时间 pending create 抢占、与 archived/history session 重叠、跨 workspace 恢复错位，或者 ACP child 实际创建了另一个 id 但调用方误以为请求被 honor。

## 当前实现方案

PR 新增共享 session id validator 和 `session_id_override` capability。caller-supplied ID 只能是 lowercase RFC UUID v1-v5，不允许 nil UUID、unsupported version/variant、Arena suffix、路径字符或非 string。内部 session id 仍可使用 Arena suffix，外部请求入口不接受。

daemon 侧新增 `RequestedSessionIdAdmission`。创建路径同步安装 pending claim，再检查 live bridges、draining/replaced bridge generation、registered workspace 的 active/archived/worktree history；restore 路径允许同一 bridge/workspace 共享 restore claim，但拒绝其它 owner。claim release 绑定 identity，防止其它路径误释放。

协议层面，REST `POST /session {sessionId}` 与 ACP `session/new._meta["qwen-code/sessionId"]` 都强制 `sessionScope:"thread"`。bridge 返回后必须比较 actual id 与 requested id，不一致映射为 `session_id_not_honored` 并清理 orphan。Stdio ACP agent 在读取 settings/fs 前先验证 session id，同 ID startup 串行化，错误以 ACP INVALID_PARAMS 返回而不是直接退出进程。TS/Java/MCP SDK 都新增字段、capability gate 与 response verification。

## 关键代码路径

- `packages/cli/src/config/session-id.ts`：caller-supplied session id validation，锁定 lowercase RFC UUID v1-v5。
