# PR #8414 · fix(webui): recover complete turns after live journal truncation

状态：open
规模：+2394 / -166，17 个文件

## 解决了什么问题

WebUI 依赖 live journal / SSE 展示当前会话。当 live journal 因大小上限丢弃旧 event 时，客户端只能看到 `history_truncated` marker 和残缺 turn。对长输出、慢客户端、移动端后台恢复等场景，这会让同一 prompt 的后续内容与 terminal 状态不可完整恢复。

## 当前实现方案

daemon bridge 把 `history_truncated` live journal marker 映射为带 `scope:"live_journal"`、`maxEvents` 和 `promptId` 的 SDK event。SDK normalizer 在 UI 文案上区分普通 replay history 截断与 live journal 截断，避免把“旧 replay 丢失”误读成完整会话不可恢复。

WebUI 新增 live journal repair 流程：看到 marker 后先建立 checkpoint，不立即清空当前 transcript。repair target 优先使用 marker `promptId`，否则只在 retained events 能唯一定位当前 prompt 时 fallback。等目标 prompt 的 `turn_complete` 或 `turn_error` 到达后，WebUI 用同一 session 做一次 memory replay load，校验 user input 与 terminal 是否匹配，再重建 marker 之后的 suffix 并原子替换 UI tail。失败时只发一次 notice，然后恢复原 SSE 消费，不重复触发副作用。

后续 patch 还处理 marker block 被 UI trimming 移出视图后的 pagination anchor：优先用 fresh persisted first record id 更新 `beforeRecordId`，否则走 bounded full snapshot fallback，避免 repair 与历史分页状态互相破坏。

## 关键代码路径

- `packages/acp-bridge/src/bridge.ts`：live journal truncation marker 带 active prompt id。
- `packages/sdk-typescript/src/daemon/events.ts` 与 UI normalizer：增加 truncated event optional fields 和展示文案。
- `packages/webui/src/providers/live-journal-repair.ts`：定位 repair target、构造 repair suffix、拒绝 degraded/non-recoverable 场景。
- `packages/webui/src/providers/QwenSessionProvider.tsx`：串接 marker checkpoint、terminal 后 load、suffix 替换和 failure notice。

## 验证方式

PR diff 中包含 deterministic daemon / WebUI integration 覆盖：用 `--max-journal-events 3` 触发截断，断言 WebUI 只做两次 load、不重复提交原 prompt，并恢复 chunks 0..19 的完整输出。
