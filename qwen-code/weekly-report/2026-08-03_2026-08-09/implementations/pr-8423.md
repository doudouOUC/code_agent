## 解决了什么问题

daemon status 已能报告 RSS、heap 和 memory budget，但缺少真实 denominator。只有绝对字节数时，操作者不知道当前进程是安全、接近软上限，还是已经逼近 cgroup/host 限制；资源预算后续也缺少统一 pressure signal。

## 当前实现方案

PR 新增 `--memory-pressure-mode off|observe`，默认 `observe`。status 中新增 `runtime.memory.pressure`：ratio 同时计算 daemon root RSS / available memory 与 V8 heap used / heap size limit，并取较大者；source 标明触发项是 `rss`、`heap` 或 `unknown`。返回字段包含 `mode`、`level`、`ratio`、`rssBytes`、`rssRatio`、`availableBytes`、`heapUsedBytes`、`heapRatio`、`heapLimitBytes`。

available memory 使用 cgroup/host 可用内存和 `limits.memory.availableMemoryMb` 的真实容量口径，而不是 advisory effective budget。observe 模式只在 status issues 中报告 `daemon_memory_pressure` warning，不做 admission、kill、throttle 或 enforce；off 模式保留压力字段但不产生 warning。
