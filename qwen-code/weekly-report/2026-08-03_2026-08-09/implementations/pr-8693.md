# PR #8693 最终实现：integration-tests TypeScript 覆盖修复

> 规模：+224 / -76，25 个文件

## 解决了什么问题

`integration-tests/tsconfig.json` 之前无法真正运行 `tsc -p integration-tests/tsconfig.json`：`compilerOptions.paths` 里有 `"//"` 字符串注释，触发 TS5063；继承的 composite 设置又要求所有 imported source 都在 include/files 中，导致大量 TS6307。由于 integration tests 不是 workspace，`npm run typecheck --workspaces --if-present` 覆盖不到它；ESLint 对 TypeScript 文件也不会报 `no-undef`。

这掩盖了真实缺陷：#8620 相邻的 streaming 测试曾引用未声明的 `REPO_ROOT`，在开发机上被 bare catch 吞掉而跳过关键安全回归，在 CI module scope 下则可能直接失败。测试 helper 和 terminal-capture scenario 也有一批只有 TypeScript 能发现的错误。

## 当前实现方案

#8693 先修正 integration-tests TypeScript 工程：移除 `paths` 中的非法注释，关闭 inherited `composite`，补 `DOM` / `DOM.Iterable` / `ES2023` lib，使浏览器 terminal-capture 和 SDK source 中的 Web API 类型可用。workspace package 通过 `paths` 指向 source，包括 `@qwen-code/qwen-code-core`、transcript records、`@qwen-code/sdk`、daemon subpaths 和 `@qwen-code/acp-bridge`，避免依赖 stale `dist` 或 project reference。`@lydell/node-pty` 指到仓库内 `node-pty.d.ts`，因为其 exports map 在 nodenext 下没有 types condition；根依赖补 `@types/jsdom`。

随后按 `tsc` 发现的问题修测试代码和少量 SDK 源码类型：telemetry attributes 改为 `unknown` index signature，tool log helper 接受 optional `name/args/success/duration_ms`，`createToolCallErrorMessage` 支持 optional tool name，`readLastApiRequest` 返回 `ParsedLog | null`。测试侧用 optional chaining、bracket env access、JSON parse default、显式 `String(...)` 和 `asAccepted()` helper 处理 union narrowing。SDK daemon 源码中修 `process.env` / index signature 读取，删除未用变量。

PR 也修正了两个被 typecheck 暴露的测试逻辑问题：`write_file.test.ts` 把失败 message 从被忽略的 `toBeTruthy(arg)` 参数移到 `expect(value, message).toBeTruthy()`；terminal-capture 两个 scenario 把 `gif:true` 从嵌套 `streaming` 对象移到 runner 实际读取的 scenario-level config。

## 边界与风险

- TypeScript paths 只影响 integration-tests 的静态检查；Vitest runtime alias 仍按现有配置指向构建产物。
- 该 PR 不把 integration-tests 纳入 workspace typecheck 命令；如果希望 CI 默认覆盖，需要后续单独接线。
- 对 SDK 源码的改动是类型可见性/索引访问修复，不改变 transport 或 query 行为。
