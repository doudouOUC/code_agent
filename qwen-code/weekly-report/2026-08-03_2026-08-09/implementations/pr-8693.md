# PR #8693 最终实现：integration-tests TypeScript 覆盖修复

> PR: [fix(integration-tests): make the project typecheckable and fix what that found](https://github.com/QwenLM/qwen-code/pull/8693)
> 状态：merged，已合入 `main`。
> 规模：+316 / -61，19 个文件

## 解决了什么问题

`integration-tests/tsconfig.json` 之前无法真正运行 `tsc -p integration-tests/tsconfig.json`：`compilerOptions.paths` 里有 `"//"` 字符串注释，触发 TS5063；继承的 composite 设置又要求所有 imported source 都在 include/files 中，导致大量 TS6307。由于 integration tests 不是 workspace，`npm run typecheck --workspaces --if-present` 覆盖不到它；ESLint 对 TypeScript 文件也不会报 `no-undef`。

这掩盖了真实缺陷：#8620 相邻的 streaming 测试曾引用未声明的 `REPO_ROOT`，在开发机上被 bare catch 吞掉而跳过关键安全回归，在 CI module scope 下则可能直接失败。测试 helper 和 terminal-capture scenario 也有一批只有 TypeScript 能发现的错误。

## 最终实现方案

#8693 先修正 integration-tests TypeScript 工程：移除 `paths` 中的非法注释，关闭 inherited `composite`，补 `DOM` / `DOM.Iterable` / `ES2023` lib，使浏览器 terminal-capture 和 SDK source 中的 Web API 类型可用。workspace package 通过 `paths` 指向 source，包括 core、transcript records、`@qwen-code/sdk`、daemon subpaths、`@qwen-code/acp-bridge`、webui 和 channel package，避免依赖 stale `dist` 或 project reference；同时关闭 `noPropertyAccessFromIndexSignature`，贴合既有 integration test 写法。`@lydell/node-pty` 指到仓库内 `node-pty.d.ts`，因为其 exports map 在 nodenext 下没有 types condition；根依赖补 `jsdom` 与 `@types/jsdom`。

随后按 `tsc` 发现的问题修测试代码：telemetry attributes 改为 `unknown` index signature，tool log helper 接受 optional `name/args/success/duration_ms`，`createToolCallErrorMessage` 支持 optional tool name，`readLastApiRequest` 返回 `ParsedLog | null`。测试侧用 optional chaining、bracket env access、JSON parse default、显式 `String(...)` 和 `asAccepted()` helper 处理 union narrowing；channel plugin test 统一从 `@qwen-code/channel-base` 导入基础类型。`integrations/external-context/tsconfig.json` 覆盖 root vitest globals/types，避免 integration tests 为引入 jsdom 而把 DOM/Vitest type 环境泄漏到 external-context package。

PR 也修正了两个被 typecheck 暴露的测试逻辑问题：`write_file.test.ts` 把失败 message 从被忽略的 `toBeTruthy(arg)` 参数移到 `expect(value, message).toBeTruthy()`；terminal-capture 两个 scenario 把 `gif:true` 从嵌套 `streaming` 对象移到 runner 实际读取的 scenario-level config。

## 关键代码路径

- `integration-tests/tsconfig.json`：integration tests TypeScript 工程修复、source path aliases、DOM lib、`composite:false`。
- `integrations/external-context/tsconfig.json`：覆盖 root vitest globals/types，隔离 jsdom/DOM 类型环境。
- `integration-tests/test-helper.ts`：telemetry/tool log/API request helper 类型收窄。
- `integration-tests/channel-plugin.test.ts`：统一 channel base import，避免依赖错误 package surface。
- `integration-tests/cli/qwen-serve-streaming.test.ts`：streaming prompt union narrowing 和未声明变量相邻问题修复。
- `integration-tests/cli/write_file.test.ts`：断言 message 位置修正。
- `integration-tests/terminal-capture/scenarios/bugfix-2833.ts` / `pr-2371-review.ts` / `table-pending-height-scroll-lock-regression.ts`：`gif:true` 配置层级修正。
- `integration-tests/terminal-bench/terminal-bench.test.ts`：环境变量读取按 TS index signature 收窄。
- `package.json` / `package-lock.json`：新增 `jsdom` 与 `@types/jsdom`。

## 边界与风险

- TypeScript paths 只影响 integration-tests 的静态检查；Vitest runtime alias 仍按现有配置指向构建产物。
- 该 PR 不把 integration-tests 纳入 workspace typecheck 命令；如果希望 CI 默认覆盖，需要后续单独接线。
- 该 PR 最终不修改 SDK runtime source；重点是 integration-tests / external-context TypeScript 配置和测试代码本身。
