# PR #8636 · fix(core): Resolve symlinks before granting read permission

链接：https://github.com/QwenLM/qwen-code/pull/8636
状态：merged
规模：+429 / -69，5 个文件

## 解决了什么问题

`read_file` 的默认权限会对若干 always-allow roots 放行，例如 agent 管理的内部文件、受管 memory 文件等。旧实现用请求路径的 lexical 形态和 allow root 比较，如果攻击者在这些可写目录里放一个 symlink 指向外部敏感文件，就可能让路径看起来仍在 allow root 下，从而绕过 ask 直接读取真实外部目标。

这个问题的核心不是读取工具本身缺少权限，而是默认权限判断在自动 allow 前没有先解析 symlink。

## 最终实现方案

`getFileReadDefaultPermission` 在比较前先对请求路径执行 `path.resolve()`，再用 `realpathNearestExisting()` canonicalize 到最近已存在前缀。always-allow roots 也用同一 helper canonicalize 后再比较，因此 planted symlink 会暴露真实目标，不再命中 allow root；旧的静默 allow 会降级成 ask。

managed memory 分支只 canonicalize candidate，memory root 本身保留 lexical 边界。这是有意设计：local-memory root 可以位于 repo-tracked `.qwen/` 下，如果把 root 自身 canonicalize，仓库内 symlink 可能反过来搬走受管 memory 边界。

PR 将原先 memory 模块里的 `realpathNearestExisting` 提升到 `packages/core/src/utils/paths.ts`，memory 代码改为复用 shared helper。helper 支持不存在尾段、悬挂 symlink 叶子和最多 40 跳解析；出现错误时不抛出给权限层，而是保守返回可比较路径。

## 关键代码路径

- `packages/core/src/tools/file-read-permission.ts`：在 read default permission 判定中 canonicalize candidate 与 always-allow roots。
- `packages/core/src/utils/paths.ts`：提供 shared `realpathNearestExisting()`。
- `packages/core/src/memory/paths.ts`：删除本地 helper，改用 shared utils。
- `packages/core/src/tools/file-read-permission.test.ts`：覆盖 allow root 内 symlink、目录 symlink traversal、悬挂 symlink、root symlink 与 missing file。
- `packages/core/src/utils/paths.test.ts`：覆盖 helper 的最近存在前缀、symlink 和错误容忍行为。
