# PR #8462 · feat(serve): report aggregate ACP child RSS, not just the primary's

## 解决了什么问题

daemon memory status 原来只报告 primary ACP child RSS。多 workspace 或多个 active ACP child 同时存在时，操作者无法从 status 看出子进程总内存，也看不到哪些 child 没有最近采样；这会低估实际资源压力。

## 最终实现方案

status 响应中 `runtime.memory.childRssCoverage` 扩展为 `active_children`，新增 `runtime.memory.children`：

- `rssBytes`：所有 live ACP child 最近一次自报 RSS 的求和；
- `sampled`：有缓存读数的 active child 数量；
- `oldestReadingAgeMs`：最旧读数年龄，或无样本时为 null。

daemon 在构建 status 时用和 `activeAcpChildren` 相同的 `isChannelLive()` predicate 同步遍历 managed runtimes。没有 snapshot 的 child 不贡献 RSS，也不增加 sampled，因此调用方可以用 `sampled / activeAcpChildren` 判断覆盖缺口。`run-qwen-serve` 在 watcher active 时刷新所有 managed workspace child；旧的单数 `childRssBytes` 保留 primary child 读数兼容。aggregate 不折入 pressure ratio，因为它不是完整 process tree RSS，可能 double-count shared pages，也不包含 MCP descendant。

## 关键代码路径

- `packages/cli/src/serve/status.ts`：active children RSS 汇总。
- `packages/cli/src/serve/runQwenServe.ts`：刷新所有 managed workspace child RSS。
- `packages/sdk-typescript/src/daemon/types.ts`：新增 `childRssCoverage:"active_children"` 与 `children` 字段。
- daemon status tests：覆盖 sampled gap、pre-age bridge 与 dormant child exclusion。

## 验证方式

PR diff 中 status focused tests 验证 aggregate RSS、sampled 缺口、oldest reading age 和 dormant exclusion；SDK type tests 覆盖 additive wire shape。
