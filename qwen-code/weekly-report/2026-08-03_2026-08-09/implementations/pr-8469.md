# PR #8469 · feat(acp): Protect against repeated tool execution failures

规模：+2750 / -63，24 个文件

## 解决了什么问题

ACP 前台工具如果反复因为同一种 execution error 失败，模型可能在没有新用户信息的情况下继续重试同一工具。现有保护多针对 Todo continuation 或特定 flow，不能基于统一 execution outcome 识别“同类工具执行失败循环”。

## 最终实现方案

PR 新增 prompt-local repeated tool execution failure guard，环境变量 `QWEN_CODE_ACP_REPEATED_TOOL_FAILURE_GUARD` 控制 `off|shadow|warn|enforce`，默认 shadow，并在 Session start 固定模式。

guard 只统计完全 settle 的 foreground ACP batch，且 terminal event 必须满足：`status=error`、`executionStatus=error`、有可解析工具身份、`executionErrorType` 不是 UNKNOWN。validation、permission denial、not_started、cancellation、post-execution failure、unknown outcome、duplicate provider event、mixed/incomplete batch、queued input 或不可靠 drain 都排除。聚合 key 是 `(policyToolName, executionErrorType)`，不纳入参数、结果、raw error、路径或 MCP server 名。

阈值为 8 次失败并跨至少 2 个 complete batch。第一次到阈值进入 warned 状态：shadow 只记录 would_warn，warn/enforce 注入固定纠偏提醒。下一次 complete matching batch 命中时进入 latched：shadow/warn 记录 would_stop 但继续；enforce 记录 stopped，保留当前 batch function responses，追加固定 stop context，不再开启第四次 model stream，并关闭自动 Todo continuation，直到新用户输入重置。channel bridge 会给 channel-driven prompt 打私有 route marker，Session 对这类 prompt 强制 off；旧/第三方 ACP host 无法提供可靠 queued-prompt contract 时记录 `unreliable_input` 并 fail-open。

telemetry 增加 `qwen-code.repeated_tool_failure_guard` event/metric，只包含 route、mode、phase、decision、bucket、reset reason、terminal/execution status、error type 和 tool type 等低基数字段；不采集参数、输出、路径、raw error、MCP server、session/user/private key。终态 repeated-execution loop event 显式绕过 QwenLogger/RUM，只保留 OpenTelemetry 关联。
