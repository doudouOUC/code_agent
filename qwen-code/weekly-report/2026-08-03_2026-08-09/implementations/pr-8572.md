# PR #8572 最终实现：REST SSE stream 与客户端重连观测

> PR: [feat(daemon): Add SSE stream and client observability](https://github.com/QwenLM/qwen-code/pull/8572)
> 状态：merged；按最终合入 diff 记录。

## 解决了什么问题

daemon 的逻辑 session id 无法区分同一 session 下多条物理 REST SSE 连接。WebUI 或 SDK 重连后，旧日志只能看到 session 级 open/close、ring eviction 或 slow-client warning，难以判断这是初连、正常续连、prompt restart、transport error、state resync，还是同一慢客户端不断制造 backlog。

这会影响三类排障：一是 session id 相同但 stream 多次重建时，无法还原前后连接关系；二是 slow-client warning / eviction 只暴露队列结果，不知道触发事件类型和大小；三是 close 日志缺少 settled frame、last event id、backpressure 与 terminal 归因，无法区分网络断开、writer idle、EventBus eviction、session terminal 或 iterator error。

## 最终实现方案

#8572 给每条被 daemon 成功接受的 REST SSE stream 分配一个 UUID，并通过 `X-Qwen-SSE-Stream-Id` response header 返回给客户端。SSE route 在打开、slow-client warning、client eviction、state resync、writer idle eviction、socket error 和关闭时输出统一的 daemon log 与 OTel log/route attributes，所有记录都带 `session.id`、stream id、可验证的 client id、连接原因，以及可选 previous stream id。

EventBus 新增 per-subscriber diagnostic callback。慢客户端 warning 和 eviction 会把 queue size、maxQueued、queuedBytes、maxQueuedBytes、triggerEventType、triggerEventBytes 等低敏信息传给 SSE route；route 成功写入结构化 daemon log 后会抑制旧 stderr fallback，logger 失败时仍回退旧路径。触发 event type 会做长度和控制字符清洗，诊断不包含 event payload、auth token 或正文内容。

SSE close path 统一走 finalize。它记录 duration、settled event frame 数、last written event id、backpressure 次数、最大 drain 等待、live publish-to-write-settled 最大延迟、slow warning 次数、EventBus eviction reason、terminal event type 和 close reason。close reason 会在 writer idle、socket error、iterator error、EventBus eviction、session terminal、source complete、client disconnect 之间归因；`state_resync_required` 也会额外写出 gap、reason/detail 与 stream/client 线索。

TS daemon SDK 扩展 `SubscribeOptions`，REST transport 会发送 `X-Qwen-Client-Id`、`connectReason` 与 `previousStreamId`，并在 response header 中学习 accepted stream id。`DaemonSessionClient` 只允许 session 自己注入 client id 和 previous stream id，运行时也删除 untyped JS 传入的同名字段，避免外部调用方伪造 session-owned lineage。非 REST transport 会清空 REST stream lineage。

WebUI 只在它能确定原因时写 `sseConnectReason`：`prompt_restart`、`stream_end`、`transport_error`、`state_resync`。无法区分时不强行猜测，由 SDK 默认按首连/续连填 `initial` 或 `resume`。所有字段都是 additive；老 daemon 忽略 query/header，代理剥离 header 时 SDK 只学不到 stream id，不影响 replay、cursor 或 prompt terminal 语义。

## 关键代码路径

- `packages/cli/src/serve/routes/sse-events.ts`：分配 stream UUID，解析/sanitize client id、connect reason 和 previous stream id，输出 lifecycle telemetry/log，记录 close attribution、backpressure、live lag 与 resync gap。
- `packages/acp-bridge/src/eventBus.ts`：新增 `EventBusSubscriberDiagnostic`、slow warning / eviction payload 和 `onSubscriberDiagnostic` callback；logger 未处理时保留 legacy stderr fallback。
- `packages/sdk-typescript/src/daemon/RestSseTransport.ts`：发送 client id、connection reason、previous stream id，读取并校验 `X-Qwen-SSE-Stream-Id`。
- `packages/sdk-typescript/src/daemon/DaemonSessionClient.ts`：维护最近 accepted REST stream id，自动选择初连/续连 reason，并屏蔽 caller 覆盖 session-owned stream identity。
- `packages/webui/src/daemon/session/DaemonSessionProvider.tsx`：在 prompt restart、normal stream end、transport error 与 state resync reconnect 上设置可解释的连接原因。
- `packages/core/src/telemetry/daemon-tracing.test.ts`、`packages/acp-bridge/src/eventBus.test.ts`、`packages/sdk-typescript/test/unit/*`、`packages/webui/src/daemon/session/DaemonSessionProvider.test.tsx`：覆盖 diagnostics、transport header/query、stream id lineage 和 WebUI reason 传播。

```bash
curl -i -N -H "Authorization: Bearer $QWEN_SERVER_TOKEN" \
  "http://127.0.0.1:4170/session/$SESSION_ID/events?connectReason=initial"
```

预期响应头包含 `X-Qwen-SSE-Stream-Id`；daemon log 中同一 stream id 应出现在 opened/closed 记录里。随后用 SDK/WebUI 重连，应看到 previous stream id 和可解释 connect reason；制造 slow consumer 时，warning/eviction 只记录 queue 与 trigger metadata，不写 event payload。

## 边界与风险

- #8572 只增强观测，不改变 EventBus replay、ring eviction、backpressure、writer idle、prompt terminal 或 WebUI recovery 行为。
- `connectReason` 是客户端报告的诊断线索，不是安全事实；daemon 只接受白名单值并按低敏属性记录。
- stream id 是物理连接诊断 id，不是 session id、client id 或权限凭据。
- 代理剥离 `X-Qwen-SSE-Stream-Id` 时，SDK 会继续工作，只是无法报告 previous stream lineage。
- 后续如果 telemetry attribute key、reason 枚举或 close attribution 再调整，文档需要按新 diff 复核。
