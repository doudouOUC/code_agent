# PR #8428 · fix(core): Clarify write_file prior-read guidance

## 解决了什么问题

`write_file` 的工具说明和系统 prompt 示例没有足够清楚地区分“已经确认目标不存在后创建文件”和“没读过目标就直接写”。在 prior-read enforcement 打开时，blind overwrite 会被拒绝；在未开启或提示理解偏差时，也可能覆盖用户已有文件。

## 最终实现方案

`WriteFileTool` 描述新增明确规则：创建/生成请求本身不等于目标路径已知为新文件。除非本轮会话已经确认目标不存在或读过当前内容，否则必须先 `read_file`。如果读到文件不存在，再创建它；如果 prior-read enforcement 启用，盲覆盖会被拒绝。

系统 prompt snapshot 中的 `write_file` 示例同步改为先读目标测试文件，再在 `read_file` 报不存在之后写入。这样模型示例、工具描述和 runtime enforcement 方向一致。

## 关键代码路径

- `packages/core/src/tools/write-file.ts`：收紧 tool description。
- `packages/core/src/tools/write-file.test.ts`：断言描述包含 prior-read guidance。
- `packages/core/src/core/prompts.ts` 与 snapshots：示例先读后写。
- `packages/core/src/core/prompts.test.ts`：锁定 prompt 示例顺序。
