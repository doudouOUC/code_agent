# PR #8450 · fix(cli): Bound ACP textual tool-result payloads

链接：https://github.com/QwenLM/qwen-code/pull/8450
状态：open
规模：+1057 / -4，9 个文件

## 解决了什么问题

ACP live update 和 replay 会把工具结果文本投影给 WebUI/IDE。即使最终 model-facing tool response 已有预算，transport 上的 textual `content` / `rawOutput` 仍可能很大，导致 live SSE、history replay 和 virtual subagent replay 传输超大 payload，拖慢 UI 并放大内存占用。

## 当前实现方案

PR 新增 ACP transport-only 文本投影预算。`ACP_TOOL_RESULT_TEXT_JSON_BYTE_BUDGET` 固定为 65,536 byte，按 JSON serialization 后的 UTF-8 byte 计量，每个可裁剪字段独立预算。只裁剪 canonical ACP text blocks 的 `content` 和 primitive string `rawOutput`；A2UI tool updates、structured/diff/terminal/media/mixed/non-canonical payload 不改。

超限字符串保留约 20% head 和 80% tail，中间插入固定 marker `[..., truncated for ACP transport ...]`；实现考虑 JSON escaping、surrogate pair、lone surrogate，并复制 slice 避免持有巨大原始字符串。多 text block 走 deterministic max-min allocation；如果预算太小无法容纳内容，则 fallback 为单个 omission marker。

该投影仅作用在 ACP live `Session.sendUpdate`、history replay pages 和 virtual subagent replay。canonical transcript、model-facing response、artifact metadata 与 offline export 保持 lossless。

## 关键代码路径

- `packages/cli/src/acp-integration/session/acp-tool-result-text-projection.ts`：预算、裁剪与 allocation。
- `packages/cli/src/acp-integration/session/Session.ts`：live update 发出前投影。
- `packages/cli/src/acp-integration/session/history-replay.ts`：history replay 复用投影。
- `packages/cli/src/acp-integration/session/virtual-subagent-replay.ts`：virtual subagent replay 复用投影。

## 验证方式

PR diff 覆盖 live ACP delivery、history replay、多 block allocation、Unicode/JSON byte accounting，以及 offline export SHA 不变，确保 transport 缩短不影响持久记录。
