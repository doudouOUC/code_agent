# PR #8464 · perf(core): clear tool results to a low watermark to preserve prompt cache

链接：https://github.com/QwenLM/qwen-code/pull/8464
状态：open
规模：+265 / -26，7 个文件

## 解决了什么问题

active tool-result history budget 超过阈值后，旧 microcompaction 只清到刚低于阈值。长会话中工具结果不断追加时，会反复小幅清理，导致历史频繁变化、prompt cache 更难命中。另一个问题是 pending tool result batch 会错误占用 committed history 的 keep-recent 槽，让较新的 committed result 更早被清掉。

## 当前实现方案

PR 保持触发条件不变：总 compactable tool result chars 超过 `toolResultsTotalCharsThreshold` 才触发，`-1` 仍表示禁用。触发后目标不再是低于阈值，而是清理到 `floor(threshold / 2)` low watermark。实际清理仍是 best effort，如果近期保护项太多，可能 soft-exceeded。

keepRecent accounting 修复为：pending result 继续计入虚拟总量，也继续参与 kept path resolution，但不消耗 committed history 的 protection slot；pending 本身不会被 microcompaction 清掉。metadata 新增 `toolResultsLowWatermark`，debug log 显示 target low watermark，并在清理后仍高于 low watermark 时标记 `(soft-exceeded)`。

## 关键代码路径

- `packages/core/src/core/geminiChat.ts`：active tool result budget / microcompaction 调度。
- `packages/core/src/core/tool-result-history-budget.ts`：low watermark 目标、pending/committed accounting。
- `packages/core/src/core/geminiChat.test.ts` 与 focused budget tests：阈值边界、低水位清理、pending keep-recent 修复。

## 验证方式

PR diff 覆盖恰好等于阈值不触发、超过 1 字符触发并清到 target、167 个 25.5K result 的 compaction 次数从约 148 次降到 14 次、pending batch 不偷 committed protections、自定义阈值与 disable 语义。
