## 解决了什么问题

#10198 允许一个 Channel owner 保留多个命名 session，但异步结果、stream block、平台分片、卡片、后台回复、直接 shell 和权限提示仍不显示来源任务。延迟输出因此无法和 `review`、`feature-a` 等任务可靠对应，尤其在重启重试或多个 owner 的群聊中容易产生歧义。

## 最终实现

最终实现在 `NamedSessionManager` 建立 exact session ID 到 task name/status/target 的派生索引，原子 catalog commit 成功后才发布新索引；miss 时只允许按既有 owner lock 和 exact legacy route 规则有界收养 `default`。Turn 或 permission admission 捕获不可变 `sourceLabel`，私聊格式为 `[task]`，群聊为 `[sender · task]`，标签与 model text、transcript、telemetry 分离。

各 adapter 在自己的最终可见边界转义和渲染标签，使普通回复、每个独立 stream/platform split、card/fallback、media、background、direct shell 与 GitHub restart-safe final-delivery retry 都恰好带一次标签。Feishu 在 bot-origin card reply extraction 时剥离已渲染标签，避免 attribution 重新进入引用输入；Telegram 在 4096 字符上限内做 markup-balanced 分片，每片重复标签，无法安全分割时按片回退 plain。命名模式文本权限提示展示 exact request ID 和带 ID 的 approve/deny 命令；catalog/selection 同步回执不加标签。Part 2 的单 selected task、busy guards、bare permission command、owner/workspace 隔离和 disabled-mode 行为不变。

## 关键代码路径

- `packages/channels/base/src/named-session-manager.ts`：session-to-task presentation index、原子更新与有界 legacy route bootstrap。
- `packages/channels/base/src/ChannelBase.ts`：source label 捕获、turn/permission/shell/background delivery 传播和 exact request 文本。
- `packages/channels/base/src/types.ts`：output segment 与 user-input context 的 optional `sourceLabel`。
- `packages/channels/*` adapters：Markdown/HTML/card/split/fallback/retry 的平台边界渲染与转义。
