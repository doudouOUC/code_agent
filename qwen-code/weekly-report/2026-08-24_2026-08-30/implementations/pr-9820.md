# PR #9820 最终实现：限制 conditional-close refusal holds

> PR: [fix(daemon): Bound conditional-close refusal holds](https://github.com/QwenLM/qwen-code/pull/9820)
> 状态：merged，2026-08-24 合入 `main`。
> 规模：+104 / -12，5 个文件

## 解决了什么问题

#9134 让 ACP child 在 automatic conditional close 时返回 active-work holds，daemon 据此保留仍有后台工作的 session。拒绝语义是正确的，但返回数组原先没有长度上限；异常或恶意 child 可以让 daemon 遍历、缓存和报告无界 holds，把一条本应轻量的 close/reap 控制路径变成内存与 CPU 放大点。

## 最终实现方案

实现复用共享常量 `ACTIVE_WORK_MAX_SESSION_HOLDS = 1024` 作为采纳边界。child 返回 conditional-close refusal 时，daemon 仍无条件保留 session；只有 response 中 hold 数组长度不超过 1024，才遍历、规范化并替换该 session 的 hold cache。超限数组不遍历、不采纳，保留最近一次合法 cache，因此不会因为一条异常响应丢掉既有 active-work 证据。

边界测试明确锁定恰好 1024 条可以采用、1025 条拒绝采用；已有非空 cache 在新的合法子集返回时可变成 partial，但 session 保留和自动 close 拒绝不受 cache 是否更新影响。该变化不新增 public protocol、capability 或持久化格式。

## 关键代码路径

- `packages/acp-bridge/src/bridge.ts`：conditional-close refusal 先做数组长度门控，再决定是否采纳 hold cache。
- `packages/acp-bridge/src/bridgeTypes.ts`：复用 active-work hold 数量上限。
- `packages/acp-bridge/src/bridge.test.ts`：覆盖 1024/1025 边界、旧 cache 保留与合法 partial replacement。
- `docs/design/active-work.md`：修正 conditional-close response 与 hold 上限。
- `docs/design/daemon-deep-health.md`：明确 daemon-wide 聚合统计的 grade 口径。

## 边界与风险

- 超限 response 仍表示 conditional close 被拒绝；上限只控制详细 holds 的采纳，不把拒绝降级成允许关闭。
- 保留旧 cache 可能让诊断暂时显示上一轮合法 holds，但比采纳无界响应或清空活跃证据更安全。
- public status 仍只消费既有 activeWork 投影；本 PR 不新增 wire 字段或改变显式 close/kill/shutdown 的强制语义。
