## 解决了什么问题

#10113 定义了 configurable Mem0 extension 的信任和方言边界，但尚无可构建、可配置、可测试的 runtime。需要先把严格配置加载、请求执行、响应归一化和 MCP surface 落成独立骨架，同时避免在没有已审核 preset 时误连真实 provider。

## 当前实现方案

当前 diff 新增自包含 `integrations/external-context-mem0` package、manifest 和 bundle。runtime 只从 `QWEN_EXTERNAL_CONTEXT_MEM0_CONFIG` 指向的绝对路径读取最多 64 KiB 配置，验证 instance schema、已知 preset、exact ID、静态 path/endpoint 和 HTTPS 默认；credential 从配置指定的环境变量读取，不接受 inline secret。

request engine 只执行 preset 白名单中的 GET/POST 和鉴权/字段位置，redirect 为 manual 且直接拒绝，不 retry。response 最多 1 MiB，UTF-8/JSON 解析失败为稳定错误，最多归一化 5 条 Profile v1 untrusted result。MCP server 只暴露 `context_search`，使用 AbortSignal timeout 并对错误做稳定 redaction。`builtInPresets` 当前故意为空，因此骨架不能连接任何真实 provider。

## 关键代码路径

- `integrations/external-context-mem0/src/config.ts`：绝对路径配置、schema、preset、HTTPS 和 credential env 验证。
- `integrations/external-context-mem0/src/request.ts`：allowlisted HTTP 请求、timeout、redirect/size/UTF-8/JSON 边界。
- `integrations/external-context-mem0/src/server.ts`：单一 MCP tool、Profile v1 normalization 与错误 redaction。
- package manifest、bundle/pack scripts 和 49 项 package tests。

## 边界与风险

- PR 仍为 open；#10113 设计已合入，但 runtime schema 与 preset 接线仍可能变化。
- 空 preset 是刻意的 fail-closed 状态；当前 package 可构建但不可用，不能宣称支持某个 Mem0 服务。
- 无 retry/probing/cache/write；Windows/Linux、真实 TLS/proxy 和 provider payload 未验证。
