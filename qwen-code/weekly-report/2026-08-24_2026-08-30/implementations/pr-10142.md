## 解决了什么问题

ACP transport 关闭、daemon shutdown 或 child 根进程意外退出时，既有 `ProcessRegistry` 主要跟踪 root child。child 派生的后代或自建 process group 可能继续持有资源；root exit 也不能证明它们消失，导致 daemon 报告关闭完成后仍有进程残留。

## 最终实现方案

最终实现让标准 ACP spawn 显式 opt in `ownsProcessTree`。POSIX child 在独立 process group 启动，registry 用绝对 `/bin/ps` 获取有界进程表快照，按 parent 关系追踪最多 256 个进程、8 层后代和相关 PGID。graceful cleanup 先 TERM 已知组，等待后再 KILL，并在 release ownership 前验证 group 已消失；root 意外退出也触发已知组回收。

process snapshot 限制 2 秒和 8 MiB；同步 shutdown 只做一次快照并 KILL，避免退出钩子无限等待。Windows 使用 taskkill tree。Linux zombie-only group 只有在状态验证后才从 registry 移除。daemon SIGHUP 现在与 SIGINT/SIGTERM 走相同 graceful/second-signal lifecycle。没有 `ownsProcessTree` 的 legacy attach 仍保持直接 child 语义。

## 关键代码路径

- `packages/acp-bridge/src/process-registry.ts`：tree ownership、process snapshot、PGID cleanup、deadline 与平台分支。
- `packages/acp-bridge/src/spawnChannel.ts` / `channel.ts`：标准 ACP spawn opt-in 与 root exit 通知。
- `packages/cli/src/serve/run-qwen-serve.ts`：SIGHUP 接入统一 shutdown lifecycle。
- 对应 process-registry、spawn/channel 和 serve signal 测试：覆盖 tree、zombie、timeout 和 second-signal。

## 边界与风险

- process table 存在 PID/PGID reuse 竞态；逃逸出已知 ancestry/group 的 daemonized 后代不在保证内。
- `/bin/ps` 可用性和 Windows taskkill 行为尚未跨平台实机验证。
