# PR #9978 当前实现观察：projectless task 的 standalone session 内部核心

> PR: [feat(cli): Add standalone sessions for projectless tasks](https://github.com/QwenLM/qwen-code/pull/9978)

> 规模：+9,150 / -710，67 个文件

## 解决了什么问题

已有 Conversations runtime 和 standalone source/identity primitives 仍缺少完整的创建、恢复、prompt admission 与 owner routing 服务。projectless task 因此可能继续继承 legacy Conversations 或 workspace 行为，在用户没有选择项目时观察共享 cwd、project settings 或 workspace-scoped 能力；遇到目录损坏、spawn outcome 不明或 close 无法确认时，错误 fallback 到 primary workspace 还会扩大隔离破口。

## 当前实现方案

当前 diff 新增内部 `StandaloneSessionService`。服务通过 `ensureRuntime()` 获取唯一 Conversations runtime，在 owner activity gate 内提供 `get/list/load/resume/createWithInitialPrompt/createChildWithInitialPrompt/dispatchPrompt/continueSession`；caller-supplied UUID 先 canonicalize，active/archive storage 仍以 persisted spelling 为权威。每个 standalone session 在初始 prompt admission 前准备 owner-only、non-symlink、Conversations root 下 direct-child 的确定性私有目录，并在后续 load/resume/prompt/continue 前重新核验 pinned device/inode/realpath identity。

creation 先占用 session ID、准备目录，再由 daemon-only bridge path 持久化 `sourceType:'standalone'` 并确认 source persisted，最后才接纳初始 prompt。projectless Live task 改为调用同一 service；standalone child 继承 source 与 private directory boundary，但从顶层 list 中排除。普通 workspace/Live owner routing 保持原语义，已知 standalone owner 即使 provenance 读取失败也不会 fallback primary。

Source-aware guard 在副作用之前拒绝 standalone 的 generic `cd`、branch/fork、side task、worktree/working-directory pin、project permission persistence、project/global model default、workflow 和 durable cron。目录 compromise、unknown spawn outcome 或 close refusal 无法证明 containment 时，service 冻结正在创建的 entry 并 quarantine Conversations runtime；owner record 保持 unavailable，而不是尝试在 primary runtime 继续执行。

这仍是 PR2B 内部集成：当前 diff 没有注册 `/standalone/*` route、没有广告 `standalone_sessions_v1`、没有 SDK/WebUI，也不补 archive/unarchive/delete/repair、attachment、durable standalone cron、parent-child cascade 或 move/fork-to-project。

- `packages/cli/src/serve/conversations/standalone-session-service.ts`：standalone CRUD/restore/prompt 核心、directory binding、exclusive creation、rollback 与 terminal quarantine。
- `packages/cli/src/serve/conversations/conversation-runtime-manager.ts` / `conversation-runtime-activity.ts`：唯一 Conversations runtime、activity gate 与 quarantine 生命周期。
- `packages/acp-bridge/src/session-source.ts` / `bridge.ts` / `bridgeTypes.ts`：reserved standalone source、daemon-owned creation key、canonical owner 与 private bridge contract。
- `packages/cli/src/acp-integration/acpAgent.ts` / `session/Session.ts`：deferred workspace activation、session-local config 和 standalone source-aware ACP 行为。

- `packages/core/src/config/config.ts` / `core/permission-helpers.ts` / `tools/cron-create.ts`：workspace/project-scoped 设置、权限和 durable cron 的 fail-closed guard。
