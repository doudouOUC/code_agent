> 规模：+317 / -0，2 个文件

## 解决了什么问题

External Context MCP Profile 已固定搜索工具和返回结构，但不同 Mem0-compatible 服务的 endpoint、鉴权、请求字段和结果 shape 并不一致。若为兼容性直接开放任意 URL、header、模板或 JSONPath，管理员配置会演变成不可审计的通用 HTTP 执行器，并扩大凭据泄漏、重定向、响应放大和方言漂移风险。

## 最终实现方案

最终设计选择自包含的本地 stdio extension `external-context-mem0`，对 Qwen Code 仍只暴露 `context_search({query})` 和 External Context MCP Profile v1。管理员通过绝对路径配置一个 immutable instance，实例引用 closed、versioned dialect preset；profile、instance schema、dialect 和 upstream 版本分别演进，不把 provider registry、动态模块或新的 Core provider union 暴露为公共契约。

方言只允许枚举的 GET/POST、鉴权位置、请求字段位置和结果字段路径；禁止任意 header/template/JSONPath/code、env expansion 和 redirect。默认要求 HTTPS，credential 只引用命名环境变量，配置和响应都有大小边界。请求不 retry、不 probing、不 cache，只做 retrieval；写入、删除和 automatic recall 不在范围内。

## 边界与风险

- 本 PR 只合入设计契约；目前仍没有可用的内置 dialect preset，不能据此宣称支持真实 Mem0 服务。
- 设计不保证任意 Mem0 deployment 都可适配，未进入 closed preset 的方言应拒绝而不是退化为通用 HTTP 配置。
- provider 写入、自动召回、跨租户授权和动态发现明确不在本阶段。
