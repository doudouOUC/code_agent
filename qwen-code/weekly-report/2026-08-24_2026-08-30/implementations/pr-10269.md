# PR #10269 最终实现：运行时热同步 model provider

> 规模：+3,025 / -206，43 个文件

## 解决了什么问题

Web Shell 安装 provider 或删除模型后，持久化 settings 和 provider 列表立即变化，但既有 ACP child 与 live sessions 仍持有旧 registry。用户选择刚显示的新 route 会失败，通常只能重启 daemon；删除和 credential 更新也存在同样的父进程 env、child config、session registry 多副本漂移。

## 最终实现

provider install/model delete 成功持久化后调用专用 runtime sync：daemon 在 workspace generation guard 下重读 env 文件并重建未来 child 使用的 effective env；读取、重建或应用失败时保留此前有效 env，不把半更新环境发布给新 child。active workspace child 再通过 private `workspaceModelProvidersReload` 重载 user/workspace settings、process env 与 model registry；bootstrap、初始化中和 live Session 的 registry 随后刷新并清理 per-model generator cache。active turn 已持有的 generator 不被替换，也不隐式切换当前模型。

响应增加 optional `runtimeSync.status = applied|deferred|failed`。没有 live ACP channel 时返回 `deferred`；parent env 或 child 刷新失败不回滚已提交 settings，也不把 mutation 改成 HTTP error，而由 Web Shell 提示重试或重启。generation assertions 防止旧 workspace runtime 发布结果；private reload 使用 30 秒预算，JSON-RPC 错误展示复用结构化 message extractor。

## 边界与风险

- 只处理显式 provider install/model delete，不是通用 settings watcher，也不自动迁移 live session 当前模型。
- `failed` 表示持久化已成功但运行时副本可能陈旧，调用方需提示重试或重启。
