# PR #10269 当前实现观察：运行时热同步 model provider

> PR: [fix(serve): Hot-reload runtime model providers](https://github.com/QwenLM/qwen-code/pull/10269)
> 状态：open；以下描述 2026-08-29 复核到 head `5f3f00d2c0` 的当前 diff，不能视为 `main` 已落地能力。
> 规模：+2,179 / -155，39 个文件

## 解决了什么问题

Web Shell 安装 provider 或删除模型后，持久化 settings 和 provider 列表立即变化，但既有 ACP child 与 live sessions 仍持有旧 registry。用户选择刚显示的新 route 会失败，通常只能重启 daemon；删除和 credential 更新也存在同样的父进程 env、child config、session registry 多副本漂移。

## 当前实现方案

当前 diff 在 provider install/model delete 成功持久化后调用专用 runtime sync：daemon 重新加载环境并重建未来 child 使用的 effective env；active workspace child 通过 private control method 重载 settings/environment；bootstrap、初始化中和 live Session 的 model registry 随后刷新并清理 per-model generator cache。active turn 已持有的 generator 不被替换，也不隐式切换当前模型。

响应增加 optional `runtimeSync.status = applied|deferred|failed`。没有 active child 时返回 `deferred`；env 或 child 刷新失败不回滚已提交 settings，也不把 mutation 改成 HTTP error，而由 Web Shell 提示重试或重启。generation assertions 防止旧 workspace runtime 发布结果；JSON-RPC 错误展示复用结构化 message extractor。

## 关键代码路径

- `packages/cli/src/serve/workspace-service/index.ts`：`reloadModelProviders()` 协调父环境和 child runtime。
- `packages/cli/src/acp-integration/acpAgent.ts` / `session/Session.ts`：重载配置并刷新 bootstrap、initializing/live registry。
- `packages/cli/src/serve/routes/workspace-auth.ts` 与 `workspace-models.ts`：持久化后的 sync 接线和 additive response。
- `packages/sdk-typescript/src/daemon/types.ts`、`packages/web-shell/client/App.tsx`：SDK 类型、45 秒 transport budget 与失败提示。

## 边界与风险

- 当前仍为 open；`runtimeSync` 不能作为 `main` 响应承诺。
- 只处理显式 provider install/model delete，不是通用 settings watcher，也不自动迁移 live session 当前模型。
- `failed` 表示持久化已成功但运行时副本可能陈旧，调用方需提示重试或重启。
