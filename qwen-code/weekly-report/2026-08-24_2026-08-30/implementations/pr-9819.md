# PR #9819 最终实现：统一 Live task 的 bridge session ID

> PR: [fix(serve): Canonicalize Live task bridge session IDs](https://github.com/QwenLM/qwen-code/pull/9819)
> 状态：merged，2026-08-24 合入 `main`。
> 规模：+396 / -42，4 个文件

## 解决了什么问题

Live task 既要按持久化 transcript 中的 session ID 读取 metadata，又要在内存 bridge、runtime owner、event stream 和 Conversations private directory 中定位同一个逻辑会话。旧实现把调用者看到的 `threadId` 原样用于全部路径；mixed-case UUID 因此可能读到持久化记录，却找不到 canonical bridge entry，继而重复 resume、订阅错误 event key，或让 live owner 与 storage owner 比较落在不同 spelling 上。

## 最终实现方案

实现把两个身份明确分离：`threadId` 保留持久化和协议可见 spelling，`bridgeSessionId = normalizeSessionIdForLookup(threadId)` 专供内存/runtime 操作。storage lookup、task response 和已有记录仍返回原 spelling；Live owner resolution、bridge summary、resume、event epoch/id、subscribe、prompt dispatch、Conversations directory materialization/relocation统一改用 canonical ID。

恢复前先同时核对 storage owner 与 live owner。若 mixed-case 查询命中多个存储 runtime，或 storage/live owner 不一致，继续 fail closed；若 bridge 已有 canonical resident entry，就直接复用，不再重复 cold resume。cold path 仍按 persisted spelling 读取 metadata，但向 bridge resume 传 canonical ID。`LiveSessionCoordinator` 也在调用 `bridge.resumeSession()` 前规范化候选 ID，避免上层漏传。

## 关键代码路径

- `packages/cli/src/serve/live/live-task-service.ts`：分离 persisted `threadId` 与 canonical `bridgeSessionId`，统一 owner、resident reuse、resume、events 和 prompt dispatch。
- `packages/cli/src/serve/live/live-task-service.test.ts`：覆盖 mixed-case resident reuse、cold resume、owner mismatch、live race、polling/events 与 caller-visible ID 保留。
- `packages/cli/src/serve/live/live-session-coordinator.ts`：resume 前规范化 session ID。
- `packages/cli/src/serve/live/live-session-coordinator.test.ts`：锁定 coordinator 传入 bridge 的 canonical spelling。

## 边界与风险

- canonicalization 只用于 bridge/runtime/map key；persisted transcript spelling、metadata lookup 和 wire response 不被重写。
- 多存储 owner、storage/live owner 不一致继续拒绝，不自动选择或合并。
- 本 PR 不扩展 mixed-case session list、organization、scheduled-task identity，也不处理 UUIDv7/undashed lock key folding。
- standalone storage maintenance 与 reserved source enforcement 仍由各自生命周期方案负责。
