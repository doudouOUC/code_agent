# PR #10554 当前实现观察：sessionless 用户级语言同步

> PR: [feat(serve): add sessionless POST /language for user-level language sync](https://github.com/QwenLM/qwen-code/pull/10554)
> 状态：open；以下描述 2026-08-31 复核到 head `581dbf9e34` 的当前 diff，不能视为 `main` 已落地能力。
> 规模：+1,180 / -4，22 个文件

## 解决了什么问题

host 在创建任何 session 之前没有 daemon API 可以切换用户语言；既有 `POST /session/:id/language` 又绑定单 session，无法安全表达 process-global user settings。若每个 workspace runtime 都写 `~/.qwen/settings.json` 和全局 `output-language.md`，还会出现 sibling runtime 竞争同一文件、部分 session 保持旧 system instruction 的问题。

## 当前实现方案

当前 diff 仅在 settings persistence 可用时条件广告 `user_language_sync` 并注册 non-strict mutation route `POST /language`。body 要求受支持的 `language`，可选 `syncOutputLanguage:boolean` 和已校验 client ID。daemon 是唯一持久化写者：先写 user `general.language`；同步输出语言时再写全局 `output-language.md` 与 user `general.outputLanguage`。任一步失败返回 `500 persist_error` 并跳过后续步骤，但不回滚此前已成功的写入。

持久化后 daemon best-effort 切换自身 i18n，再把 private `qwen/control/user/language` fan-out 到所有 trusted 且有 live ACP channel 的 runtime。child 只从磁盘 reload user settings，不重复写文件；`syncOutputLanguage:true` 时才刷新每个 local session 的 hierarchical memory 与 system instruction。项目绑定的 output-language 路径不改，继续覆盖全局值。没有 live channel 按 skipped success 处理；runtime/session refresh failure 只计入响应，不回滚用户设置。最后向所有 registry（含 untrusted）发布 `language_changed` workspace event，并透传可选 originator client ID。

## 关键代码路径

- `packages/cli/src/serve/routes/user-language.ts`：校验、唯一持久化写入、daemon i18n、trusted runtime fan-out、事件与 response summary。
- `packages/cli/src/serve/capabilities.ts` / `server.ts`：`user_language_sync` 条件广告与 route dependency 接线。
- `packages/acp-bridge/src/bridge.ts` / `bridgeTypes.ts` / `status.ts`：sessionless private control method 与结果类型。
- `packages/cli/src/acp-integration/acpAgent.ts`：child reload user settings，并按 sync flag 刷新 local sessions。
- `packages/sdk-typescript/src/daemon/DaemonClient.ts` / `types.ts`：`setUserLanguage()` 和 additive refresh summary。

## 边界与风险

- 当前仍为 open；`POST /language`、`user_language_sync` 和 SDK method 不能视为 `main` 已可用。
- 这是 process-global user setting，不接受 workspace selector；project-level output-language override 有意保留。
- 持久化成功后的 runtime fan-out 是 best-effort，调用方必须检查 `refresh.failed`；`persist_error` 也可能发生在先前 user setting 或全局文件已经写入之后。
