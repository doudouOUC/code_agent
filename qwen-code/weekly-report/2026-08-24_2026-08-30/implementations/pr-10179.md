## 解决了什么问题

#9978 已合入 projectless task 的 internal `StandaloneSessionService`，但外部 daemon caller 仍没有公开 API，也不能通过 capability 判断完整 runtime 是否可用。归档、导出、修复和删除还需要精确 owner 校验与 crash-safe cleanup，不能复用 workspace/primary fallback。

## 最终实现方案

最终实现只在 standalone service 和完整 dependency graph 安装时广告 `standalone_sessions_v1`，并增加 `/standalone/sessions` 路由族：prompt-less caller UUID create、分页/过滤 list、精确 get、load/resume、managed-directory repair、rename、export、archive/unarchive 和 delete。请求 schema 严格，mutation 经过 auth，不提供 workspace selector。

所有 public route 都要求 top-level exact standalone owner；child、Live、project/worktree、ambiguous/unreadable/foreign/identity mismatch 均 fail closed，不能 fallback primary。create 的响应断开只 detach response client，已 commit session 继续存在；list 断开则 abort scan。

delete 使用私有 `StandaloneDeletionJournal`。transcript unlink 是 commit point：此前 crash recovery 还原 staged directory，此后 recovery 继续删除 sidecar、attachment 和目录，并通过 `fileCleanupPending` 暴露待清理状态。internal LiveTask child restore 保持原行为。

## 关键代码路径

- `packages/cli/src/serve/routes/standalone-sessions.ts`：public route family、schema、auth、disconnect 和错误映射。
- `packages/cli/src/serve/conversations/standalone-session-service.ts`：精确 owner、list/load/repair/archive/export/rename/delete lifecycle。
- `packages/cli/src/serve/conversations/standalone-deletion-journal.ts`：delete commit point 与 crash recovery。
- `packages/cli/src/serve/capabilities.ts` / server wiring：`standalone_sessions_v1` 条件广告与完整 runtime 安装。

## 边界与风险

- SDK、WebUI/WebShell、worktree、scheduled-task 集成和跨 runtime move/fork 不在范围内。
- deletion journal 降低 crash 窗口，但 filesystem cleanup 仍可能 pending；调用方必须处理 `fileCleanupPending`，不能把 HTTP 成功等同于所有文件已删除。
