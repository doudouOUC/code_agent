> 规模：+4,921 / -449，36 个文件

## 解决了什么问题

Channel 的 user/chat route 过去只保留一个选中 session。同一发送者在同一聊天中并行处理 review、feature 等多个任务时，无法安全切换并恢复各自 transcript；若只替换 route，还会在排队 turn、慢媒体准备、pending permission 或 daemon 重启时把消息交给错误 session。

## 最终实现方案

最终实现新增 opt-in `multiSession:true`，并强制 `sessionScope:'user'`、daemon-managed worker 和兼容配置。`NamedSessionManager` 以 channel instance、chat/thread 与 sender 生成 owner key，在有界原子 JSON catalog 中保存最多 8 个命名任务和精确 daemon session ID；`/sessions`、`/session current|new|use|close` 只返回任务名与隔离状态，不泄露底层 ID。

入站消息在异步媒体准备前绑定接收时选中的 session 与 generation，并登记 queued-turn ownership；active prompt、queued turn、permission、cancel wind-down 或 bridge active-work 均使 task mutation fail closed。恢复只按 catalog 中的精确 ID load，失败不静默新建替代 session。旧 route 仍作为当前选择兼容指针，未启用 `multiSession` 时行为不变；standalone startup、非 user scope、history backfill、webhook 和 Channel loop 配置会被拒绝。

## 关键代码路径

- `packages/channels/base/src/named-session-manager.ts`：owner key、catalog 原子持久化、命名校验、create/use/close/reopen 与精确恢复。
- `packages/channels/base/src/ChannelBase.ts`：命令面、turn binding、busy 判定、异步入站归属和兼容路由。
- `packages/channels/base/src/SessionRouter.ts`：selected session 指针与精确 session route 协作。
- `packages/cli/src/commands/channel/config-utils.ts`：`multiSession` 配置组合的 fail-closed 校验。

## 边界与风险

- 当前只支持 shared-workspace 命名任务；worktree、非选中 task cancel、主动投递、webhook、loop 和 history backfill 仍在范围外。
- JSON catalog 提供单 daemon owner 下的有界持久化，不是跨 daemon 分布式协调或消息 exactly-once journal。
