# PR #10294 当前实现观察：standalone session TypeScript SDK

> 规模：+1,924 / -10，10 个文件

## 解决了什么问题

#10179 已合入 standalone REST lifecycle，但 TypeScript SDK caller 仍需手写私有 route、重复 response validation，并可能在 create timeout 或 malformed response 后盲目重试，造成两个 session。普通 workspace reattach 也不能安全替代 standalone exact-owner restore。

## 当前实现方案

当前 diff 在 `DaemonClient` 增加 capability-gated create/list/page/get/load/resume/repair-directory/rename/export/archive/unarchive/delete 方法，并为每类 response 提供严格 runtime parser。请求不会携带 `cwd` 或 `workspaceCwd`，所有 session ID 规范化后走 standalone route。

create 在 dispatch 前使用 caller UUID 或 `globalThis.crypto.randomUUID()`。结构化 outcome-unknown、transport failure、timeout 或 malformed success 只触发一次 exact get：返回 existing/creating/not-found/unavailable recovery context，再抛 `DaemonStandaloneCreationOutcomeUnknownError`，绝不自动重试 create。`DaemonSessionClient` 保存显式 `standalone` 或 `workspace` restore strategy，断线重附着不会跨 owner surface。browser bundle budget 由 208 KiB 调整为 215 KiB。

## 关键代码路径

- `packages/sdk-typescript/src/daemon/standalone-sessions.ts`：公开类型、runtime validators、protocol 与 outcome-unknown errors。
- `packages/sdk-typescript/src/daemon/DaemonClient.ts`：standalone lifecycle methods、capability gate、exact recovery。
- `packages/sdk-typescript/src/daemon/DaemonSessionClient.ts`：standalone create/load/resume factory 与 reattach strategy。
- `packages/sdk-typescript/test/unit/DaemonClientStandalone.test.ts`：route shape、malformed response、timeout/recovery 和兼容性矩阵。
