## 解决了什么问题

#10288 合入 detached supervisor 后仍有一组边界加固项：非法 timeout 可能被平台 timer 强制转换，staged-input 路径可能被 Node 当参数解析，loader 环境可影响内部 supervisor，Windows taskkill fallback 与 parent 漂移，deadline 最后一个 polling interval 的自然 exit 0/124 也可能被误报为 timeout。

## 关闭前方案

关闭前 diff 在统一 dispatch boundary 拒绝非正数或非有限 timeout，并在 eval source 后增加 `--`。Parent 从 supervisor 环境移除 `NODE_OPTIONS`、`LD_PRELOAD`、`DYLD_INSERT_LIBRARIES`，把原值作为 inert JSON argv 传入，仅在启动真实 hook 时恢复；Windows 终止常量和 taskkill 成功/失败 fallback 与 parent-side 行为对齐。

到达 deadline 时先让当前 event-loop turn 已送达的 child close 更新状态；若 root/group 已自然结束则保留真实 exit 0 或 124，只有实际发出 process-tree termination 才报告 timeout。方案还补 parent-side staged-input cleanup 与 Windows-only real-process coverage，但 PR 已关闭且没有进入 `main`。
