# PR #10268 最终实现：取消超时的 daemon session 初始化

> PR: [fix(daemon): Cancel timed-out session initialization](https://github.com/QwenLM/qwen-code/pull/10268)
> 状态：merged（2026-08-29）；以下描述按最终 head `93c909cede` 与当前 `main` 复核。
> 规模：+1,949 / -242，22 个文件

## 解决了什么问题

bridge 的 `newSession` timeout 过去只拒绝外层 Promise，child 内部配置加载、Gemini startup 和 `SessionStart` hook 仍可继续。调用方收到 `init_timeout` 后，迟到工作可能发布一个 bridge 未登记的 session，并留下 hook 进程树；直接杀共享 ACP channel 又会误伤健康 sibling sessions。

## 最终实现方案

最终由受管 bridge 在 `newSession` 私有 metadata 中传递绝对初始化 deadline。ACP child 将其转换为 AbortSignal，贯穿 Config、Gemini client 和 `SessionStart` hook；deadline 后在 session 发布前返回稳定 timeout kind，并依赖 tree-aware hook cancellation 回收进程。

兼容旧 child 时，bridge 保留原始 ACP request、requested-ID fence 和 admission token。迟到成功会按精确 session ID 执行一次 close；close 拒绝或请求在额外一个 init budget 后仍未 settle 时，只隔离该 channel 的 fresh session admission，并返回新增的 `acp_channel_unavailable` reason，既有 sibling session 继续可用。空 channel 可直接回收，shutdown 会等待有界 settlement。

## 关键代码路径

- `packages/acp-bridge/src/bridge.ts`：deadline dispatch、public timeout、迟到 settlement/close、ID fence、fresh-admission quarantine。
- `packages/cli/src/acp-integration/acpAgent.ts`：解析可信 deadline、建立 cancellation signal、发布前拒绝超时 session。
- `packages/core/src/config/config.ts` 与 `packages/core/src/core/client.ts`：把 AbortSignal 传播到配置、client 初始化和 SessionStart hook。
- `packages/acp-bridge/src/bridgeErrors.ts`：稳定 timeout 与 quarantine reason 映射。

## 边界与风险

- 只覆盖 new-session 初始化；load/resume、prompt 与 endpoint-specific deadline 不在范围内。
- 旧 child 无法被请求级取消，依赖迟到 close 或 fresh-admission quarantine 收敛不确定状态。
