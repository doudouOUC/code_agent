## 解决了什么问题

standalone daemon routes、capability、TypeScript SDK 与 #10418 显式 provider context 已合入，但 WebShell 缺少 projectless chat 的可见入口、独立 Recents、生命周期操作和 context-aware 深链。若 UI 继续根据空 cwd 猜测目标，还可能把 standalone 创建失败静默回退到 primary workspace，让项目状态、附件、draft/history 或 split-session ingress 穿透到非 workspace 会话。

## 最终实现方案

最终引入显式 `NewSessionIntent`。Home/global New Task 在 `standalone_sessions_v1` capability 存在时创建 standalone session；capability 尚在加载时等待、加载失败时 fail closed，只有加载完成且明确缺少 capability 才回退 trusted primary workspace。项目、Goals、Git、Scheduled Tasks 等调用方传 exact workspace cwd，当前会话继承已经附着的显式 context，Live 的 New Task 继续使用既有 `startLive('new')`。Standalone create 只发送 product context 与 approval，不携带 workspace source、worktree 或 branch。

入口加载在 `WorkspaceSessionProvider` mount 前先执行 standalone gate：拒绝 standalone/Live 与 workspace selector 冲突，等待 capability，按 exact ID 查询 summary，对 creating 状态做可取消的有界 poll，对 archived summary 先 unarchive，再挂载 `{kind:'standalone'}` provider。查询、创建和恢复都用 session owner/generation guard，旧请求的迟到结果不能覆盖新 context；create outcome unknown 保留原意图并要求 exact recovery，不盲目重试。

新 `StandaloneRecents` 分页维护 active/archived lanes，过滤 child session，并按 exact ID 执行 rename、export、archive、unarchive 和 delete。批量响应按每个 ID 的 partial-success envelope 展示，删除成功但附件清理未完成时保留 `fileCleanupPending` 提示。URL 使用显式 `?context=standalone|live`；非 workspace context 不保留 workspace query 参数。

App/provider/sidebar/composer 同步按 effective product context 做隔离。Standalone/Live 不展示 workspace selector、Git、Goals、Scheduled Tasks、项目设置/provider/skills、文件上传、Web Terminal、split view 和 workspace action refs，也不启动相关后台 effect 或项目 slash command；Shell 和普通 session 工具仍可用。Composer 用独立 scope key 隔离 draft/history，非 workspace 不读取 legacy unscoped history fallback，context 切换会丢弃 held attachments，并在 ingestion 与 submit 边界再次校验。URL、sessionStorage、controlled split IDs 先逐项精确排除 standalone owner，能力未就绪或 owner 查询不确定时 fail closed。

daemon session action 还把 standalone `working_directory_missing` 与 `working_directory_compromised` 投影为 typed state。前者可 repair 后 reload，后者只给安全终端指引；recreated directory 会显示警告。Mock daemon 和 public root 接线同步补齐这些状态与 context propagation。

## 关键代码路径

- `packages/web-shell/client/App.tsx`：显式新会话意图、global fallback、入口接线、surface gating、split sanitization 与 typed recovery。
- `packages/web-shell/client/components/WorkspaceSessionProvider.tsx`：pre-provider capability/exact-owner gate、creating poll、archived unarchive 与 standalone provider mount。
- `packages/web-shell/client/components/sidebar/StandaloneRecents.tsx`：active/archived catalog、分页和逐 ID 生命周期操作。
- `packages/web-shell/client/components/sidebar/WebShellSidebar.tsx`：standalone Recents、workspace action 与非 workspace navigation 边界。
- `packages/web-shell/client/main.tsx`、`packages/web-shell/client/index.tsx` 与 session routing/preparation utilities：public product context、deep link、URL 和 controlled ingress 分类。
- `packages/web-shell/client/hooks/useComposerCore.ts`：standalone/Live draft/history scope、附件与 workspace action refs 的提交边界。
- `packages/web-shell/client/daemon/session/actions.ts`：standalone working-directory typed errors。
- `packages/web-shell/client/e2e/web-shell.standalone.spec.ts` 与相关 App/provider/sidebar/mock-daemon tests：入口、恢复、隔离和生命周期覆盖。
