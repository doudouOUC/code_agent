## 解决了什么问题

standalone daemon routes、capability、TypeScript SDK 与 #10418 显式 provider context 已合入，但用户仍看不到 standalone chat 入口、Recents catalog、生命周期操作或恢复状态。若 UI 继续从空 cwd 猜测目标，还会在失败时错误回退 primary workspace，并让项目控件出现在 standalone/Live 会话中。

## 当前实现方案

当前 docs-only 计划建立入口路由表：Home/global New Chat 在 daemon 广告 `standalone_sessions_v1` 时设置 pending standalone context，项目/Goals/Git 入口保持 exact workspace，当前会话 New Chat 继承显式 context，Live 的新文本会话映射为 standalone 是待 reviewer 确认的开放决策。Capability 缺失才允许 legacy primary fallback；capability 已存在但 create 失败时必须保留 standalone intent 并展示结构化错误。

计划新增独立 standalone Recents lane，消费分页 list 与 rename/export/archive/unarchive/delete；深链使用 `/session/<id>?context=standalone`，不猜 primary。Standalone/Live 隐藏 workspace selector、Git、项目设置、文件浏览、pin/group 和两类 upload，并呈现 recreated directory、repair offer、creation outcome unknown 与 `fileCleanupPending`。本 PR 只有计划文档，没有修改 WebShell/WebUI 运行时代码。
