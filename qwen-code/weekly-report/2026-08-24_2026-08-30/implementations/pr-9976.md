# PR #9976 最终实现：ACP channel 传输活性探测

> PR: [feat(daemon): Add ACP channel transport liveness](https://github.com/QwenLM/qwen-code/pull/9976)
> 状态：已于 2026-08-25 合入 `main`。
> 规模：+851 / -1，9 个文件

## 解决了什么问题

daemon 已能处理 ACP child 进程退出和显式 transport failure，但无法识别“进程和 stdio pipe 仍存在、child 事件循环或 ACP request dispatch 已停止响应”的半失活状态。一个 channel 会承载多个 session，若没有 channel 级信号，这些 session 会无限驻留；单个 session 的 activeWork 静默又不能证明共享 transport 已死，否则会误杀同 channel 的 sibling sessions。

## 最终实现方案

实现增加 opt-in `CHANNEL_LIVENESS_VERSION = 1` 协商。ACP child 只在 initialize 中确认支持后处理无状态 ping，并原样返回 `{v, nonce}`；未确认能力的 child 完全保留旧行为。daemon 在每次合法响应后等待 15 秒发起下一次探测，每次 request 的 deadline 为 10 秒；第一次按时 timeout 立即重试，只有连续两次按时 timeout 才生成 `acp_channel_liveness_timeout`。

`startChannelLivenessMonitor()` 使用 `performance.now()` 判断 parent timer 是否比预期晚超过 1 秒。宿主休眠、daemon event-loop stall 等 local delay 会清零 timeout streak 并重新计时，不把 parent 自身延迟归咎于 child；旧 probe 的迟到响应也不能重置新 probe。返回版本/nonce 不符或 request rejection 则立即归为 `acp_channel_liveness_protocol_error`。

终止性失败复用 bridge 已有 transport-failure 路径：停止该 channel 新准入、写入有界 failure code、终止 child，并让 channel exit 清理其上所有 session。新 session 在旧 child reap 后由新 channel 承载；协议不包含 session ID、workspace path，也不新增 public Serve capability 或配置项。

## 关键代码路径

- `packages/acp-bridge/src/channel-liveness.ts`：固定 interval/timeout/threshold、nonce 校验、单调时钟 local-delay 分类和 terminal failure。
- `packages/acp-bridge/src/bridge.ts`：在协商成功的 daemon-owned channel 上启动/停止 monitor，并把失败接入既有 transport teardown。
- `packages/acp-bridge/src/bridgeTypes.ts` / `status.ts`：定义 private liveness version、typed failure code 与状态投影。
- `packages/cli/src/acp-integration/acpAgent.ts`：child initialize 确认能力并实现无 session 状态的 ping 回显。
- `packages/acp-bridge/src/channel-liveness.test.ts` / `bridge.test.ts`：覆盖 healthy、双 timeout、parent delay、stale response、invalid/rejected response 和共享 session teardown。

## 边界与风险

- terminal 判定会清理共享 channel 的全部 session，因此只能在 private capability 协商后启动，并要求两次连续且按时的 timeout。
- 该机制证明 transport request/response 活性，不证明 Agent 有逻辑进展，也不替代 activeWork、runtime recovery 或 generation draining。
- interval、timeout 和 threshold 当前是固定内部策略；未协商 child、public/standalone ACP transport 不自动获得该行为。
