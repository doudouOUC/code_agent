## 解决了什么问题

delete、archive、unarchive 或 conflict repair 已提交 transcript unlink/move 后，runtime generation 可能关闭。继续使用 generation fence 会永久遗留 worktree、PR、prompt ledger、file history 和 organization sidecars；取消所有 fence 又可能删除 replacement writer 新建的数据。#10286 未覆盖已合入的 standalone lifecycle，因此需要按 #10179 基线重新接线。

## 当前实现方案

当前 diff 保留主 transcript mutation 前的 snapshot、runtime-generation 与 `assertOwnedAndUnchanged()` 校验；commit 后改用 `SessionWriterLease.assertCleanupOwned()`。lease acquisition 时通过 `O_NOFOLLOW` 打开 lock，核对 descriptor 与 path 的 dev/inode、普通文件、active owner 和 byte-for-byte raw record；每个破坏性 sidecar/organization step 前重新验证，lock 缺失、替换、symlink、malformed 或 owner 变化均停止清理并返回 writer error。

普通 daemon lifecycle 直接传 cleanup fence；standalone archive/unarchive/delete 和 committed deletion-journal recovery 还组合 selected-runtime assertion，因此仍不允许跨 workspace fallback。writer ownership error 不会被 sidecar best-effort warning 吞掉；已经提交的 transcript 操作不回滚。

## 关键代码路径

- `packages/core/src/services/session-writer-lease.ts`：lock descriptor/path identity 与 `assertCleanupOwned()`。
- `packages/core/src/services/sessionService.ts`：remove/archive/unarchive/conflict repair 的逐步 cleanup fence 和错误传播。
- `packages/cli/src/serve/server/session-archive.ts`：普通 daemon lifecycle 的 pre/post-commit fence 分层。
- `packages/cli/src/serve/conversations/standalone-session-service.ts`：standalone lifecycle 与 deletion recovery 的 runtime+lease 组合校验。
