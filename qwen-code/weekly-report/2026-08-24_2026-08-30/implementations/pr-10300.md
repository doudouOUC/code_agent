## 解决了什么问题

delete、archive、unarchive 或 conflict repair 已提交 transcript unlink/move 后，runtime generation 可能关闭。继续使用 generation fence 会永久遗留 worktree、PR、prompt ledger、file history 和 organization sidecars；取消所有 fence 又可能删除 replacement writer 新建的数据。#10286 未覆盖已合入的 standalone lifecycle，因此需要按 #10179 基线重新接线。

## 最终实现

最终实现保留主 transcript mutation 前的 snapshot、runtime-generation 与 `assertOwnedAndUnchanged()` 校验；commit 后改用 `SessionWriterLease.assertCleanupOwned()`。lease acquisition 时通过 `O_NOFOLLOW|O_NONBLOCK` 打开 lock，核对普通文件、可验证 inode、descriptor 与 path 的 dev/inode、active owner ID、byte-for-byte raw record，以及 acquisition inode；每个破坏性 sidecar/organization step 前重新验证，lock 缺失、替换、symlink、malformed 或 owner 变化均停止清理并返回 writer error。

普通 daemon lifecycle 直接传 cleanup fence；standalone archive/unarchive/delete 和 committed deletion-journal recovery 还组合 selected-runtime assertion，因此仍不允许跨 workspace fallback。already-active/already-archived 的 archive/unarchive 路径也取得 writer/maintenance lease，以便重试时对账 pending sidecars。writer ownership error 不会被 sidecar best-effort warning 吞掉；已经提交的 transcript 操作不回滚。

## 关键代码路径

- `packages/core/src/services/session-writer-lease.ts`：lock descriptor/path identity 与 `assertCleanupOwned()`。
- `packages/core/src/services/sessionService.ts`：remove/archive/unarchive/conflict repair 的逐步 cleanup fence 和错误传播。
- `packages/cli/src/serve/server/session-archive.ts`：普通 daemon lifecycle 的 pre/post-commit fence 分层。
- `packages/cli/src/serve/conversations/standalone-session-service.ts`：standalone lifecycle 与 deletion recovery 的 runtime+lease 组合校验。

## 边界与风险

- 主 transcript mutation 已提交后若 ownership 丢失，会返回 per-session error 并保留辅助残留，而不是冒险跨 owner 清理。batch item 因此可能出现在 `errors` 中但 transcript 状态已改变，调用方应重试权威 lifecycle 操作完成对账。
- scheduled-task、attachment、最终 route response、mixed-case lookup 与 parent-child cascade 未改变。
