# PR #10288 最终实现：保留 fire-and-forget hooks

> PR: [fix(core): Preserve fire-and-forget hooks after exit](https://github.com/QwenLM/qwen-code/pull/10288)
> 状态：merged（2026-08-29）；以下描述按最终 head `73d978c001` 与当前 `main` 复核。
> 规模：+1,170 / -64，5 个文件

## 解决了什么问题

#10100 的父进程退出清理允许 `MessageDisplay` hook 继续执行，但 hook 仍继承 Qwen-owned stdout/stderr pipe；父进程退出后再写可能触发 broken pipe。仅把输出改成独立 sink 也不足以保住排队中的 stdin、由父进程持有的 timeout，以及根进程先退出后的后代监督。`StopFailure` 和 `SessionDelete` 具有相同的忽略输出 fire-and-forget 契约。

## 最终实现方案

最终把 `MessageDisplay`、`StopFailure` 和 `SessionDelete` 归为 output-ignored fire-and-forget events。Qwen 先把完整输入写入 mode-0600 临时文件，再启动 detached、unref 且标准流独立的 Node supervisor；supervisor 启动真实 hook、持有 timeout，并在 POSIX 上持续监督 owned process group，即使 hook 根进程早于后代退出也不提前释放。

普通 `async:true` hook 仍捕获输出并保持 process-scoped。显式 AbortSignal 经 supervisor 转发并继续回收完整进程树；用户 `NODE_OPTIONS` 只对内部 supervisor 清除，启动真实 hook 时恢复。正常完成和同步 supervisor spawn 失败都会删除 staged input。

## 关键代码路径

- `packages/core/src/hooks/hookRunner.ts`：fire-and-forget event 分类、mode-0600 input staging、detached supervisor 与显式取消转发。
- `packages/core/src/hooks/hookRunner.test.ts`：事件分类、临时文件清理、普通 async 回收和显式取消单测。

## 边界与风险

- 三个事件放弃 stdout/stderr capture 并增加一个短生命周期 supervisor/临时文件是有意契约，不适用于普通 async hook。
- 外部 SIGKILL 仍可能留下 staged input 或独立 hook group；Windows 父退出后的后代回收仍依赖 Job Object/后代追踪支持。
