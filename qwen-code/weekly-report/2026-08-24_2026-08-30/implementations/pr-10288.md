> 规模：+185 / -78，5 个文件

## 解决了什么问题

#10100 的父进程退出清理允许 `MessageDisplay` hook 继续执行，但 hook 仍继承 Qwen-owned stdout/stderr pipe；父进程退出后再写可能触发 broken pipe。`StopFailure` 和 `SessionDelete` 具有相同的忽略输出 fire-and-forget 契约，却没有完整采用这条生命周期边界。

## 当前实现方案

当前 diff 把 `MessageDisplay`、`StopFailure` 和 `SessionDelete` 归为 output-ignored fire-and-forget events，spawn 时把 stdout/stderr 接到 parent-independent sink，不再进入 HookRunner 的内存输出 registry，也不随普通父进程退出清理。普通 `async:true` hook 仍捕获输出并保持 process-scoped；显式 timeout 或 AbortSignal 仍对完整 process group 执行 TERM→KILL。

## 关键代码路径

- `packages/core/src/hooks/hookRunner.ts`：fire-and-forget event 分类、独立 output sink 和既有显式取消语义。
- `packages/core/src/hooks/hookRunner.test.ts`：事件分类、普通 async 回收和显式取消单测。
- `packages/core/src/hooks/hook-runner.process.test.ts`：父进程退出后延迟 stdout/stderr 写入与完成标记真实进程测试。

## 边界与风险

- 当前仍为 open；三个事件放弃 stdout/stderr capture 是有意契约，不适用于普通 async hook。
- Windows 父退出后的后代回收仍依赖平台后续支持；显式 cancellation 行为保持不变。
