# PR #9933 最终实现：默认关闭 ACP 权限响应超时

> PR: [fix(acp-bridge): Disable permission timeout by default](https://github.com/QwenLM/qwen-code/pull/9933)
> 状态：merged，2026-08-24 合入 `main`。
> 规模：+179 / -58，15 个文件

## 解决了什么问题

ACP bridge 的普通工具权限与 `ask_user_question` 默认在 5 分钟后自动取消。这个默认 deadline 对跨时区审批、长时间离席、恢复后的 HITL 和需要长期等待人类决定的 daemon 会话并不安全：用户没有显式配置 timeout，也会得到一次取消并停止当前 turn。CLI help、settings schema、consensus breadcrumb 和设计文档还把 5 分钟写成必然存在，容易让 operator 误判等待语义。

## 最终实现方案

共享 `DEFAULT_PERMISSION_TIMEOUT_MS` 从 300,000 改为 0。operator 省略配置或显式传 0 时，bridge 不安装 permission/AUQ timer，请求会等待投票/回答、voter/session cancellation、channel teardown 或 daemon shutdown；正整数配置仍进入同一 normalization/clamp，并同时约束普通权限与 AUQ。非法非有限、负数、非整数继续在启动期拒绝，超大正数继续 clamp 到 Node timer 上限。

empty-voter 和 split-vote stderr breadcrumb 改为说明请求会等待 cancellation 或可选的 configured timeout，不再承诺默认 timeout。CLI option、Serve/Bridge types、settings schema、设计文档和测试同步更新。restore AUQ 的 no-client 路径仍不能制造无人可回答的无限等待，相关内部判断只改注释和默认口径；wire、permission policy、restore flag 与 prompt deadline 都不变。

## 关键代码路径

- `packages/acp-bridge/src/bridgeTypes.ts` / `bridge.ts`：默认 timeout 为 0，只有正数才安装 timer。
- `packages/acp-bridge/src/permissionMediator.ts`：empty-voter/split-vote breadcrumb 反映 optional timeout。
- `packages/cli/src/commands/serve.ts` / `serve/types.ts` / `runQwenServe.ts`：CLI help、默认值和启动校验。
- `packages/cli/src/config/settingsSchema.ts`：配置说明与默认值同步。
- ACP bridge/CLI tests：覆盖 omitted/0 无限等待、显式正数 timeout、取消/关闭 settle 与 AUQ 共用默认。

## 边界与风险

- 这是有意的默认行为变更；需要保留旧 5 分钟语义的部署应显式设置 `--permission-response-timeout-ms 300000` 或对应配置。
- timeout disabled 不等于请求无法结束；用户/agent cancellation、session/channel teardown 和 daemon shutdown仍会 settle。
- 该配置不是 public capability，客户端仍不能仅靠 `/capabilities` 推断 operator 的实际 timeout。
- 本 PR 不改变 prompt deadline、permission mediation 策略、AUQ restore 是否启用或任何 wire schema。
