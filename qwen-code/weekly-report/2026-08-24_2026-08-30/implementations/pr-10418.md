## 解决了什么问题

WebUI daemon provider 过去主要从 `workspaceCwd` 推断目标，无法明确表达 standalone 与 Live 会话。继续复用 cwd 会把内部 Conversations runtime 误当产品 workspace，或在目标不明确时回退 primary；切换期间还可能初始化不属于非 workspace 会话的 provider、skills、ACP preheat 与 Git 状态。

## 最终实现方案

最终新增 `DaemonProductSessionContext = workspace|standalone|live`，同时保留 legacy `workspaceCwd` 兼容入口；显式非 workspace context 与 legacy cwd 同时出现时直接拒绝。Workspace 仍走原 route，standalone 通过 #10294 的 capability-gated SDK create/load/resume，create 不套通用 action timeout、不自动重试，并把 working-directory 与 outcome-unknown recovery 保存在 typed connection state。

Live 恢复要求 daemon 广告 `multi_workspace_sessions`，并在发请求前解析唯一 trusted、non-primary、ID/cwd 均不重复的 Live runtime。context key、restore matching、generation 与 supersession guard 共同保证快速跨 context 切换时只有胜出目标能发布 transcript、warning、cwd 或 recovery。Standalone/Live 不启动 workspace providers、skills、ACP preheat、Git status 或 workspace invalidation；本 PR 只落 provider/routing boundary，没有新增可见 WebShell 入口。

## 关键代码路径

- `packages/webui/src/daemon/session/session-context.ts`：context 解析、冲突检查、Live runtime 精确选择与 standalone typed state 映射。
- `packages/webui/src/daemon/session/actions.ts`：context-aware create/load/resume、standalone timeout/recovery 和切换错误发布。
- `packages/webui/src/daemon/session/DaemonSessionProvider.tsx`：跨 context 生命周期、supersession fencing 与 workspace-only provider gating。
- `packages/webui/src/daemon/session/types.ts`：产品 context、standalone connection state 与 public action/props surface。

## 边界与风险

- 现有只传 `workspaceCwd` 的 caller 保持兼容；显式 standalone/Live 与 cwd 冲突会 fail closed。
- Live 只支持精确恢复，不支持 create；standalone 上传、可见入口、Recents 和生命周期 UI 不在本 PR。
- standalone create outcome unknown 不自动重试，调用方必须展示并消费 recovery state。
