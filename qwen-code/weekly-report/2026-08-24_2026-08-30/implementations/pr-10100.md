## 解决了什么问题

command hook 通过 shell 启动命令时，超时、取消或父进程退出只终止直接 child，孙进程可能继续运行并持有 stdout/stderr pipe。结果是 hook 已决定失败却仍等待 close，或者后台进程跨 turn、跨 CLI 生命周期残留。`ChildProcess.killed` 只表示 signal 已发送，也不能证明 root 或后代真的退出。

## 当前实现方案

当前 diff 在 POSIX 把每个 command hook child 作为 detached process-group leader 启动。取消或超时后先向整个 group 发送 SIGTERM，最多轮询 2 秒；仍存活则发送 SIGKILL。root child 提前 close 不会取消 escalation，完成路径最多再等 1 秒让 child close 和 stdio drain，超时后主动 destroy stream，保证 hook 自身有界返回。

HookRunner 同时登记活跃 process group，并为 SIGHUP、SIGINT、SIGQUIT、SIGTERM 和父进程退出安装同步兜底清理。Windows 使用绝对 `%SystemRoot%\System32\taskkill.exe /f /t /pid`，异步 taskkill 最多等待 2 秒，失败时回退直接 child kill。清理函数幂等，多个 timeout/cancel/signal 路径不会重复改变结果。

## 边界与风险

- PR 仍为 open，signal 时序、等待上限和平台 fallback 可能继续变化。
- POSIX 依赖独立 process group；主动 setsid/逃逸到其他 group 的后代不在回收保证内。
- Windows taskkill 与真实 Console/Job Object 行为尚未实机验证。
