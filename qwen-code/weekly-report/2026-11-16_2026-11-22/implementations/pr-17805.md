## 解决了什么问题

本 PR 提案时，Phase 1/2 拒绝带未来 wake 输入或活后台观测的 Session 挂起：时钟/输出观察在 Harness，长延迟 loop 或安静 Monitor 仍支付常驻成本；原崩溃兜底不是及时的到期调度器。

## 最终实现方案

本PR最终仅英文/中文两个Markdown（678行），合入时为实现前提案；以下保留原提案，3a/3b的后续替代以本节末为准；不是 WakeDispatchJob 或 staging 运行时代码。3a 先行：在 head 提议 wake_due_at 提示而非按输入新表，接受输入时空安全地取最早到期，pending 但未知到期保守为0；proof 扩成前缀未完/立即到期/仅未来T/清空四态，按所读 revision 刷新，完整仅未来证明不入128槽缓存，避免挤掉长 journal 的部分证明。

提议有界、已知且到期扫描及单调 fence/claim；所有候选统一被动 recoverForWake，避免主动接管顺带执行未结算前台工具。transport 通知也先复核所有 pending 输入的到期事实；SQL 兜底继续作正确性地板。取消项只有有独立结算者或已证明结算才可移除，仍欠 writer 取消结果的输入需投递。放宽 pending wake 的挂起资格与 ready 前，要在 seal 时逐输入证明未尝试，控制面能从已提交记录冷态重导；水位相等不等于证明。

3b 是独立后续，不随3a交付：后台捕获从 fail-stop 改 buffer-and-redirect，经 Broker staging 保留原始观测字节/稳定身份，wake 后仍由唯一 Harness writer 发布资源并提交记录。须区分已接收/已持久位置、幂等重传和协调 drain-then-open，generation 围栏与持久 binding 授权跨 worker 重启有效；主动结算加 exited-pending-commit 桥接后台退出到 journal 终态。挂起 teardown 两条 drain 路径均改只探测，接受已核验后台 held，mount 成员资格只对同代逐 run hold 容忍，并阻止活后台 owner 被 MCP 回收。

原提案中的两个能力门是默认关闭的提议；先让消费者实际工作再放宽挂起准入，回滚先停新生产者、排空/交接后再停消费者。候选1秒周期、8候选、延迟收益及成本比例都需测量，不是本次已测结果。Phase 4 审批、外部存储后台工作、跨主机进程附着与压缩感知 proof 均不在交付范围。后续 #17869 以seal戳取代3a的wake_due_at/四态proof/独立dispatcher/冷态重导，#17908已默认关闭地实现；transport并未整体改成被动。#17912又以worker捕获、Broker租约拉取和先attach后drain取代原3b持久worker授权/三方交接提议，仍仅设计。原提案对应阶段当时无wake_due_at/staging表；后续状态以下段为准。

当前 main 后续 #17955 已统一 transport passive wake，#17953 已合入 Phase 3b worker 捕获/staging/attach 后 drain（默认关闭），#18110 补后续修正；Phase 4 另有 #18047 设计和 #18115 open 实现候选，不能作为 main 能力承诺。原设计、最终实现与独立验收分开。
