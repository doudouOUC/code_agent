> 规模：+392 / -225，10 个文件

## 解决了什么问题

Turn、lifecycle、action response、取消与 worktree 服务各自维护 active 集合和续租线程，重复代码的提交失败清理、失租标记与关闭行为容易分叉。

## 最终实现方案

抽 LeaseRenewalRunner，实例持 owner UUID、active 集合与 daemon scheduler。dispatchOnce 在任务结束或 executor.execute 抛错时移除 key；scopedKey 用 tenant/session/id 隔离。RenewalHandle 保 AtomicBoolean 失租状态，续租 false 或 RuntimeException 后置位且不恢复，close 只取消原 future；runner.close 关闭调度器。

保留 fixed-delay 与 fixed-rate 两种模式、原 leaseDuration/3 或 min(renewInterval,leaseDuration/3) 周期；Turn 成功续租后仍触发取消检查。各 coordinator 与 ChildWorkspaceService/SessionWorktreeService 改用 helper；ManagedArtifactConfiguration 另抽单线程 scheduler builder，保线程名前缀与 defaultCandidate=false。SQL claim/generation 和业务成功/重试决策留在调用方，不把进程内去重当分布式 exactly-once。
