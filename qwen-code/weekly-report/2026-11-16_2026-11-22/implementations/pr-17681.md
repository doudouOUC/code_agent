## 解决了什么问题

Java SDK 心跳确认 attachment 消失后，控制面独立缓存仍可能留旧引用；closing/cold-open/pool 等暂态等待若永远豁免预算，Turn 会无进展地无限重试，teardown 阻塞还可能丢失原错误码。

## 最终实现方案

HostedHarnessClient 新增 onAttachmentRetirement，只有其内部成功移除观察到的引用时通知，包括心跳 coded404、已证实代际变动和 teardown。单地址及 pool connector 注册 listener，在 tenant/Session/placement epoch 键下只清仍持同一对象的 attachment/MCP management cache，并同步原 recovery marker；迟到通知不清新引用。

hosted_session_open_busy 加入公共暂态冲突映射，与 closing 一起为 retryable 503；hosted_session_teardown_blocked 不属暂态。Turn 将 generation 与 pool waits 的无进展老化阈值统一为 max(1, 当前阶段预算)×4，consecutiveFailures 计跨等待家族，超过后按准入前/后阶段 unavailable 终止；teardown_blocked 直接保原码失败。Lifecycle 暂态等待保不收费但过预算公开 recovery_blocked，阻塞 teardown 保原码；message/child relay 对 open_busy 等待但不把 teardown_blocked 当无限等待。

## 边界与风险

- 老化是无 journal 进展的失败次数阈值，不是统一墙钟超时，也不保证 cold-open 公平性；通知不扩大任何 mutation 的重试范围。
