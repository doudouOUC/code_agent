## 解决了什么问题

仅按旧 Qwen 默认值接入 qwen4-max 会暴露错误 effort 档位、压低 thinking 输出预算，关闭 thinking 又可能发送超限 token；缓存保留与图片细节还缺完整配置透传。

## 最终实现方案

Alibaba Standard/Token Plan、QwenCloud Standard（其 Token Plan 复用目录）加入 qwen4-max，声明 1,000,000 context、image/video 和 low/high/xhigh，默认 high。ACP exact 与 qwen4-max 前缀回退用新 ladder，medium→high、max→xhigh；其他 qwen4 路由保既有档位/预算，不按全族覆盖。

qwen4-max 输出上限按代码声明为 262,144，免旧 64K auto ceiling，仍受剩余窗口限制；subscription thinking_budget 对应 4096/131072/262144。最终 wire 为 reasoning_effort:none 或 enable_thinking:false 时，max_tokens 及 provider output budget keys 限 131,072；不是按 endpoint 猜 thinking 状态。

DashScope 的 qwen4 wire model 在 cacheRetention=1h 时给原 breakpoint 加 ttl:1h，默认不发 ttl，未引入 Anthropic 的分块覆盖语义。generationConfig.imageDetail=low/high/auto 经 config/context 传到 inline/file image_url.detail；未设置不发送，保留 modality/PDF 例外规则。上述是本代码的请求构造契约，不是本次测得的模型服务配额、效果或价格。
