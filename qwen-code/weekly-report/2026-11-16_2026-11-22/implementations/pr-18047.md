## 解决了什么问题

持久 await_action 已可经 G3 冷恢复，但常驻 waiter 仍占 Harness 内存、控制面 SSE 与派发续租；若只切断流，协调器会当成故障立即重新加载。

## 最终实现方案

最终4文件均为双语设计及父设计互链，没有运行时或 DDL 改动。提出只允许根 Session、控制面派发且非 wake 输入、无 Hooks/MCP、无 command-step、完整可恢复 continuation 的唯一等待进入停靠；其他活工作继续阻止挂起。冻结清理 waiter/轮询/deadline 注册但不 resolve、不 abort，避免误写取消或过期终态；已冻结栈只可经冷恢复续跑。

提议随精确 journal revision 的 seal 写入 promptId/wakeAt/approvalRevision 证书，wakeAt 取 Action 到期与 Turn deadline 较早者。协调器在流结束后 flush，再按证书 CAS 保持 RUNNING、写 HARNESS_ACTION_PARKED/retry_after 并释放派发租约；决定、取消和模式切换在各自事务清停靠，到期复用原 dispatch sweep。恢复用 G3 审批 continuation driver，不是 G1 Runtime continue；保 Action/Prompt/批次身份。

第一增量不释放该 Turn 的 Runtime 成员资格，也不合并 Phase 3b 后台证书。默认 action-parking.enabled=false，设计要求 wake-dispatch 同开；10分钟默认审批过期通常早于带抖动的10分钟空闲挂起，所以收益不是默认部署已证实的节省。后续 #18115 已合入运行时，与本设计范围分开；默认关闭且要求 wake-dispatch，同步资格/冻结、证书及 park/unpark，真实验收仍待单独证据。
