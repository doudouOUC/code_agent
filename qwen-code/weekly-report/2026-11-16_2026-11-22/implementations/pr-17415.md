## 解决了什么问题

Kubernetes Runtime、Resident Workspace/CSI 与 EndpointSlice Harness discovery 混在日常 Java reactor 内，使 local/SSH/external/static 部署也承担专属配置、schema 字段和锁/验证路径维护成本。

## 最终实现方案

将专属 Java 类、测试与资源移到 packages/sdk-java/managed-kubernetes-archive；归档无顶层 reactor 接线，不是可直接加载的 SDK 插件。活动 reactor/server/verification 移除 runtime-kubernetes 依赖，Harness discovery 只保 static，去专属配置、内部管理入口和分发引用。原 PR 当时保留 deploy/distribution 的说明；后续 #18118 已将分发/脚本冷归档并删除 hosted-csi 私有 Session 链，managed-csi worker 协议族仍活跃，不等于恢复 Kubernetes 后端。

修改唯一 V1：删除 ma_session.runtime_request_key/is_csi_guard、CSI retirement/worker/pod work 字段与枚举、native_authorization_json、ma_storage_owner 的 CSI reservation 列等；共享业务表仍保留，该 PR 合入时46表；当前 main 后续增加 ma_pr_watch_binding 和 #17953 的 ma_runtime_stage 后为48表，不把该演进计入本 PR，表数不能证明旧 catalog 兼容。通用严格 JSON/JSONL、资源引用及 canonical 校验迁至 ManagedCheckpointHistory/RuntimeToolMeasurements，活动消费者不依赖归档 CsiNativeActivationProof。数字reader5是本PR合入时口径；当前main后续 #17864 已删除该协商，不新建升级链，旧开发 catalog 应按仓库策略重建。
