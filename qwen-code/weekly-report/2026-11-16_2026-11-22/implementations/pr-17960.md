## 解决了什么问题

设计把 receipt 派生 workspace id 误算成约46字符，VARCHAR64 会拒绝真实74字符与外部注册128字符；把所有重复 hash 当索引又会破坏生成身份、跨表引用或 tenant 定位 operation 的幂等。

## 最终实现方案

最终4文件全为双语设计/实施计划，无运行时或 DDL 改动。更正 workspace receipt 形态为 workspace-加64hex（74），storage created-/imported-为72/73；公开 workspace 契约最长128、storage 可打印 ASCII最长256，不收紧契约，提议分别保 VARBINARY128/256。其他身份类仍需逐列预算，不能一概换 VARCHAR。

调研逐项区分同表冗余唯一键、跨表 scope/资源引用、登记标记和生成 id。receipt_key 作为创建/导入身份根与目录重试依据保留；ma_read_lease 不存原始身份，不能直接删 hash。tenant 定位的 operation 派生不统一，提议 tenant_operation_id 生成列及(tenant,kind,id)唯一键保护特定 kinds，不依赖 target 唯一。这里是后续方案，不是当前新增生成列。

后续 #18019 只实施同行冗余 hash 的一个切片，未把全库转 VARCHAR，也未完成这些 operation/跨表原子簇。设计内宽度与测试要求是验收计划，不是本次独立基准或生产证据。
