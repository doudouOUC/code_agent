## 解决了什么问题

父设计对已挂起远期 head 反复重放，完整仅未来证明不入缓存仍不能消除部分证明占满128槽的饥饿；控制面每次读恢复视图都冷态重导 transcript 尝试也过重。

## 最终实现方案

本 PR 最终只合入两篇115行补充设计及父设计双语互链，原合入状态为实现前提案。它用持有完整前缀的 writer 在正常挂起 seal 时认证 wake 投影，提出一个 wake_seal_revision 列和可选 wake:{revision,pending,dueAt}；同一 head 锁/原 token-generation 围栏下精确匹配 revision，更新 is_wake_pending/wake_head_revision，并复用 wake_retry_at 存到期时间。

递增 generation 的新 acquire 清戳、把未来 retry 上限压回 NOW+30秒，拒载/普通 seal 不继承正常挂起证明。现有兜底在到期时对同 revision 的 stamped head 跳过 replay，沿原父 run 检查和 passive recoverForWake；无戳崩溃 head 保原独立证明。ready 可接受同 revision 戳，但仍要求 seal、activation released/当前投影及无其他义务。

取代 wake_due_at、提交路径提示、四态 proof、独立 WakeDispatchJob、仅未来不入缓存和读路径冷态重导，不改后台3b。transport 对 stamped 且未来/无pending 的通知返回 NOT_DUE；到期仍沿现有 activateForWake，不能按父设计写成 transport 已改被动。后续 #17908 已实现此切片并把附录标为 accepted/实现中；本 PR 自身仍是4个 Markdown 的设计交付。

当前 main 后续 #17954 抽出 wakeDispatchOwnsInput 并复用 stamp/recovery 断言到 MySQL；#17955 已把 transport load 改为 recoverForWake。上文到期仍 active 是原 PR 的历史范围，不再代表当前 transport 行为。#17953 的3b staging/后台 seal 已默认关闭地合入，并有 #18110 后续修正；Phase 4 的 #18115 已合入默认关闭的 Action parking，不能视为部署或真实验收完成。
