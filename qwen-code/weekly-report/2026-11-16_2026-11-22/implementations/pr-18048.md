# PR #18048 最终实现：OSS 新对象 key 使用可读身份段

> 规模：+110 / -7，6 个文件

## 解决了什么问题

资源、journal pack 与工具输出对象名只带 scope/slot hash，运维无法直接对应租户、Session 和 publication；改名又不能绕过 SQL 授权、摘要验证或误读已有对象。

## 最终实现方案

新资源对象名为 prefix/tenant/session/resource/UUID，pack 为 prefix/packs/tenant/session/pack-UUID；ToolPublicationDataStore 改为 managed-tool-results/tenant/workspace/session/publication/slot，admission 与 terminal 直接作为末段。SQL 仍存精确 object_key，读回和删除使用已存值，不按新格式推导旧对象名。

最新 main 将 publication 的同一命名集中到 ToolPublicationObjectKeys.forSlot，由 DataStore 的 admission/terminal/普通 slot 路径调用，ossScope 在 ToolPublicationContract 中保留原 tenant/workspace/session 形状；这是后续代码组织演进，不计入本 PR 的6文件。

保留 resource/publication 业务身份与 request/content digest、参数化 SQL、原审批和存储围栏；对象名不是权限凭据，也不是本机文件系统路径。只改变新分配对象的命名，不重写旧对象、二进制正文或数据库 schema。可读 tenant/workspace/session 会出现在对象目录与日志中，不能把 scope hash 当作保密或授权边界。
