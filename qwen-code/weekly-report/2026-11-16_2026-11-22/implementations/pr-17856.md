## 解决了什么问题

终态历史增长会放大 active-run/子结果发现、列表窗口、全历史 GC 补偿及逐项补查；只在最外层 LIMIT 不能限制 UNION/过滤前源扫描，减少查询又可能破坏终态镜像、锁顺序与未知对象 PUT 的清理安全。

## 最终实现方案

最终合入查询侧把 action 结算所需字段一次投影，子 Session 可读授权只按本次请求去重；扩展单包改定向最新 listed 查询，但在同一只读 repeatable-read 内以最多257个不同 id 保256目录上限。Session 列表窄投影、worktree 复用已读行、MCP/request/storage alias 补 canonical 键；native snapshot 首候选去多余 GROUP BY。artifact 首屏从实际过滤结果首行取 watermark，后续仍按水位/游标并重新核可见性；不是跨页快照缓存。

索引/谓词侧补 public event type/sequence、record identity、Workspace parent/access 与 Runtime recovery generated-flag 索引；latest turn 回连明确 SESSION/空 stream_id。权限递归 CTE 只在 CTE 一侧去 sentinel，保原表列可索引及 UTF-8/尾空格语义。child relay UNION 两臂先各按原顺序 LIMIT，再全局按工作优先于 close_debt 排序 LIMIT；最终撤回channel的scope-key join优化（PUBLIC Session的session_scope_key为空），保原tenant/session连接；user message 从 queue 用 EXISTS 判可投递；migration 多处 COUNT=0 改 LIMIT1 存在探针，quota 把 reserved/used/retained 合并两次聚合，不加 TTL 缓存。诊断 rebuild 以32事务小批聚合资源字节，仍保读取预算。

automation occurrence 增 is_run_terminal，由同一 journal projection、recordOccurrence 与 settleOccurrence 在 Session root 锁顺序下维护；结算 current-read 核 run/decision/lease fence，删除镜像清标记。active count 在一个 SQL snapshot 计 firing 加 fired且非终态两段；blocking run 仅翻 active 候选、以(createdAt,occurrenceKey) keyset 走页，并按(sessionId,runId)256一批读镜像，避免同 run id 跨 Session 混合。

生命周期退役在原事务直接撤 queued 消息并 bump revision，retire/replay 同事务 enqueue Session/capture GC；后台补偿按源 id 每页32行、固定 round end 循环，活行/已入账行也推进游标，SKIP LOCKED 的队列下轮回访，不以筛后 LIMIT 假装源扫描有界。这个轮次机制仍随全量源行完成整轮，不承诺恒定全轮成本。

pack 改动是独立正确性边界：V1 增 is_put_closed、active_from_revision（RETIRED为NULL）及 active range唯一约束。每个UUID只发一次物理 putIfAbsent，SQL短事务记闭合、核长度/摘要后发布；10分钟 BUILDING 过期只退役并让出range，不证明旧PUT已停止。外部对象IO不持SQL事务；compaction/collection拒ambient事务，单pack独立事务按 root→head→pack→resource 顺序。未知PUT保持退役删除债务，只有读回长度/摘要匹配才补闭合再删对象和精确SQL身份；对象仍不存在不能认定迟到PUT不会再到。固定id轮次避免持续新包饿死旧债务；删除正文与EVICTED同事务，Session GC进入WAITING_JOURNAL_PACKS，不能在pack债务未清时成功。

本PR最终为47表/reader5，新增列/约束/索引并替换pack唯一键；后续 #17864 已删除数字reader协商，当前main因 Phase 3b 为48表且catalog继续演进；没有V2或开发库升级链，应按仓库策略重建。两个设计文件中的基准/测试通过声明不是本次独立证据；新增 SQL rig 是单连接、暖缓存、确定性历史比较，不是生产容量或全热点均已受界的证明。

最终还抽出AutomationLedgerRows/ChildResultRelayQueries以保类规模门禁，enqueueCollections归SessionResourceCollectionCollector。当前main的后续 #17907 已撤销正文回收的 ACTIVE-only 限制，并为pristine/header/receipt三个证明reader补pack回读；这些不反计入本PR73文件。

当前 main 后续 #17958/#18019 已清理冗余存储/同行身份 hash，相关 SQL 改用保留 canonical key 或原 tenant/session 业务键；此为后续演进，不反计入本 PR 原规模。原租户、登记标记、锁序与 writer/generation 约束仍需保留。
