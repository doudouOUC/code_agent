# PR #18041 最终实现：清理无消费者列与重复唯一约束和索引

## 解决了什么问题

V1 仍维护无人读写的 CSI 遗留列和已被其他约束覆盖的索引；继续对它们做身份迁移会扩大维护面。删除 PUBLIC 全局唯一列时，还必须保留跨租户 Harness 身份歧义的拒绝。

## 最终实现方案

最终删除 ma_session.public_session_id 生成列及其跨租户唯一键，不改 tenant/session 主键；PUBLIC 创建仍由服务端 UUID 生成，JdbcHarnessPlacementStore.assign 在暴露 Harness handle 前继续检查同 Session ID 跨租户歧义并拒绝。不是允许任意租户共享可用的 Harness 身份。

ACTION_DECISION 的 decision_scope_key 与重复 uk_ma_decision_slot 删除，reserved lookup 改查原 scope_key；namespace、tenant_key、receipt_key 及原幂等唯一键仍保证同一 Action 决策互斥。还移除 delivery 的 source_record_key/source_revision/provider_id/payload_version、operation/work 的 payload_version、message.tool_call_key、capture.manifest_sha256 和 binding.first_activation_journal_revision，保实际使用的 seal_manifest_sha256。三个重复索引 idx_ma_work_page、idx_ma_work_session_page、idx_ma_operation_claim 删除，projection/identity 清单与测试同步。

本 PR 不删业务表，不改公共 payload 或锁序；当前 main 因后续 Phase 3b 为48表。唯一 V1 原地调整，旧开发 catalog 重建，不新增升级迁移。
