# PR #17654 最终实现：worktree restore 期间延后自动工作

> PR: [fix(serve): Prevent automatic work from blocking worktree restore](https://github.com/QwenLM/qwen-code/pull/17654)

> 规模：+989 / -114，19 个文件

## 解决了什么问题

恢复持久 worktree Session 时，cron/goal/notification 在 cwd relocation 前先启动会使恢复被 active work 阻塞，或在旧目录执行；AUQ 恢复还需保工具调用与回答相邻。

## 最终实现方案

最终合入 diff 在 ownership lock 下重新读取严格 sidecar，只有仍是 strict 且 bridge 支持 deferred AUQ 的路径才设置 deferAutomaticWorkUntilCwdRestore。ACP 私有 metadata 仅 trusted managed parent 可请求；创建 Session 时先置 cwdRestorePending，hold 自动工作并拒新 Turn/continue，已执行工作仍可 drain。

只有成功 set-cwd（含已在目标目录）才释放 hold，并恢复 cron、goal 和 notification 队列；错误或严格 sidecar 降级则 cleanup/fail closed，不释放半恢复对象。scheduled keepalive/启动 rehydrate 注入 restoreSessionCore，跟随 owning runtime generation guard，而非直接 bridge.resumeSession。Core 插入 cwd context 时保 pending AUQ call 仍为最后一项，避免在 call/answer 中间追加。

最终版将 automatic-work hold 与 worktree-context suppression 解耦：非 Channel restore 继续由 child 修复缺失 ownership marker、发 resumed notice，不因 hold 一并 suppress；deferred AUQ 参数独立传递。保留 Channel 原 suppression 规则，补真实 worktree route 的缺 marker/notice 回归。
