# PR #18118 最终实现：K8s 分发移至冷归档并移除活动私有 CSI Session 残留

> 状态：merged；已合入 main，merge `7084d5a73f75`，最终 head `ff7232dd6bff`；对照 main `d4b28087f457`。

## 解决了什么问题

Java Kubernetes/CSI 后端已归档，但分发 manifests、构建/preflight 脚本和 Hosted CSI 专属路由还在活动树中，容易误导部署并继续携带不可用入口。

## 最终实现方案

将原 managed-agent-server/distribution/kubernetes、根 build/render/preflight 脚本及专属测试、resident-acceptance 资源移到 packages/sdk-java/managed-kubernetes-archive；归档仍不接 Maven/CI，脚本内部保留旧布局常量，不能在新路径直接视为可运行部署。当前 Harness pool 仍只支持 static，新增配置与连接器拒绝非 static discovery 的测试。

删除 hosted-csi-* 私有 Session、cold recovery、file-history、evidence 与专属测试，撤 run-qwen-serve/server 的路由、drain 与 hostedCsiSessionStoreUrl 接线，移除最后消费者对应 csi-native-file-declarations 活动副本及 publication 私有 CSI 方法。managed-csi-* worker 协议族仍活跃，普通 Hosted Shell/files、publication v3 和 local/SSH/external/static 并未整体删除。

Broker prepare 遇 inputBytesBase64 或 toolDefinitionBytesBase64 显式400 runtime_broker_csi_removed（含混入v3），旧 read-batch 仍501；测试核没有执行副作用。这是对既有归档的后续清理，不把原部署模板存在当作支持，也不把文件移动当 Kubernetes 集群迁移/验收。没有新增 schema 升级。

## 关键代码路径

- `packages/sdk-java/managed-kubernetes-archive/README.md`：完整归档布局与不可直接恢复边界。
- `packages/cli/src/serve/hosted-harness-profile.ts`：移除私有 CSI option 校验。
- `packages/cli/src/serve/server.ts`：撤私有 CSI 路由及 shutdown 接线。
- `packages/managed-agent-server/server/src/main/java/com/alibaba/qwen/code/runtimebroker/http/RuntimeBrokerHttpServer.java`：旧 prepare 字段显式拒绝。
