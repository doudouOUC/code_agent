# PR #17958 最终实现：逻辑存储 alias 与物理 owner 冗余键清理

> 规模：+429 / -207，42 个文件

## 解决了什么问题

ma_storage 同时存 alias_key 与拆出的 tenant/storage hash，ma_storage_owner 同时存相等的 storage_key/physical_key；重复唯一键、插入参数和身份核对增加 schema 与锁路径维护成本。

## 最终实现方案

最终唯一 V1 删除 ma_storage.tenant_key/storage_key 及其复合唯一键，逻辑 alias 继续由原 canonical alias_key 唯一定位；删除 ma_storage_owner.physical_key 及唯一键，物理协调继续用原 storage_key。不是把逻辑 alias 与物理 owner 合成一张表：ma_storage.physical_key 仍连接共享物理存储，跨逻辑别名共享 owner 语义不变。

注册、SSH/local materialization、maintenance、迁移、重认证与 Broker admission 同步改读保留键，参数化 SQL 与原 root/owner 锁序、generation、成员数量和 registration identity 校验保留。移除 storageFenceKey 帮助方法，storageFence 改按 storageAliasKey 查询。同步 schema projection/fixture 与 MySQL 锁路径测试，仍47表，无新升级迁移。
