# PR #17932 最终实现：原 Runtime 丢失时只结算全 abandoned 的 parked Turn

> PR: [fix(managed-agent): settle a parked turn whose runtime is terminally lost](https://github.com/QwenLM/qwen-code/pull/17932)
> 状态：merged；已合入 main，merge `82a0f3031f71`，最终 head `9d4232cb15aa`；对照 main `0ca8266fff86`。
> 规模：+390 / -3，5 个文件

## 解决了什么问题

Broker对LOST且无writer-stop证明的原generation拒绝adopt；即使每个pending执行已在持久账本abandoned，passive恢复仍被acquire拒绝挡住，Turn长期留在park。

## 最终实现方案

仅在passive恢复且有in-progress执行时容忍acquire的503 runtime_broker_runtime_lost，保留该原拒绝供后续判定；其他状态/代码仍立刻抛出，不标acquiredRuntime、不调用onPassiveRuntimeAcquired。逐pending execution只调原broker.status读持久账本，必须全部为abandoned，才交原恢复结算路径产生失败结果和终态；任一状态非abandoned、status读不到/抛错，或pending为空，都重新抛原LOST拒绝并保持park。

不请求死Runtime刷新、不execute/cancel/release、不provision替代owner，也不重跑副作用。普通成功acquire后的refresh/held handback纪律不变；主动continuation接管不在本次容忍范围。补CLI回归与Java DurableRuntimeRecoveryTest证明LOST原账本仍可查、且不创建第二generation。

## 关键代码路径

- `packages/cli/src/serve/hosted-runtime-recovery.ts`：精确LOST拒绝分类、全abandoned持久证明。
- `packages/cli/src/serve/hosted-runtime-recovery.test.ts`：全abandoned、混合/未知/无pending与非passive拒绝。
