## 解决了什么问题

macOS 的设备号可能跨重启变化，原 numeric dev 身份和被排除的 reboot 判定使未移动的 Workspace/worktree 也被当成变更或无法回收旧 Runtime。

## 最终实现方案

最终合入 diff 用 diskutil 的 VolumeUUID（32 位小写 hex）联合 host、inode、birthTime 构造稳定文件/卷身份；探测前后重查 canonical path 和属性，拒符号链接、设备不符和歧义值。LocalRuntimeStore 要求 macOS/非 macOS 类别一致、同 host 且 bootId 不同才认定 reboot，不用新进程 PID 代替旧 writer 停止证据。新 marker v3 与旧 numeric v2 分流核验，不在线静默改写历史身份。

显式 WorkspaceIdentityReattestationMain/store 提供 plan/begin/retire/complete：冻结 owner/alias/worktree/marker 字节与 digest，给 storage/owner 设 fence，按原 binding generation 取得 JOURNAL_LOST 和 WRITERS_STOPPED 证据并退役。确认无成员、活跃 Runtime/journal writer 或未结算操作后，逐文件幂等原子替换，复核 identity，再事务更新 physical key、registration/worktree revision 和 receipt。仅同路径、同 host/inode/birthTime、无重叠 owner 的旧根可转，不是一般路径迁移或跳过授权的 repair。

最终合入还处理升级/重启间的混合记录：稳定 macos-volume/1 plan 核同卷全部锚点后原样保留；legacy plan 配稳定 completion 时核当前 identity，保原 completion 字节。错卷、inode/birthTime 或 marker 改变仍拒绝，不重新生成已稳定证据。

当前 main 后续 #17958/#18019 已清理冗余存储/同行身份 hash，相关 SQL 改用保留 canonical key 或原 tenant/session 业务键；此为后续演进，不反计入本 PR 原规模。原租户、登记标记、锁序与 writer/generation 约束仍需保留。
