# PR #18019 最终实现：同行冗余身份 hash 迁回原始业务键

> PR: [refactor(managed-agent): drop redundant same-row identity hash keys](https://github.com/QwenLM/qwen-code/pull/18019)
> 状态：merged；已合入 main，merge `8c805ca2ea23`，最终 head `4021b1ff54d2`；对照 main `d4b28087f457`。
> 规模：+1906 / -2088，198 个文件

## 解决了什么问题

同一行同时存原始身份和只由其派生的 hash，读写/索引/碰撞复核重复；直接全局删除又会破坏跨表引用、已登记 Session 筛选、生成身份和 MySQL 索引上限。

## 最终实现方案

最终198文件的切片只删除同行冗余 hash，仍保 VARBINARY，并非全库 VARCHAR 转换。head 改 UNIQUE(tenant_id,harness_session_id)；Session record/resource/ref、operation/journal pack、client-files 等用原 tenant/session 前缀；client request 唯一键显式含 binding_generation/request_id，side query 用 tenant/query，memory entry 用 tenant/store/memory；扩展 package/settings/operation 去 scope_key，output capture 去 tenant_key。查询、插入、join、projection 与 fixtures 同步，针对已删 hash 的碰撞复核不再需要。

部分 child 身份列对齐父表512字节宽；head 的原 tenant/harness 键2560字节。三个非唯一索引对 record/resource/delivery id 使用 MySQL1024字节前缀，所有唯一键仍完整，最宽重建键3072字节。原参数绑定、业务身份及租户限定继续，不用数据库自增 id 替代授权或幂等。Session退役按重建唯一键顺序锁 side query/client-files 请求。

ma_session 的 tenant/session/session_scope hash 仍作为 CONTROL upsert 的登记标记，迁移 join 保 s.session_scope_key IS NOT NULL，未登记 Session 不被误纳入；跨表 resource/record/operation/target/delivery/actor/storage/runtime键、capture scope、receipt生成身份与 read lease 仍保留。新增 delivery 原始源索引，不删除二进制 payload，也不实施 #17960 的 operation 生成列提案。本 PR 合入时 V1 为47表；当前 main 因 Phase 3b 为48表、无数字reader协商，旧开发catalog按策略重建，没有升级链。
