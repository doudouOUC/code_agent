> 规模：+7685 / -5996，382 个文件

## 解决了什么问题

identity hash 与原身份双存、过宽二进制列及跨表隐式键让 SQL 和索引预算难维护；直接改 VARCHAR 又可能因尾空格折叠、字符宽度和复合键超限改变身份语义。

## 当前实现方案

当前 open diff，不能作为 main 能力承诺。382文件横跨 contracts、控制面、持久层、Broker、TS 消费者/fixture 与验证。ManagedIdentityRef 用 v1|arity|length:percent-encoded tuple 可逆编码，区分 null/空串，按 UTF-8 长度和大写转义重新编码核 canonical，超字节预算拒绝；ManagedIdentityRefs 将 resource/operation/owner/publication/receipt/request 等协调身份改为显式有界引用，仍以 VARBINARY 存储，而非内容摘要或授权凭据。

已见 schema 的 tenant_id VARCHAR36、Session 类64、资源 ID VARCHAR256、workspace 按表128或512，以及 guard96；BrokerValues/WorkspaceValues/EventIdentity 等同步收紧 tenant、actor、operation/owner 与外部输入，拒超界、畸形 Unicode 和尾空格，防 PAD SPACE 折叠。ChildActorId 保留 c:加32位 SHA-256 派生以适配 actor36；内容 digest、HMAC、密文和生成身份不能一概删除。插入/查询/锁与 projection/fixture 随真实列类型改绑定，跨表 operation/资源引用一同调整。

最新 head 进一步把 record/child-run/execution/delivery 身份转为 VARCHAR256、model/tool-call/runtime instance/lease 转128、isolation64、provision160、loss evidence192、platform account/sender/chat/thread256、PR owner64/repo128；相关 Java/TS 准入、model catalog 与 child snapshot 同步，tool-result manifest 仅 callId 增128限制，不改其他 ID 的共享512预算。这是候选契约收紧，不是第三方提供方长度已独立核验。

设计的 Tier B 预算仍不能直接当成端到端完成证明：child-run 协议虽改256，JdbcChildResultRelayStore 的 claim/close-debt 还因镜像 operation_id 保留128门禁；ma_runtime_stage 的哈希设计也保留，canonical refs 保二进制。不能把预算表或 MySQL IT 定义写成全库已收敛/兼容。候选仍48表，新增真实 MySQL catalog/3072字节索引 gate；同表数不说明与 main 的列、约束、编码兼容。唯一 V1 原地改、开发库重建，无升级链。
