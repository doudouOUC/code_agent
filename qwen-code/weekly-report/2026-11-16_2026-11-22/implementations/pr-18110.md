## 解决了什么问题

worker 重发指定 resourceId 时本地 publish 未与 read 对齐单路径段校验；Broker 重启后 stop 只查内存 owner 会404；真实进程测试又把初始 Promise 当最终 drain，可能漏掉管道尾字节。

## 最终实现方案

LocalManagedSessionResourceStore.write 在任何目录/临时文件落地前对 client-chosen resourceId 调 assertPathSegment，与读取路径一致；pending、target 和 ref 统一用 safeResourceId，拒绝 ../、斜杠和点段，合法 worker ID 仍可发布读回。

RuntimeExecutionRecovery.stopBackgroundProcess 先以调用方 tenant/harness/runtime Session 做只读 findHistorical 预检，错误租户404且不 adoption、不发控制 RPC、不结算；合法请求再经 adoptedSessions 恢复原持久 owner，沿原 binding/generation 停后台执行，支持 Broker 重启或其他副本内存为空的情况。后置 tenant 核验也保留，不新建任意 Runtime。

第三项只修测试 rig：driveRealProcess 等 child close（含 stdio 关闭）而不是 exit，返回 exited.then(() => chain)，确保立即解构的 drained 也等待最终异步写链；增加大于64KiB管道输出及受控 writeGate 回归。这不应误写成修改生产 child_process 生命周期。
