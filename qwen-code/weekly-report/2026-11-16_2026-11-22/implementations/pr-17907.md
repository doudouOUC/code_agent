# PR #17907 最终实现：跨 SEALED head 推进已覆盖 journal 正文回收

> PR: [fix(managed-agent-server): keep journal blob reclamation moving past sealed heads](https://github.com/QwenLM/qwen-code/pull/17907)
> 状态：merged；已合入 main，merge `1cc608e0236f`，最终 head `8775a7bc6cdd`；对照 main `d4b28087f457`。
> 规模：+150 / -19，8 个文件

## 解决了什么问题

正文回收先取32个老PUBLISHED pack，逐项只接受ACTIVE head；正常闲置SEALED的包无法变EVICTED，积满32项会挡住全局后续包。正文外置后仍直读SQL的少数证明路径也会误报缺字节。

## 最终实现方案

deleteCoveredBlobs保原root/head/pack锁与coverage/watermark、未compacted和PUT闭合检查，只撤ACTIVE状态限制。SEALED是正常休息状态，coverage由packedThroughRevision>=throughRevision证明；满足条件的包将EVICTED和record_bytes置空同事务提交，从全局窗口退出。

JournalHistoryQueries的pristine初始journal、JdbcWorkspaceLifecycleStore的首header，以及ToolPublicationAdmissionStore的original receipt，SQL正文为null时用原revision/digest/length调packs.resolveBytes，再走原UTF-8/JSONL/identity/commitproof校验；无pack或无法证明仍返回false/blocked/拒绝，不编造空正文。补回归并只抬受影响类规模基线。

- `packages/managed-agent-server/persistence/src/main/java/com/alibaba/qwen/code/managedagent/persistence/JournalHistoryQueries.java`：pristine journal的pack-aware读取。
