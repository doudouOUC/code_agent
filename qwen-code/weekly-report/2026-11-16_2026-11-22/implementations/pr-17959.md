## 解决了什么问题

Runtime Session getters 在调用方已持 guard 时重复加锁；external placements 两张 map 同时用 ConcurrentHashMap 和外层 monitor；归档后 legacy Session guard 已成空方法和别名。

## 最终实现方案

最终 SessionContext 的 backgroundProcesses/mountClaim/activeControls/release/releaseAttempt getters 直接读字段，调用方仍必须持 context.lock；完成回调也会调用的 setter 继续自行加 ReentrantLock。不是删除 SessionContext 整体互斥，也不把任意 getter 宣称线程安全。

ExternalRuntimeProvisioner 两张 placement map 改 HashMap，由同一个 placements monitor 保护，原 provision 的首次 get 补入 monitor。AgentStoreRows 删除空 requireLegacyMutation 与 legacy 别名/未使用布尔参数，调用方改为原 requireSessionForUpdate/requireSessionTurnForUpdate；真实 SQL FOR UPDATE、事务、鉴权、generation 与 lease 守卫保持，不恢复已归档 legacy 后端。没有 schema 或协议改动。

- `packages/managed-agent-server/runtime-broker/src/main/java/com/alibaba/qwen/code/runtimebroker/service/RuntimeBindingRegistry.java`：调用方锁内 getter、回调 setter 保 guard。
- `packages/managed-agent-server/runtime-external/src/main/java/com/alibaba/qwen/code/runtimebroker/provisioning/external/ExternalRuntimeProvisioner.java`：两张 map 的单 monitor。
