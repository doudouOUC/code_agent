## 解决了什么问题

client 创建/close 用 clientLock，而 generation adoption 用 synchronized(this)，并发换代与关闭可能同时取走并关闭同一个 client，或干扰刚协商出的后继。

## 最终实现方案

最终 adoptGeneration 与 client()/close() 统一用 clientLock，try/finally 释放；精确比较当前 client/boot identity 后只移走匹配的旧引用。按旧 boot 清 attachment/marker 和关闭 stale client 仍在锁外，避免 ConcurrentHashMap.computeIfAbsent 的 in-flight load bin lock 与 clientLock 反转，也不清新 generation 已创建的缓存。

新增并发回归让 adoption 与 close 交错，约束同一个 client 只被一个交接方接管/关闭；client() 重建仍在相同锁下协商。此 PR 只改 Java adapter 与测试，不修改 SDK 类、wire、发行版本或 Runtime 租约。
