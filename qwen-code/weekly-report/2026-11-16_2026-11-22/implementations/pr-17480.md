## 解决了什么问题

findByHarnessSession 只适用于 session-isolated binding；共享 Workspace 没有 Harness isolation key，identity-free extension status 因此查不到原 READY owner。

## 最终实现方案

最终合入 diff 按 scope 分支：带 expectedBindingId 仍 findById；无身份的 workspace isolation 用完整 provisionRequest(scope,harnessId) 的 findActive 查原 slot，要求 READY 且未 drain，不创建 placement/session。session isolation 仍分页找唯一匹配；repository 文档明确 scan 的范围，避免再拿它解析共享 owner。

HarnessOwnership.sharesRuntimeSessions 只放开“共享 owner 不等于单 Harness isolationKey”这一条件，仍核完整 scope、可选 expectedGeneration、lease、state 与原观察/attestation。带原身份的恢复读取可观察 DRAINING；无身份 probe 不接管 DRAINING，mutation 仍受 Harness drain/admission 围栏，不能跨 Workspace 或 fallback 到新 owner。
