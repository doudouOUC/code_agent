## 解决了什么问题

缓存 attachment 指向已被 Harness 移除的 Session 时，合法准入会重复命中 coded 404；旧引用清理还可能删掉并发新 attachment 的 recovery marker，导致后续恢复丢快照。

## 最终实现方案

只在 404 hosted_session_not_found 时按引用相等移除观察到的 attachment，并在 attachments.compute 内同步 pendingRecovery；旧代/旧引用不得抹掉新 marker。可安全复试的 admission 经 passive load 恢复；单地址最多重试一次，pool 抛 HarnessAttachmentLostFailure 到池层，重选 SQL placement/writerToken 后再试一次，不能复用旧 PoolCall。

Turn submit 不在 leaf 盲重投：coordinator 捕获 attachment lost，复核 lease 并重读 Turn，再走 runClaimed 的绑定、recovery snapshot 和 watermark 流程；未绑定提交按 prompt id 结算，不接管 Session snapshot。action response 与新 automation/child/message/channel admission 可使用窄重试；cancel_run、cancel、close_scope、stop、cancel_delivery 等不自动复试。hosted_session_closing 按暂态等待处理，不消耗对应重试预算；不是所有 404 或所有操作都重开。

后续 main 已由 #17680 补 epoch-less continuation-ready park 的 continue 驱动，#17681 为 closing/open_busy 等待加入无进展老化；不把这些后续修改计入本 PR 规模，也不把“预算豁免”理解为无限等待。
