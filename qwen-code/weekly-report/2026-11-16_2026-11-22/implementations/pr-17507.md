## 解决了什么问题

十余个验证 profile 重复声明相同 Failsafe 版本和执行目标，容易漂移；嵌入宿主还需防止专用调度器成为默认候选，发布 gate 也不能被跳过 Javadoc 或忽略错误绕开。

## 最终实现方案

将 integration-test/verify 执行放入 verification 的 pluginManagement，各 profile 继续显式激活 Failsafe，并保留自身 includes/excludes、超时、并发和报告检查，不是关闭完整 gate。新增反射枚举 ManagedAgentConfiguration 导入配置内的 TaskScheduler/TaskExecutor/ExecutorService Bean，要求 defaultCandidate=false，防回归影响宿主默认执行器。

发布元测试扩大禁止的 Javadoc 绕过参数，并断言 executable JAR/publication 验证步骤没有 continue-on-error。同步设计文档中的收敛进度，不将文档所列剩余工作算作实现。

## 关键代码路径

- `packages/managed-agent-server/verification/pom.xml`：共享 Failsafe 管理配置与各 profile 选择器。
- `packages/managed-agent-server/verification/src/test/java/com/alibaba/qwen/code/managedagent/config/ManagedAgentEmbeddingTest.java`：检查实际导入配置的专用 Bean。
- `scripts/tests/managed-runtime-release.test.js`：Javadoc 与发布失败不可忽略的元测试。
