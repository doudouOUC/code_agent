## 解决了什么问题

普通 files 仍走 lifecycle v1，而 Shell/MCP 已用 v2，形成并行关闭流程；SSH 和 pooled Harness 即便声明公开子 Agent 能力仍被部署形态挡住，关新建开关还可能破坏已受理 child 的 attach。

## 最终实现方案

WorkspaceToolProfiles 仅将 ordinary hosted-workspace-files/1 迁到 lifecycle2，external-files 保1。Harness 默认 v2 profile 列表加入files；单地址/pool connector 都按协商profiles并保文件能力可用门判断。v2 resource verifier 在已核 executions/file history 后让files像MCP一样结束，不要求它没有的Shell capture/publication/monitor。两类 lifecycle fence 码统一转 hosted_lifecycle_operation_active。

公开 child 准入保 workspaceChildAgents/workspaceShell、session isolation、profile和feature门，但将 durable local-process 与已配置 nodes/隔离正确的 SSH 均纳入；删除 SSH 必须启扩展执行的额外条件，不取消原内置 qwen-code 或扩展自定义 Agent 门。pool以协商 PUBLIC_CHILD_AGENTS + Shell lifecycle2 判断，不再一律因 poolEndpoint 拒绝；resident/CSI 仍由 provisioner/profile 结构排除。

只有root能再launch，depth1 child不递归。SSH已受理 Session 的 foregroundOnly 依持久 publicChildAgentsVersion，而非可热变的新建开关：关闭开关停止新launch，不搁浅既有root/child的attach/background surface。同步reference包及测试fixture；不是增加新版本兼容链或启用Kubernetes Runtime。
