# PR #17864 最终实现：投产前版本机制收敛与内容事实门禁

> PR: [refactor(managed-agent): converge pre-production version machinery](https://github.com/QwenLM/qwen-code/pull/17864)
> 状态：merged；已合入 main，merge `33fdbb37387a`，最终 head `fb4e3bf15e2d`；对照 main `d4b28087f457`。
> 规模：+1851 / -940，101 个文件

## 解决了什么问题

私有 storage floor、reader 天花板、版本请求头与旧 Action 分支叠加，要求共同发布的 Server/worker 也维护未投产的混合版本矩阵；直接删数字版本又会丢失 restore 后重建 activity 投影的持久依据。

## 最终实现方案

最终 diff 删除 ManagedStorageVersions、StorageReadPolicy、ManagedSessionReaderVersion 及请求头 X-Qwen-Managed-Max-Readable-Storage-Version；WriterGrant/RestoreHead/native snapshot 不再携带数字 storageVersion 或 supportedStorageVersion。唯一 V1 把 storage_version 替换为 has_activity_diagnostics，提交发现 activity 证据或 tool.measured 时单调 OR 置位，restore/写入准入仍按该持久事实重建并要求 activity ready，不把历史版本号当内容存在证明。

Core 新 header 不再写 minimumReader；parser 将其变可选，但旧 header 若显式携带仍须解析合法、且不高于 reader capability。formatVersion、各资源 schema/kind、摘要/长度/引用闭包、writer token/generation、租户隔离及 recovery proof 都保留；删除的是统一部署前提下的数字协商，不是接受任意旧开发 catalog。普通 Hosted Action options 收敛为 v3、question batch 保 v4；inputRef/continuationRef 按真实字段闭集校验，extension-command input 仍强制 continuation，旧 v1/v2 不再接受。

涉及审批 continuation、side query、CSI snapshot/恢复 reader、Java Action 投影与诊断读取的调用点同步改读事实字段。最终101文件包含双语收敛/删列设计与 rebuild handoff；这些设计中的其他收敛路线不等于全部实现。当前 main 仍47业务表，但已没有数字 reader5 协商；按仓库投产前策略原地改 V1、重建开发状态，无 V2 升级链，不承诺跨版本滚动或旧 checkpoint 兼容。
