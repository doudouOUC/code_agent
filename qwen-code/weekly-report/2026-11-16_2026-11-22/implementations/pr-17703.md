# PR #17703 最终实现：业务 Workspace 默认 Skills 的发现、固定与目录读取

> 规模：+1144 / -98，35 个文件

## 解决了什么问题

业务来源缺少默认 Skill 发现协议，创建 Session 只能靠显式选择；直接动态读来源又会让撤权/版本变动污染已受理请求，自动导入包还可能意外暴露在 Workspace 显式目录中。

## 最终实现方案

新增可选 ManagedSkillCatalogSource SPI，按授权 context 发现精确 revision 的 skill Reference、target、名称/描述和 preinstall；在 Managed SQL 事务外运行，检查 deadline、provider/kind/重复、最多256条与字段上限。preinstall 最多32个且同 provider/resource 不重复，沿原 resolve/open/摘要验证/Harness prepare/持久幂等发布得到不可变 pin；默认导入还必须有 Harness 编译的 standaloneSkill 元数据，不接受仅来源自报信息。

仅 extensionPins 为 null、无追加 inline Skills，且 Session 扩展/lifecycle、profile 与导入就绪才发现默认项：读最终 Workspace/profile，要求可创建、OPERATOR、原 extensions allowedActors/self-service 等权限。显式 extensions:[] 或已有选择跳过默认发现；files/READ/external 等不可用 profile 不写默认包。非空默认 pin 绑定解析出的 Workspace，空目录不改原省略 Workspace 的锁顺序；受理后沿原 receipt 冻结选择，失败前已发布包不冒充 Session 创建已成功。

ma_extension_package 增 standalone_skill_json 与 is_catalog_listed（含0/1约束），默认导入标为未显式列出，可复用同 source/manifest/digest/metadata 的 revision；显式 list 只看 listed 的最新已发布 revision。该 PR 合入时唯一 V1 为46表、reader5；当前main后续为47表，#17864已删除数字reader协商；字段也已改变，不能据版本号相同认定旧开发 catalog 兼容，按仓库策略重建而非新增迁移。

Core 的 managedSkillCatalogEntry 统一 Harness 与 preparation 对 instructions/asset URI 的构造，body 上限512KiB，Java 预准入用编译后 JSON UTF-8 字节和名称核 agent/builtin/package 联合目录（256条及总字节），loop 注入也计入。Session Skills 查询先原可读授权，在 repeatable-read 内优先读 installed config；仅还无安装 revision 时回退初始 pin 的元数据，过滤非 user-invocable 与 command。配置覆盖不完整返回409，不热读业务来源伪造已安装目录；OpenAPI/生成类型同步目录语义。

当前 main 的 creationToolProfile 已由后续 #17753 从 AgentSessionPolicies 移至 AgentSessionAdmissions，facade 改委派但默认发现门禁不变；这不计入本 PR 的35文件。
