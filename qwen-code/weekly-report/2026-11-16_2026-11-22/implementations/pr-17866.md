## 解决了什么问题

模型把本机截图路径写为 Markdown 图片时，浏览器不能读取该文件，会显示破图或丢失路径；远程图片失败同样缺少可读回退，修改回退又容易泄露导出 URL 或破坏回复复制语义。

## 最终实现方案

MarkdownImage 增本地路径展示启发式：Windows盘符/UNC、波浪号及常见 Unix 绝对目录直接渲染可选择文本 chip，而非 img。它是显示层判断，原共享 isSafeImageSrc 安全门不放宽，因此正常同源 /images/logo.png 仍可渲染。只对本地路径安全 percent-decode；失败远程 URL 保原转义，避免展示另一个资源身份。

实时 chat 的 img onError 记录失败 src 并退为 alt、原 src 或翻译后的失败文本；src 改变可以重新尝试。document/export 模式不回显远程 src，也不把 data URI 的 base64 倾倒为文本；允许的 data img 保 src，不为其绑定实时失败回退。span 使用 role=img/aria-label，CSS 4px 圆角、最大宽度和 break-all 控制长路径。

回退 span 分别保 data-markdown-image-alt 与非 document 模式的原 src。plainText 像读取 img.alt 一样保留空 alt；selection Markdown 复制按原图片语法重建，避免把视觉文本替代成回复内容。补组件、CSS、复制和 Playwright 本地路径/失败图片定义；没有改变后端文件权限、图片下载路由或传输协议。

## 边界与风险

- 路径正则是展示启发式，不是文件访问安全边界；漏掉的不可加载 src 仍靠 onError 回退。不能把文本片段说成浏览器已获得本地文件读取能力。
