## 解决了什么问题

常驻 idle Session 持续续租、占内存与 MCP/Hook owner；直接复用 detach 又会终结输入，不能把关闭流程当可逆的暂停。

## 最终实现方案

本 PR 最终合入的是英文/中文设计与旧 idle parking 互链，四个 changed files 全为 Markdown，合入时状态为 proposed、未实现/未接受。Phase 1 提议仅对无待处理输入/后台工作/cleanup debt/活跃 client-files 等 blocker 的 Session 悬挂，先 gate/有界等待，再非终态资源清理、activation release 与 seal；placement 保留，不新增 schema。当前 main 的父设计已链接 #17690 和恢复附录，状态行仍写 being implemented；实际合入进展须以下述后续代码为准，不能只照抄该状态行。

第一次 teardown 调用起不可回滚为普通服务；失败/未知保原 writer/generation/token 和 gate，有界重试后转 operator-visible blocked，不能清 flag 复活半关闭对象。10 分钟、8 个冷开并发和 jitter 都是候选而非出厂默认。Phase 2 Runtime 连接所有权、Phase 3 控制面 wake/观察与 Phase 4 parked approvals 仅定义后续边界，各需独立设计。当前 #17521 只是 Java 恢复前置的一部分。

后续 #17680/#17681 补 Java 前置，#17690 的 Phase 1 与 #17749 的默认关闭 Phase 2 MCP parking 已合入 main；#17805展开Phase 3设计，后续 #17869 的seal戳路线由 #17908 默认关闭地实现；#17912 的3b仍只设计。本页四个 Markdown 的原合入范围不变；后续实现和常量不能反写成本设计本身已验收。

当前 main 后续 #17955 已统一 transport passive wake，#17953 已合入 Phase 3b worker 捕获/staging/attach 后 drain（默认关闭），#18110 补后续修正；Phase 4 的 #18047 仅设计，后续 #18115 已合入默认关闭的 Action parking；需 wake-dispatch 同开，源码落地不代表验收完成。原设计、最终实现与独立验收分开。
