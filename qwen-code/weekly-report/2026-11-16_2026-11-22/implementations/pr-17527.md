## 解决了什么问题

常驻 idle Session 持续续租、占内存与 MCP/Hook owner；直接复用 detach 又会终结输入，不能把关闭流程当可逆的暂停。

## 最终实现方案

最终合入的是英文/中文设计与旧 idle parking 互链，四个 changed files 全为 Markdown，状态仍 proposed、未实现/未接受。Phase 1 提议仅对无待处理输入/后台工作/cleanup debt/活跃 client-files 等 blocker 的 Session 悬挂，先 gate/有界等待，再非终态资源清理、activation release 与 seal；placement 保留，不新增 schema。

第一次 teardown 调用起不可回滚为普通服务；失败/未知保原 writer/generation/token 和 gate，有界重试后转 operator-visible blocked，不能清 flag 复活半关闭对象。10 分钟、8 个冷开并发和 jitter 都是候选而非出厂默认。Phase 2 Runtime 连接所有权、Phase 3 控制面 wake/观察与 Phase 4 parked approvals 仅定义后续边界，各需独立设计。当前 #17521 只是 Java 恢复前置的一部分。

后续 #17680/#17681 已补部分 Java 前置，#17690 是仍 open 的 Phase 1 实现候选；本页四个 Markdown 的合入范围不变。当前 main 尚无该候选的自动暂停接线，候选自动清 gate 方案也不能反写为本设计已验收。
