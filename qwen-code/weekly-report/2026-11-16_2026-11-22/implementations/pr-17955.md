## 解决了什么问题

transport wake 仍调用 activateForWake，会驱动崩溃 Session 的 Runtime 恢复或前台 Turn；它与 SQL 兜底的 passive recoverForWake 不一致，不能只靠未来通知 NOT_DUE 过滤保证恢复职责。

## 最终实现方案

最终 TransportWakeActivator.load 改调 harness.recoverForWake，成功仍通知 activated consumer 并返回 ACTIVATED；删除依赖 active verb 布尔返回的 ALREADY_ATTACHED 分支。NOT_DUE、claim 和失败后 SQL 二次核 live writer 的 FENCED/FAILED 分类保留，未增加第二 dispatcher 或新主动重试。

同步 EventTransportBrokerGate、SQL consumer 和 activator 测试，双语 seal-stamp 附录改为 passive。#17908 的原 diff 当时只加 NOT_DUE、到期仍 active；当前 main 已由本 PR 补齐 passive，不能把本次修正反计入原 PR34文件。
