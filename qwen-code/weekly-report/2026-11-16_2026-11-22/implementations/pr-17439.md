> 规模：+507 / -3，5 个文件

## 解决了什么问题

合法扩展的 hook description/statusMessage 被 worker 的闭集 parser 当未知字段拒绝，HTTP hook 的 if 条件也被挡在准备阶段，导致包无法完成预备。

## 最终实现方案

ManagedHookRuntime 的 command/http/prompt/function config 闭集均接受 description/statusMessage，先要求可选值为字符串；HTTP 再接受字符串 if。保留 timeout 范围、URL 协议/凭据限制和未知字段拒绝。改的是 manifest 接受面，不是引入新的执行器或跳过 Hook 授权。

内部 pinned catalog 保留这些字段；对外 control catalog 的 command/http/function 仍裁成公开摘要，handler 仍只公开 id/revision，只有 prompt catalog 继续返回其 prompt config。测试同时覆盖 extension staging 的保留、非字符串/未知键拒绝，以及私有 display/HTTP if 不泄露到公开 control view。

## 关键代码路径

- `packages/cli/src/serve/managed-extension-manifests.test.ts`：准备阶段元数据与 HTTP 条件保留。
