## 解决了什么问题

Phase 4 设计尚无运行时：审批与提问等待一直占 resident、SSE 和派发租约，普通流结束又触发失败重试，无法有意放下并凭持久等待接回原 Turn。

## 当前实现方案

当前 open diff，不能作为 main 能力承诺。候选通过 WeakMap 记录已持久的审批/提问等待，要求唯一根控制面输入、requested Action、可恢复且非 command-step continuation，无 Hooks/MCP/lineage/其他待处理输入，并同时具备 actionParking 与 wakeDispatch grant；与后台证书互斥。live approval 在资格判断重读 selection，提问须 mount handback 完成且重试链已停。

HostedApprovalWaiters.park 在无 polling/resolution 时移除 resolver 并清定时/abort 注册，但不 resolve、不 abort；beforeTeardown 冻结后清 Turn deadline。只豁免自身输入/stream/cleanup，保该 Turn Runtime 成员资格；其他工作仍阻止。seal 的 parkedTurn 带 promptId、较早 expiresAt/deadline 与可选 approvalRevision，精确 journal revision 校验，不能与 pending wake/backgroundHeld 混用；新 writer acquire 清证书。V1 新增3列、不增表。

协调器流结束先 flush，再由 AgentActionParking 按 Session→head→Turn 锁核 owner/lease、RUNNING、SEALED/released、revision/prompt、approval revision、无未完成 ACTION_RESPONSE 且仍 requested，CAS 写 HARNESS_ACTION_PARKED/retry_after，释放派发租约而不结束 Turn。Action 决定、取消、模式变更事务清停靠，原 sweep 到期派发且 claim 清标记，经 G3 continuation 冷恢复，不是新增 Runtime continue 协议。恢复视图区分匹配证书的 turn_active 与证据不匹配，不把它报成 ready。

配置 qwen.managed-agent.action-parking.enabled 默认 false，仅开启它而不开 wake-dispatch 会在启动拒绝。当前 main 只有 Phase 3b、没有这3个停靠列或接线。默认超时下停靠收益、冻结栈可回收性、双加载/决定竞争与恰好一次副作用仍需真实进程/数据库证据，不能从候选测试或设计估算直接宣称完成。
