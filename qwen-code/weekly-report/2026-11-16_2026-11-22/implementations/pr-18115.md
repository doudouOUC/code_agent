## 解决了什么问题

原先审批等待没有停靠运行时：审批与提问等待一直占 resident、SSE 和派发租约，普通流结束又触发失败重试，无法有意放下并凭持久等待接回原 Turn。

## 最终实现方案

最终实现通过 WeakMap 记录已持久的审批/提问等待，要求唯一根控制面输入、requested Action、有原 prompt 文本、可恢复且非 command-step continuation，无 Hooks/MCP/lineage/其他待处理输入，并同时具备 actionParking 与 wakeDispatch grant；与后台证书互斥。live approval 在资格判断重读 selection，提问须 mount handback 完成且重试链已停。

HostedApprovalWaiters.park 在无 polling、且 resolution 引用计数为0时移除 resolver 并清定时/abort 注册，但不 resolve、不 abort；重叠解析按计数成对释放。beforeTeardown 冻结成功后清 Turn deadline；轮询/解析竞争返回 false，走可逆 revert 并重新布置空闲计时，不当成 teardown 异常。资格在 attempt 内及 gate 下重读，恢复后的可持久审批等待也重新注册冻结入口。只豁免自身输入/stream/cleanup，保该 Turn Runtime 成员资格；其他工作仍阻止。seal 的 parkedTurn 带 promptId、较早 expiresAt/deadline 与可选 approvalRevision，精确 journal revision 校验，不能与客户端 pending wake/backgroundHeld 混用；若服务器发现 staged wake 则按该分支 seal 并清停靠列，新 writer acquire 也清证书。V1 新增3列、不增表。

协调器流结束先 flush，再由 AgentActionParking 按 Session→head→Turn 锁核 owner/lease、RUNNING、SEALED/released、revision/prompt、approval revision、无未完成 ACTION_RESPONSE 且仍 requested，CAS 写 HARNESS_ACTION_PARKED/retry_after，释放派发租约而不结束 Turn。Action 决定、取消、模式变更事务清停靠，原 sweep 到期派发且 claim 清标记，经 G3 continuation 冷恢复，不是新增 Runtime continue 协议。恢复视图对仍 RUNNING 的停靠 Turn 沿用 recovering/turn_active，不要求证书仍存在；后续 writer 已清证书也不把 Turn 报成 ready。HARNESS_ACTION_PARKED 是内部派发记账，Public/WebShell Turn errorCode 将其隐藏。

配置 qwen.managed-agent.action-parking.enabled 默认 false，仅开启它而不开 wake-dispatch 会在启动拒绝。当前 main 已有这3个停靠列与 Phase 4 接线，仍共48业务表。审批/规则变更仅在 certificateMatches 证明单一 SEALED/released head、相同 journal/approval revision、唯一无 owner 的停靠 RUNNING Turn 且无其他 prompt 的 requested Action 时豁免相应 busy gate；原权限、Workspace、开放 operation 等检查保留。Action 投影 INSERT 同步 prompt_id 供证书关联。默认超时下停靠收益、冻结栈可回收性、双加载/决定竞争与恰好一次副作用仍需真实进程/数据库证据，不能从测试定义或设计估算直接宣称完成。
