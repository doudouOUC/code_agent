## 解决了什么问题

Java 模拟 WHATWG 宽松 URL 归一化既复杂又容易与 Node 分叉，非标准 IPv4、空端口或 dot path 可在预检和实际启动得到不同判定。

## 最终实现方案

CLI Harness resolver 与 Java HarnessBrokerUrl 共同要求 http(s)://host[:port][/] 的原始拼写；端口 1–65535，IPv4 必须四段十进制且无前导零，拒 shorthand/octal/hex、空标签/尾点、userinfo/query/fragment、缺失/多余 scheme slash 和非根 path。Node 在 canonical 门禁后仍用 URL；Java 对字面 IPv6 用 JDK 解析并序列化，punycode 等不完整可判定输入保留 UNCLASSIFIED，而非伪装完全实现 WHATWG。

HTTP 仍限 loopback，远程必须 HTTPS；本 PR 当时的 Kubernetes Harness launcher 对 Secret 同样提前拒绝非 canonical URL 并点名变量。共享 fixture 与各侧测试同步。后续 #18118 已将该 launcher/专属测试移入冷归档，当前活动 CLI/Java URL 门禁保留。这里收紧配置接受面，不改变部署身份/凭据验证，也不是 DNS rebinding、重定向或任意出站网络的完整 SSRF 方案。

## 关键代码路径

- `packages/cli/src/serve/managed-runtime-broker-url.ts`：Harness 原始拼写与 origin/loopback 校验。
- `packages/managed-agent-server/server/src/main/java/com/alibaba/qwen/code/managedagent/preflight/HarnessBrokerUrl.java`：Java canonical 预检与 verdict。
